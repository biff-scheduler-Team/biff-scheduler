# PLAN-20260913190500 — 修复账号体系落地后遗留的三处文档/配置漂移

## 目标

2026-09-13 IFFDAY 账号体系（`apps/api` + D1 + OIDC）落地后，仓库里留下三处「文档/配置说的」与
「实际跑的」不一致。本轮把它们逐条对齐到事实，**不改任何运行时行为**：

1. **`biff.iff.day` 是死域名** —— `apps/api/wrangler.jsonc` 的 `APP_ORIGIN` 白名单与
   `docs/account-integration.md` 都写成「两个域名并存、都接受」，但该子域**没有任何 DNS 记录**，
   自定义域名并未挂到 `biff-scheduler` Worker 上（实测见下）。
2. **`PLAN.md` 严重过期** —— §4 白纸黑字写「没有 API」「全站零后端」「D1 已整体退役」，
   §1 架构图里没有 `apps/api` / D1 / OIDC，而仓库实际已是 monorepo。
3. **`AGENTS.md` 部署口径不全** —— 只写「push → Workers Builds 上线」，没写 `postbuild`
   会在 `main` 分支上跑生产 D1 迁移 + 部署前端 Worker 这一整条链。

## 事实基线（本轮动手前的实测证据）

```
dig +short @1.1.1.1 biff.iff.day   → （空）
dig +short @8.8.8.8 biff.iff.day   → （空）
dig +short @1.1.1.1 biff.lcandy.co → 172.67.186.153 104.21.76.38
dig +short @1.1.1.1 account.iff.day→ 172.67.187.45 104.21.56.166
curl https://biff.iff.day/         → 000（连不上）
curl https://biff.lcandy.co/       → 200
curl https://account.iff.day/      → 302
npx wrangler whoami                → Not logged in（本机无法挂 Custom Domain）
```

结论：`iff.day` 这个 zone 是活的（`account.iff.day` 解析正常），但 **`biff` 子域没挂**。

  **值不动** —— 保留白名单是前向兼容，且不会产生坏状态。

## 方案取舍

| 备选 | 结论 | 理由 |
|---|---|---|
| 把 `biff.iff.day` 从 `APP_ORIGIN` 删掉 | 否决 | 它是 2026-09-13（`26b21e0`）**有意引入**的迁移目标，删掉等于撤销既定功能，之后还要再加回来 |
| 本机用 `wrangler` 挂 Custom Domain | 不可行 | `wrangler whoami` = 未登录；且即便挂上，账号系统没登记回调就会变成「能打开但登录失败」的**更坏**状态 |
| 保留白名单 + 文档如实标注「未接入」 | **采纳** | 仓库侧唯一能做到、且不制造新坏状态的修法；把「需要人去控制台点一下」这件事显式写出来 |
| 只改文档、`wrangler.jsonc` 不动 | 否决 | 配置里留一个无解释的死域名，下次还会有人来问「这域名怎么不通」 |
| 顺手把 `PLAN.md` 整体重写成新版 | 否决 | §1/§3 的数据管线部分仍然准确，整体重写会引入新错误；只做**定点**回写 |

1. 全仓库 `grep -n "biff.iff.day"` 的每一处，都在描述「已登记 / 待挂载 / 未接入」，
   没有任何一处断言它当前生效。
2. `PLAN.md` §4 不再出现「没有 API」；§1 出现 `apps/web` / `apps/api` / `packages/contracts` / D1。
3. `AGENTS.md` §6 写明完整部署链（build → postbuild 迁移 + web 部署 → api 部署）；
   §5 的片单口径与实现一致（访客本地、登录后同步到**本人**文档）。
4. `git diff --name-only` 不包含任何 `*.ts` / `*.tsx` 运行时源码。
5. `npm run verify:quick`（typecheck → lint → 单测）全绿。
