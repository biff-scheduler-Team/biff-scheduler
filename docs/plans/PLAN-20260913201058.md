# PLAN-20260913201058 — 把「与 AI 协作的约定」写进三层规范(AGENTS.md / 完整版 / 自动加载副本)

## 目标

现有规范(§0–§8)管的是「AI 拿到需求后怎么做」—— 五步工作流 / 门禁 / 测试 / 提交 / 部署 / 并行协作。

**缺的是上游那一半:需求怎么提、AI 必须先交什么、需求变了怎么记。** 这一半目前只存在于若干次
历史对话与个别 PLAN 的正文里(`PLAN-20260912002532` 的「硬约束:PC 端零影响」、
`PLAN-20260913184357` 的「修订 1」、`parallel-agent-safe-commit` 的踩坑清单),没有沉淀成规范。

本轮把它补成 **§9「与 AI 协作的约定」**,并保持仓库既有的三层文档纪律:

- 用户侧:只描述「症状 + 约束」,不指定实现;长期约定一次讲清、写进规范,之后不再重复叮嘱。
- AI 侧:交付物固定为 PLAN(含「不做」与取舍表)+ 回归测试 + 证据,缺一即返工。

## 范围

**做:**

- `docs/DEVELOPMENT-STANDARDS.md`:新增 **§10「与 AI 协作的约定」**(完整版,含三档需求的提问模板、
  五条话术纪律、可复制的 PLAN 模板、交付物清单、反模式);§9 变更记录追加 v5。
- `AGENTS.md`:新增 **§9「与 AI 协作的约定」**(精简版,指向完整版),与 §0–§8 同一体例。
- `.codebuddy/rules/biff-development-standards/RULE.mdc`:同步 §9 精简版
  (该文件是 `AGENTS.md` 的等价副本,且是 IDE 每次自动加载的那一份 —— 不同步等于新规范不生效)。
- `PLAN.md`:§0 快照加一条,更新页眉「最后更新 / 上一轮」。

**不做:**

- **不改任何运行时源码**(`apps/web/src/**`、`apps/api/src/**`、`e2e/**`、`tests/**` 一律不碰)。
- **不新增 / 修改任何测试** —— 本轮无行为变更,无回归测试可写(`npm run verify:quick` 仍须全绿)。
- 不重排 §0–§8 的编号(新增章节一律追加在末尾,避免整篇 renumber 带来的无谓 diff)。
- 不改 `docs/CONVENTIONS.md`(本轮不涉及任何代码口径)。

## 方案取舍

| 备选 | 结论 | 理由 |
|---|---|---|
| 只写进 `AGENTS.md` | 否决 | `AGENTS.md` 自称是「完整版」的入口,只在入口加章节会立刻产生文档漂移 —— 仓库刚为同类问题开过一轮 `PLAN-20260913190500` |
| 只写进 `docs/DEVELOPMENT-STANDARDS.md` | 否决 | 该文件是「改代码前必读」,不是每轮对话都会加载;要「用起来顺手」必须落在自动加载的那一份上 |
| 三层同步(完整版 + `AGENTS.md` + `.codebuddy` 副本) | **采纳** | 与既有 §0–§8 的分工完全一致:完整版放论证与模板,入口放可执行条款,副本保证 AI 每轮都看得到 |
| 新建独立文件 `docs/AI-COLLABORATION.md` | 否决 | 规范一分为二后,「冲突以谁为准」又要多一条;而且独立文件不会被自动加载 |
| 把 §9 插在 §1 后面(逻辑位置更顺) | 否决 | 会导致 §2–§8 全部 renumber,产生与内容无关的巨大 diff;追加在末尾 + 开头一句说明即可 |
| 顺带把 §0–§8 也改写一遍 | 否决 | 一次提交只做一件事;现有条款是刚定稿的,无改写必要 |
