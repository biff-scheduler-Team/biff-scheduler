# PLAN-20260914141643 — 修正「素香剧场」分区口径（旧版归到了南浦洞）

> 本文件 = 本需求唯一规划文档；**只读本 PLAN，不整读 `PLAN.md` 活文档**。

## 目标

用户转来的现场反馈原话：

> 有一个问题 东西大学 Sohyang Theatre 显示分区在南浦洞 我理解应该不是吧？应该就是主会场旁边的那个
> …那这里的分区可能有点误导性

**定位结论（均为实读代码事实，非推测）**：分区文案写错的那一份在**旧版 `/legacy/`**，
新版（React）早就是对的 ——

| 来源 | sohyang 的分区 | 位置 |
|---|---|---|
| 数据 | `region: "centum"` | `apps/web/public/venues.json`（`id: "sh"`） |
| 新版文案 | `CENTUM 主场区 · 东西大学 Sohyang Theatre` | `apps/web/src/legend.ts:111` |
| 旧版文案 | **`南浦洞 · 东西大学 Sohyang Theatre`** | `apps/web/legacy/src/legend.ts:342` |

旧版这条还与项目自己记的官方三区模型相左 —— `docs/history/2026-09-09-开发落地记录.md:263`：
**Centum 主场区 = BCC / CGV Centum / LOTTE Centum / KOFIC / Sohyang / Community Media Center**；
南浦洞只有 BIFF Square / MEGABOX Busan Theater / Catholic Center Space 101.1。
即 2025 导入时把 `sohyang`、`bcm` 误归南浦洞（`docs/plans/PLAN-20260910122007.md:34` 的「nampo：megabox→sohyang→bcm」），
新版重写时按官网口径纠正了，旧版作为冻结件把错误留在原地。

判定截图来自旧版的依据：场次行是 `[CODE][影院码]时间[时长]…` 单行结构 + 票价章在行右缘
（`legacy/src/row.ts:245-266`、`legacy/src/agenda.ts:520-542`），且 tooltip 只有 3 行、**没有地址行**
（新版 `venueTip` 一定带地址，见 `apps/web/src/legend.ts:238-250`）。

## 范围

**做：**

1. 旧版 `GROUP_AREA` 把 `sohyang` / `bcm` 归回 `CENTUM 主场区`，并同步更新冻结闸门
   `apps/web/legacy/source-manifest.json`（否则 `legacy-snapshot.test.ts` 必红）。
2. 新版残留：`FilterBar` 的「南浦洞」分区预设按钮在 2026 数据下**零命中**（点了没反应的死控件）
   → 改成**按数据渲染**（哪个分区真的有厅才出按钮），并把这条口径抽成纯函数
   `apps/web/src/filters.ts::regionPresets()` 以便单测。
3. 新增**分区口径一致性**回归测试（数据 ↔ 新版文案 ↔ 旧版文案）。
4. 同步 `docs/CONVENTIONS.md` 的分区口径段。

**不做：**

- **不改** `apps/web/public/venues.json` / `schedule.json` —— 数据本来就是对的。
- **不删** 新版 `GROUP_AREA` 的 `megabox` 条目（理由见方案取舍 A）。
- **不动** legacy 的其它口径（`legacy/src/filters.ts` 的分区预设本来就是按 `region` 数据驱动的，无需改）。
- **不退役** legacy（`docs/legacy-retirement.md` §三 判据未到）；**不引入** React 组件 / 样式进 `legacy/`。
- **不改** `REGION_LABEL` / `regionLabel()` / `types.ts` 的 `nampo` 枚举 —— `nampo` 是合法分区值，
  只是 2026 没有影院落在那一区。
- **不加** E2E 用例（`legacy.spec.ts` / `compatibility.spec.ts` 只保留「能打开」「共享数据」两层语义）。
- 不碰上一轮账号一体 / 桌面分栏（`PLAN-20260914003600`）的任何文件。

## 方案取舍

| 备选 | 结论 | 理由 |
|---|---|---|
| A. 删掉新版 `src/legend.ts:110` 的 `megabox: "南浦洞 · …"` | **否决** | MEGABOX Busan Theater 本来就属南浦洞（官方三区模型，见 `docs/history/2026-09-09-开发落地记录.md:263`），它只是**本届未参与** —— 删掉是丢掉一条**正确**信息，不是清残留。改为补注释写明它只服务未参与的影院 |
| B. 旧版 `GROUP_AREA` 的 `sohyang` / `bcm` 改为 `CENTUM 主场区` | **采纳** | 与官方口径、与 `venues.json` 的 `region`、与新版三者对齐；这是**事实性错误**而非体验优化，属冻结条款允许的例外（用户 2026-09-14 明确授权） |
| C. 旧版不动，只引导用户用新版 | 否决 | 旧版是回退件、可能被长期使用；错误分区会继续误导现场找路 |
| D. `FilterBar` 直接删掉「南浦洞」按钮 | 否决 | 硬编码删 = 换回有南浦洞场次的届次时又要改代码；按数据渲染则换 JSON 自动跟着变 |
| E. `FilterBar` 保留按钮（点了没反应） | 否决 | 这正是「误导性」本身 |
| F. 把新版 `GROUP_AREA` 也改成从 `venues.json` 的 `region` 派生 | 否决 | 会改变文案（`GROUP_AREA` 带影院中文名，`venues.json` 只有厅名），超出本需求；本轮只用测试把两边的**分区前缀**钉在一起 |
| G. 删掉 `legacy/src/legend.ts` 的 `megabox` 条目 | 否决 | 同 A；且旧版是冻结件，能少动就少动 |

## 验收标准

1. 新增 `apps/web/tests/venue-region-parity.test.ts` 绿：`venues.json` 每个 `group` 的 `region`
   ↔ 新版 / 旧版 `GROUP_AREA` 的分区前缀，三者一致；把旧版改回「南浦洞」必红（先红后绿，红值见提交 body）。
2. `apps/web/tests/filters.test.ts` 新增用例绿：2026 数据（全 `centum`）只出「主场区」；
   注入一个 `region: "nampo"` 的厅后「南浦洞」才出现。
3. `npm run verify`（typecheck → lint → 单测 → build）全绿，证据贴测试计数。
4. 线上 `https://biff.lcandy.co/legacy/` 里 `SH` 章的 hover 显示
   `分区 — CENTUM 主场区 · 东西大学 Sohyang Theatre`；新版行为不变。
