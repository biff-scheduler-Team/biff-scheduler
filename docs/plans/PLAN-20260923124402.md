# PLAN-20260923124402 — 红黑榜投票行自查接口（查「线上那两张贴纸是谁贴的」）

## 目标

用户原话：

> https://biff.lcandy.co/redblack 线上两张贴纸分别是谁贴的
> 我感觉是之前 gaaiyeoi 丢失登录态 然后变成匿名存进去的 这样就永远变成死贴纸了?
> 我没有这个账号的权限 你还是写个接口?

现状（已核实，非推测）：

- 线上公开接口只有**聚合数**，且这是刻意口径（`apps/api/src/index.ts:553-556`）。
  实测 `GET /api/stats/film-votes?edition=biff-2026` 当前返回
  `{"cat:f001":{"red":1,"black":0},"cat:f002":{"red":0,"black":1}}` —— 两张贴纸分别在
  《彼此的日夜》与《蓦然回首》上，各 1 票。
- 「谁贴的」只存在于生产 D1 的 `film_vote_contribution.contributor`：登录期是 IFFDAY `subject`，
  匿名期是 `anon:<SHA-256(匿名 cookie) base64url>`（`apps/api/src/crypto.ts:16`、
  `apps/api/src/index.ts:586-602`）。
- 用户**没有**该 CF 账号（`62cbe67b…`）的任何权限：dashboard 进不去，本机 wrangler 登录的是
  另一个账号（`c591765d…`，旧 Pages 账号），远程查询被 7403 拒绝；仓库 / GitHub CI 里也不存在
  任何 Cloudflare 凭据（部署走 CF 侧的 Workers Builds），所以「加个 workflow 跑 d1 execute」这条路
  同样不通。

因此本需求的唯一可行交付：**在 Worker 里加一个读接口**，靠 `push main` 部署后自查。

## 范围

**做：**

- 新增 `GET /api/account/film-vote-contributions?edition=biff-2026`，挂在 `/api/account/*` 下
  （自动继承既有的 `requireIdentity` 中间件 → 未登录 401，不新造鉴权）。
- 返回**投影**，不返回任何 contributor 原文：

  ```json
  {
    "edition": "biff-2026",
    "truncated": false,
    "mine":    [{ "filmKey": "cat:f001", "vote": "red",   "updatedAt": 1758600000000, "anonymous": false }],
    "others":  [{ "filmKey": "cat:f002", "vote": "black", "updatedAt": 1758600000000, "anonymous": true }],
    "thisBrowser": { "hasAnonCookie": true, "matched": [] }
  }
  ```

  - `mine` = `contributor === 我的 subject` 的行；
  - `others` = 其余行，只给 `filmKey` / `vote` / `anonymous`(布尔) / `updatedAt`；
    **字段名走 camelCase**（与 `/api/account/sync`、讨论区 / 反馈的 DTO 一致，库里那套
    snake_case 不外漏）；
  - `thisBrowser.matched` = **本浏览器**匿名 cookie 算出 `anon:<hash>` 后命中的行 ——
    这是唯一能证明「那枚匿名票是不是这台机器贴的」的判据；
  - `truncated`：命中 `MAX_VOTE_ROWS`(500) 上限时置 true。**不静默截断** —— 这是给人下结论用的
    接口，「没看到」被读成「不存在」比报错更糟。
- `film-vote-store.ts` 新增 `readVoteRows`（一次读出该 edition 的贡献行，限 500 行）与
  `auditVoteRows`（纯投影函数，白名单复用 `film-vote-stats.ts::isFilmVote`）。
- 单测：`apps/api/tests/film-vote-audit.test.ts`（纯函数分档 + d1 垫片上跑真 SQL）。

**不做：**

- ❌ 不返回 `contributor` 原文（subject / anon hash 都不回）—— 裸接口会把全站投票者的账号 id
  暴露出去，那是 `apps/api` 目前**唯一**一处隐私破例，代价远大于本次排查收益。
- ❌ 不做 `ADMIN_TOKEN` 之类的管理门禁 —— 设不了（用户没有该账号后台 / wrangler 权限）。
- ❌ 不做「撤回别人的票」「把匿名票 claim 到账号下」—— 那是下一步的功能，本轮只读。
- ❌ 不动 D1 schema、不加迁移、不动 `apps/web/**`。
- ❌ 不解决「匿名票永久不可撤」这个机理问题（PLAN 只描述、不修）。

## 方案取舍

| 备选 | 结论 | 理由 |
|---|---|---|
| CF 控制台 D1 Console 跑 SQL | 否决 | 用户没有 `62cbe67b…` 的 dashboard 权限（已实测） |
| GitHub Actions + `wrangler d1 execute` | 否决 | 仓库与 CI 里没有任何 CF 凭据（部署是 CF 侧 Workers Builds） |
| 裸公网接口直接回 contributor 行 | 否决 | 泄漏全部投票者身份；且匿名行本来也不可反查，收益为零 |
| `ADMIN_TOKEN` 门禁的接口 | 否决 | 需要 `wrangler secret put`，用户没权限 |
| **登录门禁 + 「我的 / 本浏览器」投影** | **采纳** | 零 secret、零隐私破例；能回答「这些票里哪些是我名下的」+「本机匿名 cookie 是否命中」 |

## 验收标准

1. `auditVoteRows` 单测覆盖：我名下 / 别人（登录与匿名）/ 坏 vote 行丢弃 / `hasAnonCookie=false` /
   匿名 cookie 命中与不命中。
2. `readVoteRows` 在 `tests/d1-shim.ts` 的内存 SQLite 上跑真 SQL 通过（证明 SQL 与 drizzle 用法可用）。
3. `apps/api` typecheck + lint + 该目录单测通过；`npm run check:test-map` 仍绿（未改映射）。
4. 部署后手测（用户侧）：
   - 未登录 `curl https://biff.lcandy.co/api/account/film-vote-contributions?edition=biff-2026` → 401；
   - 登录后同 URL → 拿到 `mine` / `others` / `thisBrowser`，据此判断那两张贴纸的归属。
   - ⚠ 判读前**不要在 /redblack 上动任何贴纸**：登录后一旦 ping，`clearAnonContributions` 会把这个
     匿名身份的行全清掉（`apps/api/src/screening-stats-store.ts:169-188`），证据就没了。
