# PLAN-20261005195116 — 收窄「小改动走 PR」判据 + 明确 `main` 全量 E2E 不阻塞交付

## 目标

用户观察:每轮部署收尾都要写「等 `main` 的全量三浏览器 CI 跑完」,而它要 5–9 分钟;且**小功能也要全量**。
用户提出的模型是「测试跑在远程、有问题再反馈」+「小功能走 PR(CI 只跑受影响 spec),合并 main 才触发全量 + 部署」。

用户原话(不转述):

> 为什么经常跑这个"部署已核实（新 bundle main-DlxRSs6z.js 带 clientId + redblackpending.v2，老 bundle 两个都没有；API 新路由 401 而非 404）。等 main 的全量三浏览器 CI 跑完：" 而且需要很久 一个小功能也要全量跑吗?
>
> 而且我觉得本来应该在远程全量 E2E 然后有问题我再和你说 然后小功能改走 PR：CI 自动只跑受影响 spec（chromium），合并到 main 才触发全量 + 部署。?是不是应该这样?

## 范围

**做:**

1. **交付口径**(`AGENTS.md` §2 / `docs/DEVELOPMENT-STANDARDS.md` §2 / 本机 `RULE.mdc` §2):
   明确「§6 部署核对(asset hash + 自增字符串 + 阴性对照)完成即视为**上线成功**;`main` 上的全量三浏览器 E2E 是
   **非阻塞的事后体检**,交付话术里**不写「等 CI 跑完」**,结果另行跟进」。
2. **PR 判据收窄**(`AGENTS.md` §4 / `DEVELOPMENT-STANDARDS.md` §4.5 / `RULE.mdc` §4):
   由「默认直接 push,只有三类走 PR」改为 **先按 `docs/TEST-MAP.md` 判** ——
   `node scripts/affected-specs.mjs --files <path>` 输出 **≥1 个业务 spec(非仅 `smoke`,含 `allOn` 全量)→ 走 PR**;
   **仅 `smoke` / 无映射 → 直接 push `main`**。原三类(大规模重构、`apps/api` / D1 迁移、依赖升级)**无条件走 PR** 保留。
3. **订正过期表述**:`DEVELOPMENT-STANDARDS.md` §4.5 第 3 条「PR 不能替代本地门禁」与 §2「本地不跑门禁」矛盾,一并改成
   「PR 不承担部署前门禁(那是 Cloudflare 构建的职责),也不等于『合并前跑过全量』」。
4. 变更记录加 **v11**。

**不做:**

- 不改 `.github/workflows/ci.yml`(PR 仍跑受影响 spec/chromium;`main` 仍跑全量三浏览器)。
- **不**把全量 E2E 改成部署前置(否决,见取舍表)。
- **不**动 `main` 的全量体检本身(它是唯一的 webkit 兜底)。
- 不碰仓库里另一会话的在途改动(`RedBlackPage.tsx` / `redblack-parity.css` / `StickerSkinWheel.tsx` /
  `e2e/react/redblack.spec.ts` / `docs/plans/PLAN-20261005183113.md`)—— 见 §7 并行协作。

## 方案取舍

| 备选 | 结论 | 理由 |
|---|---|---|
| 所有小功能都走 PR | 否决 | 只映射到 `smoke` 的改动(纯文档 / 内部重构)收益≈0,只多一步流程 |
| **按 TEST-MAP 命中判据走 PR** | **采纳** | 判据机械可查(`scripts/affected-specs.mjs`),收益与 spec 覆盖面成正比 |
| `main` 改成按 diff 跑受影响 spec | 否决 | `main` 全量是唯一的跨浏览器(webkit)兜底;且它本来就不阻塞交付 |
| 全量 E2E 变成部署前置 | 否决 | 换来「每次发布先等 5–9 分钟」,小改动不划算;要合并前保障走 PR 判据 |
| 交付话术明确「不等全量」 | **采纳** | 现状本就非阻塞,是叙述在误导 |

## 验收标准

1. 三处口径一致:`AGENTS.md` §2/§4、`docs/DEVELOPMENT-STANDARDS.md` §2/§4.5/变更记录、本机 `RULE.mdc` §2/§4
   互不矛盾,且与 `ci.yml` 实际行为对得上。
2. `npm run verify:quick` 通过(`check:repo` / `check:test-map` 不因本次文档改动变红)。
3. 判据可执行性用真实举例验证:
   `node scripts/affected-specs.mjs --files apps/web/src/pages/RedBlackPage.tsx` 输出含 `redblack`(→ 走 PR);
   纯文档路径(如 `docs/CONVENTIONS.md`)输出仅 `smoke`(→ 直推 `main`)。
