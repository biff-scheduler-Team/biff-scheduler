# PLAN 2026-09-11 23:05 — 方案对比:同一部片只留一场

> 需求(用户原话 + 截图):
> 「顶部的方案为什么会出现 071 和 027 峡湾在一个方案里面?请你看看这里是不是有问题」
> 截图里「方案 1 最优先 · 顺位 1+1」两行都是《Fjord · 峡湾》。

## 1. 问题定性

**不是渲染 bug,是「方案枚举」的语义缺口。**

用户行程里的真实结构(已用 `public/schedule.json` 核对):

| code | 影片 | 时间 | 影厅 |
|---|---|---|---|
| 027 | Fjord · 峡湾 | 10/07 12:20–14:46 | C3 |
| 071 | Fjord · 峡湾 | 10/08 09:00–11:26 | BH |
| 005 | Satoko Always · Satoko总是这样 | 10/07 12:20–15:03 | BH |
| 089 | Possible Love · 可能的爱情 | 10/08 09:00–12:09 | CX |

* 冲突组按 `date` 分桶 ⇒ 组① = {027, 005}(10/7 12:20 同开)、组② = {071, 089}(10/8 09:00 同开);
* **027 与 071 是同一部片**,但分属两组、各自又是组内顺位 1;
* `方案 = 「每个冲突组各取一场」的所有组合`、`成本 = Σ 各组所选顺位`
  ⇒ `027+071` 成本 1+1 = 2,稳居「最优先」那套 —— 读起来就是**同一部片看两遍**。

文档里甚至把这个组合当预期产出写了进去(`PLAN-20260911223000` §1 末:`005+071 / 005+089 / 027+071 / 027+089`)——
说明当时只把「同片多场」当成两个互相独立的备选槽位,漏掉了「一套方案里不能出现同片两场」这条约束。

## 2. 关键决策

### D1. 去重放在**枚举维度**(picks 之间),不是「把同片当成冲突边」

把同片多场当作冲突边 → `conflictGroups()` 的连通分量会把组①组②**合并成一个大组**(027~005、071~089、
027~071 三条边连通),方案退化成「每套只保一场」,`005+089` 这种完全可行的组合也会消失。故不采用。

现行做法:枚举出组合后,若组合里出现**两部同片**,该组合**直接剔除**(不进 `options`,计入 `droppedSameFilm`)。
剔除后成本层会自然往上走、补上下一批可行组合,所以「套数变少」是唯一表现,**不会出现空窗**。

### D2. 影片身份复用 `util.ts::filmNodeKey`

与网格 / 影片库 / 详情弹层**同一口径**(`cat:<目录 id>` / `sched:<片名>`),不在 `plans.ts` 里另立一套。
`plans.ts` 仍是纯函数 —— 由调用方注入 `filmKeyOf: (code) => string | null`
(`main.ts::computePlanSet` 传 `filmKeyOfCode`)。返回 `null`(排期换版后查不到该 code)的场次**不参与判定**:
宁可不判,不误杀。

### D3. 兜底:去重后一套都不剩 → 退回不去重结果

若每个冲突组的成员恰好都是同一部片的两场(同日不同厅、时间重叠),所有组合都会被判死。
此时**退回不去重的结果**(`droppedSameFilm` 归零):宁可比对里出现同片重复,也不给一个空列表
(空列表会让「方案对比」整块不渲染,用户反而看不到任何东西)。

### D4. 把「为什么少了一套」交代给用户

`PlanSet` 新增 `droppedSameFilm`;`agenda.ts::buildPlanCompare` 在其 > 0 时追加一行
「已剔除 N 套「同一部片排了两场」的组合」+ 副标题补「同一部片只保留一场」。
否则「明明有 4 种组合,为什么只列 3 套」会变成新的疑问。

## 4. 已知边界(本轮不做)

* **共同场次与 pick 同片**:去重只作用在 picks 之间;若某个共同场次(不属于任何冲突组)与某个 pick 同片,
  那一套里该片仍会出现两次。修它要先定义「共同场次 vs 冲突组同片谁让路」,属新语义。
* **跨午夜的相邻两日**仍不成冲突组(`conflict.ts` 按 `date` 分桶)—— 继承既有口径,与 `PLAN-20260911223000` §5 同。
* `PlanSet.total` 仍是 ∏|组|(原始组合数),**不扣**去重剔除数;UI 只在 `truncated` 时展示它,不构成误导。
