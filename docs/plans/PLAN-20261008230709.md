# PLAN-20261008230709 — 贴纸视觉尺寸归一 + 分享图我那一枚去白描边 + 出图倍率用满安全像素

## 目标

红黑榜分享图刚加上影片海报缩略图（`PLAN-20261008225335`）后，用户看实机出图提了三条：

> 请你统一一下贴纸大小 然后就是红黑榜分享的截图需要高清一点 因为加上了海报
> 然后就是有一些贴纸(胶片尺孔)有白底 导致分享出来不好看

三条**已逐条确认口径**（2026-10-08 追问后）：

1. **统一贴纸大小** = **三款皮肤之间拉齐**：票根 / 胶片残片 / 胶片齿孔 在同一个 32 设计盒里
   视觉占位差很多（实测顶点环面积 **470 / 463 / 280**），并排看就是「大小不一」。
2. **白底** = **分享图里「我贴的那一枚」沿轮廓那一圈近白描边**（`C.ink` `#f4f4f6`）。
3. **高清** = 出图倍率**按面积上限反算成连续值**，用满安全像素；不碰「超限静默出空图」那条风险。

## 范围

**做：**

- `apps/web/src/sticker-shape.ts`：三款轮廓按**视觉面积**归一（目标 = 三款原始面积均值，
  绕设计盒中心等比缩放；`sharp` 标记与「形状只有一处实现」不变）。
- `apps/web/src/redblack-poster.ts`：
  - 「我那一枚」的描边由 `C.ink`（近白）改为海报自己的强调色 `C.note`（琥珀），线宽 1.6 → 1.2；
  - **补上中心微图标的 `clip(body)`**（贴纸区与行内色标两处）：`sticker-sprite.ts` 第 ⑤ 步一直是
    「先裁到轮廓内再印图标」，海报这两处漏了 —— 胶片残片那种窄条比图标矮，不裁就会从贴纸两侧探出
    两撮白边（同属用户说的「有白边不好看」，且会让「图像与卡片长得不一样」）；
  - 画布尺寸 / 变换改走新的 `posterPixels()`。
- `apps/web/src/poster-brush.ts`：`posterScale` 由「2 或 1」改成**连续倍率**
  （`min(SCALE, √(MAX_PIXELS/(w·h)), MAX_SIDE/max(w,h))`，下限 1）；新增 `posterPixels()`
  （逻辑尺寸 → 物理像素 + 倍率，**取整只在这一处**）。
- `apps/web/src/poster.ts`：`drawPoster` 同样走 `posterPixels()`（两张分享图一个口径）。
- `apps/web/src/components/RedBlackShareDialog.tsx`：尺寸提示用 `posterPixels` 的整数，
  否则非整数倍率下会印出 `1566.0000000000002 px`，且 E2E 的 `(\d+) × (\d+) px` 正则也匹配不上。
- 单测：`sticker-shape.test.ts` 增「三款视觉面积一致」守卫；`poster.test.ts` 增
  「出图倍率按面积取连续值」一组断言。
- E2E：`redblack.spec.ts` 那条「宽度是 1080 / 2160 之一」放宽成区间断言。

**不做：**

- 不动 `STICKER_SIZE`（页面贴纸仍是 24px）、不动分享图贴纸区的 `FIELD_STICKER`（14px）——
  用户已明确「不一致」指的是**三款皮肤之间**，不是分享图与页面之间。
- 不动分享图左侧「我贴的那一色」色标（24px）—— 它是**另一列**的标记，不是贴纸区里的贴纸。
- 不引入「先按 2× 出图、失败再回退 1×」那条路：iOS 超限时是**静默出空图**（不抛错、也拿不到
  可判定的失败信号），按面积反算连续倍率是唯一不碰这条风险的写法。
- 不动 `legacy/`（只读回退件）；不动页面 `.rb-dot` 的常驻纸白边（那是页面上的刻意设计）。
- 不新增颜色 token：琥珀色复用海报配色里已有的 `C.note`。

## 方案取舍

| 备选 | 结论 | 理由 |
|---|---|---|
| 三款轮廓按**视觉面积**归一（目标取三款均值） | 采纳 | 用户说的「大小不一」正是**感知面积**问题；票根 470 / 齿孔 463 只缩 7%，残片 280 放大 20%——都在肉眼难察的范围，而并排的失衡消失 |
| 按**包围盒**归一（三款都撑到 24×24） | 否决 | 残片是根斜窄条，包围盒对齐后**看上去**仍比方形小 —— 这正是当前的问题 |
| 放大到三款里**最大**那个面积 | 否决 | 残片要放大约 1.28 → 顶点被顶出 32 设计盒（实测它最多只放得下 409 < 470），只能再夹取，一夹取就又不一致 |
| 手调三款顶点数值 | 否决 | 只要有人改一款就得重新手算另外两款；归一写成一个函数，三者自动一致，且新形状进来自动跟随 |
| 「我那一枚」**去掉描边** | 否决 | 用户 2026-09-23 明确要求「自己那枚始终找得到」（页面那圈常驻纸白边就是为它加的）——去掉是丢信息，不是修缺陷 |
| 「我那一枚」改用**贴纸本色的亮档**（红→`red2`） | 否决 | 海报配色里 `red` 与 `red2` 在 14px 上几乎同色，红贴上等于没画（页面上选白就是因为这个） |
| 「我那一枚」改用 `C.note` 琥珀 | 采纳 | 深底海报自己的强调色；红贴 / 黑贴上都够对比；不像白色那样被读成「这枚贴纸自带白底」 |
| 出图倍率改成连续值 | 采纳 | 现在的判定是「2 或 1」：1080×6900 这类长图（三榜 TOP10 + 我贴过的十几行）面积一超就**直接掉回 1×**，海报缩略图只有 59px 物理宽 → 加上海报后糊得最明显 |
| 抬 `MAX_PIXELS` 让长图也能 2× | 否决 | 那条上限就是 iOS 的单张画布面积上限（超了静默出空图），抬它等于赌机型 |

## 验收标准

1. `npx vitest run apps/web/tests/sticker-shape.test.ts apps/web/tests/poster.test.ts
   apps/web/tests/redblack-poster.test.ts` 全绿（含新增：三款视觉面积一致、连续倍率取满安全像素）。
2. `npm run verify:quick` 绿（typecheck + lint + 单测 + `check:repo` / `check:test-map`）。
3. 本地渲染实测（**已核对**）：同一份数据（12 部我贴过 + 三榜 TOP10）出图**由 1080×5400(1×)
   变成 1788×8944(1.66×)**，海报物理宽由 59px 提到约 98px；
   `npx playwright test -c playwright.react.config.ts e2e/react/redblack.spec.ts --project=desktop-chromium` 仍绿。
4. 并排看三款皮肤（放大渲染核对过）：票根 / 胶片残片 / 胶片齿孔 的视觉大小一致；
   分享图里「我贴的那一枚」不再有白描边，改为一圈琥珀色细边。
