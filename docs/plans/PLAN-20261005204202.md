# PLAN-20261005204202 — 「建议反馈」免登录即可发帖与点反应

## 目标

用户 2026-10-05 反馈：

> 「建议」区域不需要登录也能评论

现状（读代码还原的机制，非推测）：`pages/FeedbackPage.tsx` 在提交前挡了一道
`if (!authed) { requireLogin(); return; }`，按钮在未登录时渲染成「登录后发布」；
后端 `POST /api/feedback` 与 `POST /api/feedback/:id/reactions` 都挂了 `requireIdentity`
（`apps/api/src/index.ts:507` / `:528`）。文案也明写「任何人可读；登录后可发帖与反应」。

用户已拍板的三条口径：

1. **放开范围** = 发帖 + emoji 反应都可匿名（**删除仍要登录**）；
2. **匿名署名** = 固定「匿名观众」（不新增昵称输入项）；
3. **加限流** = 复用 `rate-limit.ts` 的 isolate 内存固定窗口器挡匿名刷屏。

## 范围

**做：**

- **后端免登录写**（`apps/api/src/index.ts`）：
  - `POST /api/feedback`：去掉 `requireIdentity`，改用 `optionalSession`；无会话时身份 =
    匿名 cookie 派生的 `anon:<hash>`（与全站统计 ping **同一枚 cookie**，见下），署名为
    `FEEDBACK_ANON_DISPLAY_NAME`；有会话时仍用账号 subject + profile 昵称。
  - `POST /api/feedback/:id/reactions`：同上（无会话走匿名 subject）。
  - `GET /api/feedback`：`mySubject` 追加匿名分支，否则匿名者刷新后看不到自己点过的反应
    （`myReactions` 恒空 → chip 不亮）。
  - `DELETE /api/feedback/:id`：**不动**（仍 `requireIdentity`）。
- **匿名身份抽成单一实现**（`apps/api/src/index.ts`）：新增 `anonContributor` / `dropAnonContributor`，
  并**替换 5 处既有的内联复制**（want-ping / screening / film-votes / tickets / telemetry）。
  理由见「方案取舍」第 1 条。
- **限流**（`apps/api/src/rate-limit.ts` + `index.ts`）：新增 `FEEDBACK_WRITE_RATE_LIMIT`
  与 `feedbackLimiter`，挂到两条匿名写路由上（`limited()` 按 `scope + IP` 分桶）。
  - ⚠ **自查发现的真实缺陷，一并修掉**：`limited()` 原先固定用 `c.req.path` 做桶键，
    而 `POST /api/feedback/:id/reactions` 的路径**含动态段** → 每个帖子 id 各开一个 20 次额度桶，
    限流形同虚设。改成 `limited(limiter, scope?)` 可显式传固定 scope，该路由传常量
    `"feedback:reactions"`；并补了一条跨帖共用额度的断言（改前断言实测为红：`expected 200 to be 429`）。
- **匿名署名常量**（`apps/api/src/feedback.ts`）：`FEEDBACK_ANON_DISPLAY_NAME = "匿名观众"`
  —— 与红黑榜评语前端兜底文案同名（`FilmCommentsDialog.tsx:171`）。
- **前端**（`apps/web/src/pages/FeedbackPage.tsx`）：提交 / 点反应去掉登录前置；未登录也渲染
  「发布」；文案改成「无需登录即可发帖与反应」；`429` 给一条可读提示。
- **回归测试**：
  - 新增 `apps/api/tests/feedback-anon-route.test.ts`（真 `app.request()` + `d1-shim` 内存库）：
    匿名 201 + 署名「匿名观众」、匿名 cookie 才能看到自己的反应、匿名 reaction 可 toggle、
    超出额度 429、登录态仍走账号 subject。
  - 改写 `e2e/react/feedback.spec.ts` 第一条：由「客人被挡在登录弹层」→「客人不发登录也能发帖 + 点反应」。

**不做：**

- **不做匿名删除**。用户选的档位不含「删自己的」；匿名帖因此**作者本人也删不掉**（只能走后端管理端，
  而反馈板目前没有管理端删除接口）。这条当**已知欠账**记在 PLAN 里，不在本轮补。
- 不动 `DELETE /api/feedback/:id` 的鉴权与 `canDeleteFeedbackPost`。
- 不动场次讨论（`/api/discussions`、`/api/screenings/:code/discussion`）—— 它前端已整体下线
  （见 `docs/CONVENTIONS.md`），改它没有收益。
- 不新增 D1 迁移：`feedback_post.subject` / `display_name` 都是 `TEXT NOT NULL`，
  `anon:<hash>` 与「匿名观众」都装得下。
- 不引入 KV / Durable Object 做限流（那要改 `wrangler.jsonc`，且要单独跟用户确认）。
- 不动仓库里另一会话的在途改动（`RedBlackPage.tsx` / `redblack-parity.css` / `StickerSkinWheel.tsx` /
  `e2e/react/redblack.spec.ts` / `PLAN-20261005183113.md` / `PLAN-20261005195116.md`），见 AGENTS §7。

## 方案取舍

| 备选 | 结论 | 理由 |
|---|---|---|
| 匿名身份**复用**全站那枚 `biff.want` cookie（`anon:<hash>`） | **采纳** | 全站只有一份「这台机器是谁」；另发一枚等于同一浏览器两个匿名身份，反应 / 统计两套归属迟早打架 |
| 为反馈**单独发**一枚匿名 cookie | 否决 | 会产生第二个匿名身份（见上）；且要多一份 cookie 生命周期与清理逻辑 |
| 在反馈路由里**再抄一遍**匿名身份的内联写法 | 否决 | 那会变成第 6 份复制 —— 红线 5「同一口径写第二份实现」；`film-vote-store.ts:580` 已把这条欠账留痕 |
| 顺手把 5 处内联复制抽成 `anonContributor` 并全量替换 | **采纳** | 机械替换、行为不变；不抽的话第 6 处就是新欠账。**这是本轮唯一超出发帖本身范围的动作，理由写在这里** |
| 匿名也允许 `DELETE` 自己的帖 | 否决（本轮） | 用户选的档位不含它；且登录会清匿名 cookie → 归属会漂移，语义要另立 |
| 不加限流，先开口子 | 否决 | 用户明确选「加限流」；匿名写没有账号可封，isolate 内存窗口是零成本的第一道闸 |
| 登录态但 profile 拉不到时返回 503 | 否决 | 与 `optionalSession` 对公开读的降级口径一致：署名为展示信息，退回「匿名观众」但不阻塞写入 |
| 读路径（`GET`）也创建匿名 cookie | 否决 | 其余公开读端点都不在 GET 上下发身份；反应状态靠「POST 时建的那枚 cookie」在下次加载时对齐即可 |

**已知代价（写清楚，别当没有）：**

- 匿名帖**不可删**（作者与登录用户都删不掉，`canDeleteFeedbackPost` 判定的是账号 subject）。
- 登录会把匿名 cookie 整份撤掉（`clearAnonContributions`），所以「匿名点过的反应」在登录后
  会变成撤不掉的残留 —— 与红黑榜「匿名死贴纸」是同一类已知问题，出口仍是既有的管理端认领 / 删除。
- 限流是 **isolate 内存固定窗口**，跨 isolate / 冷启动会重置，挡不住有规模的刷屏
  （边界与既有 ping 限流完全一致，见 `rate-limit.ts` 文件头）。

## 验收标准

1. 未登录打开 `/feedback`：能直接写内容并「发布」，卡片出现且署名「匿名观众」；能点亮 emoji chip。
2. 未登录刷新页面后，自己点过的 emoji 仍为 `aria-pressed="true"`（`GET` 回填 `myReactions`）。
3. `POST /api/feedback` 未登录第 1 条返回 `201`；同一 IP 超过额度返回 `429`（带 `Retry-After`），
   前端提示「操作太频繁，请稍后再试。」。
4. 登录态行为不变：署名仍是账号昵称，`DELETE` 仍只允许作者。
5. `npm run verify:quick` 通过（`check:repo` / `check:test-map` 不因本次改动变红）；
   `apps/api` 单测全绿（含新增的 `feedback-anon-route.test.ts`，先红后绿）。
6. `e2e/react/feedback.spec.ts` 两条用例在 `desktop-chromium` 下全绿。
7. ⚠ 本分支涉及 `apps/api`，按 §4.5 **走 PR**（不直接推 `main`）。
