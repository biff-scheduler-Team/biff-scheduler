# PLAN-20260923103830 — 红黑榜拖拽：补单手势守卫 + 对齐 keyboard 收回 + 回写口径文档

## 目标

code review（`code-review-skill` 四阶段）对 `PLAN-20260923101147` 落地改动给出 2 条 `🟡 important`
与 1 条同源 `🟢 nit`，本 PLAN 收口这三条：

> 1. **多指手势会导致一次松手触发两次落点结算（无单手势守卫）** …
>    `beginDrag` 现在每次 `pointerdown` 都往 window 挂一套监听，且 `onUp` 不按 `pointerId` 过滤。
>    旧实现不会这样：那时 `useEffect([drag])` 的 cleanup 会先摘掉上一套监听，任意时刻只有一套生效。
> 2. **`docs/CONVENTIONS.md` 未同步本轮口径**（`:607` 仍写着「不做常驻『这枚是你的』标识」，
>    与已落地的常驻纸白边冲突；`2026-09-23` 三件事均无登记）。
> 3. `movedRef` 是全局单例，键盘路径有缺口：`Enter` 触发的 `click` 不经过 `pointerdown`，
>    紧接一次拖拽之后按回车，收回会被静默吞掉。

## 范围

**做：**

1. `apps/web/src/pages/RedBlackPage.tsx`：拖拽改成「**同一时刻只有一个手势**」——
   - 新增 `gestureRef`（手势单例：`pointerId` + `end()` 收尾），第二个指针 `pointerdown` 直接忽略；
   - `onMove` / `onUp` 一律 `if (event.pointerId !== pointerId) return;`，`onUp` 里清空单例；
   - 卸载时跑一次 `end()`（同步挂的监听器没有 effect cleanup 兜底，手势中途换页会留在 window 上，
     而 `finishRef` 还指着已卸载树的闭包）；
   - `RbCard` 的 `onTakeBack` 带上 `event.detail`：**只有指针触发的那次 click（`detail > 0`）**
     才受 `movedRef` 约束 —— 键盘激活 / `element.click()` 的 `detail === 0`，不再被上一次拖拽吞掉。
2. `docs/CONVENTIONS.md`：回写 2026-09-23 口径 —— 张贴区按片独立、`.rb-src { touch-action: none }`、
   常驻纸白边（含「`sticker-sprite.ts` 不跟着加」的单向差异）；订正 `:607`，
   并给「贴纸外观只允许一处实现」补上白边这一唯一例外。
3. 回归测试：单测覆盖不了多指（需真机），故补 **E2E**：
   - 键盘 `Enter` 收回：先拖一次（`movedRef` 置位）再按回车 —— 断言贴纸**被收回**（旧行为会吞掉）；
   - 双指同时按住两张卡的贴纸再抬起：断言两张卡的 `.rb-dot` 计数与红黑数字都**不因第二次结算而变**。

**不做：**

- 不改 `film-votes.ts` 的上报防抖、不改 `StickerCanvas` / 分享图 / 排序冻结机制；
- 不改 `biff.*` 任何存储结构；
- 不给 `.rb-canvas` 加 `touch-action`（那会让卡片右半张没法滚页）；
- 不碰 `freshKey` 单槽（量级极小，且属另一个判断：它不影响正确性）；
- 不动 `App.tsx` 的埋点迁移（已完成且有 E2E 覆盖；拆分提交由用户在提交阶段决定）。

## 方案取舍

| 备选 | 结论 | 理由 |
|---|---|---|
| 第二指针 `pointerdown` → **忽略** | **采纳** | 与旧 `useEffect` 的「任意时刻只有一套监听」等价：旧实现是被 cleanup 顶掉第一套，新实现是直接不接受第二套。忽略可预测；「顶掉」会让第一套的 ghost 悄悄留在 DOM 上 |
| 第二指针 `pointerdown` → 顶掉当前手势 | 否决 | 需要先跑一遍 `end()` 才能保证 ghost 不残留，复杂且用户读到的是「手势被抢」，不如「第二指无效」直白 |
| 靠 `event.pointerId` 过滤，不设单例守卫 | 否决 | 两套监听仍都会挂上；虽只有一套会命中，但泄漏两套监听与两个 ghost 的创建路径 |
| 键盘缺口 → 用 `event.detail > 0` 判「这次 click 来自指针」 | **采纳** | 规范行为（键盘激活与 `element.click()` 的 `detail` 为 0），一处判断同时治「拖完被吞」与「回车被吞」 |
| 键盘缺口 → 在 `onUp` 里复位 `movedRef` | 否决 | `pointerup` 之后浏览器**还会**补发 `click`，提前复位等于把「微调位置」变回「撤销」—— 正是 2026-09-23 修掉的那个 bug |
| 键盘缺口 → 用 `suppressClickRef` 一次性消费 | 否决 | 指针移出元素时浏览器**不补发** `click`，标记会一直悬着，下一回车照样被吞 |
| 卸载时不收尾 | 否决 | 手势中途换页（浏览器返回手势）会把监听器永久留在 window 上，且 `finishRef` 仍能写 localStorage |

## 验收标准

1. 双指同时按住两张卡各自的贴纸，先抬起一根再抬起另一根：**每张卡画布上的贴纸数不增不减**，
   页面也不会出现第二枚贴纸或越权落点。
2. 拖动本片贴纸微调位置后立刻按 `Enter`（贴纸仍持焦点）：贴纸**被收回暂存区**（旧实现静默无反应）。
3. 不回归：同片内拖动仍是「挪位置」；拖到页面空白仍是收回；鼠标单击仍是收回；
   暂存区点一下仍是随机贴；跨片拖拽仍不落到别片。
4. `docs/CONVENTIONS.md` 不再出现与常驻纸白边冲突的表述，且登记了 2026-09-23 三项口径。
5. `npx playwright test -c playwright.react.config.ts e2e/react/redblack.spec.ts --project=desktop-chromium`
   与 `apps/web` 单测全绿。

## 实施记录(2026-09-23)

### 「先红」实测:症状比预测更重

按 §3 先跑一遍**回退版**(把守卫与 `detail` 判断摘掉)取失败值,两条新用例都红:

| 用例 | 失败值 |
|---|---|
| 两指同时按住两张卡的贴纸 | `expect(aAfter 位移).toBeGreaterThan(4)` → **Received: 0** |
| 拖过一次之后,键盘回车照样能把贴纸收回来 | `toHaveCount(0)` → **Expected: 0, Received: 1** |

「两指」那条的红比 PLAN 里预测的「挪到错误落点」严重两级 —— 实测链路是:

1. 两套 `onUp` 都被第一指的 `pointerup` 触发;
2. 第二套用**第一指的坐标**调 `finishRef` → `canvasAt` 命中《A》的画布 → 对《B》而言是「拖出画布」
   → 走 `takeBack` **把《B》那枚当场误收回**(还弹一条「收回暂存区」的 toast);
3. 更糟的是两次 `commitBoard` 都拿**同一份** `board` 快照(`latest.current`)算下一状态 ——
   第二条 `setBoard` 把第一条**整体覆盖**,于是《A》那次位移也**丢了**(故 `Received: 0`)。

即「一次松手 = 误收回一张 + 丢掉另一张的位移」。修完之后两条都转绿。

⚠ 测试写法上的一个坑(已修):`pointerup` 一开始派发在**具体元素**上,回退版里《B》那枚被误收回后
元素消失,断言卡在 `locator.evaluate` 超时 —— 失败信息读起来像「元素等不到」而不是「次数不对」。
改成直接派发到 `window`(监听器本来就挂在它上面)之后,红是干净的断言失败。
