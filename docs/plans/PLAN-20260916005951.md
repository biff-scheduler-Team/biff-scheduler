# PLAN-20260916005951 — 「抢票」页去掉与「我的行程」重复的场次卡,改成一栏式紧凑清单

   它是「已抢到 N 场」摘要与行程页「仅看实际行程」的数据来源,不能在本页丢掉。

## 方案取舍

| 备选 | 结论 | 理由 |
|---|---|---|
| 抢票页继续复用 `ScreeningCard`,只靠传参阉割(如 `showTitle=false`) | 否决 | 卡片是给「挑片 / 出门找地方」设计的,阉割到只剩一行时它的结构(海报位 / 多行 meta / 操作行)全成噪声 |
| 抢票页自持一份清单行,只保留票务三态控件 | **采纳** | 抢票当天要的是「哪天 · 哪个号 · 几点 · 什么片 · 哪个馆 · 第几顺位」,一行说完 |
| 顺位在本页另算一份(按时间先后给号) | 否决 | 顺位只有一个含义 = **冲突组内**的偏好次序(用户拖出来的);另算一份必然与行程页 / 分享文案打架 |
| 顺位文案照 `share.ts::rankMark`(主选 / 备选②) | **采纳** | 分享文案与分享图片已共用它;抢票页是同一件事的第三个视图,措辞必须一致 |
| 清单行里省掉「日期」 | 否决 | 抢票要知道**哪一天**去抢(批次是跨日的);原卡片里根本没有日期,是本次补上的 |
| 摘要条保留倒计时(与批头重复) | 否决 | 同一份数据两处印;倒计时放在「哪一批要开了」旁边才有意义 |
| 样式追加进 `style.css` | 否决 | 命中 TEST-MAP `allOn` → 触发三浏览器全量 E2E(5–9 min),为几行清单样式不值 |
| 票务三态也一起删掉(「更简单」) | 否决 | 它是「已抢到 N 场」与行程页「仅看实际行程」的唯一数据入口,删了会截断既有功能 |
