## 1. PWA —— `vite-plugin-pwa`

**动机**:电影节现场(釜山 Centum / 南浦洞)网络不稳;precache 后离线可用 + 加到主屏 = 从「网页」变「App」。

**配置要点**:
- `registerType: "autoUpdate"`(有新版自动接管,无需用户确认);`injectRegister: "auto"` → **零 TS 改动**(插件往 index.html 注入注册脚本)。
- precache:`globPatterns` 覆盖 `js/css/html/json/ico/png` —— 核心数据 `schedule.json`(260KB)/ `films.json`(55KB)/ `venues.json`(6.5KB)必须进缓存,否则离线打开是空表。
- **`/api/*` 走 `NetworkOnly`**(用户明确要求):豆瓣映射是服务端权威,缓存它会拿到脏数据。
- `navigateFallback: "index.html"` + `cleanupOutdatedCaches: true`。
- `devOptions.enabled: false` —— 开发期不装 SW(否则热更新会被缓存干扰)。

**图标(两轮迭代后的最终方案)**:
- 品牌目录里两个 SVG(`biff-mark.svg` 96×36 / `biff-wordmark.svg` 306×36)**都是横版 wordmark**,不适用方形图标。
  ⚠ 它们**不是死资源** —— `docs/history/2026-09-09-开发落地记录.md` §15.1 写明是**有意保留的回退备份**
  (顶栏从 `biff-mark.svg` 换成 2026 全字标后留档)。故**不删**,只从 `public/brand/` 移到
  `docs/brand-backup/`(仓库内保留、不进部署产物,省 224KB)。
- `biff-2026-wordmark.png` 解码后主色 = **`rgb(32,32,32)` 近黑**(67% 透明,单色字标)。
- **第一版(SVG)已废弃**:手写 `app-icon.svg` = 白底 + 品牌红带 + data URI 内联 wordmark。
  内联是必须的(SVG 作为 image 加载时**不允许外部引用**,secure static mode,外链 `<image href>` 会静默失败);
  但 **iOS 不支持 SVG 的 apple-touch-icon** → iOS 加主屏会退化为截图。
- **最终版(PNG,用 Node 手写解码 / 编码生成,零依赖)**:
  ① 解 `biff-2026-wordmark.png`(zlib inflate + PNG 反滤波);
  ② 512×512 品牌红底 `#ce1e36`,用 wordmark 的 **alpha 通道作遮罩**把字标涂成**白色**
     (近黑字标压红底对比度极差,故做反转);
  ③ 字标按**原生 306×36 贴入、不放大** → 锐利,且落在 maskable 安全区(中心 80%)内;
  ④ 面积平均降采样出 192×192 / 180×180;
  ⑤ 手写 PNG 编码(zlib deflate + CRC32,colorType 2)落盘。
  产物:`brand/app-icon-512.png`(8.9KB,`any` + `maskable`)、`brand/app-icon-192.png`(2.8KB,`any`)、
  `brand/apple-touch-icon.png`(2.6KB,iOS 用,`index.html` 里显式 link)。

## 3. tailwind-merge —— 评估后**否决**(曾实施,已回退)

**动机(原始)**:`buttonEl(cls, label, { extraCls })` 是字符串拼接,同类冲突(如 `text-12` vs `text-16`)
靠**生成 CSS 的源序**决胜负,不是靠调用方意图。

**实施后发现三点,结论反转**:
1. **成本是预估的 10 倍**:实测 bundle `140.5KB → 169.0KB`(gzip `52.2 → 61.9KB`),即 **+9.7KB gzip**;
   `dist/assets/index-*.js` 是唯一增量来源(registerSW.js 只有 0.14KB)。
2. **收益是 0**:全站 grep `extraCls` —— 4 个共享工厂(`buttonEl` / `iconButton` / `priTag` /
   `metaChipRow` / `doubanChip`)**没有任何调用点**真的传过这个参数。它在防一个当前不存在的风险。
3. **它解决不了原本想解决的问题**:`style.css` 那批 `@utility` + `!important` 补丁(如 `in-plan` / `tight`
   压 `.bg-card`)是**自定义 utility 与 Tailwind 生成类之间的层序问题**,且 `in-plan` 这类自定义类名
   tailwind-merge **并不识别** → 与 `extraCls` 无关。

**过程记录(留档)**:接入时踩到一个真陷阱 —— tailwind-merge v3 的 `text-` 同时属于 `font-size` 与
`text-color` 两组;本仓库字阶是**值命名**的 `text-9…text-18`,而 `12` 不是 t-shirt size → 被判进
`text-color`(该组 `isAny` 兜底),于是 `twMerge("text-12 text-on-brand")` 会把 `text-12` 当成**颜色**
冲突删掉 → 字号静默丢失。当时用 `extendTailwindMerge` 注册 `text-9…18` / `rounded-2…12`,并配
`tests/tw.test.ts` 钉住。**该陷阱只属于 tailwind-merge,撤掉后不复存在。**

**最终方案 = 契约(零依赖、零运行时成本)**:
`extraCls` 明确为**布局 / 变体专用** —— 只放间距(`ml-auto`)、对齐、`hover:` / `disabled:` 变体、
`tabular-nums` 这类无冲突工具类;**不覆盖字号 / 颜色 / 背景 / 圆角**(基础串是该视觉的唯一来源)。
需要新视觉 → 改 `ui.ts` 的基础串。契约落在 `ui.ts` 的字段注释 + `docs/CONVENTIONS.md`。

**已回退**:删 `src/tw.ts` 与 `tests/tw.test.ts`、卸载依赖、`ui.ts` / `library.ts` 回到纯拼接。

## 4. 列表渲染优化 —— **降级实现,不做完整虚拟滚动**

**为什么不做完整虚拟化**:
- 甘特网格是手写 CSS Grid + 绝对定位卡 + 粘性影厅列 + 缩放锚点(`centerCardX` 读 `offsetLeft/offsetWidth`);
  虚拟化后未渲染元素的尺寸是估算值 → **反向定位居中会算错**。这是整个视图最精密的一段代码,不值得为性能赌一把。
- 影片库行高**可变**(展开态含场次行)→ 可变高度虚拟化复杂度远高于固定行高。
- 结论:完整虚拟化(`virtua` 或自研)属**独立一轮**的工作,本轮不做。

**本轮做的(近零风险、拿到大部分收益)**:给影片库/我的选片行加
`content-visibility: auto` + `contain-intrinsic-size: auto 92px`
—— 浏览器跳过视口外行的布局/绘制(等于「原生版虚拟化」),`auto` 关键字会记住上次渲染尺寸,展开/折叠不会跳。
**只加在抽屉列表行上,不加在甘特卡上**(理由见上)。

## 6. 边界与风险

- PWA 的 `autoUpdate` 会在新版本就绪时自动接管 —— 对自用工具合适;若出现「旧页面被 SW 缓存」问题,可退回 `prompt`。
- precache 总量约 **0.6MB**(JS 140KB + CSS 36KB + 三个 JSON 322KB + wordmark 8KB + 图标),可接受;**不含**那两个 112KB 死 SVG(用 `globIgnores` 排除)。
- 测试只覆盖**纯函数**;DOM 交互仍靠既有无头验收流程。
- `content-visibility` 在抽屉列表上若出现滚动条跳动,回退方案是加 `contain-intrinsic-size` 的固定值(已用 `auto` 关键字缓解)。
