# PLAN-20260930160000 — 五款贴纸皮肤换成「场记板 / 金棕榈 / 票根 / 胶片残片 / 胶片齿孔」

> 用户原话：
> 「参考戛纳金棕榈」
> 「（b）顺手把 ICON_RATIO 抬到 0.55 再一起提，」

## 目标

原来的五款皮肤里有两款（`torn` 撕裂圆片 / `reel` 胶卷盘）在 20px 上读不出是什么，
且不符合「电影/电影节」这一套意象。换成五款**同一套**（红黑只是纸色不同）：
**场记板 `clap` / 金棕榈 `palm` / 票根 `stub` / 胶片残片 `scrap` / 胶片齿孔 `sprocket`**。

顺带解决一件被这件事**暴露**出来的旧账：中心微图标实际只有 `20 × 0.45 = 9px`
（`ICON_RATIO` 那句「0.45 是下限」是按 **32px** 写的），五款图形全糊成一粒噪点。

## 范围

**做：**
- 契约：`packages/contracts/src/sticker.ts` 的皮肤键换成新五款（**旧键下线**，不是加字段）。
- 形状族：`sticker-shape.ts` 加 `clap`（板身 + **斜顶条**）与 `sprocket`（齿孔边），
  仍走**单一闭合环**那一套（`outline()` 按顶点派生圆角，不引入子路径）。
- 图形族：`sticker-glyph.ts` 加 `palm`（花苞 + 两片宽侧叶 + 茎）；
  场记板的图标**留空**（它本身就是一块有内容的板子）。
- 材质与映射：`sticker-skin.ts` 的 `SKINS` 表逐款给出 `shape / glyph / material`。
- 墨色：金棕榈**红贴黑贴都是金**（唯一不跟纸色走的一款），
  三条绘制路径一起改 —— DOM（CSS 规则 + `data-rb-glyph`）、群点 sprite、分享图。
- 清理迁移：`0013_drop_retired_sticker_skins.sql`（见下）。
- `ICON_RATIO` 0.45 → 0.55（20px 上 9 → 11px）。

**不做：**
- **不动贴纸尺寸**（`STICKER_SIZE` 仍是 20）。它被用户改过四轮（26 → 20 → 32 → 20），
  且 `.rb-dot` 的 width/height 有单测逐字钉着 —— 那是另一件事，本次只动**占比**。
- **不给场记板加条纹**：形状族只支持**单一闭合环**，挖空需要子路径支持。
  当前靠「板身 + 挑出板外的斜顶条」认它，是五款里最弱的一款，已如实告知用户。
- 不动红黑**总数**那本账（`film_vote_stat`）与卡片版面。

## 清理迁移为什么要做（这是代码里写明的操作约束，不是顺手清库）

`film-vote-store.ts::prevSkins` 那段写明：读侧的白名单会把**白名单外的款**归一成 `null`，
于是撤票 / 改款时**无从知道该从哪个桶里减** —— 那些桶永远减不掉，
表现是「群点比卡片上的数字多一枚」，而且**永不自愈**（聚合只在贡献行有差分时修正）。

```sql
DELETE FROM film_vote_skin_stat WHERE skin IN ('torn', 'reel');
UPDATE film_vote_contribution SET skin = NULL WHERE skin IN ('torn', 'reel');
```

贡献行置 `NULL` 而不是留旧字符串：`null` 的语义是「这一票没有款」（与迁移前的旧票一致），
留旧字符串则是「一个白名单外的款」，两回事。

## 方案取舍

| 备选 | 结论 | 理由 |
|---|---|---|
| 加字段兼容旧款（新旧并存的 7 款） | 否决 | 轮盘只有 5 个座位；两套并存的代价要一直背着，不如一次性迁移。 |
| 旧款保留在契约里但不上轮盘 | 否决 | 「读得到但永远选不出来」的值迟早被当成有效值用（正是上面那类桶减不掉的成因）。 |
| 金棕榈的金只改 DOM | 否决 | 群点 / 分享图会一个白一个金；墨色必须三条路径同一份来源。 |
| 靠放大贴纸（20 → 32）让图标读得出 | 否决 | 用户四轮改过尺寸、最终停在 20；这次是**占比**错了，改比例才是对症的那一刀。 |
| 场记板用条纹（挖空）表达 | 否决（本次） | 形状族是单环模型，要子路径支持 —— 那是形状族本身的改造，另开。 |

## 验收标准

1. 换款轮盘里恰好 5 款，顺序为 `clap / palm / stub / scrap / sprocket`；
   逐款点选后 `data-rb-glyph` 与映射表一致。
2. 金棕榈在**红贴与黑贴**上计算墨色都是 `rgb(217, 180, 92)`；
   其余四款仍随纸色（红 `white 92%` / 黑 `white 72%`）。
3. `ICON_RATIO = 0.55`：`20 × 0.55 = 11px`，窄形状（`scrap` / `sprocket`）上不被裁剪。
4. `npm run verify:quick` 全绿（web 857 / api 305 / 根 4）。
5. 迁移登记进 `_journal.json`（idx 13）并经 `prepare-cloudflare.mjs:22` 在部署前执行。
