# PLAN 2026-09-10 01:02:19 — 修复:平移/滚动到右后选片,甘特图弹回最左

> 需求(用户原话):「拖动到右边 然后选片后 甘特图会重新定位」。
> 本文件 = 本需求唯一规划文档。仅改 `src/main.ts` renderGrid;grid.ts/agenda.ts 零改动。

## 现状(代码事实)

- 甘特网格每次渲染都全量重建:`renderGrid()` 里 `buildGrid(...)` 生成**全新**滚动容器(`overflow-x-auto`),再 `host.replaceWith(grid)`(main.ts renderGrid)。
- `scrollLeft` 是 DOM 节点自身状态 → 换新节点即归零(弹回最左 = 时间轴起点)。
- 触发重建的路径远不止选片:`toggleCode`(点卡选中/取消)/`setPriority`/`flipGroup`/`removeCode`/`replaceGroup`/方案切换 → `notify → renderAll → renderGrid`;跨分钟定时器(每 20s 当日在看时)也走 renderGrid —— 全都丢横向平移位置。
- boot() 注释已承认该代价("重渲 replaceWith 会丢失用户横向平移位置"),当时仅用于论证移除 ResizeObserver 重渲;但 plan 变更类重渲仍天天触发,未做补偿。
- 同一日期下轴界(axisRangeFor)只依赖静态 schedule,与 plan/hourFilter 无关 → **同一日期重建前后内容总宽一致**,平移位置恢复是精确的(无需近似)。

## 改动方案

### main.ts renderGrid:同一日期重建恢复 scrollLeft,换日期不恢复

- 模块级记忆:`let lastGridDate = ""; let lastGridLeft = 0;`
- `renderGrid()` 入口:`host.replaceWith(grid)` **之前**先读旧容器 `host.scrollLeft`,仅当 `currentDate === lastGridDate`(视图仍是同一天,只是数据刷新)才记下;换日期/首渲记 0(保持既有"切日期回最左"行为)。
- `replaceWith` 后立即回写:`grid.scrollLeft = Math.min(lastGridLeft, grid.scrollWidth - grid.clientWidth)`(钳制防御;同日期下宽度一致,正常是精确恢复)。容器内容宽为显式 inline px(`min.style.width = totalW`),插入后同步布局即正确,无需 rAF,且避免闪回最左一帧。
- 末尾 `lastGridDate = currentDate` 推进。
- hourFilter 切换只加/去 hour-dim 类,轴宽不变,归入"同日期恢复"路径即可(平移位仍有效)。

## 验收

1. 拖/滚到时间轴右侧任意位置 → 点选/取消某场 → 网格停留原位,不再弹回最左(agenda/角标/徽章照常刷新)。
2. 切日期仍回最左(行为不变);影片库反向定位自动居中滚动不受影响(跳转发生在 renderGrid 之后的 rAF,晚写入覆盖)。
3. 平移到右后等待跨分钟自动重画(当日场景),位置不跳。
4. `npm run typecheck` 通过;不启动本地 dev server(读代码自查 + 一次性 build 验收)。
