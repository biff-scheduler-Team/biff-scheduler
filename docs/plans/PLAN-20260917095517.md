# PLAN-20260917095517 — 定位闪烁不再抹淡内容（CODE 徽章不再「变透明又变不透明」）

## 目标

用户原话：

> CODE 197  一直在变透明又变不透明

已核实（真页面采样，非推测）：

- 排片表里**唯一**会做透明度变化的只有「定位闪烁」`SchedulePage.tsx::flashScreenings()` ——
  全仓库只有这一处 `element.animate`，CSS 里没有任何 `@keyframes` / `animation`。
- 它动的是**整格的 `opacity`**：`[{opacity: 0.55}, {opacity: 1}]`，`duration 1000ms, iterations 3`
  （`SchedulePage.tsx:73-76`）。
- 实测（`/agenda` 点「定位场次 197」→ 客户端跳到排片表，每 200ms 采样）：

  | 时刻 | 197 格子 | 动画 |
  |---|---|---|
  | 548ms | op=**0.55** + `schedule-located` | running t=0 iter=3 |
  | 812→1418ms | 0.73 → 0.91 → **0.55** | 第 1 轮结束、第 2 轮开始 |
  | 2428ms | **0.55** | 第 3 轮开始 |
  | 3422ms | op=**1** | 动画结束、摘掉 `schedule-located` |

- CODE 徽章是 `background: transparent` + 红框（`style.css:1528`），格子一淡，读到的就是
  「红框 197 在变透明又变不透明」。`legacy/src/style.css:269` 当年就写明了同一个道理：
  定位反馈**不能用会掉色的方式**做（那边用的是 `box-shadow` 描边）。
- 用户确认：**约 3 秒闪 3 下就停**（不是无限重放；25 秒探针实测 `Element.animate` 0 次调用、格子 class 0 次变化）；
  触发方式是**直接刷新 / 新开这一页** —— URL 里带着 `focus` / `locate`，等于重放一次定位请求。

## 范围

**做：**

1. `SchedulePage.tsx::flashScreenings()`：改成**只闪描边**，不再碰 `opacity`。
   - 关键帧走 `outlineColor`（`transparent → 品牌色 → transparent`，1s × 3）。
   - 颜色取**计算后的 `outline-color`**：WAAPI 的关键帧不收 `var()`，而 `.schedule-located` 已经把
     `outline: 3px solid var(--brand)` 解析成具体颜色 —— 亮 / 暗两套主题各取各的。
   - `prefers-reduced-motion: reduce` 分支保持「不闪」（描边静态），语义与现状一致。
   - `.schedule-located` 的加 / 摘时机**不变** —— 三处 E2E 断言依赖它
     （`parity-schedule.spec.ts:70,88,91`、`floating-panel.spec.ts:35`）。
2. 回归测试（先红后绿）：`e2e/react/parity-schedule.spec.ts` 追加一条 —— 定位后连续采样 2.5 秒，断言
   ① 格子与其 CODE 徽章的 `opacity` **全程 = 1**；② 期间**确实跑着**一条描边类动画
   （关键帧含 `outlineColor`、**不含** `opacity`）—— 后半条是为了「删掉闪烁」不能变绿。

**不做：**

- 不改「刷新重放一次定位」的语义：URL 里的 `locate` 就是定位请求令牌，重放是**有意**的；
  本次只改闪法，不动触发条件。
- 不动 `.gantt-slot:hover` 的 `box-shadow` 描边、不动 `[data-highlighted]` 的 outline。
- 不动 `legacy/`（只读回退件，本次不是 P0 数据丢失 / 打不开）。
- 不新增 CSS 类、不新增 `@keyframes`：`outlineColor` 动画足够，避免同一口径出现第二份实现。

## 方案取舍

| 备选 | 结论 | 理由 |
|---|---|---|
| 闪 `outlineColor`（本方案） | 采纳 | 内容零影响；与 `.schedule-located` 现成的 3px 品牌色描边同源；不与其他属性打架 |
| 继续闪整格 `opacity`，只是把 0.55 调高到 0.9 | 否决 | 仍然抹淡内容（用户抱怨的正是内容跟着淡），只是变轻 |
| 闪 `box-shadow`（照抄 legacy `biff-flash`） | 否决 | 会顶掉格子常态阴影 `0 1px 2px #00000005` 与 hover 描边 `0 0 0 2px var(--brand)` —— 等于把 hover 反馈关掉 3 秒 |
| 叠一层独立描边覆盖元素再闪它 | 否决 | 要往 React 管理的格子里手工插 DOM（与 reconcile 抢节点），成本远高于收益 |
| 干脆去掉闪烁 | 否决 | 定位后「找到哪一格」的反馈消失，且三处 E2E 依赖 `schedule-located` |

## 验收标准

1. 从「我的行程」点任一「定位场次」跳排片表：**格子内容（红框 CODE 徽章 / 剧照 / 片名）全程不透明**，
   只有格子外圈描边闪 3 下。
2. 亮 / 暗两套主题下描边都取到本主题的品牌色。
3. 命令：
   - `npx playwright test -c playwright.react.config.ts e2e/react/parity-schedule.spec.ts --project=desktop-chromium` 绿；
   - `npm run verify:quick` 绿。
