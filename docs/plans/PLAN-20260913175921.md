# PLAN-20260913175921 — 行程页两个「定位」的文案区分 + 影院代码徽章辨识

## 目标

1. 行程页（`/agenda`）日期行的定位按钮可见文案由「定位」改为「定位当日」，
   与场次卡内的「定位」（定位单场）在**说法**上分开，消除同名误读。
2. 行程卡影院块里的影院代码徽章（如 `B1`）与卡片顶部的场次代码徽章（如 `001`）
   都是小代码块、样式相近，加「影院」前缀在说法上区分二者。

## 范围

**做：**

- `apps/web/src/pages/AgendaPage.tsx`：日期行 `ActionButton` 可见文案与 `aria-label` 改为「定位当日 …」。
- `apps/web/src/components/ScreeningCard.tsx`：影院块的 `.venue-code` 内容加「影院」前缀，并补 `title`。
- `e2e/react/parity-agenda.spec.ts`：同步影院块断言；新增一条「日级定位 / 场级定位文案不撞名」回归用例。

**不做：**

- 不改 `locateDate` / `locateScreening` 的跳转参数、滚动与高亮行为。
  两者功能**不重复**：日级定位滚到当日首个已选场次并高亮当日全部已选场次；
  场级定位把单场居中、`focus()` 落焦、只闪这一场。删任一个都会丢能力。
- 不改排片表列头（`SchedulePage.tsx`）与说明弹层（`InfoDialogs.tsx`）里的 `.venue-code`：
  那两处上下文已带影院全名，再加前缀是冗余。
- 不改 `.venue-code` 的全局配色 token，不引入新色值。

## 方案取舍

| 备选 | 结论 | 理由 |
|---|---|---|
| 删掉日期行定位按钮 | 否决 | 会丢掉「当日全部已选场次一起高亮」的能力 |
| 两处都保留同名「定位」 | 否决 | `aria-label` 虽已分别写明日期 / 场次，但可见文字撞名，读屏以外的用户无从区分 |
| 日期行改「定位当日」+ 卡片保留「定位」 | **采纳** | 最小改动，语义直白，不动交互 |
| 影院徽章换实心底 / 换形状 | 否决 | 会影响排片表列头与说明弹层，收益不抵扩散面 |
| 影院徽章加「影院」前缀 | **采纳** | 影院代码与场次代码语义不同，文字前缀比颜色更不易混，且不引入新 token |

## 验收标准

1. 日期行按钮可见文字为「定位当日」，`aria-label` 为「定位当日 <date>」；卡片内按钮仍为「定位」，`aria-label` 为「定位场次 <code>」。
2. 行程卡影院块徽章文本为「影院 B1」（前缀 + 官方影院代码）。
3. `npm run verify:full` 全绿（typecheck / lint / 单测 / build / Playwright 三浏览器）。

## 追加（2026-09-13，用户口径变更）

行程卡影院块**不再展示地址行**（原「区域 · 楼层」+「中韩文地址」两行 `muted` 文本）。

- 理由：行程卡要回答的是「去哪、怎么走」，卡面不再堆两行长地址；具体地址交给地图入口。
- 地图入口 `title` **仍保留**完整地址 —— 那是点按唤起 Google Maps 导航时的辅助说明，不占版面。
- 验收补充：行程卡 `.screening-venue` 不再含 `120, Suyeonggangbyeon-daero` 等地址文本；影院名与地图入口保留。

两者同属行程卡 UI 调整、不可拆分提交，故一并入库。
