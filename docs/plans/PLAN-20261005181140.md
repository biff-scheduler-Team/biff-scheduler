# PLAN-20261005181140 — 贴纸只留三款（票根 / 胶片残片 / 胶片齿孔）、贴纸放大、中心图标尺寸不变

> 用户原话：
> 「贴纸只保留三种 去掉场记板和金棕榈 然后 把贴纸的放大一点  中间挖孔大小不变」

## 目标

1. **款数从 5 → 3**：下线 `clap`（场记板）与 `palm`（金棕榈），只留
   `stub`（票根）/ `scrap`（胶片残片）/ `sprocket`（胶片齿孔）。
2. **贴纸整体放大**：`STICKER_SIZE` 20 → **24**（「放大一点」；32 已被用户否决过一轮）。
3. **中心微图标（用户口中的「中间挖孔」）绝对尺寸不变**：仍是 ≈11px。
   它由 `ICON_RATIO` 派生，贴纸变大后按比例会跟着变大 —— 所以要把比例从
   0.55 调回 **0.46**（`24 × 0.46 ≈ 11px`，与放大前 `20 × 0.55 = 11px` 同值）。

> 「中间挖孔」的判读依据：`sticker-glyph.ts` 文件头记着用户原话「在圆点正中央**掏空**/印上一个
> 白色的极简五角星…」—— 中心那枚图案在用户的口径里就是「掏空出来的东西」。若用户指的是别的
> 东西（例如某一款轮廓上的镂空），本 PLAN 的第 3 条改回来即可，前两条不受影响。

## 范围

**做：**

- 契约：`packages/contracts/src/sticker.ts` 的 `STICKER_SKINS` 删 `clap` / `palm`，
  留 `stub` / `scrap` / `sprocket`（顺序 = 轮盘顺序）；`DEFAULT_STICKER_SKIN` 仍是 `stub`。
- 形状族：`sticker-shape.ts` 删 `clap` 轮廓；`torn`（撕裂圆片）**只被 `palm` 复用**，
  随之下线 —— `StickerShape` 只剩三种，`ALL_SHAPES` 同步。
- 图形族：`sticker-glyph.ts` 删 `palm` 图形；`ICON_RATIO` 0.55 → 0.46（第 3 条）。
- 皮肤表：`sticker-skin.ts` 的 `SKINS` 只剩三行（材质分配不动：票根 `ink`、残片 `grain`、齿孔 `grain`）。
- 材质：`screen`（丝网重影）**唯一消费者就是场记板**，随之下线 ——
  契约 `STICKER_MATERIALS`、配方表、`stripe` 层类型、CSS 规则一并删。
- 尺寸：`sticker-sprite.ts::STICKER_SIZE` 24；CSS 里 `.rb-dot` / `.rb-ghost` / `.rb-preview`
  三处逐字同步；材质 `--rb-mat` / `--rb-mat-size` 按 24 重新生成。
- 绘制分支：删「金棕榈的叶子恒为金」这一支（sprite / 分享图 / CSS token `--rb-icon-gold`）。
- 迁移：新增 `0014_…` 清理库里 `clap` / `palm` 两款的贡献行与聚合行（**不是可选操作**，
  见 `film-vote-store.ts::prevSkins` 那段：留着这两款的行 → 桶永远减不掉 → 群点比数字多）。
- 测试同步：web 单测（shape / sprite / material / wheel / canvas-guard / film-votes）、
  api 单测（film-vote-skin / ping-contract）、e2e（redblack 的尺寸与款名白名单）。

**不做：**

- **不动**红黑总数那本账（`film_vote_stat`）与卡片版面（列宽 / 画布高度）。
- **不动**轮盘几何（`WHEEL_RADIUS` / `NODE_SIZE`）：3 款仍按均匀分布落座，公式本来就按 `count` 算。
- **不动**分享图里贴纸的尺寸（`FIELD_STICKER = 14`）—— 用户说的是卡片上那枚。
- 不新增款、不重画轮廓、不调色。

## 方案取舍

| 备选 | 结论 | 理由 |
|---|---|---|
| 只从契约删两款，形状 / 图形 / 材质留着 | 否决 | 留下三处「有实现但永远选不出来」的死代码；`torn` / `palm` / `screen` 的测试守卫也会互相打架。 |
| 保留 `screen` 材质但放宽「不许有空材质」的守卫 | 否决 | 那条守卫正是防「登记了却没人用」；放宽等于把口径改小去迁就改动。 |
| 让某一款改用 `screen` 材质以保住它 | 否决 | 用户没要求改观感；三款里哪款都不像「丝网重印」，硬套只会更怪。 |
| 贴纸放大到 32 | 否决 | 用户 2026-09-29 已实测否决过一次（「20 左右差不多」）。 |
| 只放大贴纸、`ICON_RATIO` 不动 | 否决 | 与用户「中间挖孔大小不变」直接冲突。 |
| 把图标尺寸改成**绝对 px** 常量（脱离比例） | 否决 | 四条绘制路径（DOM / sprite / 分享图）全靠比例派生；改常量会多出一处口径。 |

## 验收标准

1. `STICKER_SKINS` 恰好 3 款：`stub` / `scrap` / `sprocket`；轮盘里 3 个座位。
2. `STICKER_SIZE = 24`，且 `.rb-dot` / `.rb-ghost`(+2) / `.rb-preview` 与它逐字对齐。
3. `24 × ICON_RATIO ≈ 11px`（`Math.round` 后为 11），与放大前同值。
4. 单测：`apps/web` 与 `apps/api` 的贴纸相关 spec 全绿；`--rb-mat` 与生成器逐字一致。
5. E2E `redblack.spec.ts` 里尺寸断言 `24px`、款名白名单 `^(stub|scrap|sprocket)$`。
6. 迁移 `0014` 能把库里 `clap` / `palm` 的行清干净（贡献行置 NULL、聚合行删桶）。

## 修订 1（2026-10-05，review 收尾）

这一轮落地之后又过了一遍，四条处理如下（第 4 条是个**待跑**的核查，别当它已经做完）：

| 发现 | 处理 |
|---|---|
| `ICON_RATIO` 是**全局比例**，而分享图的贴纸尺寸没跟着放大 ⇒ 那张图上的中心图标从 `14 × 0.55 = 7.7px` 缩到 `14 × 0.46 = 6.44px`（左列「我贴的那枚」是 13.2 → 11.04px）。上面第 3 条「与放大前同值」只对 **24px 的卡片那一枚**成立 | **订正口径**，不引第二处尺寸口径：影响写进 `sticker-glyph.ts::ICON_RATIO` 与 `redblack-poster.ts::FIELD_STICKER` 的注释。要让分享图停在原像素，得给 `glyphPlacement` 加一个「目标图标 px」入参 —— 那正是取舍表里否决过的做法 |
| `StickerGlyph` 里的 `none`（唯一消费者是场记板）/ `star` / `exit` 三个图形**没有任何皮肤指向** —— 「有实现但永远选不出来 = 死代码」这条此前只用在了材质（`screen`）上 | 三个死项删掉；轮廓 / 图形 / 材质**三样一起**由 `tests/sticker-skin.test.ts` 新增的一条守卫盯着（断言「登记表 == 被用到的集合」） |
| 一批注释指着已经删掉的东西 | 逐条订正：`sticker-shape.ts`（`SHAPE_BOX` 不是贴纸尺寸；文件头那段是 2026-09-29 的原话、不等于现役清单）、`sticker-wheel.ts`（5 颗 → N 颗）、`StickerFace.tsx`（20 → 24）、`redblack-poster.ts`（「比 32 小一号」） |
| **迁移与部署顺序**：`scripts/prepare-cloudflare.mjs` 的顺序是 `db:migrate:remote → deploy web → deploy api`，所以「0014 清干净」与「旧 API worker 下线」之间有**分钟级窗口** —— 那期间旧 worker 的 `normalizeSkin` 仍认 `clap` / `palm`，可能把桶写回来 | 验收加一条**隔日核查**（见下）。⚠ 这条**还没跑过** |
