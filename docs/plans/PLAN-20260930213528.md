# PLAN-20260930213528 — 我的行程只留日程表 + 转票场次改按场次编号添加

## 目标

用户原话：

> 我的行程里面只用保留日程表这种形式 然后把添加转票场次改成通过 Code 添加

二轮确认（`ask_followup_question`）：

| 岔路 | 用户选择 |
|---|---|
| 「通过 Code 添加」的形态 | **编号为主，保留搜索兜底** —— 优先按场次编号精确匹配，仍保留片名模糊搜索与候选列表 |
| 卡片视图删掉后的抢票顺位 | **整块删除** —— `RankGroup` 顺位卡、`setRanks`、`biff.ranks.v1` 读写与相关 `plans` 逻辑（含一次性迁移清理） |
| 编号输入 | **支持批量** —— 逗号 / 空格分隔多个编号一次全部加入 |
| 卡片视图删掉后的票务三态 | **三态一并删除** —— 三态机制 + 转票徽章 + 「仅看实际行程」筛选全部下线，只保留「添加转票场次」直接记入行程 |

  - 抢票顺位 `RankGroup`（`AgendaPage.tsx:58-222` → `setRanks`）；
  - 按日折叠 `isAgendaFolded` / `toggleAgendaFold`（`state.ts:517-528`，键 `biff.agendafold.v1`）；
  - 场次间隔提示 `Gap`（`AgendaPage.tsx:231-255`）；
  - 票务三态 + 转票徽章 `ScreeningTicketControl`（`components/ScreeningTickets.tsx:21-52`，
    经 `ScreeningCard` 的 `social` 块挂载，`ScreeningCard.tsx:375`）；
  - 同场人数 `SameScreeningCount`（`ScreeningTickets.tsx:55-68`，同一 `social` 块 `:335`）。

## 方案取舍

| 备选 | 结论 | 理由 |
|---|---|---|
| 保留 `cards` 视图只删顺位 | 否决 | 用户口径是「只用保留日程表」；且顺位卡是 `cards` 的主要内容 |
| 「添加转票场次」只留编号输入 | 否决 | 用户选「编号为主，保留搜索兜底」—— 编号记错时仍需按片名找回 |
| 三态搬到日程表格子 / 弹层 | 否决 | 用户选「三态一并删除」 |
| 三态保留但不再上报服务端 | 否决 | 无展示面的状态就是死数据，只会污染 `biff.*` 与云端 |
| 同场人数搬到日程表格子 | ~~否决~~ → **采纳**（修订 1） | 用户随后明确要求「日程表还是可以加上同场 N 人」——原判断「没有展示面就让它消失」被推翻 |
| 旧键「留着不删」（`savedplans` 先例） | 否决 | 用户明确要求「含一次性迁移清理」；三只键的宿主机制都已删除 |
| 服务端一起删统计接口 | 否决 | 跨端改动超出本轮；存量数据 / 其它消费方未评估，保留更安全 |

## 验收标准

1. `/agenda` 只有日程表：无「日程表 / 卡片」切换按钮、无 `.agenda-day`、无 `.rank-group`；
   日期条 / 图例 / 缩放 / 「添加转票场次」仍在工具栏。
2. 全库 `rg "biff\.ranks|biff\.agendafold|biff\.tickets|rankOf|setRanks|TICKET_STATES"`
   在 `apps/web/src` 下**零命中**（注释除外）；`hydrateStorage()` 会清掉这三只旧键。
   ⚠ `SameScreeningCount` **不在此列** —— 它搬进了 `components/SameScreeningCount.tsx`（修订 1）。
3. 「添加转票场次」：输入 `419`（或 `1 419` 这类多枚编号）→ 出现「加入这 N 场」按钮，
   点一次全部进入行程；输入片名 → 候选列表照旧可逐行加入；输入不存在的编号 → 提示未找到。
4. `npm run typecheck`、`npm run lint`、单测全绿；`npm run verify:quick` 通过
   （`check:repo` / `check:test-map` 不因本次改动变红）。
5. E2E：`e2e/react/agenda-gantt.spec.ts` 全绿；受影响的 spec（卡片视图 / 顺位 / 三态 / 同场人数）
   已同步更新或删除，不留指向已删元素的断言。
6. 本地起 dev server 交用户验收；**用户确认后**再提交推送（本机约定：默认不推）。
