# PLAN-20260910144138 — 甘特缩放改为**纵向行高**(一屏看到更多影厅)+ 卡片等比缩小

## 1. 用户诉求(逐字)

> 「我不想卡片本身被缩放影响 缩放是能看到下面的更多的影院吧 因为现在长条很长 影院很多」

`AskUserQuestion` 口径确认(用户选定):

| 问题 | 用户选定 |
|---|---|
| 「缩放」到底要控制哪个方向? | **纵向:行高** |
| 「卡片本身不被缩放」具体指什么? | **卡片等比缩小** |

解读:**缩放的主体从「横向时间刻度」改成「纵向行高」**——29 厅 × 92px ≈ 2668px,100% 时一屏只看得到
7~8 行,痛点是纵向。卡片不再被横向拉伸/挤压,而是**随行高等比缩小**(字号、留白、行高一起走)。

## 2. 现状(动手前读到的真实代码)

| 项 | 现状 | 位置 |
|---|---|---|
| 缩放语义 | **横向**:`pxPerMin = PX_PER_MIN(3.0) × zoom` | `main.ts:170/243` |
| 阶梯 | `ZOOM_LEVELS = [0.35, 0.5, 0.7, 1, 1.4, 2, 3]`,沿 `stepZoom` 走 | `grid.ts:25-43` |
| 影厅列宽 | 也随横向倍率变(`labelMetrics(pxPerMin)`) | `grid.ts:60-71` |
| 行高 | **常量** `ROW_H = 92`,不参与缩放 | `grid.ts:12` |
| 卡片高度 | `ROW_H − CARD_INSET_Y×2` = 88px(满高泳道) | `grid.ts:532` |
| 卡片字号 | 硬编码字面量类:`text-[12px]`(CODE/时间)、`text-[13px]`(中文名)、`text-[11px]`(英文名) | `grid.ts:543/545/551/563/575` |
| 徽章行 | `legend.ts::appendMetaRow` + `durChip`,`CHIP_BASE` = `text-[9.5px]`(**不在 grid.ts 内**) | `legend.ts:13-15/206` |
| 控件 | `− / 百分比读数 / + / 适应 / 1:1` | `main.ts:221-234` |
| 视口锚点 | **只有横向**:`pendingAnchor`(旧刻度算 → 新刻度回写 `scrollLeft`) | `main.ts:54/169-175/240-266` |

**根因**:缩放绑在横向刻度上,纵向行高是写死的常量 → 用户「想看下面更多影院」这个诉求**没有任何入口**。

## 3. 设计决策

### 3.1 缩放主体 = 纵向行高;横向只留「适应宽度」一个动作

- 新增纵向阶梯 `ROW_ZOOM_LEVELS = [0.5, 0.65, 0.8, 1, 1.25]` → 行高 **46 / 60 / 74 / 92 / 115px**。
  50% 档 29 厅 ≈ 1334px,一屏能看到 ~19 厅(现在 7~8)。
- `− / 读数 / +` 改为走**行高**阶梯(控件主体)。
- 横向时间刻度**回归固定** `PX_PER_MIN`,但保留 `适应宽度` 按钮(一次性反解,保住「整天一眼看完」能力,
  不让上一轮 `194b419` 刚交付的能力倒退)。横向倍率独立状态 `pxZoom`,**会话内**(不持久化)。
- 读数显示 `行高 100%`;横向 ≠ 100% 时追加 `· 时间 43%` —— 让「适应宽度」的效果**可见**(否则是个隐形状态)。
- `1:1` = 行高与横向**一起**回基准比例。

> 为什么不彻底删掉横向缩放:横向刻度仍决定「一天能不能一眼看完」,而「适应宽度」只多一个按钮、
> 零新增状态机(`fitZoom` 已存在)。代价是控件从 4 个变 5 个。

### 3.2 卡片等比缩小 = `rowMetrics(z)` 单一来源

```ts
rowMetrics(z) → { rowH, fontScale, insetY, showBadges }
```

- `rowH = round(92 × z)`;`insetY = max(1, round(2 × z))`(留白归零后相邻行卡片会糊成一片,故保底 1px)。
- `fontScale = z^0.6` —— **阻尼**,与 `labelMetrics` 的字号口径同源。纯线性的话 50% 档标题掉到 6.5px
  完全不可读;阻尼档 8.6px 仍可扫读。
- 字号一律**内联** `font-size`(Tailwind 拼不出 `text-[${n}px]`,与 `ROW_BASE_CLS` 同一条坑);
  `fontScale === 1` 时不写内联 → **100% 档外观零变化**。

### 3.3 徽章行:不缩放,矮到装不下就隐藏

`CHIP_BASE` 住在 `legend.ts`(正被并行会话写入 → **不碰**),`text-[9.5px]` 是显式 px,
父级 `font-size` 不会级联下去。故:

- 徽章章体**保持原尺寸**(9.5px)—— 章是「固定尺寸的控件」,与标尺、ⓘ 同性质;缩小到 7px 反而看不清。
- `rowH < 70`(即 46 / 60 两档)时**整行不画** —— 四行内容装不下,最先舍信息量最低的它
  (等级/字幕/GV/页码/片长在 ⓘ 弹层与 hover 里都还在)。

高度预算(全局 `line-height: 1.45`,`style.css:171`):

| 档 | rowH | cardH | 内容高 | 结论 |
|---|---|---|---|---|
| 50% | 46 | 44 | ~41(三行,无徽章) | ✓ |
| 65% | 60 | 58 | ~48(三行) | ✓ |
| 80% | 74 | 70 | ~67(四行) | ✓ 4px 余量 |
| 100% | 92 | 88 | ~74 | ✓ |
| 125% | 115 | 109 | ~83 | ✓ |

### 3.4 纵向视口锚点(必须做,否则会「跳走」)

纵向是**页面**在滚。网格每次重建换新容器 → 若不动 `window.scrollY`,行高一缩,
「你正在看的第 20 厅」会瞬间飞出屏幕上方(19 行 × 46px ≈ 874px 的位移)。

- 重建前:`rowAnchor(grid)` = 参考线(视口顶 `y=0`,或网格顶若它还在视口下方)落在**第几行(小数行号)**。
- 重建后:按新行高反算该行应处的视口位置,`window.scrollBy(0, delta)` 补回来。
- 与横向 `pendingAnchor` 并存(横向缩放同样会重建容器 → `scrollLeft` 归零,两者都要修)。
- 锚点参考行 = 行上新增的 `data-vrow`(同时给无头验收当选择器)。

### 3.5 不动的部分

- `labelMetrics` / `fitZoom`(横向,仍被「适应宽度」使用,`clampZoom` → 改名 `clampFitZoom`)。
- `ZOOM_LEVELS` 与 `stepZoom` **删除**(横向不再有阶梯,`fitZoom` 只需上下界)。
- 标尺行高(`min-h-[28px]/[44px]`)与字号:它是**轴头**,不是影厅行,不随行高缩放。
- 影厅列代码 chip:随**横向**倍率变(`labelMetrics`),不随行高变 —— 46px 行里一枚 15px 高的 chip
  比例仍正常。

## 5. 验收(无头,`playwright-core` + 缓存 chromium)

1. 五档行高实测 = 46 / 60 / 74 / 92 / 115。
2. 卡片字号等比:100% vs 50% 标题 computed `font-size` 比值 ≈ 0.66。
3. 卡片**不溢出**:每档 `card.scrollHeight ≤ card.clientHeight`。
4. 徽章行在 46/60 档不存在,74 档存在。
5. 一屏可见影厅数:固定 900px 视口,50% 档 ≫ 100% 档。
6. 纵向锚点:滚到第 20 厅 → 按 `−` → 第 20 厅仍在视口顶部附近(±20px)。
7. 横向 `scrollLeft` 在行高缩放前后保持。
8. `1:1` 回 92px + 横向 100%;`适应宽度` 生效且读数出现 `· 时间 xx%`。
9. `typecheck` + `build` 绿。
