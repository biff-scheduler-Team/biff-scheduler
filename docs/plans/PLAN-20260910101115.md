# PLAN 2026-09-10 10:11:15 — 「影片库 / 我的选片」也靠右(顶栏控件全数归右簇)

> 需求(用户原话):「影片库和我的选片这两个按钮也要向左对齐」→ 澄清后用户更正:「**说错了 向右**」。
> 口径 = 这两个按钮**并入右簇**,与 A/B 方案 · ⚠ · 导出 · 设置 一起贴 header 右端;logo 独占左侧。
> 本文件 = 本需求唯一规划文档。

## 现状(代码事实,HEAD a339ba2,上一轮 `88e8e50` 之后)

`<header id="topbar">`(index.html:12–36)四个直接子元素,**左右分簇**:

```
[logo 组] [#library-btn 影片库] [#my-picks-btn 我的选片] [div.ml-auto 右簇: group-switch → conflict-badge → export-wrap → settings-btn]
```

线上实测(1440px):右簇右缘 1424 = header 内容右界(贴边 0px);logo 右缘 355 → 影片库左缘 369 → 我的选片左缘 452。
→ 本次把 `影片库` / `我的选片` 移入右簇,header 回到**两个直接子元素**(logo 组 + 控件群),即 `PLAN-20260910012009` 描述的「logo + 右侧按钮群」形态。

## 方案(仅动 `index.html` 的 header 一段)

1. `#library-btn`、`#my-picks-btn` 从 header 直接子级**移回右簇容器**,插在 `#conflict-badge` 之后、`[data-export-wrap]` 之前
   → 恢复改动前的相对顺序:`A 方案 / B 方案 → ⚠ → 影片库 → 我的选片 → 导出 .ics → 设置`。
2. 右簇容器加 `flex-wrap`:宽屏内容装得下 → 不换行(与现状一致,依旧 `ml-auto` 贴右);
   窄屏容器被压缩时 → **内部**换行而不是整块溢出(不加剧 `flex-shrink` 造成的横向滚动)。
3. 窄屏(≤720px)追加 `max-[720px]:w-full max-[720px]:justify-end`:
   - `w-full` 让控件群**独占一行**(否则会被挤到 logo 右侧只剩几十像素,内部折成三四行、把 header 顶得很高);
   - `justify-end` 让该行(及其内部折行后的每一行)**右对齐**,与宽屏"靠右"语言一致。
4. 不动:logo 组、`ml-auto`、任何 id / data 属性 / 类名文案、`main.ts` / `style.css`。
   交互全部走 id / data 委托(`#group-switch [data-g]` / `#library-btn` / `#my-picks-btn` / `#export-btn` / `#export-menu button` / `[data-export-wrap]` / `#settings-btn` / `#conflict-badge`),不依赖 DOM 层级或兄弟顺序 → JS 零改动。

## 验收

1. 宽屏(≥ 1100px):`logo` 贴左;`A 方案 / B 方案 · ⚠ · 影片库 · 我的选片 · 导出 .ics · 设置` **一整排**贴 header 右端(右缘与 header 内容右界差 ≤1px),单行不换行。
2. 窄屏(720 / 480 / 390px):logo 独占一行,控件群整块换行并**右对齐**;无横向溢出、无重叠、无半截按钮。
3. 交互回归:A/B 切换、影片库、我的选片(计数角标)、导出下拉(仍紧贴按钮下方右对齐、点外部关闭)、设置、⚠ 角标滚动,全部与改动前一致。
4. `npm run typecheck` + `npm run build` 通过;不启动 dev server(项目约定:读代码 + build + 一次性无头断言)。
5. 线上以无头几何断言复核:各视口下控件群右缘 = header 内容右界,且 `documentElement.scrollWidth <= innerWidth`。
