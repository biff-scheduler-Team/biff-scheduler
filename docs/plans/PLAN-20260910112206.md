# PLAN-20260910112206 —「智能排片」结果弹层视觉降噪重排

## 0. 需求来源（用户原话要点）

1. **分割线过于高调**：粗灰虚线框把每个单元都切开 → 整体割裂、杂乱。
2. **提示文本阅读成本高**：顶部说明字号偏小且未分段；底部「未纳入原因」多条重复文案
   `暂无排期(等 9/11 官方排期后自动可排)` 占满视觉空间。
3. **时间 / 地点未拆分**：`11:00–13:05` 应稍深色 / 半加粗；日期与影院走次级浅灰，影院放第二行。
4. **标签样式不统一**：「备选 / 必看」纯文本混在标题里 → 统一微圆角 Tag（浅紫 / 浅蓝底 + 深色字）。
5. **日期分组**：同一天聚合在子区块，标题写 `10/8 周四`，下面只列时间与片名，避免重复 5 次。
6. **顶部 Header 精简**：长规则句提炼为短标签（`跨馆缓冲 10min`）或藏进 `i` Tooltip。
7. **方案切换**：A/B 做成 Segmented Control；「采纳为 A 方案」主色高亮且与所选方案对齐。
8. **底部「未纳入与原因」**：合并同类项 + 浅灰/浅红 Card 收纳。

## 1. 定位：问题全部落在同一个视图

用户描述的 4 个专属名词 —— `采纳为 A 方案`、`未纳入与原因`、`暂无排期(等 9/11 …)`、
`日期 + 时间 + 影院` 同排 —— 全部只出现在 **`src/library.ts` 的「智能排片」结果弹层**
（`openEngineDialog` / `enginePlanBox` / `enginePickRow`）。故本次重做该弹层的渲染层。

**关键结构性缺陷（本次一并修掉）**：现在 A / B 是两个**各自完整**的卡片
（`for (const plan of plans) list.appendChild(enginePlanBox(plan, ctx))`），
所以同一部片的「未纳入原因」在 A 卡里印一遍、B 卡里再印一遍 —— 这正是
「多条重复文案占满视觉空间」的根因。**改为「一个面板 + A/B 分段控件」后，重复天然消失。**

## 2. 改动清单

### 2.1 `src/style.css` — 新增档位浅底 token
- `--pri-must-soft: #e9eefc`（浅蓝）/ `--pri-maybe-soft: #f4eafc`（浅紫）/ `--pri-wild-soft: #eef1f5`（浅灰蓝）
- `@theme` 映射 `--color-pri-must-soft` / `--color-pri-maybe-soft` / `--color-pri-wild-soft`
  → 生成 `bg-pri-*-soft`（Tailwind v4 需源码里出现完整字面量，故写在 `pick.ts` 的 Record 里）。
- 复用既有 `--bg-hover`(#fafafa) 作「暂无排期」浅灰 Card、`--biff-red-soft`(#fdecec) 作「被占用」浅红 Card。

### 2.2 `src/pick.ts` — 统一 Tag 层（单一来源）
- 新增 `PRI_TAG: Record<Priority, string>`（浅底 + 深字完整字面量）。
- 新增 `priTag(p)` 构造器：`inline-flex rounded-[5px] px-[6px] py-px text-[10.5px] font-bold`。
- 建议行程的 Tag、未纳入 Card 的 Tag 全部走它，不再各写一份。

### 2.3 `src/engine.ts` — 未纳入原因结构化
- `EngineDrop` 增 `kind: "noshow" | "blocked" | "unpicked"`（供 UI 选色 / 分组）。
- `describeDrop` 返回 `{ kind, reason }`；`noshow` 文案缩短为
  `暂无排期，预计 9/11 排期发布后可自动排`（原句带括号、过长）。

### 2.4 `src/library.ts` — 弹层重排
| 位置 | 现在 | 改为 |
|---|---|---|
| 顶部说明 | 12.5px 一长句 | 一行短标签（`基于 N 部已打标影片` + `跨馆缓冲 10min` + `必看优先覆盖` + `随缘不自动排`）+ `i` 圆钮挂 `data-tip`（tip.ts 的「标题 + 分点」多行格式） |
| 方案容器 | A / B 两张完整卡各带边框 | 一个面板：顶部 Segmented Control 切 A/B，下方单卡 |
| 卡片描边 | `border border-line`（灰实框） | `border border-line-faint`（#f4f4f4 极浅）+ `rounded-[12px]` |
| 场次行 | 每行 `border-b border-dashed`（粗灰虚线切割） | 去线 → `gap` + `hover:bg-hover rounded-[7px]`；仅在日期组之间留极浅实线 |
| 场次行内容 | 一行 muted：`10/8 周四 11:00–13:05 · 影院` | 两列：左 `11:00–13:05`（`text-ink font-semibold tabular-nums`）；右第一行 片名 + Tag + code，第二行 影院（`text-meta text-[11.5px]`） |
| 日期 | 每行重复 | 分组头 `10/8 周四`（`text-meta font-bold`），组内只列时间 + 片名 |
| 档位 | `text-pri-*` 纯文本 | `priTag()` 微圆角 Tag |
| 未纳入 | `border-t dashed` + 每条一行重复文案 | `border-t border-line-faint` + 按 `reason` 分组，每组一张 Card（浅灰 = 暂无排期 / 浅红 = 被占用或未命中），Card 内片名做 chip（Tag + 片名） |
| 采纳按钮 | 每张卡一个 | 单卡一个，随分段控件联动；已采纳的方案显示 `✓ 已采纳为 X 方案` 且禁用 |

### 2.5 保留不动的「语义虚线」
以下虚线是**信息本身**，不是装饰分隔，本次不改（避免丢语义）：
`grid.ts` 放弃映后谈块（`gv-talk-off`）、`badges.ts` 连场 `묶` 章、
`legend.ts` KN 字幕章 / `(空白)` 占位章。

### 2.6 顺带降噪（同属「粗虚线切割」）
- `library.ts` 影片库行「详情展开容器」与「还没排场」提示条的 `border-t border-dashed border-line`
  → `border-line-faint`（极浅实线）。
- **决策**：`library.ts` 的「未设」章 / 「未排场」章虽也是虚线，但那是 11px 小章、语义本身
  （"占位/待定"），不是"粗灰虚线框"，本次**不动** —— 改了反而丢语义。见 §2.5 同一口径。
