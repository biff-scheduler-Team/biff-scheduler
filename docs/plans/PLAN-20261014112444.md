# PLAN-20261014112444 — 红黑榜：合集场次拆成成员片（搜 062 出现「她说」）

## 目标

红黑榜搜索场次编号时，命中的是**合集场次**整块，卡片顶着英文单元名；合集里的影片在榜上无处可寻、也无处贴票。

> 用户原话：
> 「我在红黑榜搜索062 在影片库是出现"她说" 但是红黑榜出现的是 "Asian Short Film Competition 1"
> 我希望出现的是和影片库一样是"她说"」

盘点后用户确认要的形态（单选已选第一项）：

> **拆成成员片单独成卡**：红黑榜不再把 062 当作一张「Asian Short Film Competition 1」合集卡，
> 而是把 5 部成员片各自成卡（她说 / Beneath the Barren / αLPα / Salt Electric / Downwind），
> 搜 062 命中这 5 张，每部可单独贴票。

## 现状（代码事实，2026-10-14 用真实产物核过）

- `062` 是**合集场次**「Asian Short Film Competition 1」（`public/schedule.json:1141-1164`）：
  官方排期 `title_zh` **为空**，`midnight_members` 列了 5 部成员片的英文名；同一节目另有两场
  （`326` / `492`），三个场次合成**同一个影片节点** `sched:asian short film competition 1`
  （`model.ts::buildFilms` 按 `filmNodeKey` 归并，实测其 `shows = [062, 326, 492]`）。
- 「她说」是**独立目录片** `cat:f228`（`public/films.json:7283-7301`，`title_zh:"她说"`、
  `title_en:"She Said"`）：**没有自己的场次**，只有 `block_code:"062"`，在 `buildFilms` 里长成
  `shows: []` + `block: Screening(062)` 的节点（`model.ts:100`）。
- 红黑榜候选 `redblack.ts:836 boardFilms()` = `films.filter((f) => f.shows.length > 0)`
  → 合集节点在榜上，**成员片一律不在**（`shows` 为空）。
- 搜索 `model.ts:135 searchFilm()` 认「片名 / 其余片名 / 元信息 / **场次编号**」；成员片的
  `shows` 为空 ⇒ **搜 062 命中不了它们**。实测：搜 `062` 全库只命中那 1 个合集节点，
  影片库与红黑榜**结果相同**（用户所述「影片库出现她说」应是按片名搜那张「收录于合集」的卡）。
- 全库共 **11** 个带 `midnight_members` 的节点，分两类（实测）：
  - **8 个「短片竞赛 / 双片连映」**（Asian 1/2、Korean 1/2/3、Bus Stop+Flesh Impact、
    Kakurenbo+Shiranui、Sandiwara+EEAAO）：成员片**全部**是纯目录片（有 `block`、`shows` 为空）
    → 这些片在榜上**别无落脚点**；
  - **3 个「午夜联映」**（Midnight Passion 1/2/3，code 075/168/269）：成员片（Sapiens、
    Angel′s Egg…）**自己就有场次**，节点是排期节点、**没有** `block` 指针 → 它们本来就在榜上。
- 贴票与评语按 `film.key` 存（本地 `biff.redblack.v2` + 服务端 `film_vote_*`），
  **键就是字符串，无白名单校验** ⇒ `cat:f228` 可直接作为投票键。

## 范围

**做:**

1. `apps/web/src/redblack.ts::boardFilms()` —— 合集节点**改成由它的成员片各占一张卡**：
   按成员片的 `FilmNode.block.code` 倒排（成员片的 `block` 就是它所属的合集场次），
   合集节点本身不再上榜；**只有能全部解析出成员才拆**，一个都解析不出（午夜联映）原样保留。
2. `apps/web/src/redblack.ts::searchBoardFilm()`（新）—— 榜单搜索在 `searchFilm()` 之外，
   额外认这张卡**所属合集场次**的编号 / 片名 —— 否则拆完之后「搜 062」会一张都不剩。
3. `apps/web/src/pages/RedBlackPage.tsx:500` 的候选过滤改走 `searchBoardFilm`。
4. 单测（`apps/web/tests/redblack.test.ts` 补合成用例 + `apps/web/tests/model-parity.test.ts`
   补真实产物用例：062 → 那 5 张、午夜联映不动、无重复 key、搜 062 命中 `cat:f228`）。
5. E2E 一条（`e2e/react/redblack.spec.ts`）：搜 `062` → `cat:f228` 卡片可见且片名为「她说」，
   合集卡 `sched:asian short film competition 1` 已不在。
6. 回写 `docs/CONVENTIONS.md`（红黑榜榜单口径那条）。

**不做:**

- 不动影片库 / 排片表 / 我的选片 / 我的行程：`searchFilm()` 与 `buildFilms()` **一行不改**，
  这次只改红黑榜自己的候选与搜索。
- 不动服务端与 D1：投票键是自由字符串，无需迁移；也**不做**「旧合集票搬到成员片」的一次性迁移
  （旧票留在库里，只是不再有卡片显示 —— 见下面「已知代价」）。
- 不动 `Midnight Passion 1/2/3` 三张卡（成员片自己已有卡片；拆了反而会让「搜 269」落空）。
- 不给成员片卡加「收录于合集 X」的额外文案（红黑榜卡片本来不印场次信息，本轮不扩）。

## 方案取舍

| 备选 | 结论 | 理由 |
|---|---|---|
| 只把合集卡**改名**成「她说」 | 否决 | 062 是 5 部短片的合集，改名会让「一张票连看 5 部」读成一部片，且其余 4 部彻底消失 |
| 拆成员片，成员按 `midnight_members` **片名**解析 | 否决 | 需要 `cat.filmByEn` 索引，而 `boardFilms(films)` 只有榜单自己那份 `films`；按 `block.code` 倒排是同一份对应关系的现成出口（且实测 8 个节点的解析结果与片名解析**逐个一致**） |
| 拆成员片，**一律**拆（含午夜联映 3 张） | 否决 | 那 3 张的成员片自己就有卡片（不靠 `block`），拆完卡片没了、票也无处显示；且「搜 269」会落空（成员片只认自己的场次编号）。按 `block` 倒排天然排除它们 —— 判据是「成员片在榜上别无落脚点才拆」 |
| 成员片卡**额外**认合集编号做搜索 | **采纳** | 拆掉合集卡之后，成员片自己 `shows` 为空、`searchFilm` 的场次编号那一段恒不命中；不补这一步，「搜 062」会从「搜到 1 张错的」变成「一张都不剩」（比原问题更糟） |
| 给合集卡**下方列成员**（保留投票归属） | 否决 | 用户明确选了「拆成成员片各自成卡」，且「一部片一张卡、一部一枚票」是既有口径 |

## 已知代价（写清楚，不偷偷改口径）

- 此前贴在那 8 张合集卡上的贴纸（键如 `sched:asian short film competition 1`）在榜上**不再有卡片**：
  本地数据不删、服务端票数照旧在库里，只是不再参与页面显示与 hero 的「全站」小计。
  这是「合集 → 成员片」换口径的必然结果，用户已知情并选择该形态；清理留到将来需要时再谈。
- 榜单卡片数 299 → **319**（-8 合集 + 28 成员片，实测）。

## 验收标准

1. 单测：`boardFilms()` 对真实产物给出 `cat:f228`（她说）等 28 张成员片、不含那 8 个合集节点、
   不含重复 key，且 `sched:midnight passion *` 仍在；榜单长度 = 319。
2. 单测：`searchBoardFilm(cat:f228 节点, "062") === true`、`searchBoardFilm(合集节点, "062")` 不再有卡片
   （该节点不在榜上）、`searchBoardFilm(午夜联映节点, "269") === true`。
3. E2E（`redblack` spec）：搜 `062` 后 `[data-film-key="cat:f228"]` 可见、片名逐字为「她说」，
   且页面上没有 `sched:asian short film competition 1` 这张卡。
4. `npm run typecheck` / `npm run lint` 通过（本地跑一次；门禁本体仍在云端）。
