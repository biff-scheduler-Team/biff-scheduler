# PLAN 2026-09-10 10:17:13 — 「GV 映后」移出网格红绿灯图例条,并在 ⓘ 说明里改用真徽章图标

> 需求(用户原话):「目前只有 GV 这一种类型显示在"已选""时间紧张""完全冲突"这个模块这里 感觉有点不对 是不是要放到问号里面 问号里面也写的是 GV 而不是图标式的 GV」
> 本文件 = 本需求唯一规划文档。

## 口径(为什么这样改)

网格卡下方那条图例(index.html:46–53)= **红绿灯「状态」图例**:绿=已选 / 黄=时间紧张 / 红=完全冲突。
这三项都是「排得怎么样」的**状态**,而 `GV 映后` 是**场次特性徽章**(Guest Visit),属于「这一场是什么」——
两类东西并列在同一个图例条里,确实是分类错误(用户直觉正确)。

→ GV 的说明归位到「ⓘ 日程表说明 · 图例总览」弹层(`buildGuideBody`),那里本来就有专属章节
「4 场次特性徽章」(legend.ts:317–327),且**已经用真徽章 `badgeEl("gv")` 渲染**。

第二问「问号里面也写的是 GV 而不是图标式的 GV」:弹层里另有两处把 GV 写成**纯文本**,与徽章章节 / demo 行
(`legend.ts:273` 用的是真徽章)口径不一致:

| 位置 | 现状 | 问题 |
| --- | --- | --- |
| `legend.ts:285`「1 一格怎么读」表格「元素」列 | 文本 `"GV"` | 同表 demo 行是实心黑徽章 → 表格用文字指代图标 |
| `legend.ts:361`「6 网格与行程图例」列表 | 文本 `"GV(实心黑标)"` | 同上;且「网格与行程图例」是状态色列表,GV 混入仍是分类错误 |

## 方案(只动 3 处;不动 JS 逻辑 / 不改任何 id)

1. **`index.html:50`** —— 删除图例条里的 GV 那一整行 `<span>`(`data-tip` + 黑方块 + 「GV 映后」)。
   保留:已选 / 时间紧张 / 完全冲突 / 我的选片(色点)/ ⓘ 日程表说明。该 span 无 id、无 JS 引用,删除零副作用。
2. **`legend.ts:285`** —— 「一格怎么读」表格 GV 行的「元素」列由文本 `"GV"` 换成 `badgeEl("gv")`(实心黑徽章)。
   同表其余文本行(`09:00–10:40` / `004` / `片名`)保持不变 —— 它们本就是文本元素,非图标。
3. **`legend.ts:361`** —— 「网格与行程图例」列表的 GV 行标签换成 `badgeEl("gv")`;该列表渲染循环
   (`lines.forEach`)由「模板字符串拼接」改为**支持 HTMLElement 标签**(字符串走 `textContent`,节点走 `append`),
   徽章外包一层 `inline-flex align-[-1px]` 保证与行内文字基线对齐(与图例条色块同口径)。

不改:图例条的其它项、`abbrTooltip()`(`badges.ts:25`,tooltip 只能纯文本)、任何 CSS / 交互。
