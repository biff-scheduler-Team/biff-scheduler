# PLAN 2026-09-11 21:00:00 — 快捷分享:定一套「微信里也读得清」的文案模板

> 需求(用户原话):「做一个快捷分享的模板 不止需要导出 ics 最好定一个格式 在微信中也能清晰明了」。

## 1. 问题:现有两个文本出口都不适合分享

| 出口 | 形态 | 分享到微信的问题 |
|---|---|---|
| 导出 `.ics` | 文件 | 微信里贴过去是一坨不可读的 `BEGIN:VEVENT…`;对方还得先存文件再用日历打开 |
| 抢票顺位清单(复制) | 单行塞满 6 个字段 | 是**排票用**的紧凑清单:手机上一折行,时间 / 片名 / 影院 / 档位全糊在一起;且按**档位**排序,不是按日程读的顺序 |

于是「分享给朋友」这件事实际上**没有出口**。

## 2. 定格式:两行一场 + 日期分节

```
🎬 BIFF 2026 看片计划 · A 方案
📅 10/8–10/9 · 共 2 场 / 2 部
━━━━━━━━━━━━

【10/8 周四 · 1 场】
10:00–11:40  Alpha
📍 BCC 1 · 001 · 必看

【10/9 周五 · 1 场】
13:00–14:40  Beta
📍 BCC 1 · 002 · 备选 · GV 含映后谈
📝 带朋友
```

**微信适配的三条约束**(改格式时别破坏):

1. **不用 Markdown** —— 微信不渲染,`**加粗**` 会原样印出来。层次只靠全角标点(【】· —)与换行。
2. **emoji 只做行首标记**(🎬 标题 / 📅 概要 / 📍 影院 / 📝 备注)—— 全平台可渲染,
   且让「两行一场」在纯文本里也能看出哪行是附属信息;正文里不夹 emoji,免得被当噪声。
3. **每行尽量短** —— 影院走短名(`legend.ts::venueShort`,如 `BCC 1`),片名**单独一行**,
   长片名折行也不会把时间 / 影院挤错位;跨午夜场印「次日 05:35」,绝不把 24+ 制的 `29:35` 丢出去。

**口径**(与网格 / 行程 / `.ics` 同源,勿另起一套):

* 时间 = **有效结束**(`gv.ts::effEndMin`)—— 含 / 弃映后谈按单场解析,与网格冲突判定同一口径;
* 片名 = `util.ts::displayTitle`(英文名 · 中文名,全站唯一口径);
* 日期标签 = `util.ts::dateInfo().label`(与网格日期条 / 行程日期头同一份,故是 `10/8` 而非 `10/08`);
* 档位 = `pick.ts::PRI_LABEL`;**未设档位(null)整段省略** —— 「未分级」是内部术语,印出来只会让朋友困惑;
* 排序**在函数内做**(日期 → 开场时间):分节头与日期区间都依赖有序,不把这件事留给调用方。

## 4. 设计取舍

* **只给一个入口,跟随当前方案**(与「抢票顺位清单」同口径)—— 菜单已有 4 项,
  再按 A / B / A+B 铺三份分享就是 6 项;分享本来就是「先切到我要分享的那个方案,再点一次」。
* **`which="ALL"` 仍支持**(文案头印「A+B 全部」)—— `buildShareText` 是纯函数,
  将来若要在别处(如「我的行程」)加分享入口,不必改格式。
* **不做「生成图片」**:分享图片要引入 canvas / 字体渲染,收益(美观)与代价(包体 + 排版维护)不成比例;
  纯文本在任何聊天工具里都能转发、复制、搜索。
* **不追加站点推广尾巴**(如「由 biff-scheduler 生成」)—— 用户没要求,对外分享多一行噪声。
