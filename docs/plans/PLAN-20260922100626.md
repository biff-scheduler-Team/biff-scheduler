# PLAN-20260922100626 — 收掉「数据分析」页在手机上的三条 E2E 红

## 目标

> 把那批 rush-analysis mobile 红也顺手收掉

`e2e/react/rush-analysis.spec.ts` 的三条用例在 **mobile-chromium / mobile-webkit** 上红，且**从上一轮
（2026-09-20「抢票分析」那批改动）起就一直红**，main 上已经连续两次 CI 失败。桌面端全绿，所以问题在
「同一段断言换个视口就不成立」，而不是功能坏了。

三条红（CI run `35618505228`，本地 `--project=mobile-chromium` 同样复现）：

| 用例 | 失败断言 | 实测值（手机 412 宽） |
|---|---|---|
| `:117` 影片明细最多 30 行、一次看得见 10 行 | `tenth.y + tenth.height ≤ box.y + box.height + 1` | 第 10 行底 1677.6 > 容器底 1598.1（差 79.5px） |
| `:192` 类目名太长时 hover 轴标签看全名 | `expect.poll(readTooltip).toContain(prefix)` | tooltip div 一个都没出现 |
| `:289` hover 柱子时高亮块压在柱子下面 | `svg path` `toHaveCount(countBefore + 1)` | 15 → 15（高亮块没画） |

## 范围

**做：**

- 让明细表在**任何视口**下都满足「一次看得见 10 行」这条已写在 CSS 注释里的不变量。
- 让两条 hover 用例在窄视口下量到正确的坐标（先滚进视口再 hover）。

**不做：**

- 不动 `VISIBLE_ROWS` / `LIST_ROWS`（10 / 30 是用户 2026-09-20 定的口径）。
- 不改 ECharts 配置（`sharedTooltip` / `axisPointer` 的 `z` / alpha 全部保持原样，那是上一轮刚验过的东西）。
- 不碰 `review-library` mobile-webkit 那条红 —— 那是另一处 flake（同一轮里 `parity-library` 也红过、名字不同），
  与本页无关，本 PLAN 不覆盖。
- 不新增依赖。

## 诊断（先量后改，不靠猜）

用一次性脚本（现已删除）在 `vite preview` 上分别量桌面 1512 与 Pixel 7：

```
[表格 桌面]     thead 23.5  row 33  可见 10 行
[表格 Pixel 7]  thead 23.5  row 51  可见  6 行      ← 行高被撑到 51px
[图表 桌面]     柱子 y=840（视口 982）→ hover 出高亮块
[图表 412 无触摸] 柱子 y=1476（视口 839）→ hover 什么都不发生
[图表 412 先滚进视口] 柱子 y=479 → hover 正常出高亮块
```

结论两条，都是**断言/样式的前提**问题，不是功能回归：

1. **行高不恒定**：`.ra-table td { padding: 7px 0 }` + 13px 字 → 单行 33px；但窄屏下首列只剩 ~44% 宽
   （四个数字列各占 14%），长片名必定折成两行 → 行高 51px。于是 `max-height: 354px`
   （= 表头 23.5 + 10 × 33，注释里写死的推算）在手机上只装得下 6 行，「一次看得见 10 行」当场失效。
2. **hover 打在视口外**：`facet-year` / `crowd-want` 在窄视口下都落在首屏之外，`page.mouse.move`
   给的是视口坐标 —— 打到视口外的坐标等于没 hover（不是「手机没有 hover」：**无触摸**的 412 窄视口同样不触发，
   而先滚进视口后在 Pixel 7 上 hover 一样出高亮块）。

## 方案取舍

| 备选 | 结论 | 理由 |
|---|---|---|
| **D1** 手机上把「可见 10 行」放宽成「可见 6 行」/ 改成按视口动态算行数 | **否决** | 「TOP 30，一次看得见 10 行、其余滚动」是用户 2026-09-20 定的口径。按视口动态算还得同步改 caption 文案与 `VISIBLE_ROWS`，等于把一条硬承诺降级成视口相关的不确定行为。 |
| **D2** 固定行高（`td { height: 33px }` + `overflow: hidden`） | **否决** | 折行的第二行会被**切一半**露在那里，比省略号更难看，也仍然不是「行高恒定」的干净解法。 |
| **D3** `table-layout: fixed` + 单元格 `nowrap` + 省略号（**采纳**） | **采纳** | 列宽只由 % 决定 → 行高在所有视口恒为 33px，`max-height: 354px` 的推算前提重新成立；长片名 / 长影厅名以省略号收尾，完整值挂到 `title` 上（鼠标可看，手机长按也能看）。 |
| **D4** 只改断言（加容差 / 断言「至少 N 行」） | **否决** | 把产品承诺改小去迁就实现，正是 §9「不得为让测试变绿去改实现」的反面。行高不恒定本身就是要修的东西。 |
| **D5** hover 用例只在桌面跑（`test.skip(isMobile)`） | **否决** | 上一轮刚加的「hover 轴标签看全名」在手机上是**能用**的（先滚到图前再 hover 就出），跳过等于拿覆盖率换绿。 |
| **D6** hover 前 `scrollIntoViewIfNeeded()`（**采纳**） | **采纳** | 真实用户也是先滚到图前再 hover；修的是「测试把视口外元素当成可 hover」这个错误前提。 |
