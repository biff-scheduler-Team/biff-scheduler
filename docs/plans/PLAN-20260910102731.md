# PLAN-20260910102731 · 「我的选片 · 打标清单」定位按钮改为逐场定位

## 1. 需求

「我的选片 · 打标清单」(`openMyPicks`)里,影片行右侧只有一个「定位 ▸」按钮,点击后跳到**该片首场**(`n.shows[0].code`)。
实际使用中用户想定位的是**具体某一晚/某一场**,而不是"这片的第一场"。

> 定位按钮需要是具体场次的定位,所以可能每一个场次要渲染一个按钮。

## 2. 现状

`src/library.ts` → `openMyPicks()` → `pickRow(n)`:

- **head 操作区**(`ops`):`${n.shows.length} 场` 章 + `${group} 已选 N` 章 + **`定位 ▸`(整片级,跳 `n.shows[0]`)** + `详情 ⓘ` + `✕ 取消打标`。
- **场次摘要块**:`n.shows.slice(0, 3)` 纯文本行 `[code] 日期 时间 场馆`,无操作;超出 3 场只给一行「… 另有 N 场,点「详情 ⓘ」看全部」。

问题:① 场次行没有定位入口;② 整片级按钮语义含糊(哪一场?);③ 只列 3 场,第 4 场起根本无法定位。

## 3. 方案

只改 `src/library.ts` 的 `pickRow`(单文件,与并行会话在途文件无交集)。

1. **删掉 head 里整片级 `定位 ▸`**:head 只留 `N 场` / `A 已选 N` / `详情 ⓘ` / `✕ 取消打标`。定位语义彻底下放到场次行,不再出现"点了不知道跳哪场"的按钮。
2. **场次摘要块改为逐场行**:去掉 `slice(0, 3)` 与「另有 N 场」提示,**全部场次**都渲染一行 —— 每场一个按钮才叫"每一个场次渲染一个按钮"。
3. **每行一个 `定位 ▸`**:行结构改 `grid grid-cols-[minmax(0,1fr)_auto]`,左列 `[code] 日期 周几 时间 · 场馆`(场馆 `truncate`),右列小号红渐变 `定位 ▸`(与「影片库」场次行同一视觉语言,只是尺寸收一号)。
4. **行本身也可点**:行加 `data-lib-row` + `data-code` + `cursor-pointer hover:bg-hover`,与「影片库」场次行同款交互;`list` 上挂**一次**委托监听(列表每次 `innerHTML=""` 重建,委托不用重绑),命中 `[data-code]` → `ctx.onLocate(code)`。
5. **文案**:按钮 `data-tip` / `title` 从"该片首场"改为"该场";`legend.ts` 里「顶栏『我的选片』」词条 `跳转定位` → `逐场跳转定位`。

## 4. 不做

- 不动 `openLibrary` 里「影片库」的场次行(它本来就是逐场 `定位 ▸`,本次只让两边口径一致)。
- 不在场次行加"已选/未选"章(本次只解决定位粒度,避免顺手扩需求)。
- 不动 `ctx.onLocate` → `jumpToScreening`(跳日期 + 横滚 + flash 高亮,已满足"定位到具体场次")。

## 5. 验收

- 打标清单里每部片:场次行数 == 该片实际场次数(不再截断到 3)。
- 点任一行的 `定位 ▸`(或点行本身)→ 弹层关闭、跳到该场所在日期、横向滚到该卡并闪烁高亮。
- 同一影片的 4 个场次,4 个按钮分别跳到 4 个不同位置(而非都跳首场)。
- `npm run build` / tsc 无错。

## 6. 提交与部署

`src/library.ts` 是并行会话在途文件之外的**唯一**改动文件 → `git add src/library.ts docs/plans/PLAN-20260910102731.md` 精确提交(不带 `-a`),不卷入对方未提交的 priority nullable 改动。
部署:`npm run deploy` 走磁盘源码,会把对方在途改动一起上线 —— 需先确认对方是否已自行提交/部署,再决定隔离 worktree 部署还是等对方 deploy 带出。

## 7. 实现纪要(已落地)

提交 `01ee13a`(只含 `src/library.ts` + 本 PLAN;对方在途的 priority nullable 改动未卷入)。

**实际改动(`src/library.ts` → `openMyPicks` → `pickRow`)**

- head `ops`:`if (n.shows.length)` 分支里删掉整片级 `定位 ▸`(原 `ctx.onLocate(n.shows[0].code)`),只留 `${n.shows.length} 场` 与 `${group} 已选 N` 两个章;`暂无排期` 分支不动。行尾补一行注释说明定位已下放场次行。
- 场次块:`for (const s of n.shows.slice(0, 3))` → `n.shows.forEach((s, idx) => …)`,同时删掉 `if (n.shows.length > 3) … 「… 另有 N 场,点「详情 ⓘ」看全部」`。
- 场次行:类名从 `flex items-center gap-[8px] px-3 py-[6px] text-[12px] text-muted` 改为 `grid grid-cols-[minmax(0,1fr)_auto] gap-[8px] items-center px-3 py-[6px] text-[12px] text-muted cursor-pointer hover:bg-hover` + `idx > 0` 时补 `border-t border-line-faint`(首行分隔线仍由外层容器给);行挂 `dataset.libRow = "1"` / `dataset.code = s.code`。
- 左列包一层 `div.flex.items-center.gap-[8px].min-w-0`,code 章与时间加 `shrink-0`(时间不换行),`venue_display` 保持 `truncate`(宽度不足时只截场馆)。
- 右列新按钮:红渐变 `定位 ▸`,`px-[9px] py-[3px] text-[11.5px]`(比 head 旧按钮收一号),`dataset.tip = "跳到该场在时间轴上的位置"`(用 `dataset.tip` 而非原生 `title`,与「影片库」场次行同款即时 tooltip)。
- `list` 上新增一次委托监听(`render()` 每次 `innerHTML=""` 重建行,委托无需重绑):`closest("[data-lib-row]")` → `ctx.onLocate(row.dataset.code)`;按钮点击冒泡到行,与点行同一出口。

**未做**:`legend.ts` 的「顶栏『我的选片』」词条保留「跳转定位」原文 —— 该文件此刻正被并行会话改动,文案本身仍准确(只是粒度变细),不值得为一行措辞去碰对方的在途文件。若后续需要,单独改「跳转定位」→「逐场跳转定位」即可。
