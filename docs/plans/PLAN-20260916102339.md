# PLAN-20260916102339 — 电影红黑榜（贴纸拖拽 / 吸附 / 排序）

## 目标

新增顶层页面「红黑榜」：把**已散场且在自己行程中**的场次兑换成一枚小圆片贴纸，
用户选红 / 黑后**拖拽贴到对应影片的贴纸区**（吸附到槽位），累积后可按数量排序。

用户原话（逐字保留）：

> 想做一个这种电影的红黑榜 然后你只需要需要电影放完之后 并且有出现在行程之中的 如果有用户想投
> 然后你可以提示他是不是看过了 可以把它添加到自己的行程中 然后给用户发放对应个小圆片的贴纸
> 然后让他选择贴红或者黑 然后可以让他自己去贴到对应的位置 然后你可能做一要做一个拖拽
> 还有指定区域的吸附 这样的一个前端的动效 然后电影的话 你就把所有电影分成两列就好了
> 然后排行的话 目前是随机排 然后在顶部是可以通过 code 去搜索对应的电影是需 只保留一
> 电影是需要像影片库一样 是需要去重的 然后默认的话 是两列 等用户累积了这个贴纸之后
> 就可以进行由高到低的排序 不管是红的还是黑的都可以 主要按个数去排吧 也可以让用户去按红榜和黑榜进行排序
> 你可以先做一个 plan 出来

> 你先制作一个你的红黑榜的前端效果我预览下 先把前端效果改好了

参考图（实体墙「手游红黑榜」）只用于借鉴「**每张卡片自带一片散落贴纸区**」的形态，
**不代表**要做成左列红榜 / 右列黑榜。

### 追问后锁定的口径（用户已选）

| 问题 | 结论 |
|---|---|
| 一部电影能贴几枚 | **每看完一场发一枚**（同片看 3 场发 3 枚，可分别贴红 / 黑） |
| 「分成两列」 | **普通两列网格**，按当前排序顺序填充，每张卡自带贴纸区（红黑同区） |
| 不在行程里怎么投 | **弹层让他选具体场次**（列出该片全部场次，含已散场的），选一场加进行程后再发贴纸 |
| 排序 | **三档：按总数 / 红数 / 黑数降序（无随机）**；全 0 时等于影片库默认顺序 |

## 方案取舍

| 备选 | 结论 | 理由 |
|---|---|---|
| 引 `@dnd-kit` / sortablejs | 否决 | 违反「引入前量化 gzip 增量」红线；仓库已有 Pointer Events 范式（`AgendaPage.tsx:86-171`） |
| 贴纸存自由像素坐标 | 否决 | 卡片宽度随视口变，存像素会在窄屏跑到卡片外；改**槽位**（行优先 12×3） |
| 槽位用 36 个 DOM 元素铺 | 否决 | 250 部 × 36 槽 = 9000 节点；改为「网格画在 CSS 背景上 + 已贴圆点绝对定位」 |
| 每部只发一枚（红黑二选一） | 否决 | 用户已选「每看完一场发一枚」，否则「按个数排」没有意义 |
| 左列红榜 / 右列黑榜 | 否决 | 用户已选普通两列网格 |
| 单独持久化「发放记录」 | 否决 | 配额可由「行程 + 散场时间」推出，多存一份必然漂移 |
| 在 `util.ts` 里加散场判定 | 否决 | 该文件属于另一需求范围；新逻辑一律落 `redblack.ts` |
| 拿票务「已到手」当看过凭证 | 否决 | 弱口径（很多人不记票）；用户口径是「散场 + 在行程」 |
| 散场后自动发放并自动贴 | 否决 | 用户明确要「自己选红黑、自己贴到对应位置」 |
| 轮播全部 250 部（含无排期） | 否决 | 无排期片永远配额 0、永远贴不上，纯噪声；只列**有排期**的影片 |

## 验收标准

1. 「红黑榜」出现在导航末尾，点进去是**两列网格**，影片与影片库同源去重（同一部片只出现一次）。
2. 未散场 / 不在行程的影片配额为 0；点它弹出「你看过这部吗？」，列出该片全部场次可选加入行程。
3. 该场已散场后配额 +1，可把红 / 黑圆片拖入贴纸区并**吸附到槽位**；已贴的可再拖动换位、点击取下。
4. 排序三档切换生效；默认按总数降序，全 0 时等于影片库默认顺序。
5. 顶部输入场次 code（或片名）能筛出对应影片。
6. 刷新页面后贴纸颜色与位置保持（`biff.redblack.v1`）。
7. `npm test` 全绿（含新增 `redblack` 用例）；`npm run verify:quick` 全绿。
8. 本地起 dev server 交用户验收；**用户说「可以推」才 push**。

## 修订

- 修订 0（2026-09-16）：初稿。除「排序无随机」外，其余口径来自用户对 4 个追问的作答。

- **修订 1（2026-09-16，用户看完成品后的反馈）**：发放口径与观感都改了。
  用户原话：

  > 样式还不错 我觉得稍微改改 只需要标记方式 只需要在卡片上标记看过 然后提示用户可以开始贴就行了
  > 不需要严格限制电影是否已经放完 一部电影 可以有一张贴纸 然后贴纸样式优化下 现在有点像一个按钮 我想做成纸的感觉

  落地：
  1. **一部电影一枚贴纸**（原「每看完一场发一枚」作废）；解锁方式改为**卡片上手动标记「看过」**，
     **不再判断场次是否已散场、也不再要求场次在行程里**（影展 10 月才开始，按散场时间发贴纸，届前永远是空榜）。
  2. 贴纸观感改为**纸片**：不规则边缘（非正圆）+ 每枚固定倾斜（±6° 内，同槽位恒定）+ 哑光落影 + 极淡纸纹，
     去掉按钮式的渐变高光与内阴影。
  3. **移除**：补行程弹层（`toggleScreening` 不再被本页使用）、`?at=` 预览时间参数、
     `endsAt` / `hasScreened` / `watchedShows` 一整套散场判定。
  4. 新增独立键 `biff.redblack.watched.v1`（看过标记，`string[]`）；`biff.redblack.v1` 读取端
     收窄为**一部一枚**（初版多枚数据只留第一枚，零迁移）。
  5. 排序（总数 / 红榜 / 黑榜）、两列网格、code 搜索、拖拽吸附、示例铺底均不变。
     仍为「做」的部分：`npm test` 全绿（33 例）、`verify:quick`、受影响 E2E、文档回写。

- **修订 2（2026-09-16，用户对卡片布局的反馈）**：卡片改为**三栏**。
  用户原话：

  > 海报和电影信息 放中间 两边的空白区域作为贴贴纸的区域类似于脊骨

  落地：
  1. `redblack.ts` 的贴纸区从「一张卡一块 4×4」改为「**左右各一块 4×4**」，槽位编号统一：
     左 `0..SIDE_SLOTS-1`、右 `SIDE_SLOTS..SLOT_COUNT-1`。`slotOffset()` 返回该侧**局部**坐标，
     `slotAt()` 增加 `side` 参数，`nearestFreeSlot()` 只在**同侧**内找空位
     （跨侧会让贴纸「跳」到卡片另一边）。
  2. `SLOT_AREA_WIDTH/HEIGHT` 常量改为 `slotAreaWidth(cell) / slotAreaHeight(cell)`：
     窄屏（≤720px，与 CSS 同断点）用 `SLOT_CELL_COMPACT = 14`，桌面 22。
     尺寸由 JS 一路传到 CSS（inline 宽高 + `--rb-cell`），命中换算与视觉共用同一个 cell。
  3. CSS：`.rb-card` 改 `grid-template-columns: 1fr auto 1fr`；`.rb-card-body`（海报 + 片名 +
     标记 + 贴纸源）居中成「信息脊骨」；两侧 `.rb-zone` 在自己那一栏里 `justify-self: center`；
     窄屏 720px 断点收窄中间列并换小海报。
  4. 拖拽落点由 `data-rb-side` 告诉该编进哪一半；ghost 的歪斜角拼进 `transform` 而不是
     用 `rotate` 独立属性 —— **独立 `rotate` 会连 `transform` 的平移量一起旋转**，
     实测贴纸比指针偏出 59px（这就是用户报的「拖动时卡片不跟鼠标」）。
  5. 拖拽期间的目标高亮改为**直接改 DOM 属性**（`data-rb-hover`），不再每跨一张卡就 `setState`
     触发 296 张卡整体重渲染 —— 「不跟手」的另一半原因。

- **修订 3（2026-09-16，用户关于卡内空间的反馈）**：用户原话：

  > 「已经贴好一枚了 —— 点圆点取下就能换」这个太占空间了 请你取掉 增加可以贴的区域

  落地：
  1. **托盘里所有状态文案都删掉**（不只是那一句）：贴纸源在就说明能贴、没有源就是贴完了 ——
     靠形态表达，不靠解释。同时删掉冗余的「撤销标记」按钮（「看过 ✓」本身就是可点的开关）。
  2. 贴纸区放大：每侧 `4×4 → 6×6`，单侧 `122×122 → 166×166`，每侧 36 个位置、左右共 72。
     窄屏格子同步收到 `SLOT_CELL_COMPACT = 12`。
  3. 中间列收紧（海报 88→76、行距 5→4）：实测卡片高度 237 → **196**，两侧贴纸区反而更大。

- **修订 4（2026-09-16，用户给出「需求沟通模板（修正版）」）**：贴纸从「槽位吸附」整体换成
  **自由坐标画布**，布局也改成「左信息 + 右画布」。这是本需求改动面最大的一轮。
  1. **布局**：卡片 = 左侧信息列（158px，海报 + 片名 + 标记 + 红黑按钮）
     + 右侧贴纸画布（`minmax(0, 1fr)`，虚线框，标记后收实提亮）。
     贴纸不再可能压在片名或海报上。
  2. **数据模型**（按模板的 `{ id, type, posX, posY }`）：`posX/posY` 用 **0..1 相对坐标**
     （存像素会在换屏 / 换列数之后跑到画布外），落点钳在 `[0.08, 0.92]` 安全区。
  3. **姿态**：允许重叠、不做避让；倾斜角 **±15°**，由贴纸 `id` **推导**而不是存字段
     （存字段多一份可能与位置脱节的脏数据，推导则永远稳定）。
  4. **生成方式**：点红 / 黑按钮 → 在画布上**随机位置生成**一枚。
     ⚠ 用户模板只写了「点击生成」，但**拖拽保留**用于微调（前几轮明确要过；
     已贴贴纸可拖动改坐标、也能拖到另一张卡，**单击取下**）。
  5. **配额修正**：由「一部一枚」改为「**红黑各一枚**」—— 依据是模板里
     「每张电影卡片都可以同时被贴上红点和黑点」与「支持展示两种颜色的分布与累计数量」。
     这是对修订 1 的**又一次推翻**，若与原意不符请指出。
  6. **存储**：`biff.redblack.v2`（新结构）+ 一次性迁移 + 删 `biff.redblack.v1`
     （槽位 → 由 id 推导的坐标，`parseV1`）。`watched` 键不变。
  7. 单测重写为 34 例（坐标钳制 / 角度确定性 / 红黑闸门 / 跨卡拖动 / v1 迁移 / 旧键删除）。

- **修订 5（2026-09-16，用户第四条反馈）**：用户原话：

  > 标记看过只能选一个贴纸 而且贴纸拖到外面就需要取消 放到海报下方的贴纸的暂存区
  > 取消标记后 需要把当前这部电影自己贴的贴纸全部收回 并且暂存区贴纸总数清空
  > 通过红黑榜贴纸数量做一个评分吧

  落地：
  1. **改回「一部一枚」**（推翻修订 4 的「红黑各一枚」）：红 / 黑是同一个名额的两种取舍，
     贴上就没得再贴。`MAX_PER_COLOR` → `MAX_PER_FILM = 1`；`tallyOf` 的 `canRed/canBlack`
     合成 `canPlace`。
  2. **海报下方那两枚贴纸就是暂存区**：点一下 → 随机贴上；拖到画布 → 落在松手那一点。
  3. **拖出画布 = 取消这次放置**：已贴的贴纸拖到画布外就收回暂存区（`takeSticker`）。
     ⚠ 因此**移除了「单击取下」**（新口径里取消的方式是拖出去），避免误触。
     ⚠ ghost 也改成**移动超过阈值后才创建** —— 否则「点一下随机贴」每点都会闪一个浮标。
  4. **取消「看过」= 该片贴纸全部收回**：画布上的那枚与暂存区的选择一起清掉
     （不这么做会留下「没标记却贴着一张纸」的矛盾状态）。
  5. **红黑榜评分** `scoreOf()` = 红贴纸占比折算 0–10 分（一位小数），顶部 hero 区显示；
     一枚都没贴时为 `null`（显示「—」而非 0 分）。分母只算**已贴**的贴纸 ——
     标记了没贴的是「待表态」，不该拉低分数。
  6. 单测 36 例（新增评分三例；配额用例按「一部一枚」；v1 迁移断言同步）。

- **修订 6（2026-09-16，用户反馈「跳动很频繁」）**：用户原话：

  > 现在跳动很频繁 是因为贴贴纸/标记是否看过后马上刷新吗?

  归因：**不是「刷新」本身，而是排序依赖贴纸数量**。`sorted` 的依赖里带着 `board`，
  默认档又是「按总数降序」—— 贴一枚就让它从 0 变 1、立刻被排到榜首，
  整个两列网格跟着重排，看到的就是卡片跳位。

  落地：**顺序冻结**。
  1. `sorted` 的依赖改为 `[candidates, mode, sortTick]`，**故意不依赖 `board`**
     （带 eslint-disable 注释说明原因）；卡片里的数字 / 颜色仍然即时更新 ——
     那是内容，不影响排布。
  2. 新增「重新排序」按钮（`sortTick` 触发重排）；顺序被冻住后又贴了纸时按钮高亮成
     「有新贴纸 · 重新排序」。
  3. 实测：贴一枚后前 10 张卡的顺序完全不变；点「重新排序」后顺序按最新数量刷新。
