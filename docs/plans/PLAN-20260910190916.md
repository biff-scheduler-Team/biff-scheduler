## 1. 现状(代码事实)

```
<main class="… flex items-start gap-4">            ← PLAN-20260910184745 起
```

「选完场次想马上看到行程」这条需求从未被满足过。

## 2. 为什么搬进抽屉(收益 / 代价)

**收益**

1. **常驻可见**:抽屉 `sticky top-[64px]` + `max-h-[calc(100vh-80px)]` —— 行程从此永远在视口内。
2. **与网格并排**:抽屉 520px + 网格 872px(1440 视口),「左看行程、右点网格」正是「边选边看」最自然的形态。
3. **动线闭环**:`影片库(找片) → 我的选片(打标) → 我的行程(结果)` 是同一件事的三步;
   而「我的选片」与「我的行程」本来就是**同一份 `store.picks` 的两个视图**(按片 / 按场次)——
   分居两个屏幕才是不自然的(`types.ts::PickEntry` 注释即写明这一点)。
4. **净减法**:`#agenda-wrap` 整块从 `index.html` 删除,`#main-col` 只剩网格,页面高度 −400~900px。

**代价(评估后接受)**

- 抽屉**关着**时行程不可见。但此时用户正在网格里操作,而网格自身已给完整反馈:
  绿底=已选 / 红底=冲突 / 黄底=紧张,顶栏 `⚠ N` 冲突角标 sticky 常驻。
  「下一场几点在哪」是**执行期**信息,排片期不需要 —— 故**不额外加吸底摘要条**(见 §7 决策点 3)。

## 3. 设计决策

1. **抽屉三个 tab**:`影片库 | 我的选片 | 我的行程`。模块级 `pickerTab` 由 `"lib" | "pick"` 扩为
   `"lib" | "pick" | "agenda"`,跨开合保持。
2. **`#agenda-wrap` 删除**,`#main-col` 只剩 `#grid-wrap`;`#agenda` / `#agenda-summary` 两个 id
   **不再出现在 `index.html`**,改由注入的渲染函数产出。
3. **行程渲染职责仍留在 `main.ts`**(它持有 `conflicts` / `gvTalkOf` / `hourFilter` / `store.group`),
   通过**注入**交给抽屉:
   ```ts
   // library.ts
   let agendaRenderer: (() => HTMLElement) | null = null;
   export function setAgendaRenderer(fn: () => HTMLElement): void { agendaRenderer = fn; }
   // 行程 tab 的内容 = agendaRenderer?.() ?? 空态占位
   ```
   `main.ts::boot()` 里 `setAgendaRenderer(() => { …buildAgenda… })`。
   **理由**:反向依赖(让 `library.ts` 去读 `conflicts`)会把 main 的状态机复制一份,
   而 `library.ts` 现在只 import 了 `conflict` 的**类型**,没有运行时状态。
4. **`renderAll()` 不再无条件重建行程**:行程只在「抽屉打开 **且** 当前 tab = agenda」时渲染
   (`library.ts::render()` 已经只画当前 tab)。`renderBadge()`(顶栏角标)仍无条件跑。
5. **行程行瘦身到 520px**(必须,否则塞不下)——做法与 `PLAN-20260910184745` §8 的选片卡片**同构**:
   - 固定 grid → `flex flex-wrap` + 操作组 `ml-auto`(宽度够就单行,不够操作组折到第二行右对齐);
   - 档位三段 seg → `pick.ts::wishIcon`(★ 星标,文字走 tooltip,点击弹同一个菜单);
   - 章组走 `appendMetaRow(host, s, { uniform: true })`(统一灰描边,只有观影等级留强调色);
   - 操作图标化:GV `⏱25′` / `✓含映后` 两枚**保留**(两者正交,用户此前明确要求不可合并),但收窄内边距。
   - 目标态草图:
     ```
     ┌───────────────────────────────────────────────────────────┐
     │ 17:00–18:31 · 139min  [006] 片名  [GV][15][KE][P.43]       │ ← 信息行
     │ BCC C1 · ⚠ 与 042 重叠                                     │
     │ ↖ 距上一场 45min · 跨馆        [⏱25′][含映后][A][★][✕]      │ ← 操作行(右对齐)
     └───────────────────────────────────────────────────────────┘
     ```
   - **具体尺寸不在此拍死**:用无头测量(`scrollHeight` / `chipRows` / `sameLine`)收敛,与上一轮同法。
6. **摘要与质量分的去处**(`A 方案 12 场 · 2 处冲突 · 分 87`):放进**行程 tab 顶部**
   (它现在是抽屉里的一块,不再是 `#agenda-summary`)。同时把「本组已选 N 场」留在网格标题行
   (`#grid-count` 已有,不动)。
7. **`#conflict-badge` 点击行为改写**:原为滚到 `#agenda-wrap`(该元素已删)→
   改为 `openFilmPicker()` + 切到 `agenda` tab + 滚到**第一个冲突行**(带 `hl-row` 高亮)。
   需 `library.ts` 导出 `showAgendaTab(): void`。
8. **窄屏(≤1099px)**:`#main-col` 被隐藏,抽屉全宽 —— 行程 tab 反而拿到全宽,比 520px 更舒展。
   无需额外分支。

## 5. 边界与风险

- **`#agenda` 的 id 必须保留**(`renderAgenda` 里 `agenda.id = "agenda"`)—— `HOVER_SEL`
  (`#grid-scroll [data-code], #agenda [data-code]`)与「网格 ↔ 行程 双向 hover 联动」都靠它,
  搬进抽屉后选择器**仍然有效**,不要顺手改 id。
- **`renderAll()` 的时序**:`computeConflictsForCurrentGroup()` 必须先于抽屉渲染 —— 抽屉的
  `render()` 由 `store.subscribe` 触发,而 `renderAll` 也订阅同一个 store。需确认 `conflicts`
  在抽屉读到它时**已是本帧的新值**(两个订阅回调按注册顺序执行;`subscribe(renderAll)` 在
  `boot()` 里注册,`bindPickerState()` 在首次打开抽屉时注册 → renderAll 先跑,安全)。
  **实现时必须复核这一点**,必要时把 `conflicts` 的计算提到 `notify()` 之前。
- **抽屉高度**:行程 30+ 场 ≈1800px,抽屉 `max-h` ≈820px → tab 内容在 `panel` 内滚动(已有机制)。
- **空态**:A/B 方案都没选片时,行程 tab 要给与 `agenda.ts` 现有空态文案一致的提示
  (`当前「A 方案」还没有选片 …`),不要空白。
- **`#page-foot` 与页面高度**:删掉 `#agenda-wrap` 后页面变短,footer 紧跟网格 —— 视觉正常。
- **Tailwind v4 字面量**:本轮新增类(如 `basis-full` 若用到)必须字面量书写。
