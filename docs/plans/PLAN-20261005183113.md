# PLAN-20261005183113 — 触屏换贴纸皮肤：修好长按 + 给一条看得见的提示

## 目标

用户 2026-10-05 反馈：

> 「移动端怎么选贴纸 感觉交互有点奇怪」
> 「首先整个换贴纸样式的地方没有提示 而且手机端应该有单独的一套换肤的逻辑 我不想只靠猜」

即两件事：① 界面上**没有任何可见提示**告诉用户贴纸能换款；② 手机端本该有**独立于鼠标悬停**的那一套交互。

现状（读代码还原的机制）：桌面 = 指针悬停 160ms 自动弹环；键盘 = `Tab` 聚焦弹环；
触屏 = **长按 500ms** 弹环 —— 而这一条**实际上是坏的**，见下。

## 现状还原（三条都是代码事实，不是推测）

1. **长按被 1px 抖动作废**（`RedBlackPage.tsx` 的 `onPointerMove`）：
   它**无条件**把 `pressMoved` 置真并 `clearTimeout`，没有任何位移阈值 ——
   而同一个文件里拖拽那侧是有 `DRAG_SLOP_TOUCH = 10px` / `DRAG_SLOP_MOUSE = 8px` 的。
   触屏按住半秒几乎不可能完全不动，于是这个环在真机上大概率出不来。
2. **就算环出来了，松手就关**：贴纸的 `onPointerLeave` → `scheduleClose()`（260ms）。
   触屏没有 hover，「指针离开」在那里只等于**抬手** —— 长按开环后一松手，环 260ms 后就没了，
   用户根本来不及点节点。
3. **环在节点上按一下就可能被滚掉**：轮盘监听 `window` 的 `scroll`（capture）自动关闭，
   而 `.rb-wheel__node` **没有** `touch-action`；手指在节点上按下时页面跟着滚一点，环当场消失。

## 范围

**做：**

- **修长按阈值**：`onPointerMove` 改用与拖拽**同一套** slop（触屏 10 / 鼠标 8），
  只有真的越过阈值才算「用户想拖」。这是「开不出环」的根因。
- **触屏与鼠标分叉**（用户要的「单独一套」）：
  · 开环 —— 触屏仍走长按，但**按住时给进度反馈**（贴纸外圈 400ms 转一圈的进度环），
    松手 / 划动即消失。它同时解决「不知道能长按」与「不知道还要按多久」；
  · 关环 —— 触屏**不再**因「指针离开贴纸」而关（那只是抬手）；
    改为由「点环外任意处 / 滚动页面 / 点选定款」关掉；
  · 节点补 `touch-action: none`，防止在节点上按下时页面滚动把环带走。
- **加可见提示**：页面级一行小字，**只在 `(hover: none)` 显示**：
  「长按自己贴的贴纸 → 换一款皮肤」。桌面端 DOM 里在但 `display: none`。
- 回归测试：新增一条 E2E —— 触屏长按期间带 ≤10px 抖动仍能弹出轮盘（先红后绿）。

**不做：**

- **不动**「双击收回」「单击什么都不做」这两条既有契约（2026-09-30 用户定过，E2E 守着）。
  尤其是**不**把触屏换成「单击开环」—— 那一版 260ms 延迟开环的方案用户已经明确否过。
- **不动**环的几何 / 视觉（半径、节点尺寸、白底盘、名称胶囊）。
- **不动**桌面端的悬停与键盘两条路径（用 `pointerType` 分叉，鼠标分支一行不改）。
- 不新增 localStorage 键（不做「一次性引导」，常驻一行小字成本更低且不会被忘记）。

## 方案取舍

| 备选 | 结论 | 理由 |
|---|---|---|
| 触屏改「轻点 = 开环」 | 否决 | 用户 2026-09-30 明确否过（「单击就该是按住/拖的起手」）；且与双击收回抢同一串手势 |
| 触屏改「双击开环、长按收回」 | 否决 | 翻转既有「双击收回」契约，代价大于收益 |
| 卡片画布角落常驻一枚「换款」按钮 | 否决（本轮） | 可发现性最好，但要与 `.rb-talk` 等角落入口争位置，且贴纸是随机落点、按钮不能跟着它；先看「进度环 + 一行提示」够不够 |
| 一次性弹窗引导 | 否决 | 要多一个 `biff.*` 键 + 一套「已读」逻辑；常驻小字更省也更不会被忘 |
| 修阈值 + 进度环 + 触屏专属关环 + 一行提示 | **采纳** | 手势模型不变（单击 / 双击契约原样），把「开不出来」与「看不见」两个真问题一起解决 |

## 验收标准

1. 触屏模拟下：`pointerdown` 后 200ms 时挪 5px，再等到 400ms —— 轮盘**弹出来**（改前会被作废）。
2. 触屏模拟下：`pointerdown` 后挪 40px —— 轮盘**不弹**（走拖拽，`movedRef` 接管）。
3. 触屏模拟下：环开着时**抬手**不会关环（`pointerup` / `pointerleave` 之后环仍在）；
   点环外任意处、或滚动页面才关。
4. 桌面端：`e2e/react/redblack.spec.ts` 既有断言全绿（悬停开环 / 键盘开环 / 双击收回 /
   单击什么都不做 / 环里点数）。
5. 触屏提示只在 `(hover: none)` 可见；桌面端量 `display` 为 `none`。

## 修订 1（2026-10-05，用户第二次反馈）

> 「当时想拖动贴纸 就马上会触发换肤 这个逻辑感觉有点不对」

**问题**：触屏上「拖动」与「长按换款」共用同一个 `pointerdown` 起点，而真人拖动的起手常常是
「先按住停一下、再移」—— 那一停就超过 `PRESS_MS`（500ms），环先弹了出来；而环弹出之后
**没有任何东西取消它**，用户继续拖，环还挂在半天前量好的那个锚点上。

**这是本 PLAN 第一版的直接副作用**：为了让长按真的能触发，把容差从「1px 就作废」放宽到
`DRAG_SLOP_TOUCH`（10px），代价就是更容易把「按住犹豫」误判成换肤意图。

**修订（原则：用户动起来了，就不该再是换肤）**：

1. `onPointerMove` 补一条 **★ 拖动优先**：环已经开着、而位移又越过 `slop` → 立刻 `closeWheel()`，
   拖动照常由 `beginDrag` 接管。
   新增 `pressDown` ref，保证只有「指针真的按着」的手势才算位移（鼠标只是划过贴纸也会送
   `pointermove`，而 `pressStart` 是上一次按下的坐标，拿它算会得出毫无意义的「移动了」）。
2. 进度环**延迟 120ms 才显形**：按下去第一瞬间就闪出那一圈，会让「其实是想拖」的人
   以为自己误触了换肤；而真想长按的人本来就要按满 500ms，晚 120ms 几乎无感。

**修订后的验收标准（追加）**：

6. 触屏长按**已开出环之后**继续移动 30px → 环**立刻关掉**；
   且这一拖**真的生效**（贴纸落到松手那一点，拖动没被吃掉）。
7. 触屏「按下就立刻移动」→ 环自始至终不出现（第 2 条已有的判据不变）。
