# PLAN-20260910125633 · GV 映后谈时长改为可配置(全局默认 + 单场覆写)

## 1. 需求

「映后时长做成可配置的」—— 现状映后谈时长是**从数据推导**的死值:用户既看不到它、也改不了它。

## 2. 现状与数据口径

`src/gv.ts::gvTalkMin(s)` = `hmsToMin(end_time) − hmsToMin(start_time) − duration_min`(仅 `is_gv`)。

实测 `public/schedule.json`(2025 真实排期,699 场 / 347 场 GV):

| 推导值 | 场次数 | 说明 |
|---|---|---|
| **25 min** | **341** | 官方统一口径 |
| 25 min(跨天折回) | 4 | `end_time` 折回 24h 内,`loadCatalog()` 补 24h 后 = 25 |
| 0 | 1 | 官方未给谈后时间 |
| 120 | 1 | 槽位远大于片长(数据异常) |

→ 实质上 345/347 场 = 25min,但**这个 25 是数据里隐含的,不是配置**。三个后果:
① 换年份 / 换数据源(2026 若未把谈后算进 `end_time`)→ 映后谈**静默消失**;
② 用户想按「谈后 40 分钟」试算转场 / 冲突 → 无从下手;
③ 异常值(120 / 0)无法人工纠正。

## 3. 设计决策

| 项 | 决策 | 理由 |
|---|---|---|
| 配置粒度 | `Settings.gvTalkMin`(全局默认,**默认 25**)+ `store.gvTalkMinOv: Map<code, number>`(单场覆写) | 与既有 `gvTalkOn` + `store.gvTalk`(参加/放弃的单场覆写)同构,心智一致 |
| 优先级 | **单场覆写 ?? 全局默认**;数据推导不再参与时长 | 用户定案:「没单独配置就走配置的全局默认值」 |
| 生效范围 | **仅 `is_gv` 场次**(非 GV 恒 0,不给入口) | 谈段是 GV 的语义;`talk`/`commentary` 等 tag 场次不在本次范围 |
| 「有谈段」判定 | `is_gv && 生效时长 > 0`(旧:推导值 > 0) | 时长归零 = 该场不拆,与旧口径同义 |
| **有效结束重定义** | 含映后 = `filmEndMin(s) + talk`(**不再取官方 `end_time`**);弃映后 = `filmEndMin(s)` | 配置改了必须让谈段长度真的变 —— 否则改 40min 而结束时间仍卡在官方 12:05,配置就是假的 |
| 非 GV / talk=0 场次 | `effEndMin` **仍返回官方 `end_time`** | 保护性分支:2025 有 6 场非 GV 片长 ≠ 槽位(−2/ +1 / +15 / +90),若一律改走 `start+duration` 会静默改变这 6 场的冲突判定 |
| 轴界 | `axisRangeFor` 取 `max(end_time, filmEndMin + talk)` | 配置调大后谈块会画到官方槽位之外,轴末不跟着外扩就会被裁 |
| 全局默认值入口 | 设置弹层「GV 映后谈默认时长(分钟)」数字框(0–120) | 与既有 `alarmMin` / `transitMin` 同款 |
| 单场覆写入口 | **行程行** GV 场次加一枚 `⏱ N′` 胶囊 → 点开小弹层改本场分钟数 | 行程行是「我自己的场次」,场次级参数改这里最自然;网格谈块太窄(talk×pxPerMin ≈ 75px)放不下第二个热区 |
| 单场覆写入口的可见性 | **`is_gv` 恒显示**(即使当前时长 0) | 否则全局默认设成 0 时,该场永远回不到「有谈段」—— 入口必须与「当前值」解耦 |
| 数据推导代码 | `gvTalkMin` 保留函数名与签名(改读配置),**不再保留**推导实现 | 5 个模块(grid / agenda / ics / main)共 12 处调用点**零改动**,这是本次能压到最小改动面的关键 |
| 配置读取方式 | `gv.ts` 直接 `import { store, gvTalkMinOv } from "./state"` | `state.ts` 不依赖 `gv.ts`(它只 import `types` + `api`)→ 无循环。改用 ctx 注入要动 4 个 ctx 定义 + 12 处调用,收益为零 |

## 4. 改动清单

### `src/types.ts`
- `Settings` 加 `gvTalkMin: number`(GV 映后谈默认时长,分钟,默认 25)。
- `gvTalkOn` 注释补一句「时长另见 `gvTalkMin` / `store.gvTalkMinOv`」。

### `src/state.ts`
- `LS_GV_TALK_MIN = "biff.gvtalkmin.v1"`;`export const gvTalkMinOv = new Map<string, number>()`。
- `loadGvTalkMin()` / `saveGvTalkMin()` / `setGvTalkMin(code, min | null)`(null = 清除覆写回跟随全局;沿用 `setGvTalk` 的 notify 模式)。
- `store.settings` 初值加 `gvTalkMin: 25`(老 localStorage 无该字段 → `loadSettings` 合并后仍是 25)。

### `src/gv.ts`(核心)
- `gvTalkMin(s)`:非 GV → 0;否则 `gvTalkMinOv.get(s.code) ?? store.settings.gvTalkMin`,钳到 `[0, 24h]`。
- `effEndMin(s, talkOn)`:`talk <= 0` → `hmsToMin(s.end_time)`(原语义);否则 `filmEndMin(s) + (talkOn ? talk : 0)`。
- `effEndHms` 不变(内部走 `effEndMin`)。
- 头注释重写:口径从「数据推导」改为「配置驱动」,写明优先级与保护性分支。

### `src/grid.ts`
- `axisRangeFor`:轴末 `max(hmsToMin(s.end_time), filmEndMin(s) + gvTalkMin(s))`。
- `talkTimeRange(s)`:谈段区间右端 `hmsToMin(s.end_time)` → `filmEndMin(s) + gvTalkMin(s)`。
- `talkTip(s, ...)`:标题行区间同上;补一句「本场时长可在行程行 ⏱ 单独设置」。
- `appendCard` 内 `talk` 已由 `gvTalkMin(s)` 取得,谈块宽度/位置自动跟随配置,无需改。

### `src/agenda.ts`
- `talkBtn` 文案去掉时长数字(时长归 `⏱` 按钮);`title` 里 `hmsToMin(s.end_time)` → `filmEndMin(s) + talk`。
- 新增 `talkMinBtn`(`⏱ N′`,仅 `s.is_gv` 渲染):`dataset.act = "gv-talk-min"`。
- `AgendaCtx` 加 `talkMinOf: (code: string) => number`(或直接 import `gvTalkMin`)。

### `src/ics.ts`
- 无签名改动(`effEndHms` 自动生效);`timeNote` 文案已是 `含映后 ${talk}min`,自动跟随。

### `src/main.ts`
- `openSettings()`:加 f4「GV 映后谈默认时长(分钟)」数字框;`apply` 时并入 `setSettings`。
- 新增 `openTalkMinModal(code)`:小弹层(数字框 + 「跟随默认(N′)” + 保存),就地重绘行程行。
- 事件委托:`act.dataset.act === "gv-talk-min"` 分支。
- 复制抢票清单 / 详情:已走 `gvTalkMin(s)`,自动跟随。

### `src/legend.ts`
- 说明弹层里「GV 映后场的结束时间含映后谈(正片 + 映后 N′)」等 4 处文案:补「时长可配置(设置里给全局默认,行程行 ⏱ 逐场覆写)」。

### `docs/CONVENTIONS.md`
- §三 加一条 **GV 映后谈时长契约**(优先级 / 生效范围 / 有效结束口径 / 非 GV 保护分支 / 入口)。

## 5. 不在本次范围

- 非 GV 场次(tags 含 `talk` / `commentary` 的 9 场)设时长。
- 把「数据推导值」作为参考值展示(如 tooltip 里显示「官方 25′」)。
- 按影院 / 按影片批量设时长。

1. `npm run typecheck` 通过。
2. 设置里默认时长 25 → 全站表现与改动前**逐字节一致**(345 场推导 = 25 的场次:谈块宽度 / 结束时间 / 冲突判定 / ICS `DTEND` 均不变)。

7. 非 GV 场次:设置改 0 / 40 均不影响其结束时间与冲突判定(6 场片长 ≠ 槽位的场次行为不漂移)。

### 8.2 对 PLAN 的偏差(实现中发现,已一并处理)

1. **新增 `gv.ts::talkOnOf`**:`engine.ts::blocks` 也要按有效结束判互斥,而它拿不到 main.ts 私有的 `gvTalkOf`。
