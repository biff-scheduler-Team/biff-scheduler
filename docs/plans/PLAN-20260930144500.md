# PLAN-20260930144500 — 讨论区评语写不进去（上报载荷 422）

## 目标
> 用户原话：「评论区评论后一直没有出现在评论区 显示『评语已保存，正在同步到讨论区 —— 稍等一会儿就能看到。』」

## 症状与定位（线上实测）
1. `GET https://biff.lcandy.co/api/stats/film-comments` → **`items: []`**，且 `cache-control: no-store`（**不是**缓存问题）。
2. `GET …/api/stats/film-votes` → **11 部片有红黑票数、`skins` 为空** —— 那些票是**皮肤 / 评语功能上线之前**投的。
3. 根因：**前后端契约错配**。
   - 前端 `redblack.ts::votesOf()` 刻意**每条都带** `comment` / `skin`，没写评语时送 **`null`**
     （服务端靠「字段在不在」分辨新旧前端，所以字段不能省）。
   - 服务端 `index.ts` 的 `filmVotePingSchema` 里写的是 `z.string().max(…).optional()` 且条目对象是 `.strict()`——
     **`z.string()` 不收 `null`** ⇒ **每一次上报都 422** ⇒ 票 / 评语 / 款一个字都写不进去。
   - 两边**各自都是绿的**：api 单测测的是模块函数（`replaceContributorVotes`），E2E 把这条路由整个 stub 掉
     （只断言「载荷里有 comment」）。**这条端点此前一个测试都没有。**

## 改法
- `apps/api/src/index.ts`：`comment` / `skin` 两个字段加 `.nullable()`。
- 新增 `apps/api/tests/film-vote-ping-contract.test.ts`：拿**前端真正会发的形状**打真接口
  （真 drizzle + `d1-shim` 内存库），并从公开读接口把评语读回来。

## 范围
**做：** 服务端 schema 收 `null`；补端点级契约测试（4 条）。
**不做：** 不改前端（它的形状是对的）；不回填线上旧票（它们本就没评语 / 没款）；不动其它 ping 的 schema ——
已核查：只有这一处有「送 null / 只收 string」的错配。

## 验收标准
1. 新测试**先红后绿**：修复前 `expected 422 to be 200`（2 failed / 4），修复后 4/4 全绿。
2. `npm run verify:quick` 全绿。
3. 部署后线上能读到新写的评语（用户需**重新保存一次**——之前那次没有落库，已丢）。
