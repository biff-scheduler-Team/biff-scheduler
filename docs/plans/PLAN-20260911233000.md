## 2. 证据(三条,互相独立)

1. **GitHub 侧**:`gh api repos/.../commits/<sha>/check-runs` →
   `{ name: "Workers Builds: biff-scheduler", conclusion: "success", details_url: dash.cloudflare.com/62cbe67b…/workers/services/view/biff-scheduler/… }`;
   `2e1007d / 81d5f12 / 71f0394` 三个 commit 都有这条检查且全 success,更早的 `e1851b9 / 35a46b4` **没有**
   ⇒ 集成是今晚(≈`71f0394`「修 Git 构建 Missing entry-point」)才接上的。
2. **HTTP 响应头判别**(决定性):同一条 `curl -sI` 对比 ——
   * `biff-scheduler.pages.dev`(Pages):`content-type: text/html; charset=utf-8` + `access-control-allow-origin: *`
     + `referrer-policy: strict-origin-when-cross-origin` + `x-content-type-options: nosniff`,**没有** `cf-cache-status`;
   * `biff.lcandy.co`:`content-type: text/html` + `cf-cache-status: HIT`,上面三个 Pages 默认头**一个都没有** ⇒ **Workers 静态资源**。
3. **Cloudflare 侧**:`wrangler pages project list` 里 `biff-scheduler` 的 `Project Domains` **只有** `biff-scheduler.pages.dev`
   (没有 `biff.lcandy.co`),`Git Provider = No`;`wrangler deployments list` 在本机账号下报
   `This Worker does not exist on your account` ⇒ 自定义域与 Worker 都在**另一个账号**里。
4. **产物一致性**:`https://biff.lcandy.co/assets/index-hEXNcZ39.js` 的 `sha256` == 本地 `dist/` 同名产物
   (即 HEAD 构建结果),且含本轮新文案「同一部片」×3 ⇒ 线上跑的正是当前 HEAD。
