# PLAN-20260910145749 — AI 排片:修「21 号 17:00 开始看却只排 1 场」的 prompt 误读

## 1. 用户诉求(来自当前对话截图)

> 「现在排片 需要把没有加入片单的也排一下 21 号下午五点开始看 看到最后一场
>明明有很多场别的 你看我他只选了一场随缘」

**操作**:在「智能排片」面板里,**没给任何影片打「必看/备选/随缘」**(≡「无片单模式」,见
PLAN-20260910143929 §9),只填了一段偏好文字:

```
21 号下午五点开始看 看到最后一场
```

**期望**:21 号 17:00(含)之后的场次,按时间顺序尽可能多排,排到当日最晚(含跨午夜)。
**实际**:模型只挑了 **1 场** — KOKUHO(16:00–19:20,含 GV),并自述:

> 「仅此一场,含映后谈,16:00 开始符合下午五点前到场,选它。」

## 2. 根因(读代码 + 跑数据)

### 2.1 模型把「下午五点开始看」读反了

`SYSTEM_PROMPT` 的 C6(C6 = 用户偏好里的「排除 / 时间限定」类硬约束)虽然在 ai.ts:43–47 写了:

> "「17:00 才开始看」「X 点前结束」「上午不看片」「不接受午夜场」「只看某几家影院」「只看某几天」。
> 凡落在排除范围内的场次一律不得选入 picks..."

但这段措辞**默认用户会用阿拉伯数字写**(「17:00」「X 点」)。遇到用户用**中文数字+口语**
写「下午五点开始看」时,deepseek-chat 的解读就飘了:

- 字面:「下午 5 点开始看」= 「5 点才**开始**看」→ 5 点之前不允许开始
- 模型误读:「下午 5 点开始看」= 「5 点**前**到场 OK,5 点**之后**才正式开始」→ 16:00 仍合规

**校验证据**:9/21 共有 103 场,其中 17:00(含)之后开始的场次 = **35 场**,模型应当从这 35 场里挑,
但选了 16:00 开始的 KOKUHO → 直接撞 C6(本地没复检 C6,见 §2.3)。

### 2.2 无片单模式过度保守

无片单模式 prompt(ai.ts:322–331)写:

```
· 偏好给了时间范围(如「17:00 开始、23:00 结束」)→ 这是硬边界:范围外的场次一律不选;
  范围够宽时尽量排满,相邻场次之间按 C2 判定,允许留空档;
· 偏好没给时间范围 → 挑评分更高、含 GV(映后谈)更多的场次,组成紧凑行程;
· 不要为了凑数选明知看不完的组合。
```

「不要为了凑数选明知看不完的组合」一句**反向鼓励保守**:用户明确说「看到最后一场」,模型却
把"看完当日"等同于"挑 1 场最稳的"。「看到最后一场」的真实语义 = 排到当日最晚(含跨午夜),
**不是**「保守地只挑 1 场」。

### 2.3 本地复检缺位

`parseAiResult`(ai.ts:572–656)对 picks 的本地校验**只覆盖 C1–C3**(无效 code / 同片重复 /
时段冲突);**没有 C6 校验**。所以即便模型违反「17:00 后才能开始」,本地也不会剔除。
这是「写了 17:00 开始看却被排 16:00」漏网的原因。

### 2.4 占位符推荐写法与用户实际写法不一致

UI 占位符(library.ts:833):

```
例:21 号 17:00 才开始看、看到最后一场;上午不看片;...
```

推荐的是结构化写法,但用户实际填的是「21 号下午五点开始看」——**对人类更自然、对模型更危险**。
应该补一个「中文偏好写法」示例,引导用户写得更结构化(同时模型也应当能兼容口语化写法)。

## 3. 设计

**改 prompt + 改占位符**。**不改 UI、不做自然语言解析**(避免过度设计 ——
解析用户偏好文本是 NLU 问题,正则+NLP 写出来既不稳又容易引入新 bug;让 prompt 自己解释
「下午五点 = 17:00」语义是最稳的路径,模型做语义归一本来就比正则强)。

### 3.1 `SYSTEM_PROMPT` 强化

- **C6** 部分补一条「中文时间表达归一」:把口语化时间(「下午五点」「早上十点」「晚上七点」)
  归一到 24h 数字后再判窗口,凡未达到窗口起点分钟的场次一律排除。
- **C6** 措辞强调:**「X 点开始看」= X 点(含)之后**才允许开始;X 点前开始的场次**严格排除**,
  不得借 C5 的「优先选更早场次」绕过 C6。
- 新增「中文偏好写法对照」短段,放在 C6 之后,列举用户最常写的口语化短语及其正确语义
  (「上午不看」「下午三点开始」「看到最后」「不要午夜场」「只看 BCC」)。
  让模型**先归一**到 C1–C6 的硬约束语言,再开始求解。

### 3.2 无片单模式 prompt 强化

- 「范围够宽时排满」一句补强:**「范围够宽时应当排满 —— 不要只挑 1 场就停,除非该日确实
  只能排下 1 场(例如 17:00 开始后只到 19:00 就结束)」**。
- 「看到最后一场」明确 = **排到当日最晚(含跨午夜场)**;不要因为「看完太晚」就保守缩范围。
- 「不要为了凑数选明知看不完的组合」**保留**(有用户场景需要这条兜底),但补一句:
  「『明知看不完』= 看完该场需要撑到次日 06:00 之后且中间无 30 分钟以上的休息窗口,
  不要把『看得很晚』等同于『看不完』」。

### 3.3 占位符 + 偏好提示

- 占位符示例改为:**「21 号 17:00 开始看、看到最晚那场(含跨午夜);上午不看;只看 BCC;优先 GV」**
  —— 保留结构化,补一条「含跨午夜」明示。
- 偏好文字下方加一行小提示(11.5px 灰色):
  **「口语化时间(如「下午五点」)会被归一到 24h 数字;为避免误读,推荐写「17:00 开始看」。」**
  —— 不替换原提示(「不重叠 / 跨馆转场 / 每片一场 / 你写明的时间限定 均不可违背」),
  只在 textarea 下沿加一行,11.5px 灰色,与 ② 的日期范围提示同款视觉重量。

## 5. 边界与风险

- **不动本地复检 C6**:解析自然语言偏好的 NLU 复杂度远超本次需求边界;让模型在 prompt 层
  做语义归一(本来就是它的强项)是 ROI 最高的做法。若未来用户大量反馈模型仍误读,再单独
  开 PLAN 做「偏好结构化字段 + 本地复检」。
- **不改「并入」/「日期 chips」/「无片单模式」/「追加合并」**:本次只动 prompt 文本 +
  占位符 + 一行提示,**不引入任何新概念**。改完线上应当**逐字节**保留原有行为,只改变
  模型对偏好的解读。
- **token 成本**:`SYSTEM_PROMPT` 加约 200 字(中文,UTF-8 字节 ≈ 600),无片单模式 prompt
  加约 80 字;与 `PAYLOAD_LIMIT = 120_000` 余量比可忽略(`buildPayload` 已测全选 10 天
  约 114k,余量 ≈ 6k,payload 是用户数据部分,prompt 是请求结构,两者独立计数)。

## 8. 第二轮修复:tagged 非空 → 「无片单模式」被吞掉(同日)

### 8.1 用户反馈(本对话第二轮截图)

> 「为什么还是这样排?」

UI 显示「本次送 1 部 / 1 场(仅所选 1 天)」+ AI 仍只返回 1 场 KOKUHO,模型自述
「仅一场 GV,17:00 后开始,符合下午五点起看;排到当日最后一场」(KOKUHO 实际 16:00 开始,
模型在撒谎)。

### 8.2 根因(读代码 + 跑数据验证)

**不是 prompt 问题** —— UI 信息行显示「本次送 **1 部 / 1 场**」,根本不是 prompt 改不改能解决的:
`buildPayload` 真的只送了 1 部影片 1 场。

追溯调用链:

1. 用户**之前**给 KOKUHO 打过"备选"(影片库三选 / 甘特图点击 / AI 采纳都会落档)
2. → `ctx.picks` 里有 `{ key: 'cat:f019', priority: 'maybe', ... }`
3. → `openEngineDialog` 的 `tagged = [KOKUHO]`,**非空**
4. → `noFilmList = tagged.length === 0 = false`
5. → `wanted = tagged = [KOKUHO]`(只 1 部)
6. → `buildPayload([KOKUHO], ..., ['2025-09-21'])` 只过滤出 1 部 1 场
7. → 模型看到只有 KOKUHO 可选 → 选它

**这是「无片单模式」判定的根本缺陷**:判定只看 `tagged.length`,但用户给 KOKUHO 打
「备选」(maybe)不应**剥夺**用户用「无片单模式」的自由 —— `maybe` 本身就不强制,
意图是「你可以帮我多看看」。

校验(本机 esbuild 跑真实 bundle):
```
=== 现状:forceNoFilmList=false,picks 有 KOKUHO maybe ===
buildPayload -> films: 1, shows: 1            ← 用户实际看到的
=== 修复后:forceNoFilmList=true ===
buildPayload -> films: 99, shows: 103         ← 修复后送 99 部 / 103 场
```

### 8.3 修复

**判定逻辑**:不修改 —— 用户打了「必看/备选/随缘」就应该进入「有片单模式」(尊重打标)。
**改 UI**:加显式「强制无片单模式」开关 —— 默认 off,on 时忽略所有打标,候选池 = 全部有排期影片。

### 8.4 设计取舍

- **不写全局 `store.aiForceNoFilmList`** —— 开关只在「智能排片弹层」内有意义,关弹层不持久化;
  在 `aiPanel` 闭包内 `let forceNoFilmList = false` 就够。
- **开关位置**:放在 `modeBar` 后(默认已有 modeBar 时)、配置表单与日期 chips 之间;
  只有 `tagged.length > 0` 时才渲染(已是「真·无片单」时无意义)。
- **切开关 = 作废现有结果**:候选池变了,旧 picks/drops/rejected 都失去上下文;`plan = null`
  + 清 errText / adoptedG / adoptNote,paint 重绘。
- **采纳时仍按当前 noFilmList 判定档位**:`forceNoFilmList = true` 时采纳记 `null = 未设`,
  与原口径一致。
- **不在 runBar 信息里强行提示用户去勾开关** —— 用户可能根本不想用强制无片单,
  只是在调试为什么排不出多场。开关在面板里安静显示,需要的人会看到。

### 8.5 改动清单

| 文件 | 改动 |
|---|---|
| `src/library.ts` | ① `openEngineDialog` 去掉 `tagged` / `noFilmList` / `wanted` 计算(搬到 aiPanel 内);② `aiPanel` 签名改 `(filmList, ctx, transitMin)`,闭包内 `taggedNow()` + `wantedNow()` 重算;③ 加 `forceNoFilmList` 局部 state;④ 新增 `forceToggleRow()`(checkbox,仅 tagged 非空时显示);⑤ `modeBar` 文案按 forceNoFilmList 切换("强制无片单模式:忽略已打标的影片");⑥ `paint()` 在 cfgForm 后插 `forceToggleRow()`(tagged 非空时);⑦ `run()` / `sentFilmsOf` / 采纳 button / `runBar` 都改成按 `wantedNow()` 取实时值 |
