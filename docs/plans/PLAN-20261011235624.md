# PLAN-20261011235624 — 红黑榜按「评分」排名，撤掉总数榜

## 目标

> 红黑榜的分享榜单 或者说排行的时候 黑榜以及红榜 要按评分来算 而不是单纯按数量来算

现状（2026-10-12 核实）：榜单（页面分段控件 + 分享图）**按票数**排 ——
`redblack.ts::sortMetric` 取 `counts.red` / `counts.black` / `counts.total` 降序。
评分 `scoreOf`（红占比 ×10，0–10）**已存在**但只印在卡片右上角，不参与排序 ——
于是「1 红 0 黑 = 10.0 分」会压过「47 红 3 黑 = 9.4 分」的口碑片。

## 范围

**做：**

- 红榜 / 黑榜改为按**评分**排序：红榜降序、黑榜升序。
- 撤掉「总数榜」：页面分段控件三档 → 两档；分享图三节 → 两节。
- 评分口径由「红占比」改为**贝叶斯加权分**，页面卡片角标 / 分享图行 / 排序键**同一处实现**。
- 分享图每行印出评分。
- 单测 + E2E 同步（先红后绿）。

**不做：**

- 不改投票形态（仍是红 / 黑二选一），不改 D1 表结构与 API
  （`film_vote_stat` 已有 `red_count` / `black_count`，够算加权分）。
- 不动后端 `voteScore`（占比分，当前无调用点；只更正注释里那条「与前端同口径」的过时声明）。
- 不改「我贴过的」那一节的内容（仍按全站总数降序 —— 它是清单，不是榜）。
- 不改「顺序冻结 / 重新排序」机制，不新增排序档位到 URL。

## 方案取舍

| 备选 | 结论 | 理由 |
|---|---|---|
| 纯占比分当排序键 | 否决 | 小样本封顶：1 红 0 黑 = 10.0，会压过几百票的口碑片 |
| 占比 + 最低票门槛 | 否决 | 硬切断：N 票的第 1 名与 N−1 票完全没份，且 N 取值无依据 |
| **贝叶斯加权分** | **采纳** | `WR = (red + m·C) / (total + m)`，票少自动向全站平均收缩；连续、无硬门槛；IMDB Top 250 口径；纯函数好单测 |
| Wilson 置信下界 | 否决 | 公式可读性差，本场景有先验已足够 |
| 总数榜改名「热度榜」保留三档 | 否决（用户拍板「只留两榜」） | 评分口径下 `red/total` 与 `black/total` 互为倒数，三档只有「正着看 / 倒着看」两种，总数榜会与红榜逐字重复 |
| 行内显示占比分 | 否决（用户选加权分） | 名次与分数会不单调（第 1 名 9.3、第 5 名 10.0），看起来像 bug |
| 分享图另写一套排序 | 否决 | 分享图顺序必须与页面点了同档时看到的逐字一致（口径单一来源） |

**参数**：`PRIOR_VOTES = 5`（全站票数 ≥ 10 时先验权重 ≤ 1/3，温和）；
`C` = 全站红占比 `Σred / Σtotal`，全站一票没有时取中性 `0.5`。

## 验收标准

1. `apps/web/tests/redblack.test.ts`：加权分公式（1 红 0 黑不霸榜、票多的口碑片胜出）、红降黑升、
   同分按票数降序、并列回落目录序、无票 `null`。
2. `apps/web/tests/redblack-poster.test.ts`：两榜、各 TOP_N、hint 文案、行内带评分。
3. `e2e/react/redblack.spec.ts`：默认档 = 红榜、分段控件两档、分享图勾选组两项、行内印评分。
4. `npm run verify:quick` 绿。

## 修订

### 修订 1（2026-10-12，用户拍板）

- 算法：**C（贝叶斯加权分）**。
- 总数榜：**撤掉**，只留红榜（评分最高）/ 黑榜（评分最低）。
- 榜单行显示：**加权分**（与名次严格单调）。
