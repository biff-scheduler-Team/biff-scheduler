# PLAN 2026-09-10 18:47:45 — 「影片库 · 我的选片」由独立页面改为左侧挤压抽屉

> 需求(用户原话):「但是我总觉得有个新页面 很奇怪 有什么好的办法把交互重构下吗」→ 选定方案甲(左侧可召唤抽屉)。
> 本文件 = 本需求唯一规划文档。前置:`PLAN-20260910182939`(弹窗 → 独立页面)。

## 1. 现状(代码事实)

`library.ts::openFilmPicker(ctx)` 把左右双栏 body 挂进 `index.html` 的 `#picker-body`,并:

- `showPickerPage()` 给 `#grid-wrap` / `#agenda-wrap` / `#page-foot` 加 `is-hidden`,选片面板**独占** `main`;
- `main.is-picker-open` 放宽容器上限 1280 → 1680;
- `main.ts::renderAll()` 在 `isPickerPageOpen()` 时**早退**(被隐藏的网格 `clientWidth=0`,
  `renderGrid()` 每次 `replaceWith` 新滚动容器会把 `scrollLeft` 静默重置);
- 关页由 `setPickerOnClose(renderAll)` 回调补一次完整重绘;
- `jumpToScreening` 必须先 `closeAllModals()` + `closePickerPage()`(隐藏元素 rect 全 0)。

## 2. 问题(为什么「新页面」别扭)

1. **模态**:整页替换,打标时看不见网格与行程 —— 而打标与选场次本是同一件事的两步;
2. **不是路由**:URL 不变、浏览器后退失效,占着页面的地方却给不了页面的能力;
3. **有去无回**:打标时想「这部片在时间轴上长什么样」要关页 → 找片 → 重新打开;
4. **单向**:`影片库 → 定位 ▸ → 网格` 有,`网格 → 选片` 没有。

## 3. 设计决策

1. **挤压式左侧抽屉**(不是覆盖、不是弹层):`<main>` 由 `grid` 改 `flex`,`#picker-drawer` 是其第一个
   子项(`w-[520px] shrink-0 sticky top-[64px] max-h-[calc(100vh-80px)]`),原有三块 section 收进
   `#main-col`(`flex-1 min-w-0 grid gap-4`)。抽屉打开 → 主列变窄 → **网格仍完全可见可点**。
   (初版 400px;§8 的卡片重构要求场次行排成单行阅读流,400px 排不下,故加宽到 520。)
2. **保留 `main.is-picker-open` 放宽上限**:1280 → 1680。宽屏下抽屉尽量少抢网格宽度
   (1680 − 32 − 520 − 16 = 1112px;1440 视口下 ≈872px)。
3. **抽屉内两个 tab**(`影片库` / `我的选片`):520px 放不下并排双栏,但两个 tab 复用**同一套**
   `filmRow` / `showRow`,信息密度与原来双栏一致;tab 选择跨开合保持(模块级 `pickerTab`)。
4. **只画当前 tab**:`render()` 只重绘激活 tab。抽屉会在用户点选网格时持续存活,
   而 `store` 每次变更都广播 —— 若照旧两栏都重建,一次网格点选就要重建 250 行影片库。
5. **列表不再自带宽高**:两栏列表去掉 `max-h-[min(70vh,860px)] overflow-y-auto`,
   改为抽屉内的 `panel`(`min-h-0 flex-1 overflow-y-auto`)统一滚动,避免双滚动条。
6. **删除页面生命周期那一整套**:`showPickerPage` / `closePickerPage` / `setPickerOnClose` /
   `pickerScrollY` / `renderAll` 的 `isPickerPageOpen()` 早退,全部作废 —— 净减法。
7. **网格宽度变化的补偿**:抽屉开合后必须重绘网格(可用宽度变了)。由 `library.ts` 在
   `showPickerDrawer()` / `closePickerDrawer()` 内回调 `main.ts` 注入的 `setPickerToggleHandler(fn)`,
   调用方不必各自记得补 `renderGrid()`。横向锚点由既有 `pendingAnchor` 机制保住。
8. **窄屏(≤1099px)退化为全宽面板**:放不下「抽屉 + 网格」并排,故 `#main-col` 暂时隐藏
   (style.css 媒体查询)。移动端本就是全屏面板,语义一致。
9. **抽屉不是弹层**:不进 `modal.ts` 的栈。Esc 仍只在**没有弹层**时收抽屉(有弹层时让栈顶 Esc 先处理),
   与旧 `bindPickerChrome` 同口径;新增 ✕ 按钮(原来靠 `#picker-back`)。

## 5. 边界与风险

- **`#main-col` 隐藏后 `clientWidth=0`**:仅发生在 ≤1099px。此时抽屉是全宽面板,
  主列不参与渲染 —— 但 `renderAll` 不再早退,会重建宽度为 0 的网格。风险:窄屏下打开抽屉再点选,
  网格 `scrollLeft` 被重置。**缓解**:`renderGrid` 的 `gridAnchor` 在 `clientWidth=0` 时
  `screenX = max(0/2, lw) = lw` → `left = (min - axisStart)*px - 0`,`Math.min(left, scrollWidth - 0)`
  仍会给一个值,但语义已无意义。窄屏本就是「一次只做一件事」,关抽屉时会再 `renderGrid()` 一次
  (宽度恢复)重算 —— 可接受,不为它加分支。
- **智能排片仍是弹层**:`openEngineDialog(filmList, ctx, render, true)` 语义不变 ——
  `onReturn = render` 现在是「AI 弹层关闭时刷新抽屉当前 tab」;`fromLibrary=true` 分支不动。
- **`store.picks` 会被整体替换**(`syncFromCloud` 里 `store.picks = merged`)→ 抽屉**每次打开都重建**内容。
- **Tailwind v4 只生成源码里完整出现的字面量类**:本轮新增类(`max-[1099px]:static` /
  `max-[1099px]:w-full` / `max-h-[calc(100vh-80px)]` / `sticky` / `top-[64px]`)全部字面量书写。
- **`is-hidden` 与 `flex` 共存**:`@utility is-hidden` 是 `display: none !important`,压过 `.flex`,
  故抽屉收起时不占位。

## 7. 追加修正:「定位 ▸」不再收起抽屉(2026-09-10,用户反馈)

初版把 `jumpToScreening` 里的 `closePickerPage()` 直接换成了 `closePickerDrawer()`,理由是
「抽屉还开着的话网格只剩 ≈1000px,定位到的卡片可能落在抽屉后面看不见」——**这个理由是错的**:
抽屉是 `#main-col` 的 **flex 兄弟节点**(挤压式),不是 overlay,卡片物理上不可能落在它后面。
而收起的代价很实在:「定位 A → 看一眼时间轴 → 再定位 B」每次都要重新打开抽屉,
正是本需求要根治的「有去无回」。

改动 = `main.ts::jumpToScreening` **删掉 `closePickerDrawer()` 一行**(`closeAllModals()` 保留 ——
AI 结果弹层盖着网格时必须关)。`jumpToScreening` 的居中逻辑读 `scroll.clientWidth`,
挤压后的宽度会被自然吸收,卡片照常居中。

⚠ 独立页面时代这里必须 `closePickerPage()`,因为网格当时被 `display:none`、`getBoundingClientRect()`
全 0 会滚错位 —— **该前提已不存在**,别再照搬。
