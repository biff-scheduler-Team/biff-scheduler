# PLAN-20260917002528 — 搜索词（页面私有查询参数）不再跨页串台

## 目标

用户原话：

> 搜索框会出现 在某一处搜索 然后另一处也会出现 例如我搜索片单 Midnight Passion 然后在吃喝搜索有

把症状还原成机制（已核实，非推测）：

- 各页面的搜索词 / 筛选都写进 URL 的**同名 key**：`q` 在「影片库」（`LibraryPage.tsx:322`）、
  「红黑榜」（`RedBlackPage.tsx:333`）、「吃喝」（`EatsPage.tsx:387`）各有一份；`focus` 在「排片表」
  （`SchedulePage.tsx:204`）与「讨论区」（`DiscussionsPage.tsx:151`）各有一份。
- 主导航（`App.tsx:191-199`）把**整条 search 原样**拼到每个链接上（`to={`${path}${pageSearch}`}`，
  `pageSearch` 见 `App.tsx:74-76`，只剔掉 `quick`）。
- 于是「影片库搜 Midnight Passion」→ 切到「吃喝」，吃喝的 `SearchField` 里躺着 Midnight Passion、
  列表被同一根 needle 过滤成「没有匹配的店」。中文/英文搜索词在「吃喝」里必然 0 命中，观感就是
  「一搜就空」。

## 范围

**做：**

1. 新增单一口径模块 `apps/web/src/app/nav-query.ts`：`navSearch(search, to)` 决定**导航到某页时要带上哪些
   查询参数**。
   - 跨页保留（排片表浏览上下文）：`date` / `hour`（`schedule-selection.tsx` 是应用级状态，
     切页再切回来必须保持同一天、同一时段）。
   - 页面私有参数（`q` / `unit` / `expand` / `pickDate` / `sort` / `district` / `menu` /
     `focus` / `focusDate` / `locate`）**只在自己登记过的路由上保留**，切到别的页一律丢掉。
   - `quick`（浮动面板开关）在 `navSearch` 里一律剔除，由调用方自己决定是否加回。
2. `App.tsx` 改用 `navSearch`：主导航链接、`Escape` 回排片表、「重叠 N」进我的行程、浮动胶囊的开合。
   「打开完整页面」（同路径）语义不变 —— 同页导航保留全部页面参数。
3. `AgendaPage.tsx:435` 的「浏览影片库」也走 `navSearch`（跨页导航不该搬用当前页的 search）。
4. 回归测试：
   - 单测 `apps/web/tests/nav-query.test.ts`：直接对着 `navSearch` 断言（先红后绿）。
   - E2E `e2e/react/eats.spec.ts` 追加一条：在影片库搜索后点导航进「吃喝」，搜索框为空、卡片数回到全量。

**不做：**

- 不改各页面自己的参数名（不把 `q` 改名成 `libraryQ` / `eatsQ`）—— 那要动四个页面 + 深链兼容，
  而根因是「导航把别人的参数搬过去」，改口径比改名字小得多。
- 不动浮动面板内部两个视图（`/picks` ↔ `/agenda`）之间的 search 传递（`App.tsx:218-219`）：
  它们用 `location.search` 保持面板状态（含 `quick=1`），属于**同页**语义。
- 不动 `useFilmNavigation` / `FilmDialog` 的 `filmCode`（同页开弹层，不是跨页导航）。
- 不动 `legacy/`（只读回退件，本次不是 P0 修复）。
- 不引入 URL 之外的搜索状态存储（localStorage / 内存）：搜索词本来就该在 URL 里，可分享、可刷新。

## 方案取舍

| 备选 | 结论 | 理由 |
|---|---|---|
| 给每个参数加页面前缀（`libraryQ` / `eatsQ`） | 否决 | 要改 4 个页面的读写点 + 老链接兼容，根因却不在这 |
| 只在吃喝页忽略「非吃喝来源」的 `q` | 否决 | 治一处漏三处（红黑榜 / 讨论区 / `focus` 同样串），且引入「来源」概念 |
| 导航时按**目标页登记的参数**白名单过滤（本方案） | 采纳 | 一处口径、机械可测；`date`/`hour` 单独列为跨页保留，行为与现状一致 |
| 干脆不带任何参数跨页（连 `date` 也丢） | 否决 | 破坏「在影片库看完片子切回排片表还是那一天」的既有体验 |

## 验收标准

1. 影片库搜 `Midnight Passion` → 点导航「吃喝」：吃喝搜索框为空、卡片数为全量、URL 里没有 `q`。
2. `/schedule?date=2026-10-07` → 切「影片库」→ 切回「排片表」：仍是 `2026-10-07`。
3. `/picks?quick=1`（浮动面板）→「打开完整页面」：`pickDate` 等页面参数仍在，`quick` 被剔掉。
4. 命令：`npm run verify:quick` 绿；`npx playwright test -c playwright.react.config.ts e2e/react/eats.spec.ts e2e/react/floating-panel.spec.ts --project=desktop-chromium` 绿。

## 不做（复核后仍不做）

- 不让搜索词进 localStorage 之类的「页面级记忆」——搜索词本来就该在 URL 里（可分享 / 可刷新），
  串台的根因是导航搬参数，不是「URL 存不下」。
- 不为 `focus`（排片表 vs 讨论区同名）另造新 key：跨页丢弃已经解决撞车，改名要动两处深链。
