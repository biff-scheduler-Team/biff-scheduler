## 3. 本轮**未做**（留给后续，非阻塞）

| 项 | 原因 / 前置 |
|---|---|
| 完整虚拟滚动 | `centerCardX` 读 `offsetWidth/offsetLeft` 做反向定位居中，虚拟化后未渲染元素的尺寸是估算值 → 居中会算错；影片库行高又可变。与「DOM 复用」是两件事：复用已做，**渲染节点总数未减** |
| `style.css` 的 `!important` → `@layer` | **已查明不必做**：Tailwind v4 层序 `theme → base → components → utilities`，`@layer components` 比 `utilities` **更弱**，改过去只会让 `.bg-card` 更彻底地压掉状态类。产物字节位置实测：`.in-plan`(10496) 早于 `.bg-card`(12626)，同权重靠源序 → 必须 `!important`。**那批 `!important` 是正确写法。** 顺带修掉唯一一处漏写：`.in-other` 的 `background` 缺 `!important` → 灰底一直是死代码（已修 + 已部署） |
| 超长函数拆分（`library.openFilmPicker` ~636 行等） | 纯可维护性，零行为 / 零性能收益，diff churn 大 |
| 缩放滚轮 rAF 节流 | 当前每累计 60 才走一档，实测不构成卡顿 |
| 断点常量（1099 / 768）CSS ↔ TS 共享 | 需引入构建期常量，收益低于成本 |
| `conflict.ts::transitFor` 死参数清理 | 见 `PLAN-20260911000705` §7.5：**行为正确**，只需删形参 + 订正注释 |
