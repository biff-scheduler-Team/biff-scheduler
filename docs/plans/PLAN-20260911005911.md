## 1. 目标

1. 用 **2026 影片信息 xlsx（250 部）** 跑豆瓣富化，产出 `douban_id` / 条目直链 / 中文名 / 原始名 / 年份 / 海报 URL；
2. **三档海报全部下载到本地**（`s_ratio_poster` / `m` / `l`），不进 git、只进 `dist` → 部署到 Cloudflare Pages；
3. **文件命名用豆瓣 `subject_id`**，让 `douban.json` 可反向溯源到每张图；
4. 全程 **≈ 每分钟一次请求**，可跑一晚上；断点续跑，中断可续。

## 3. 决策

1. **三档全存**（用户明确要求）：`s` / `m` / `l` 各一张，前端按场景选（列表用 `s`、弹层用 `l`，或 `srcset`）。
2. **文件名 = 豆瓣 `subject_id`**（溯源锚点，见 §4）—— 不用 `f###`（那是按 xlsx 行序现编的，换届会撞号）。
3. **`public/posters/` 直接提交进 git**（用户明确：**未来要走 Cloudflare Git 集成构建**）——
   CI 里没有本地文件，海报必须在仓库里。Git LFS 在 Pages 的 Git 构建中不可靠，故直接提交二进制。
   代价：仓库 +~70 MB（可接受；Cloudflare Pages 单文件 ≤25 MiB、单次部署 ≤20,000 文件均无压力）。
4. **频率 = 每请求间隔 60s**（用户口径「一分钟跑一次」）。
5. **富化与海报下载分两个脚本**（职责分离，各自断点续跑）：
   `enrich_douban.py`（拿 id） → `fetch_posters.py`（下三档）。
6. **本轮不上线**：2026 排期未到，`f###` 与线上 2025 的 `f###` 含义不同 ——
   产物先落 `data/` 与 `public/posters/`，**明天 PDF 到位后随 films/schedule 一起切换上线**。

## 4. id / 命名方案（溯源）

```
public/posters/<subject_id>-s.jpg     例：public/posters/36990574-s.jpg
public/posters/<subject_id>-m.jpg          public/posters/36990574-m.jpg
public/posters/<subject_id>-l.jpg          public/posters/36990574-l.jpg
```

- **`subject_id` 是唯一且稳定的**（豆瓣条目 id），与届次、xlsx 行序、`f###` 编号都无关；
- `public/douban.json` 的 mapping **不新增字段** —— 现有 `subject_id` 即可推导三档路径
  （`/posters/${subject_id}-{s|m|l}.jpg`），json 最小、零冗余；
- 溯源链：`douban.json[code].subject_id` → `douban_url`（豆瓣条目）→ `posters/<id>-*.jpg`（本地图）；
- 富化产物 `data/enriched_douban.json` 每行保留 `row`（xlsx 行号）+ `title_zh` / `title_orig`，
  与 xlsx 原始表可双向对照。

## 5. 频率与时长预算

**每请求间隔 60s**，另加每部片固定 5s 小停顿（**不随 delay 放大** —— 现状是 `delay*0.5`，
60s 时会叠加成 30s，白白翻倍；本轮改为固定 5s）。

单部片的请求数（`build_queries` 最多 4 个 query，命中即 `break`）：

| 情形 | 请求数 | 单部耗时 |
|---|---|---|
| 首个 query 即命中 | 1 | ~65s |
| 试 2 个 query 后命中 | 2 | ~125s |
| 全 miss（试满 4 个） | 4 | ~245s |

250 部（估命中率 60%）：
`150 × 1.5 + 100 × 3 ≈ 525` 个请求 × 60s ≈ **8.8 小时** —— 正好一晚上。

海报下载：命中数 × 3 档，CDN 宽松，间隔 2s → 约 250×0.6×3 = 450 张 × 2s ≈ **15 分钟**（可在富化跑完后单独跑）。

## 7. 执行顺序（今晚）

```bash
PY=~/.workbuddy/binaries/python/envs/default/bin/python   # 已装 openpyxl 3.1.5 / pymupdf 1.28.2

# ① 豆瓣富化（≈8.8h，可中断续跑；每请求 60s）
$PY tools/enrich_douban.py --xlsx <2026影片信息.xlsx> \
    --out data/enriched_douban.json --delay 60

# ② 海报三档下载（≈15min，可中断续跑）
$PY tools/fetch_posters.py --enriched data/enriched_douban.json \
    --out-dir public/posters --delay 2

# ③ 生成 public/douban.json（enriched → mappings，键 = f###，明天拿到排期后补 code 键）
# ④ 明天 PDF 到位 → 换 public/films.json + schedule.json → 一起 npm run deploy
```

> ① 若中途被限流（`subject_suggest` 静默返回空数组 → 该 query 跳过），重跑会自动补齐 miss 行。

## 8. 断点续跑 / 中断恢复

- **富化**：`--out` 文件每处理完一部即落盘；重启时含 `douban_id` 的行自动跳过（**miss 行不跳过**，
  会重试 —— 这正是想要的，限流导致的 miss 第二次可能就命中）。
- **海报**：按文件是否存在跳过；下载中断不会留下半个文件（先写 `.tmp` 再 `rename`）。
- 两条链路都可随时 Ctrl-C，第二天接着跑。

## 9. 风险

- **豆瓣限流**：匿名高频会静默返回空数组。60s 间隔 + 断点续跑是主要对策；若仍大面积 miss，
  说明触发更严的封锁，需降到 90–120s 或次日再跑（**不要**为了跑完而缩间隔）。
- **2026 条目覆盖率**：2026 电影节在 10 月，部分片可能豆瓣还没建条目（实测第 1 部「宛如星辰的你」已命中）。
  命中率需跑完才知道；miss 不影响上线（弹层回落搜索兜底）。
- **海报防盗链**：必须带 `Referer`；不带会拿到 418 + 13 字节占位文件 → `fetch_posters.py` 要
  **校验响应大小 > 1KB** 才算成功，否则删除并记 miss。
- **dist 体积 +~70 MB**（250×0.6×3 档）：Cloudflare Pages 单文件 ≤25 MiB、单次部署 ≤20,000 文件，均无压力；
  但**首次部署上传较慢**（wrangler 逐文件）。
- **海报进 git** ⇒ 仓库 +~70 MB。**不要**改成 gitignore —— 未来走 Cloudflare Git 集成构建时 CI 拿不到本地文件。
