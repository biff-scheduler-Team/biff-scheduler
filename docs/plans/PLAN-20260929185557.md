## 1. 接口契约(前端照着写,不要改服务端)

### 读

```
GET /api/stats/film-comments?edition=<id>&cursor=<opaque>&limit=<n>
200 { edition, items: [{ filmKey, vote: "red"|"black", comment: string, displayName: string|null }],
      nextCursor: string | null }
```

- **只回写了评语的行**;按 `updated_at` **倒序**(最新在前);
- `limit` 缺省 20,服务端夹在 `1..50`;
- `cursor` 是**不透明串**:前端**原样回传**,不要解析、不要自己拼、也不要缓存成结构化对象;
- `displayName` 为 `null` → 显示「匿名观众」;
- ⚠️ **响应里没有任何身份标识** —— 前端**无法**从列表里认出「哪条是我写的」(这是刻意的)。

### 写

```
POST /api/stats/film-votes-ping
{ edition, votes: [{ key, vote, comment }] }
```

- ⚠️⚠️ **每一条都必须带 `comment` 字段**(没有评语时传 `null`)。
  **少带这个字段会被服务端当成「旧版前端」→ 这一整份的评语一个字都不碰** → 评语**永远写不进去**。
  这是有意的保护:老客户端上报时不能静默清空用户已经写过的评语(详见 `index.ts` 里 `carriesComments` 那段)。

## 2. 设计决策(已定,理由在此)

1. **读入口** = 榜单下方的页面级「大家说」模块(用户选定方案 B,理由见主 PLAN)。
2. **写入口也放在这个模块里** —— 模块顶部一个「我来评一句」表单:选一部片 + 文本框 + 保存。
   - 为什么**不**放卡片上:用户原话「评语我觉得单独做一个模块吧,**不要放在贴纸上,不然很乱**」——
     卡片 / 贴纸这一轮刚做完降噪,不能再往上加控件;
   - 选片范围 = **本地 `board` 里我贴过的片**(一人一片一票一评,没贴过就不能评);
     没贴过任何片时,表单给一句「先去卡片上标记『看过』并贴一枚」,而不是渲染一个空的 select。
3. **评语要存本地**:`redblack.ts` 的 `Sticker` 加 `comment?: string`。
   - 理由:公开接口不回身份 ⇒ 列表里认不出自己那条 ⇒ **「编辑我的评语」只能靠本地**;
   - ⚠️ 加**可空**字段是**向后兼容**的,不触发 AGENTS §5 那条「改结构必须新 key + 一次性迁移 + 删旧 key」
     (那条针对的是**不兼容**变更)。
4. **模块里不标「这条是我写的」** —— 服务端给不出这个信息,前端也别用「片名 + 文本相同」去猜。
   想改自己的评语:在表单里选那部片,文本框**预填本地已写的那份**。
5. 翻页用「加载更多」按钮(走 `nextCursor`),**不做无限滚动**:它落在页面最底部,触底加载在窄屏上不稳。

**顺带修掉一条既有假红(不在本 PLAN 范围内,但挡着「三浏览器全绿」)**:
`e2e/react/redblack.spec.ts` 的「拖出张贴区」在 `mobile-chromium` 上**每次都红**,
而**与本轮改动无关**(摘掉 `<FilmCommentsPanel>` 重建后同样 3/3 红,已实测)。根因不是坐标过期:
移动端模拟下 `boundingBox()` 与 `elementFromPoint()` **不是同一套坐标** —— 实测 Pixel 7 上把卡片滚进视口后
`window.visualViewport.offsetTop = 98`,而 `getBoundingClientRect() = boundingBox() + 该偏移`,
于是命中测试稳定落在画布**上方** 98px 处(拿到 `.rb-card-info` / `.rb-zoom`)。修法:新增
`toPagePoint(page, point)` 把 `boundingBox()` 的坐标换算到页面空间再问 `elementFromPoint`
(⚠ **指针那一侧不需要换算**:`page.mouse.move()` 与 `boundingBox()` 是同一套,实测 hover 命中的正是那个元素);
顺带把「量位置 + 挪指针 + 命中」整条放进 `expect.poll` 重试。
