## 方案取舍

| 备选 | 结论 | 理由 |
|---|---|---|
| 在红黑榜页内加"热度档位" | **否决** | 用户明确「专门开一个热门榜」；且热度行的视觉与贴纸墙无关（见下），混在一页会让 `RedBlackPage.tsx`（已 126 KB）继续膨胀 |
| 新做独立「热门榜」 | **采纳** | 与红黑榜解耦；复用排序/聚合/绘图骨架，但视觉独立 |
| 热门榜复用贴纸墙的"每行画贴纸" | **否决** | 12,092 个"想看"画不成贴纸；口径是"几枚就画几枚"只对 591 票成立 |
| 热门榜行 = 海报 + 片名 + 想看数 + 口碑角标 | **采纳** | 复刻"看片计划海报"的行内缩略图语言（`poster-brush.ts::loadPosterImages`） |
| 继续拉长图（1080 × 数千像素） | **否决** | 这正是「不适合手机阅读」的根因（长宽比，不是清晰度） |
| 新增竖版比例（建议 1080 × 1440，3:4），单屏 ≤ 8 行 | **采纳** | 符合 `poster.ts:3-8`「重排而非缩放」；公众号正文图 1080 宽通用 |
| 单元作为分享图参数（`unit?`） | **采纳** | 用户：「分享的时候可以选择需要哪个单元的就行」 |
| 热门榜新开服务端聚合 | **否决** | 现有 `want-counts`（影片级）已够；分组是纯前端计算，不增加 RTT |

## 修订 4（2026-10-14，**打开浏览器实测后**的修复 —— 单元身份回归仓库既有口径）

### 怎么发现的

用户要求起本地预览。dev server（`http://127.0.0.1:31026`）上打开榜单页与分享弹层后发现两个**真 bug**：

1. **单元下拉里 4 个一模一样的选项** —— 全是
   `Asian Filmmaker of the Year · 年度亚洲电影人奖 · 杨紫琼专题，1 部`。
2. **「午夜激情」在榜单上只有 5 部，影片库里是 9 部** —— 同一单元两套数。

### 根因

`util.ts::filmUnitOf` 是我上一轮**自己发明的一支**：它直接返回目录条目上那个**原串**
（`cats[0].unit`），于是

- 同义写法（`亚洲电影人奖` / `年度亚洲电影人奖-杨紫琼专题` / `2026年度亚洲电影人奖-杨紫琼专题`）
  各成一组，而 `unitLabel()` 对它们的展示名**一模一样** → 4 个同名选项，分享图也会被切成 4 张各 1 部片的图；
- `also_units`（联映块成员片）不参与 → 午夜单元少数 4 部。

而仓库里**早就有**这套口径：`app/model.ts::unitKey` / `unitsOfFilm`，注释里写得很清楚 ——
「**计数（`libraryUnits`）与筛选（`filmInUnit`）必须同源走这里**，否则会出现「下拉说 9 部、
点进去只有 5 张卡」」。**我违反了 §5 口径单一来源**：不能因为「只认主单元」写进了 PLAN 的取舍表，
就让它变成第二套单元归属规则。

### 改了什么

| 处 | 改动 |
|---|---|
| `units.ts` | `unitKey` / `unitsOfFilm` 从 `app/model.ts` **搬来**（叶子模块，零 import）。为什么搬：`model.ts` 依赖 `util.ts`，纯逻辑的榜单 / 分享图要用同一支归一化，留在那边只能循环 import 或各写一份 |
| `app/model.ts` | `import { unitKey, unitsOfFilm } from "../units"` + **原样转出** —— 既有 `import { unitKey } from "../app/model"` 不受影响 |
| `util.ts` | `filmUnitOf` → **`filmUnitKeys(film): string[]`**（`cats.flatMap(unitsOfFilm)` 去重）。改名是有意的：它返回的是**规范键**，不是原串 |
| `hot-board.ts` | `HotRow.unit: string` → `units: string[]`；`groupByUnit` 把一行放进它归属的**每个**组，组名取 `unitLabel(组 id)`（不是行上的主单元名） |
| 面板 / 热门榜弹层 | 筛选改 `row.units.includes(unitId)`，与分组同源 |
| `redblack-poster.ts` | 切分与 `posterUnitOptions` 都改读 `filmUnitKeys` |

### 与修订 2/3 的两处口径反转（都是有意改行为）

- 未标单元的组名由「未标单元」改为 **`未标注单元`**（`unitKey` 的兜底词，与影片库下拉同一个词）。
