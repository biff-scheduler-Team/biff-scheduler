# PLAN 2026-09-10 10:16:00 — 「我的选片」三档色改冷色系(与红绿灯底色错开)

> 需求(用户原话):「我的选片 这三个颜色和我的时间冲突的颜色 有一点冲突了 请你改一下 选片的这三个颜色」。
> 本文件 = 本需求唯一规划文档。

## 现状(代码事实,HEAD 52a24e6)

三档(必看/备选/随缘)当前**直接复用状态色 token**:

| 档位 | token | 值 | 撞谁 |
| --- | --- | --- | --- |
| 必看 must | `--must: var(--status-danger)` | `#ce1e36` 品牌红 | **完全冲突红底/红框/红标题**(`--conf` = 同一 `--status-danger`) |
| 备选 maybe | `--maybe: var(--status-warning)` | `#d97706` 琥珀 | **时间紧张黄底**(`--status-tight #e6a800`,同色系) |
| 随缘 wild | `--wild: var(--status-wild)` | `#8a8f98` 灰 | 中性灰(未选卡/次级文字),弱撞 |

红绿灯底色语义:`绿=已选(--status-ok #2f9e44)` / `黄=时间紧张` / `红=冲突`。
甘特卡上的 7px 档位色点正是**画在这三种底色卡上**(`grid.ts:418`)——红点落红卡、橙点落黄卡、灰点落灰卡时几乎不可辨。行程行三段 seg(`agenda.ts:192`)同源同病。

消费点(全部经 `pick.ts` 收口,除两处例外):
- `pick.ts` `PRI_BG_ON` / `PRI_DOT_BG` / `PRI_TEXT`(影片库行内三选 / 详情弹层 / 我的选片总览 / 甘特色点)
- `agenda.ts:33` **另抄了一份** `PRI_BG_ON` + `PRI_ORDER`(与 `pick.ts` 重复)
- `agenda.ts:246` 拿 `text-maybe` 当「偏紧」琥珀文字用(语义借用,非档位)
- `library.ts:334 / 711` 拿 `bg-must` 当「A 方案 已选 N」**红色计数章**用(语义借用,非档位)
- `index.html:51` 网格图例(色点三连 + 「红=必看 / 橙=备选 / 灰=随缘」文案)
- `legend.ts:358 / 377` 图例与「我的选片」章节文案

## 方案

**新三档 = 冷色系(蓝 / 紫 / 灰蓝)**,整族搬离红黄绿,且与品牌红(BiFF)、`--rate-*` 观影等级色(绿/橙/红)全不重叠:

| 档位 | 新 token | 值 | 白字对比度 |
| --- | --- | --- | --- |
| 必看 | `--pri-must` | `#1d4ed8` 蓝 | 6.7 ✓ |
| 备选 | `--pri-maybe` | `#7e22ce` 紫 | 7.0 ✓ |
| 随缘 | `--pri-wild` | `#64748b` 灰蓝 | 4.8 ✓ |

1. **`style.css`**:`--must/--maybe/--wild` 三别名 → 换成 `--pri-must/--pri-maybe/--pri-wild`;`@theme` 对应 `--color-must/maybe/wild` → `--color-pri-must/maybe/wild`。删 `--status-wild`(仅为旧 `--wild` 存在,改后无引用)。
2. **`pick.ts`**:三张映射改 `bg-pri-* / text-pri-*`;文件头注释补「冷色系」口径。
3. **`agenda.ts`**:删本地重复的 `PRI_ORDER` / `PRI_BG_ON`,改从 `pick.ts` 引 `WISH_ORDER` + `PRI_BG_ON`(两层档位从此单一来源,不再各自一份);`Priority` 随之从类型 import 移除;`text-maybe` → `text-tight`(偏紧文案回到琥珀,语义归位)。
4. **`library.ts`**:两处 `bg-must` 计数章 → `bg-biff`(保持品牌红,和档位彻底解耦)。
5. **`index.html` / `legend.ts`**:色点 class 与「蓝=必看 / 紫=备选 / 灰蓝=随缘」文案同步。

不动:红绿灯三色本身、`--conf`、`--rate-*`、`bg-biff` 计数、任何交互逻辑(id/data 委托)、`state.setWish` 数据层。
