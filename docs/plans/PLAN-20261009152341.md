# PLAN-20261009152341 — 普通票快速查票

## 目标
> 普通票数量也可快速查看，/general

## 范围
做：新增 `/general` 和 `/api/general`，scheduler 服务端直连官方 WEB 渠道，复用 guest 查询与影片卡片，补齐渠道隔离测试。
不做：购票、锁座、账户登录、自动轮询、修改 biff-http、依赖升级。

## 方案取舍
- 采纳：固定渠道配置复用查询逻辑与页面，避免两份状态和影片信息口径。
- 否决：浏览器跨域直连（官方拒绝 CORS）、依赖 biff-http、将 GUEST 库存当普通票。
- 沿用用户明确要求，直接推送本仓库 main。

## 验收标准
1. `/general` 显示官方 WEB 余票数量、影片资料、日期/搜索/只看有票筛选。
2. `/guest` 行为不变，两个渠道不混用库存；失败及未知不显示为零。
3. API 单测和两个渠道桌面/手机 E2E 通过；部署后实查 API、页面和 asset hash。

## 修订 1（用户追加）
> 页面展示xx人想看

两个查票页展示已有站内影片级「xx 人想看」，复用 want-counts 缓存、filmNodeKey 和 wantCountLabel；不冒充官方购买人数，不改统计权重。未匹配影片或统计未成功加载时显示未知，不捏造零。

## 验证记录
- 新增 API 测试先红：`/api/general` 返回 404（预期 200/400）；实现后 16 条渠道 API 测试通过。
- `npm run verify:ui -- e2e/react/guest.spec.ts --project=desktop-chromium --project=mobile-chromium`：类型、lint、1232 条单测及 12 条 E2E 全通过。
- 本机缺少 `code-review-skill`，按可用性回退逐项审查 diff，未发现阻断项；仅本需求文件入提交。

## 修订 2（定时采集与快照）
> 另外guest 的日期是当天和第二天，还有，guest和general的查询应该保存下来，并且每5分钟查一次，（8:00-8:30之间，每1分钟检查一次），每次结果都要 snapshot。
> GENERAL：官方全部开放日期。

- 按韩国时间：08:00–08:30（含端点）每分钟，其他时间每 5 分钟；三个无重叠 UTC cron。无人打开页面也执行。
- GUEST 固定韩国今天/明天，GENERAL 使用官方 WEB 全部开放日期；每轮每渠道日期列表只读一次，逐日查询限制并发。
- 新增 D1 快照和调度执行表，不改用户片单。每次真实查询（含失败/未开放）追加不可变快照；不自动删除历史。调度重复投递幂等，异常中断可租约重试。
- 页面默认读最新保存结果，缺失才补采集；手动刷新强制采集并保存。展示保存时间、过期提示；后台定时不会依赖浏览器。
- 新增 migration、边界/SQL 持久化/幂等/部分失败测试及快照 UI 测试；不新增第三方服务、依赖或购票功能。

## 修订 3（用户收窄页面）
> 页面不用提供历史快照查看

不提供历史快照 UI 或公开历史读取接口；历史仅保存在 D1。页面展示最新查询和保存时间，后台采集继续。

## 定时快照验收记录
- 韩国时间边界、午夜推进、幂等、两日/全部日期、失败及空开放日期快照：33 条相关 API 测试通过。
- `verify:ui`：类型检查、lint、1249 条单测、16 条桌面/手机 E2E 通过；无历史 UI，手动刷新和浏览器只读轮询分别断言。
- 本地真实 Workers + D1 + 官方网络：一轮采集 GUEST 2 天、WEB 7 天，9 份快照全部 `ok`。
- Workers 技能审查：固定官方端点、不转发凭据；数据库预编译参数绑定；cron 无重叠、请求并发限制为 2、结果落库后再返回；迁移仅新增表与索引，不触碰用户片单。
