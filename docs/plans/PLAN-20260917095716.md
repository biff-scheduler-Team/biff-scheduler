# PLAN-20260917095716 — 底部 Toast 补上默认自动收起（不再常驻）

## 目标

用户原话：

> 底部提示现在常驻 不会消失 能改成会消失的吗

还原成机制（代码事实，行号已核）：

- React 版把旧版的 `legacy/src/toast.ts`（单例 DOM，`setTimeout(..., 3600)` 后加 `is-hidden`）换成了
  Spectrum S2 的 `ToastQueue`，入口在 `apps/web/src/components/spectrum.ts:26` —— 原样 re-export。
- S2 的 `addToast`（`node_modules/@react-spectrum/s2/src/Toast.tsx:135-136`）：

  ```ts
  let timeout =
    options.timeout && !options.actionLabel ? Math.max(options.timeout, 5000) : undefined;
  ```

  —— **不传 `timeout` 就得到 `undefined`，队列永不自动关闭**（`ToastContainer` 默认 `placement="bottom"`，
  所以表现就是「屏幕底部那条提示常驻」）。
- 全仓 30+ 处 `ToastQueue.xxx("…")` 没写 `timeout`：`LibraryPage.tsx:128/132`、
  `FeedbackPage.tsx`（8 处）、`ScreeningDiscussionDialog.tsx`（7 处）、`TransferAddDialog.tsx:52`、
  `screening-actions.ts:35`、`EatsPage.tsx:273`、`DiscussionsPage.tsx:163/193`。
- 另有少数几处手写了 `{ timeout: 5000 }`（`SchedulePage.tsx:575`、`AgendaPage.tsx:61/67`、
  `RedBlackPage.tsx`、`PosterPreview.tsx:64`、`AccountHost.tsx:16`）—— 所以症状看起来是
  「有的会消失、有的不会」，漏一处的代价是永久占屏。

## 范围

**做：**

1. 新增 `apps/web/src/components/toast.ts`：包一层 `ToastQueue`，对**没写 `timeout` 的调用**兜底成
   5000ms（S2 内部对非 `actionLabel` 的 toast 有 5000ms 下限，传更小值也会被抬到 5000）；
   调用方显式传的 `timeout` 原样透传。
2. `apps/web/src/components/spectrum.ts` 改为 re-export 这个包装（调用点的 import 路径**不变**，
   全仓 `ToastQueue` 只剩一份实现，符合红线 5）。
3. 回归测试 `apps/web/tests/toast-timeout.test.ts`：mock 掉 `@react-spectrum/s2/Toast`，
   断言四个变体（`neutral` / `positive` / `negative` / `info`）在**不给 options** 时都会把
   一个有限的 `timeout` 交给 S2 队列，且显式 `timeout` 不被覆盖。

**不做：**

- **不改各调用点的文案与触发时机**，也**不逐个补 `{ timeout }`** —— 30+ 处各写一份就是第二份口径，
  以后新增一行还会漏；只改「默认值」这一处。
- **不动 `ToastContainer` 的位置/样式**（仍是底部居中、堆叠、可展开），用户只说「要会消失」。
- **不给 toast 加 `actionLabel`**：S2 对带操作按钮的 toast **刻意**不自动关（WCAG SC 2.2.1），
  本仓库目前也没有调用点用 `actionLabel`，加进去等于把常驻问题请回来。
- **不动 `legacy/`**（只读回退件，且它本来就是 3600ms 自动收起，无此问题）。
- **不推送**（本机 §0 约定：本地验收 + 用户明确说「可以推」再 push）。

## 方案取舍

| 备选 | 结论 | 理由 |
|---|---|---|
| 新增 `components/toast.ts` 包一层 + `spectrum.ts` re-export（本方案） | 采纳 | 只改默认值一处；调用点零改动；新增调用自动继承 |
| 给 30+ 个调用点逐个补 `{ timeout: 5000 }` | 否决 | 同一口径写 30 份，下一处新代码照样漏（这正是本次 bug 的成因） |
| 直接改 `node_modules` 里 S2 的默认值 | 否决 | 改依赖产物，升级即失效，且违反「产物检入 / 不改依赖」 |
| 换成自研 toast（回到 legacy 的 `toast.ts` 单例 DOM） | 否决 | 为了一个默认值丢掉 S2 的可访问性（区域 role、堆叠展开、clear all、焦点管理） |
| 靠 E2E「等 6 秒断言 toast 消失」记账 | 否决 | 一条 spec 要空等 5s，且只覆盖被点到的那一处；单测直接钉住「所有变体都带 timeout」更严 |

## 验收标准

1. `npx vitest run tests/toast-timeout.test.ts` 绿（含「不给 options 必须带 timeout」与「显式 timeout 不被覆盖」）。
2. 全仓 `ToastQueue` 的实现只剩 `apps/web/src/components/toast.ts` 一处；
   `grep -rn "@react-spectrum/s2/Toast" apps/web/src` 只有 `toast.ts`（拿 S2 队列）与 `spectrum.ts`（拿 `ToastContainer`）。
3. 手工验收：点「我的选片 → 加入选片」等任一触发 toast 的操作，底部提示约 5 秒后自己消失，可继续操作。
4. `npm run typecheck` / `npm run lint` 绿。
