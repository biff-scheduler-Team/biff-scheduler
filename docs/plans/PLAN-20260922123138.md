# PLAN-20260922123138 — 「我的行程」第三轮：砍掉右侧栏与顺位撞车提示 + 画布点掉场次先确认

## 目标

用户原话（逐字保留）：

> 1.我的行程 不需要显示 冲突组顺位这个组件 直接铺满
> 2. 我的行程中点击取消需要二次确认

开工前的三个岔路（2026-09-22，第三轮），用户拍板：

| 岔路 | 用户选择 |
|---|---|
| 「冲突组顺位」删到哪一层 | **整栏删掉，画布铺满** —— 右侧栏（冲突组顺位 + 场次详情）整块下线，日程表画布占满整幅宽；画布上方的「顺位撞车」提示（`RankClashes`）也一起删 |
| 「点击取消」指哪个动作 | **画布上点掉场次格**（日程表画布上点一下 = 把这一场移出行程，目前静默、无撤销） |
| 二次确认的形式 | **站内弹层**（沿用 Spectrum `Dialog`，与「删除方案」「应用顺位调整」同一套样子） |

> ⚠ 本轮**推翻上一轮的两条**：`PLAN-20260922105228` 的 W3「两栏版式（右＝当天冲突组顺位 + hover 场次详情）」
> 整块撤销；同轮 W1 保留的「画布上方顺位撞车提示」也撤掉。上一轮 PLAN 保留原样只作历史，不再追加修订段。

## 现状（代码事实）

- **右侧栏**：`AgendaPage.tsx` 的 `agendaSide`（`<aside className="agenda-side">`），内含
  `.agenda-side-ranks`（`<h2>冲突组顺位</h2>` + `RankGroup` 卡）与 `.agenda-side-detail`（hover 场次详情，
  读 `useHighlight().code`）。折叠状态 `agendaSideFoldedMemory`（会话内记忆）。
- **顺位撞车提示**：同文件的 `RankClashes()`（`.notice.rank-clashes`，`aria-label="顺位撞车"`），
  带「预览顺位修复」弹层（`autoFixRanks`）与逐组让路按钮（`rankSpotOrder`）。
- **布局**：`.agenda-columns` = `grid-template-columns: minmax(0,1fr) 320px`（折叠时 `40px`，`≤1099px` 单列）。
  两栏之前 `.agenda-gantt` 自己带 `padding: 0 20px 4px`（见 `60c8256^` 的 `agenda-parity.css:50-55`），
  这一内距在上一轮被搬到了 `.agenda-columns` 上。
- **画布点格子**：`components/ScheduleGantt.tsx` 的 `.gantt-film` 按钮 `onClick={() => toggle(s)}` ——
  `toggle` 是共享出口 `screening-actions.ts::useScreeningPicker`。行程档（`scope="agenda"`）的画布
  `day = shows = dayRows`（我的场次），**每一格都是已选**，所以这里点一下的语义**只有「移出行程」一种** ——
  静默生效、无撤销；票务标记（`biff.tickets.v1`）会随 `rebuildIndex()` 的 prune 一起消失。
  排片表档（`scope="schedule"`）的格子是「加入 / 移出」双向的日常动作，不属本次范围。
- **已有的两种确认范式**：`window.confirm`（`screening-actions.ts` 的「只有一场」副作用）与
  站内 `Dialog`（`SettingsDialog::ClearDialog`、`RankClashes` 的「预览顺位修复」；
  程序化开弹层用 `DialogContainer onDismiss` + 条件挂载，仓库先例 `App.tsx` / `FilmDialog` / `AccountHost`）。

## 范围

**做：**

### W1. 砍掉右侧栏与顺位撞车提示，画布铺满

- `AgendaPage.tsx`：删 `agendaSide`（连同 `sideFolded` / `toggleSide` / `agendaSideFoldedMemory` /
  `useHighlight` 的 `detail`）、删 `RankClashes()`、删 `panels`、删 `activeGroups`；
  三个渲染分支里的 `{panels}` 与 `.agenda-columns` 包裹层一并去掉，日程表分支直接渲染 `agendaGantt`。
- 随之失去调用方的 import：`autoFixRanks`、`rankSpotOrder`、`displayTitle`、`useHighlight`、`SavedPlan` 无关，
  `plans` 仍被卡片视图用（`plans.groups`），`store` / `setRanks` 仍被 `RankGroup` / `Gap` 用。
- `pages/agenda-parity.css`：删 `.agenda-columns`（含 `:has()` 折叠模板）与 `.agenda-side*` 全部规则、
  `≤1099px` 那条单列回落、`.rank-clash-item`；把 `padding: 0 20px 4px` 还回 `.agenda-gantt`
  （窄屏 `0 14px 4px`，即 `60c8256^` 的原样）。顺手删掉上一轮搬栏时留下的**无引用**规则 `.agenda-gantt-ranks*`。

### W2. 画布点掉场次 → 站内二次确认

- `screening-actions.ts`：新增**唯一判据** `removalDropsPick(cat, s)`（= 「移出这一场会不会连带把整部片
  移出「我的选片」」，即现有的 `slotOf(code) && soleShowCode(key) === code`），`useScreeningPicker` 改读它；
  再给 picker 加一个可选参数 `{ soleShowAsked?: boolean }` —— 调用方**已经**就这件事问过用户时用它跳过
  `window.confirm`，避免「弹层问一次 → 原生 confirm 再问一次」两层确认。不传 = 行为与改前逐字一致。
- `ScheduleGantt.tsx`：行程档（`agenda` scope）里 `isSelected` 的格子点击不再直接 `toggle(s)`，
  改为 `setPendingRemove(s)`；新增小组件 `AgendaRemoveDialog`（`DialogContainer` + `Dialog size="S"`，
  文案含片名 / 场次 / 时间 / 影院 + 票务标记会被清掉 + 「只剩这一场会连带移除选片」的**准确**说明），
  确认走 `toggle(s, { soleShowAsked: true })`。
  ⚠ 排片表档与「加入」方向的点击**一律不动**。

**不做：**

- **不动顺位本身**：`biff.ranks.v1`、`plans.ts::rankOf`、`setRanks()`、`RankGroup` 的拖拽实现都保留 ——
  行程的**卡片视图**仍按日就地展开顺位卡（`agendaDays` → `agendaItems`），改顺位的入口收敛到那里。
- 不动排片表档的画布点选（含 GV 映后谈那一列按钮的 `toggle`）。
- 不动 `biff.*` 任何键；不新增依赖。

## 方案取舍

| 备选 | 结论 | 理由 |
|---|---|---|
| **D1** 保留「场次详情」侧栏，只删「冲突组顺位」 | **否决**（用户选了「整栏删掉」） | 只剩一个 hover 详情块的 320px 空侧栏比画布铺满更差；用户要的是「直接铺满」 |
| **D2** 顺带把卡片视图的顺位卡也删掉 | **否决** | 那会让**整页没有任何地方能改抢票顺位**（撞车提示已删、侧栏已删），是砍功能不是收拾布局 |
| **D3** 用 `window.confirm` 做二次确认 | **否决**（用户选站内弹层） | ① 与「删除方案 / 顺位修复」的观感分家；② 原生 confirm 写不下「票务标记会一起清掉」这类必要前提 |
| **D4** 把确认挂在共享 picker 里（所有 `toggle` 都拦） | **否决** | 排片表点格子是双向日常动作、卡片里的「移出行程」也在用同一个 picker —— 全站弹确认是增加成本，不是防误触 |
| **D5** 确认后直接调 `toggleScreening` 绕过 picker | **否决** | 会绕过「只有一场必须先告诉用户」这条既定不变量（`PLAN-20260916004024`）；改为给 picker 加显式标记 |
| **D6** 弹层里只写「确定移出这一场？」 | **否决** | 用户正是在抱怨「静默、无撤销」，弹层要顺带把**后果**说清（票务标记 / 选片） |

## 集成点清单

| 机制 | 处理 |
|---|---|
| `useScreeningPicker` | 判据抽成 `removalDropsPick()`，新增可选 `soleShowAsked`；**默认调用方零改动** |
| `useHighlight` | 行程画布仍用它做格子联动高亮（`data-highlighted`）；只是不再有侧栏消费 `code` |
| `DialogContainer` | 按仓库既有范式条件挂载（`{pendingRemove && …}`），避免 S2「常驻 `Dialog` 被当成当前弹层」的坑 |
| `e2e/react/helpers.ts::agendaCards` | 顺位相关 spec 现在**必须**先切卡片视图（默认已是日程表） |
| `docs/CONVENTIONS.md` | 「顺位卡 UI 唯一入口」与 `--muted-strong` 举例里的「侧栏怎么出详情」两处措辞更新 |

## 验收标准

1. `/agenda` 日程表视图：`.agenda-side` / `.agenda-columns` / `.rank-clashes` 计数**全为 0**；
   `.gantt-scroll` 右边缘 ≈ `.agenda-page` 右内缘（画布铺满），且 `.agenda-gantt` 左右各留 20px 内距。
2. 卡片视图仍有顺位卡（`.rank-group` 存在、拖拽改顺位仍落盘）。
3. 行程画布点一个已选格子 → 出站内弹层（`role=dialog`，标题含片名）；**取消**后 `biff.picks.v2` 与
   `aria-pressed` 不变；**确认**后该场离开行程。只有一场的影片在确认时**不再**弹第二个原生 confirm。
4. 排片表 `/schedule` 点格子仍是「加入 / 移出」即时生效（无弹层）。
5. `npm run typecheck` / `lint` / `test` / `check:repo` / `check:test-map` 全绿；
   `affected-specs` 算出的 spec 在桌面 + 移动两档全绿。
6. 提交一次收口，推送前经用户确认。
