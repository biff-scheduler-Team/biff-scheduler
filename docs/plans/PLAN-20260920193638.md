# PLAN-20260920193638 — 「群体行为与口碑」的两个下拉换成搜索框

## 目标

用户原话：

> 群体行为与口碑 中的场次电影全部采用搜索框

把该面板里的「电影」与「场次」两个 `<select>` 换成**输入即筛的搜索框**
（现在要在几百部片 / 几百场里滚动选择，手机上尤其难受）。

## 范围

**做：**

- 「电影」→ 搜索框：按**片名**模糊筛。
- 「场次」→ 搜索框：按 **场次号 / 日期 / 开场时间 / 影院** 模糊筛；**刻意不搜片名** ——
  那是「电影」框的职责，两个框都能搜片名就等于同一件事有两个入口。
- **删除原来的「关键词」框**：它与新的「电影」搜索框完全是同一件事（都按片名模糊筛）。
  留两个做同样事的输入框，用户下一轮必然问「这俩有什么区别」。
- **选中语义**：筛到**唯一**一部影片 / 唯一一场时，视为「选中」——
  原有的「口碑构成环」（选中某片才画）与「本场同场 N 人」（选中某场才显示）照常工作，
  不需要用户再做一次点选。
- E2E：`rush-analysis.spec.ts` 里用 `selectOption` 的三条改写成 `fill`；
  「选影片后场次下拉只列该片场次」这条**删除**（见下）。

**不做（含代价）：**

- **不做「输入时弹候选列表」的下拉（combobox）**：用户要的是搜索框；候选列表要另配
  键盘导航 / 焦点管理 / 点外关闭一整套，而**搜索结果本身就是清单**（下面的明细表即时收窄）。
  若以后想要「边打边弹候选」，那是另一件事。
- ⚠ **代价写明**：原先「选中影片后，场次下拉只列该片的场次」这条联动**消失** ——
  场次框不再是列表，没有「列出哪些」这回事。想看某片有哪些场次，搜它的片名即可在明细表里看到。
- 不动 `.ra-grid` 布局、图形与统计口径。

## 方案取舍

| 备选 | 结论 | 理由 |
|---|---|---|
| `react-aria-components` 的 ComboBox | 否决 | 项目没有既有的可搜索下拉骨架（S2 只有 `Picker`，不可搜），自己造键盘 / 焦点 / 点外关闭不划算 |
| 原生 `<datalist>` | 否决 | 候选样式不可控，iOS 上的呈现与桌面不一致 |
| 保留「关键词」框、只换两个下拉 | 否决 | 「关键词」与「电影」框完全重复 |
| **两个纯搜索框 + 唯一匹配即选中 + 删「关键词」** | **采纳** | 最小实现，字面满足「全部采用搜索框」 |

## 验收标准

1. 该面板的筛选控件变成两个，都是**可输入的搜索框**（`input[data-filter="film"]` / `input[data-filter="screening"]`）。
2. 输入片名 → 清单收窄；输入场次号 → 清单收窄到含该场次的影片，并出现「本场同场」一行。
3. 搜不到时清单清空、`data-crowd-films` 为 0。
4. `npm run typecheck` / `lint` / `build -w @biff/web` 通过；`rush-analysis.spec.ts` 全绿。
5. 回写文档：本 PLAN；`PLAN.md` 文档头一行「最后更新」。
