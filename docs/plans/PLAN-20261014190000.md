# PLAN-20261014190000 — 红黑榜「快速投票」滑动卡片（简化投票入口）

## 目标

把红黑榜的**投票入口**从「标记看过 → 点红/黑 → 拖贴纸 → 换肤」换成**滑动卡片**：
左滑投黑、右滑投红、上滑记「没看过」，贴纸落到画布上时**位置与皮肤都随机**。

用户原话（三轮澄清）：

> 简化红黑榜逻辑 有一个模块是 快速投票 取消贴贴纸所有行为 去掉看过 直接在我的行程中取片单 然后左滑贴 右滑贴红 上滑表示没看过 需要明确的不同的左右滑动效

> 左滑 = 贴黑(投黑票；右滑 = 贴红), 需要有海报作为大图 类似于社交软件的逻辑 左滑变成碎片消失动效
> 右滑有一个另一种对应的动效

> 上滑 → 记一条「没看过」并上报(服务端也要记这个状态)

> 候选：行程内去重影片，全部都要再过一遍(已投过的也出现，用于改票)

> 贴纸需要保留 用户贴上去的贴纸需要随机分布 红黑榜不是被替代 而是简化用户投票逻辑

> 保留：分享图、讨论区/评语、全站票数总览、海报上的评分角标

## 方案取舍

| 备选 | 结论 | 理由 |
|---|---|---|
| 快速投票做成**新路由** `/quick-vote` | 否决 | 用户说的是「红黑榜不是被替代，而是简化投票逻辑」——投票是榜单页上的一个动作，独立路由会让「投完看排行」多一次跳转 |
| 快速投票做成**页内 tab**（与热门榜/红榜/黑榜并列） | 否决 | 那三个 tab 是**看结果**，快速投票是**做动作**；并列会让「红榜 tab 里也在投票」这种语义混乱 |
| 快速投票做成**全屏弹层**（S2 Dialog） | **采纳** | 滑动卡片必须在视口中央、隔离版面；S2 Dialog 现成给 role/focus trap/Esc，不必自造 a11y |
| 「没看过」复用 `remove` op 表达 | 否决 | `remove` 的语义是「撤票」，与「我明确没看过」不同；混用会让服务端永远分不出这两件事 |
| 「没看过」用 `film_vote_stat` 加一列 `unseen_count` | 否决 | 会把「没看过」灌进红黑那本账 —— 评分 / 排序 / 分享图 / 群点全部要新增分支，且它本来就不是一个态度 |
| 「没看过」另起一条独立上报管道（新独立端点 + 自己的重试） | 否决 | 同一件「把我的状态同步上去」的事写第二份实现，违反 §5 红线 5；而且要第二套水位 / 退避 / keepalive |
| 「没看过」复用既有 op 管道 + 独立聚合表 | **采纳** | 客户端零新增同步代码；服务端只多一张表与一处差分，红黑那几本账一个字都不碰 |
| 贴纸皮肤做成「按 id 推导」（现状） | 否决 | 用户明确要「随机分布」；随机落在投票那一刻（首次投票），改票保留原皮肤，避免每投一次换个样 |
| 移除拖拽后把「我贴的那枚」直接删掉 | 否决 | 用户说「贴纸需要保留 用户贴上去的贴纸需要随机分布」——画布上仍要有自己那枚，只是不再能拖 |
| 自造模态弹层（不用 S2 Dialog） | 否决 | §5 硬约束：`role=dialog` + focus trap + 焦点归还；S2 已经过全仓库验证 |
| 为滑动手势引 `@use-gesture/react` / `framer-motion` | 否决 | 只为三个方向判定引入一个动画库，gzip 增量与实际调用点不成比例（§5 依赖条款） |

## 验收标准

1. 榜单页控制栏出现「快速投票」按钮；点开是全屏弹层，`role=dialog`、Esc 可关、焦点归还按钮。
2. 候选是**行程内去重影片**且**含已投过的**；行程为空时弹层给明确空态并引导去排片表。
3. 左滑 → 该片变黑票；右滑 → 变红票；上滑 → 该片变「没看过」（画布上那一枚随即消失）；
   未越线松手 → 弹回原位，不改任何状态。
4. **两端动效可分辨**：左滑产生 12 片 `qv-shard` 碎片飞散；右滑产生 `qv-stamp` 印章/光环 +
   整卡右滑；`prefers-reduced-motion` 下两者都只淡出。
5. 贴纸落到画布上的**位置随机**、**皮肤随机**（同一部片改票时位置与皮肤不变）。
6. 「标记看过」在界面上与代码里都不再存在；旧键 `biff.redblack.watched.v1` 被一次性清理。
7. 画布上「我贴的那一枚」只读：无 pointerdown / 无双击 / 无方向键 / 无轮盘入口；
   分享图、讨论区、评分角标、hero 总览、红黑榜排序逐字不变。
8. 上滑后 `POST /api/stats/film-votes-ping` 带 `{op:"unseen",key}`；服务端 `film_vote_contribution`
   落一行 `vote='unseen'`，`film_unseen_stat` +1，且 `film_vote_stat` / `film_vote_skin_stat` 的
   红黑计数**没有任何变化**（阴性对照）。
9. `npm run typecheck` / `lint` / 单测全绿；`e2e/react/redblack.spec.ts` 在 desktop-chromium 上通过。
10. 新增文件已登记进 `scripts/test-map.json` 的 `redblack` 规则，`node scripts/affected-specs.mjs
    --files apps/web/src/quick-vote.ts` 命中 `redblack`（不退化成全量）。

## 修订 1（2026-10-14，改动中触发）

**触发原因**：实现「没看过」时读到了服务端写路径，发现原方案（新表 `film_unseen_stat` + `0017` 迁移）
**不必要**——`film_vote_contribution.vote` 列**没有 CHECK 约束**（`apps/api/src/db/schema.ts`），
而「一个人对一部片只有一个状态」这件事本身就可以直接落在这一列上。

**改后方案（采纳）**：
- 「没看过」= 贡献行上第三个取值 `vote = 'unseen'`，**复用同一条增量 op / 水位链路**
  （客户端零新增同步代码），服务端把它当**状态**读写、但**不进红黑任何一本账**。
- 守卫只有两处（`film-vote-store.ts::addVote` / `removeVote` 顶部直接 return），
  加对账 SQL ① 的 `HAVING`（否则只标过「没看过」的片会凭空多出一行全零聚合行）。
- **不新增表、不新增迁移、不新增读接口字段**；自查与管理端看得见 `unseen` 行（可删）。

**代价（写清）**：管理端多了一种要渲染的状态（`admin-view.ts` / `AdminPage.tsx` 已同步改）；
`vote` 列的语义从「票」扩成「状态」，靠 `isFilmVote`（计数口径）与 `isFilmVoteState`（落库口径）
两个函数把这条线划开——**这两者的区别是本次最容易被后人改错的地方**。

## 修订 4（2026-10-14，用户）

**触发**：「快速投票直接只要行程 … 都改成默认弹出这个快速投票，如果行程没有**主动点击**就改成 TOP50」。

**做法**
- **候选**：就是行程里的片，**不管投没投过**（这一点本来就是现状 —— 已投过的片子是改票入口，
  不是要被过滤掉的东西，代码里 `quickVoteOrder` 从不读 `board`）。
- **默认弹出**：落地 `/redblack` 且**我的行程里有片** → 缺省档直接落 `?sort=red&vote=1`，卡片当场弹出。
  判断放在 `BoardPage` 那个「落地规范化」的 effect 里，判据是 `store.picks.size > 0`
  （**不是**「有没有投过票」—— 拿「都投完了」挡掉是反的）。
  ⚠ 只在 `sort` 缺失时决定一次：否则从卡片里关掉、随手切个 tab 又会被弹回来。
  ⚠ 这里**不订阅 `useStore()`**：它是落地时刻的判断，不是要跟着变的界面状态。
- **行程为空 → 不弹**（弹空卡片只会让人以为坏了），照旧落热门榜；用户**主动点**页头那枚按钮时才
  走兜底候选。兜底从 **TOP20 改成 TOP50**。

**两个连带的坑（一并堵掉，否则这个改动本身会引入 bug）**
1. **热门榜数据是异步来的**。原实现会在 want 全为 0 时先排一份候选 —— 那份顺序与数据到了之后
   **完全不同**，而队列一换 `QuickVoteDeck` 就重开这一轮，用户划到第 6 张会被当场甩回第 1 张
   （正是规格里那句「不要闪烁 / 布局跳动」）。改成：**数据没到就先不造候选**，等它到了再给，
   队列于是只出现一次、也只被排一次序；空队列用**模块级常量** `EMPTY_DECK`（字面量 `[]` 会在
   每次渲染换新引用，等于每次渲染重置一次卡片）。
2. **`loadWantCounts()` 的触发条件**从「行程为空」收紧成「行程为空 **且卡片已打开**」——
   只是在看红 / 黑榜的人不该为一条用不到的接口付一次请求。

**卡片空态因此要分两种说**：`fromAgenda` 为真 = 真的没候选（去加行程）；
为假 = 兜底那份还没到（`正在取热门榜的候选…`）。混成一句会把用户支到错误的地方。

## 修订 5（2026-10-14，用户报了两个问题）

**触发**（用户原话）：

> 快速投票会重复投票吗 因为我记得我有一些是贴过的 就是是匿名态也要在浏览器缓存里面稍微记录一下通过快速投票的标记情况
>
> 还有就是现在 快速投票TOP50 我划了五部就又重新从 5/50变成1/50

**诊断（先读代码，两条都查清了）**

- **「会重复投票吗」= 不会。** 本地 `board` 一部片只有一个 key 位（`redblack.ts::setFilmVote` 已有贴纸走
  `retintSticker` 原地换色、没有才 `placeSticker`，内容没变时返回**同一引用**）；服务端
  `film_vote_contribution` 主键 `(edition, film_key, contributor)`，改票是 update、撤票是 delete。
  症状的成因是**另一个**：队列只按「在不在我的行程」取（修订 4 那条「已投过的也出现 = 改票入口」），
  所以划过的片下次**还会出现**。
- **「5/50 → 1/50」= 真 bug，根因是 `deck` 的依赖声错了。**
  `RedBlackPage.tsx` 的 `deck` useMemo 依赖里含 `crowd` / `priorRate`（全站票数聚合）：
  投一票 → 1200ms 上报成功 → `onFilmVotesChange` → `setVotes(新对象)` → `crowd` 换引用 →
  `deck` **重算并造出新数组** → `QuickVoteDeck` 的 `useEffect([queue])` 判成「候选换了」→ `setIndex(0)`。
  而 TOP50 的**顺序只由 `want` 决定**（`hot-board.ts::buildHotRows` 末尾 `sort(compareByWant)`），
  `crowd` / `priorRate` 只进那一行的展示列（红 / 黑 / 评分）—— 而这里**只取 key**。

**用户拍板的口径**：**投过 + 跳过都不再出现**（本地记「快速投票已处理」标记，**匿名也记**）；
改票去榜单上操作。

**做法**

1. **新增本地键 `biff.redblack.skipped.v1`**（`redblack.ts`）：只记「快速投票里**跳过过**的 key」。
   ⚠ 「投过」不另记 —— 它由 `biff.redblack.v2` 那份 board 判（board 里没有的才是没投过，
   撤票之后那部片自然重新进队列）。两个键是**两件事**：一个是我的表态，一个是我翻过这一张。
2. **`quick-vote.ts` 新增两个纯函数**（都可脱开 DOM 单测）：
   - `pendingQueue(films, handled)`：从候选里去掉**已处理**的片 —— 只在**一轮开始时**调一次；
   - `deckSignature(films)`：队列的**内容身份**（key 序列），供视图层判断「候选换了没有」。
3. **`QuickVoteDeck`**：
   - 初始 `round` = `pendingQueue(queue, handledOf)`；`queue` 变化时按同一个函数重算；
   - **重置判据从数组引用换成 `deckSignature(queue)`** —— 这是 5/50 的第二道防线：
     就算上游哪天又把什么会抖的东西塞进了 `deck` 的依赖，只要**内容没变**，卡片就不重开这一轮；
   - 跳过 → `onSkip(key)`，撤销一步是跳过 → `onUnskip(key)`（撤销要能把标记也撤掉）；
   - 空态新增一支：候选非空但**都被过滤掉**了 = 「你都划过一遍了」，与「行程是空的」分开说。
4. **`RedBlackPage`**：`deck` 的依赖**去掉 `crowd` / `priorRate`**（用 ref 读最新值喂给 `buildHotRows`），
   只留 `[agendaQueue, films, wants]`；新增 `skipped` 状态与 `handledOf`。

**代价（写清）**：改票入口从「快速投票队列」挪到「榜单上那一枚」（用户已确认接受）；
`biff.redblack.skipped.v1` 会随 `biff.*` 一起被账号同步与导出备份收录（与 board 同一个处置，
无隐私内容）。

**验收标准**

1. 单测（已落：`quick-vote.test.ts` +6 / `redblack.test.ts` +4）：
   `pendingQueue` 过滤「已投 / 已跳过」、全处理完给空数组；`deckSignature` **同内容换引用 → 签名相同**
   （这一条就是 5/50 的回归）；`loadSkipped` 的读取端白名单与「与红黑票分两个键」。
2. 快速投票里投 / 跳过若干张，票数刷新后**仍停在同一张**（`data-qv-index` 不回 0）。
3. 划过一遍的片（投过或跳过）重新打开不再出现；候选全划过时给「都划过了」空态而不是「行程是空的」。

**不做**：不动服务端（跳过不上报是既有口径，`film_vote_contribution.vote` 仍只有红 / 黑两态）；
不改 `biff.redblack.v2` 的结构；不动 `redblack.spec.ts` 里那批待重写的旧用例（见修订 3 的「仍欠」）。
