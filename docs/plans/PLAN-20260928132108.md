# PLAN-20260928132108 — 红黑榜 E2E 在 CI 上长红：把五条假红逐条钉死

## 目标

`main` 上的全量三浏览器 E2E（GitHub CI）自 2026-09-23 起**一直红**，红灯集中在
`e2e/react/redblack.spec.ts` 的同一批用例上。用户贴来的失败清单（run `36371565360`，`0ebdedc`）：

```
5 failed
  [mobile-chromium] :56   点「标记看过」不会把整页顶上去
  [mobile-chromium] :808  窗口外松手丢了 pointerup：手势不卡死，贴纸也原样留着
  [mobile-webkit]   :56   点「标记看过」不会把整页顶上去
  [mobile-webkit]   :237  屏幕外的卡片仍留着我贴的那一枚：自己的贴纸始终抓得到
  [mobile-webkit]   :747  两指同时按住两张卡的贴纸：一次松手只结算发起的那一枚
2 flaky
  [desktop-chromium] :515 跨片拖拽：别片的张贴区一枚都不会多
  [mobile-webkit]    :643 从暂存区拖出并移出画布：提示是「松开 · 取消」，暂存区不亮
600 passed
```

> 同一天（2026-09-24，run `35973244811`）的失败集合**完全相同**（`:56 / :237 / :641 / :745 / :806`，
> 行号只是被后续改动挤了 2 行）—— 所以这不是某一次提交引入的回归，而是一批**测试自身的假红**。

## 范围

**做：**

1. `:56` —— 判据从「`栅格.top + scrollY` 的绝对值」改成「页眉底边 → 栅格顶边的**间距**」。
2. `:237` —— 命中测试（`elementFromPoint`）改用 `expect.poll`。
3. `:515` / `:808` / `:643` —— 加一条**有界**的 `quiet()`（等提示条退场）并按需使用。
4. `:747` —— ① 按「两枚贴纸实际占的那段窗口」滚进视口（收敛式，最多 6 轮）；② 贴纸改用**键盘**贴；
   ③ 起手前补一发 `pointerId = 1` 的 `pointerup` 清残留手势；④ 落点/判据改走**画布内相对位置**。

**不做：**

- **不改产品代码**（`RedBlackPage.tsx` / `toast.ts` / CSS 一行不碰）：这一批红灯全部出在
  测试与环境（字体、提示条浮层、随机落点、合成指针）的交互上，没有一条指向产品行为错误。
- 不动 `:515` 的既有修法（同日另一会话已在 `6529603` 里补了「起手先横移 24px」并放宽鼠标阈值）。
- 不动工作区里他人在途的文件（`AGENTS.md` / `apps/web/vite.config.ts` /
  `docs/DEVELOPMENT-STANDARDS.md` / `apps/web/mock/` / `apps/web/public/mock-redblack.html`）。

## 现状（代码事实 / 实测数据，非推测）

- **`:56`（+2px）**：CI 报 `Expected: 433, Received: 435`（桌面）与 `781 → 783`（手机），**恰好 2px**。
  预览页会异步换上 S2 的 WebFont，而 `.rb-mine`（`redblack-parity.css:95`，`font-size: 12px`）
  走 `line-height: normal` —— 换上的那一刻它的行盒高变一次。量绝对坐标时，「标记前」量到换字体前的
  版面、「标记后」量到换完之后的，那 2px 被读成「标记把页面顶上去了」。
  本地 `document.fonts` 全是 `unloaded`（探针 `probe-fonts.mjs`）→ 本地量不到，CI 才复现。
- **`:237`**：CI 截图里 `elementFromPoint(dot 中心)` 拿到的是 `<html ... class="chyGla_toast-remove">`
  —— S2 提示条的进出场走 **View Transitions**，过渡那几帧整页被一层快照盖住。
- **`:643`**（flaky）：CI 原文 `<html ... chyGla_toast-remove> intercepts pointer events`，
  `hover()` 重试满 10s 仍拿不到元素。`react-stately` 的 `ToastQueue` 有 `pauseAll()/resumeAll()`
  （指针停在提示条上时它**不自动消失**），且 S2 对非 action 提示有 **5000ms 下限**
  （`Math.max(options.timeout, 5000)`）。
- **`:747`**：`Expected: < 664, Received: 692.4 / 746.4` —— 贴纸落点走 `Math.random`，手机上两张卡
  放不下，第二枚落在自己画布下半截就越过 `vh`。另外用探针量出：**Playwright 鼠标的 `pointerId`
  在 Chromium 与 WebKit 上都是 1**（`probe-mouseid.mjs`），而这条用例的第一指也用 `pointerId = 1`
  —— 上一拍真实鼠标交互残留的那次手势会占住 `beginDrag` 的单手势守卫，把第一指直接挡掉
  （实测同一手势 `ghost` 数 0 / 1 随机，失败值恒等于「贴纸到落点」的距离 = 一枚都没挪）。
- **`:808`**：本地复现（探针 `probe-redblack-geom.mjs`）—— `scrollIntoView({block:"center"})` 之后
  《B》的暂存区按钮 `box.y + height` 仍在 `vh` 之外（`srcBIn: false`），`mouse.down()` 落在视口外面。

## 方案取舍

| 备选 | 结论 | 理由 |
|---|---|---|
| `:56` 等版面落定（`document.fonts.ready` + 稳定窗口）再取基线 | 否决 | 字体何时换上不可控；而「页眉自己高矮」本来就不是这条用例要守的东西 —— 改判据才是根治 |
| `:56` 判据改「页眉底边 → 栅格顶边」的间距 | **采纳** | 换字体让页眉与栅格**一起**平移，间距不变；而真 bug（空榜引导条一收一放 53px）动的正是这段 |
| `:237` 改用 `expect.poll` | **采纳** | 过渡是**暂时**的，一次性量必然偶发假红；要守的「我的那一枚在最上层」是**静态**性质 |
| `quiet()` 里 `mouse.move(2, 2)` 把指针挪开提示条 | 否决 | 实测把后面量到的坐标全废掉，`:515`/`:571` 随即以「指针不在画布内」失败 |
| `quiet()` 只等、且**有界**（6s 后放行） | **采纳** | 指针正压在提示条上时它会 `pauseAll` 自己、永远不走（实测把 `:808` 卡到 10s 超时）；等不到就让后面的 `hover()` 自己重试 |
| `:747` 只删掉那条视口断言 | 否决 | 断言删了，后面「落点对不对」在视口外仍会以别的形式失败（实测 2 / 19 / 22 / 48px 不等） |
| `:747` 按两枚贴纸的窗口收敛式滚动 | **采纳** | `content-visibility: auto` 的估算高会在滚动中被换成真实高，一次滚不收敛（实测差 100px+） |
| `:747` 贴纸用键盘贴 + 起手补一发 `pointerup` | **采纳** | 这条用例全程用合成指针，前置的真实鼠标交互不该在页面上留手势（见上，实测 5/5 稳定） |
| `:747` 判据改「画布内相对位置」 | **采纳** | 贴纸存的就是相对坐标；视口坐标相减会把「画布被浮层推几像素」原样记成误差 |

## 验收标准

1. `npx playwright test -c playwright.react.config.ts e2e/react/redblack.spec.ts`
   （三浏览器）**全绿**：本地跑出 `87 passed`（含一次重复跑、以及 `:789` 单独 `--repeat-each=3` 9/9 绿）。
2. `npx tsc --noEmit -p tsconfig.e2e.json` 与 `npx eslint e2e/react/redblack.spec.ts` 干净。
3. push 之后 **GitHub CI 的 E2E 变绿**（这是最终判据 —— CI 是事后体检，本地绿不等于线上绿）。
