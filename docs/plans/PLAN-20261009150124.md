# PLAN-20261009150124 — GUEST 嘉宾余票查询

## 目标
> 增加 guest 票 查票功能，位于 /guest。参考 本地 biff-http 项目实现方式。完成后直接推上去。
> 懂吗，在biff schedule 实现该功能

在 biff-scheduler-Team/biff-scheduler 的 main 交付独立只读 GUEST 页面。

## 范围
做：React `/guest`、导航入口、同源 `/api/guest`、共享响应类型、状态与交互测试。
不做：购票、锁座、支付、账号登录、参考项目的进一步修改、数据库迁移、依赖升级。

## 方案取舍
- 参考本机 biff-http 原有 `guest_stock` 的官方开放日期、GUEST prodList 与状态判定；直接查询 GUEST，不依赖 WEB 库存。
- 每次查询一个日期，日期之外的片名、场次编号与仅有票筛选在页面完成；限制上游请求数。
- 上游字段缺失为未知，失败显示错误；零余票才表示售罄。保留韩国日期与 24+ 时间，不对小时取模。
- 使用既有 Hono 限流及 React/Spectrum 外壳，不增加依赖；不传用户 Cookie 给官方。
- 用户明确要求直接推 main，本次按该指令发布。

## 验收标准
1. `/guest` 直接进入整页，导航可达；按官方日期查票、筛选、刷新，错误时不展示旧库存为当前结果。
2. 官方未开放日期不请求库存；未知数值不变成 0；过期、未开售、售罄不标有票。
3. API 单测覆盖上述边界及上游错误，E2E 覆盖查询、筛选与失败恢复。
4. 云端构建通过，main 远程提交一致，线上 `/guest` 路由及新增产物可核验。
