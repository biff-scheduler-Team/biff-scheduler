# PLAN-20260923110401 — 拖出张贴区要有明显提示（会被收回）

## 目标

用户原话：

> 贴纸拖出可张贴区域 进入被收回区域 需要明显提示

也就是说：拖着贴纸时，一旦落点**已经不是这一部自己的张贴区**（松手就会把它收回暂存区），
用户必须能**在松手之前**看出来「松开会发生什么、它要回到哪儿」。现在是无声的 —— 松手之后
才弹一条 toast 说「收回暂存区了」，属于事后通知。

## 现状（代码事实）

- 落点判定：`RedBlackPage.tsx::finishRef` 用 `canvasAt()` 取指针下的画布，只有
  `dataset.rbCanvas === meta.srcKey`（**本片画布**）才算合法落点；其余一律出界 ——
  已贴的那枚**收回暂存区**，从暂存区拖出的那枚**什么也不做**。
- 拖拽中的高亮：`flush()` 用 `cardAt()` 取指针下的**卡片**，只要卡片是本片就挂 `data-rb-hover`
  （CSS：`.rb-card[data-rb-hover]` 亮卡 + `.rb-card[data-rb-hover] .rb-canvas` 亮画布）。
  ⚠ **判据不一致**：拖到卡片左侧的信息列（海报 / 片名 / 按钮那一栏）时卡片照样亮着，
  而松手是**收回** —— 亮灯在承诺一个不会兑现的落点。这正是用户说的「拖出可张贴区域」的边界。
- 除此之外**没有任何**出界提示：ghost 始终一个样，暂存区也没有任何反应。

## 范围

**做：**

1. **把落点判据收敛到一处**：新增 `ownCanvasAt(x, y, srcKey)`（= `canvasAt()` 再比 `data-rbCanvas`），
   `flush()`（拖拽中的高亮与提示）与 `finishRef()`（松手结算）**共用它** —— 「可张贴区 / 会被收回」
   的分界只此一处（§5）。随之 `cardAt()` 不再被使用，删掉。
2. **高亮口径改为「本片画布」**：`data-rb-hover` 只在**本片画布**被覆盖时挂上
   （CSS 选择器与 E2E 断言都作用在**卡片**上，保持不动；变的只是「什么时候挂」）。
3. **出界时的三处提示**（只在出界出现，可张贴时不加噪声 —— 那时「能放」由画布高亮说）：
   - **ghost 换装** `.rb-ghost--out`：半透明 + 去饱和（读作「这枚现在不是活的」）；
   - **跟着 ghost 的短标签**说清后果：已贴的那枚 →「松开 · 收回暂存区」；从暂存区拖出的那枚 →
     「松开 · 取消」。标签**挂在 ghost 内部**（位移自动同步、随 ghost 一起消失）；
   - **源片的暂存区点亮** `data-rb-target`（真的会回去的那个地方）。**只走「已贴的那枚」这条路**：
     从暂存区拖出来的那枚松手是「什么也不做」，给它的暂存区亮灯会读成「它会回去」——
     可它本来就在那儿。
4. 全部沿用既有手法：**DOM 直接操作、零 React state**（拖拽期间一次渲染都不做），状态只在**变化时**才写 DOM。
5. E2E：新增「拖出张贴区：先给明显提示、松手确实收回；拖回画布提示立刻消失、松手不收回」。

**不做：**

- 不改落点语义（本片画布才算数；别片画布仍是出界）——那是 `PLAN-20260923101147` 已拍的口径。
- 不做「拖到别片画布 = 把票转给别片」。
- 不加常驻的「可张贴区」呼吸灯 / 入场动画：提示只在手势进行中出现，松手即消失。
- 不弹 toast 讲「你出界了」：出界是中途状态，弹 toast 会把「松手之后那一条」盖掉。
- 不动 `.rb-canvas` 的 `touch-action`、不改 `biff.*` 存储、不动 `StickerCanvas` / 分享图。

## 方案取舍

| 备选 | 结论 | 理由 |
|---|---|---|
| ghost 加一圈 `--brand` 虚线 + 半透明 | 否决 | 品牌红 `#ce1e36` 与红贴纸 `--rb-red` `#cf3b52` 几乎同色（2026-09-23 白边那次已实测），红环画在红贴上等于没画；换白环在亮色卡片上同样等于没画 |
| ghost 半透明 + **去饱和**（`grayscale`） | **采纳** | 与贴纸颜色 / 主题都无关：「不是活的」这个语义靠灰度表达，两个主题、红黑两种贴纸都成立 |
| 标签挂在 ghost **内部** | **采纳** | 位移自动随 ghost 的 `transform` 走（不用每帧同步第二个元素）；ghost 本来 `pointer-events: none`，不会挡住落点命中测试；`ghost.remove()` 一并收掉，不留残件 |
| 标签做成独立跟随元素 | 否决 | 要自己同步 transform、自己收尾，白多一份状态 |
| **只**改 ghost 外观、不加文字 | 否决 | 不够「明显」：说清**松开会发生什么**（收回 / 取消）才是要点；只换个颜色是暗号 |
| 页面顶部挂一条常驻提示条 | 否决 | 与指针位置脱节（用户视线在指针上），还会挤动布局 —— 2026-09-23 刚修过「整点标记导致整页位移」那类问题 |
| 出界时把**本片画布**也标成「不可放」 | 否决 | 画布灭灯（回到常态）已经说明它不再是落点；再加一层负向样式是两套语言 |
| 暂存区亮灯也覆盖「从暂存区拖出」那条路 | 否决 | 见范围第 3 条：那枚松手什么也不发生，亮灯是假承诺 |
| 高亮继续按**卡片**判（现状） | 否决 | 与松手判据不一致 —— 卡片左侧信息列亮着灯、松手却收回 |

## 验收标准

1. 拖着**已贴的那一枚**移出本片画布（移到卡片左侧信息列 / 页面空白 / 别片画布，三者都要）：
   - `.rb-ghost` 带 `rb-ghost--out`，且上面有「松开 · 收回暂存区」；
   - 本片 `.rb-tray` 带 `data-rb-target`；本片卡片**没有** `data-rb-hover`；
   - 拖回画布内：上面四处**全部**恢复（ghost 不带 `--out`、标签消失、暂存区不亮、卡片亮起）。
2. 从**暂存区**拖出并移到画布外：标签是「松开 · 取消」，暂存区**不**亮。
3. 松手：画布外 → 那枚被收回暂存区（既有 toast 与落库口径不变）；画布内 → 落点照旧。
4. 拖拽期间仍**零 React 渲染**（不引入 state / 不 setState）。
5. 命令：`npm run build -w @biff/web` 之后
   `npx playwright test -c playwright.react.config.ts e2e/react/redblack.spec.ts --project=desktop-chromium`
   全绿；`apps/web` 单测全绿。
