# PLAN-20260917112233 — 搜索框打不出中文：输入缓冲 + 延迟提交

## 目标

用户提问：

> 为什么搜索框无法输入中文?

定位结论（本轮已核实，非推测）：**不是输入法或浏览器的问题**，而是「影片库 / 吃喝 / 红黑榜」三个搜索框
把 `SearchField` 的 `value` 直接绑在 URL 上，`onChange` 里 `setSearchParams` 是一次 **router 导航（异步）**。

- 中文输入法是**组合态**：拼音串暂存在 input 的 DOM 里，此刻 `input.value !== props.value`；
- React 每次提交都会把 `props.value` 回写进 DOM，而 URL 那一拍**必然滞后**，正好把组合中的拼音串擦掉；
- 英文逐字符即时提交，回写值等于刚敲的字符，所以看不出问题 —— 这也是「能打英文、打不了中文」的原因。

反证（仓库内现成对照组）：`DiscussionsPage.tsx:254-259` 与 `TransferAddDialog.tsx:65-70` 的 `SearchField`
用的是本地 `useState`，不受影响。

旁证：`react-aria-components` 自己在 `TokenField` 里放了 `CompositionRenderBlocker`
（源码注释 `Prevents React from re-rendering during composition events`）—— 上游承认「组合期间重渲染会打断输入法」，
但普通 `TextField` / `SearchField` 没有这层防护。

用户指定的修法（原话）：

> 使用方案 A（推荐）：SearchField 的 value 改为本地 useState（初值取 URL 的 q），onChange 只 setState；
> 把「写 URL」推迟到 onCompositionEnd 或 200ms debounce 之后。另用一个 effect 在「外部导航导致 q 变化」时
> 把 URL 值同步回本地。 改完后推送

## 范围

**做:**

1. 新增纯逻辑模块 `apps/web/src/app/query-search.ts` —— 输入缓冲的**唯一口径**：延迟提交调度 + 组合态闸门 + URL 回声判定。
2. 新增共享包装 `apps/web/src/components/QuerySearchField.tsx` —— 本地 `useState` 持有显示值，组合态用
   `ref.getInputElement()` 挂原生 `compositionstart` / `compositionend` 监听（S2 的 `SearchFieldProps` 把
   `GlobalDOMAttributes` `Omit` 掉了，事件处理器传不进去，只能拿原生 input）。
3. 三处接入：`LibraryPage.tsx`（影片库）、`EatsPage.tsx`（吃喝）、`RedBlackPage.tsx`（红黑榜）。
4. 回归测试 `apps/web/tests/query-search.test.ts`（先红后绿）。

**不做:**

- 不动 `DiscussionsPage` / `TransferAddDialog` 的搜索框（本地 state，本来就是对的；改它们只有风险没有收益）。
- 不动其余 URL 参数的写入方式（`unit` / `district` / `menu` / `sort` / `pickDate` 原样）。
- 不改 `SearchField` 的样式、布局、断点。
- 不把 `q` 的过滤口径搬走：三个页面的**过滤仍然读已提交的** `params.get("q")`，输入框只多一层显示缓冲。
- 不引 `jsdom` / `@testing-library`（`apps/web/vitest.config.ts` 明写「单测只覆盖纯函数、node 环境」，
  加环境的成本 > 收益，所以把可测的逻辑全部抽进纯模块）。
- **不造「合成 composition 事件」的 E2E**：原 bug 的机制是**真实输入法的组合态**与 React 受控回写抢
  DOM，而 Playwright 不驱动 OS 输入法（`fill()` / `insertText()` 都是直接设值，不产生组合态）——
  造一串合成 `CompositionEvent` 只能测「我自己的监听器被调了」，测不到原 bug，还会随上游实现漂移而假红。
  机制层的两条不变量由 `tests/query-search.test.ts` 钉死；端到端只保证**没有回归**（受影响 spec 全绿）。

## 方案取舍

| 备选 | 结论 | 理由 |
|---|---|---|
| 本地 `useState` 缓冲 + 延迟 200ms 写 URL + 回声判定（用户指定） | **采纳** | 唯一能同时保住「URL 仍是持久化真源」和「组合态不被回写」的做法；外部导航同步也留着 |
| 只做 debounce，不改 `value` 来源 | 否决 | `value` 仍滞后于 URL，组合态照样被回写 —— 没治根 |
| 改非受控 `defaultValue` | 否决 | 「外部导航改写 `q`」不再反映到输入框（清除筛选 / 分享链接进来），需靠 `key` 重挂载兜；且 `value` 会变成一次性初值，语义更弱 |
| 三处各写一份缓冲逻辑 | 否决 | 红线 5（同一口径不写第二份）；三处行为必须逐字一致，抽共享包装 |
| 在组件里手写 `setTimeout` + `useState` | 采纳为**分层**：调度逻辑进纯模块（可单测），组件只做薄封装 | 仓库单测是 node 纯函数环境，不抽出来就没法写「先红后绿」的回归测试 |
| 顺手把讨论区 / 添加转票也换成共享包装 | 否决 | 它们没有这个 bug，换了只是扩大改动面（§9.2「说清不能影响什么」） |

## 验收标准

1. 三个搜索框能**连续输入中文**（拼音组合过程不再被回写打断），过滤结果在输入停顿 200ms 后刷新。
2. `npm run typecheck`、`npm run lint`、`npm test` 本地全绿。
3. 新增单测覆盖 5 条行为：延迟提交 / 连续输入只提交最后一次 / 组合态不提交 / `composeEnd` 提交上屏值 /
   回声判定（本地刚提交的值不被回写）+ 外部值回写。
4. 受影响 E2E：`parity-library` · `review-library` · `screening-popover` · `want-counts` · `redblack` · `eats`
   （本地按需单跑，默认交云端）。

## 附：本轮顺带统一的一处口径

搜索词写 URL 统一用 `replace`（原先只有吃喝是 `push`）。搜索是**同一页面的状态**，不是导航目的地 ——
原来每按一个键就往历史栈塞一条记录，用户按返回键要按 N 次才离得开。既然实现收成一处，写入方式也必须一并统一。
