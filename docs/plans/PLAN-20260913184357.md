# PLAN-20260913184357 — 豆瓣入口从影片卡操作行移到「我的行程」片名后面

## 目标

承接 `PLAN-20260913183205`（把影片卡操作行里的「豆瓣」外链顶到行右端）。
用户看完效果后改主意（2026-09-13）：**把那个豆瓣按钮挪到「我的行程」的影片名后面**，
并**做成一眼能看出是外跳的指引**（带 `↗` 的跳转链接），让用户能直接点。

采用口径：

1. **移走** —— 影片卡（`/library` `/picks` 的 film-card）操作行里的「豆瓣 / 豆瓣搜索」外链**删除**；
2. **落在片名后** —— 「我的行程」每张场次卡（`ScreeningCard`，`showTitle` 时）的**影片名右侧**
   加一个 `豆瓣 ↗` 外链，`target="_blank"`，样式沿用本卡片已有的跳转语言
   （`在 Google 地图打开 ↗` = `agenda-parity.css::.venue-map-link`：品牌色、无下划线、hover 下划线）；
3. **口径合一** —— 外链 URL 抽成 `util.ts::doubanUrlOf(film, map)`（映射有条目 → 条目页；
   否则按片名搜索，中文名优先），替换掉散在各处的 `douban.com/search?q=` 兜底。

## 范围

**做：**

- `apps/web/src/util.ts`：新增 `doubanUrlOf()`（与 `doubanScoreOf()` 同族、同文件）。
- `apps/web/src/components/ScreeningCard.tsx`：`showTitle` 的标题块改为
  `<div className="screening-title"><h3>{info.title}</h3><a className="screening-douban">豆瓣 ↗</a></div>`。
  **外链放在 `<h3>` 之外**（同级兄弟）—— 塞进 `<h3>` 会把标题的 accessible name 变成
  「片名 豆瓣 ↗」，让 `getByRole("heading", { name, exact: true })` 一类断言全部漂移。
- `apps/web/src/pages/LibraryPage.tsx`：删掉操作行里的豆瓣 `<Link>` 及其注释、删掉随之未使用的
  `Link` 导入。
- `apps/web/src/style.css`：删掉上一轮加的 `.film-actions > a { margin-left: auto }`；
  新增 `.screening-title`（片名 + 外链一行，`gap` 分开、`align-items: baseline`）与
  `.screening-douban`（12px、品牌色、`text-decoration: none`、`white-space: nowrap`、hover 下划线）。
- `apps/web/src/components/ScreeningInfoPopover.tsx`：`doubanUrl` 改用 `doubanUrlOf()`（同一口径，去掉副本）。
- 测试：
  - `apps/web/tests/film-score.test.ts`：加 `describe("doubanUrlOf")`（映射优先 / 中文名优先 / 退回英文名 / 空格 trim）。
  - `e2e/react/parity-library.spec.ts`：**删掉**上一轮那条「豆瓣贴在操作行右端」的用例（行为已不存在）。
  - `e2e/react/parity-agenda.spec.ts`：加一条 —— 「我的行程」场次卡的片名旁有 `豆瓣 ↗` 外链，
    href 指向豆瓣，且它是 `h3` 的**下一个兄弟**（在片名之后）；`/library` 的影片卡操作行**不再有**豆瓣外链。

**不做：**

- 不改 `/schedule` 的网格卡：那里没有「影片名行」这个位置（片名在网格块里），且用户指的是「我的行程」。
- 不改 `FilmDialog`（资料弹层）里的 `在豆瓣查看 / 中文搜索 / 英文搜索`：那是一组**显式中/英文搜索**
  的独立口径（用户可自选搜哪个名字），与「映射优先、否则搜索」的 `doubanUrlOf` 不是同一件事。
- 不改 `ScreeningInfoPopover` 的按钮形态（`在豆瓣打开` 已是圆角按钮，只换 URL 来源）。
- 不引入依赖、不动 `biff.*` 数据契约、无迁移。

## 方案取舍

| 备选 | 结论 | 理由 |
|---|---|---|
| 外链塞进 `<h3>` 内联 | 否决 | 标题 accessible name 被污染成「片名 豆瓣 ↗」，`exact` 断言与读屏都会变吵 |
| 外链作为 `h3` 的兄弟、独立一行 | 否决 | 多占一行、片名与入口被拆开，看不出「这行是这部片」 |
| 片名 + 外链同一行（`.screening-title` flex） | **采纳** | 入口紧贴片名、不额外占行、不改标题语义 |
| 做成圆角按钮（S2 `ActionButton` 形态） | 否决 | 卡片底部已有「资料 / 定位 / 移出行程」一排按钮，标题行再来一个按钮会喧宾夺主；且会丢掉 `<a href>` 语义（中键新窗口 / 复制链接） |
| 沿用卡片既有的跳转样式（品牌色 + `↗`） | **采纳** | 与本卡「在 Google 地图打开 ↗」同一种「外跳」视觉语言，用户已在同一张卡上学会它 |
| 影片卡操作行的豆瓣链接保留 | 否决 | 用户明确说「把那个豆瓣按钮放到…」，是**搬**不是**加**；留着会变成两处入口 |
| 每处各写一份 `douban.com/search?q=` | 否决 | 违反「同一口径只允许一处实现」；本轮已是第 4 处，必须收敛 |

## 验收标准

1. 「我的行程」每张场次卡：片名右侧出现 `豆瓣 ↗`，点击在新标签打开
   —— 有映射开条目页，无映射开豆瓣搜索（中文名优先，中文名空则英文名）。
2. 该外链是片名 `<h3>` 的**兄弟节点且在它之后**；`<h3>` 的文本仍是纯片名。
3. `/library` 与 `/picks` 的影片卡操作行**不再有**豆瓣外链（其余按钮位置不变）。
4. `/schedule` 网格卡与资料弹层行为不变。
5. `npm run verify:quick` 全绿；`parity-agenda` + `parity-library` 两个 spec（desktop-chromium）全绿。

## 备注

- `ScreeningCard` 只有「我的行程」（`RankGroup` 冲突组 + 按日列表）传 `showTitle`，
  影片库里的场次行是 `showTitle={false}` —— 所以这一处改动**只影响「我的行程」**，不需要新加开关。
- 无数据迁移。

## 修订 1（2026-09-13，用户看效果后）

**现象**：用户发来「我的选片」影片卡的截图问「为什么我没看到」。

**原因**：两件事叠在一起 ——
1. 上一版按「搬到我的行程」把影片卡操作行里的豆瓣外链**删掉了**；
2. 截图那部片的状态是「未排场」（没有已排场次），所以「我的行程」里根本没有它的场次卡，
   片名旁那个入口自然也不出现。

**结论**：用户要的是「**片名后面能直接点**」，而不是「只在某一个页面出现」。修订为：

- 影片卡（`/library` `/picks`）的**片名行**（`h2` 右侧）也加 `豆瓣 ↗`；
- 「我的行程」场次卡的片名行（`h3` 右侧）保留 —— 两处都是「片名 + 外跳」同一形态；
- 两处共用同一对类 `.title-row` / `.douban-jump`（原 `.screening-title` / `.screening-douban` 改名），
  链接仍一律走 `doubanUrlOf()`；
- 入口仍放在标题标签**之外**（`h2` / `h3` 的下一个兄弟），不动标题的可访问名。

**验收补充**：`parity-library` 加 1 条 —— 「我的选片」影片卡片名行有 `豆瓣 ↗`、`h2` 文本仍是纯片名、
底部操作行无外链；`parity-agenda` 的既有用例选择器随类名更新。
