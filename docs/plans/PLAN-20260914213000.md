# PLAN-20260914213000 — 「已保存方案」的「查看场次」改为弹层，信息与分享图片同源

## 目标

> 用户原话：「已保存方案 这里的 查看场次 目前只展示了时间和 CODE 请你参考生成图片部分的所展示的信息
> 然后点击查看场次后 弹出这个弹窗 看到自己的场次」

现状（代码事实）：`apps/web/src/pages/AgendaPage.tsx:474-477` 用 `<details>` 内联展开，
内容是 `describeSavedPlan().details` —— 每行只有「`HH:MM` · `CODE`」（`agenda-model.ts:62-65`）。
看不出是哪部片、在哪个影院、有没有映后谈。

期望：点「查看场次」**弹出弹窗**，弹层里一场一行，展示**分享图片已经定好的那套信息**。

## 范围

**做：**

1. 新增 `apps/web/src/components/PlanShowsDialog.tsx` —— `DialogTrigger`（按钮「查看场次」）+ `Dialog`，
   渲染数据来自 **`poster.ts::buildPosterModel`**（与分享图片同一份模型）。
2. `apps/web/src/pages/AgendaPage.tsx`：把 `.saved-plan` 里的 `<details>` 换成 `<PlanShowsDialog plan={plan} />`。
3. `apps/web/src/pages/agenda-parity.css`：删掉已无用的 `.saved-plan-details*`，加 `.plan-shows*`。
4. `e2e/react/parity-agenda.spec.ts`：把「saved snapshots…」用例从 `details p` 断言改为弹层断言。

**不做：**

- **不改 `buildPosterModel` / `poster.ts`**：它已经定义了「一场该展示什么」，本次只是多一个 DOM 出口。
- **不改 `describeSavedPlan`**：`outline` 仍是列表行的概要，`details` 仍是概要那行的 hover tooltip
  （用户抱怨的是「查看场次」展开的内容，不是 tooltip）。
- 不改 `apps/web/legacy/**`（只读回退件）。
- 不改分享文案 / `.ics` / 海报绘制本身，不引入依赖，不动 `biff.*` 数据契约（无迁移）。

## 方案取舍

| 备选 | 结论 | 理由 |
|---|---|---|
| 弹层复用 `buildPosterModel`（时间 / 片名 / 影院 / GV / 备注 / 海报缩略图） | **采纳** | 用户明确「参考生成图片部分所展示的信息」；口径单一来源，海报改了弹层自动跟 |
| 弹层里改用 `ScreeningCard` | 否决 | 那是**行程卡**（带「移出行程 / 定位 / 资料」等操作），弹层里是只读清单，会把操作按钮带进来 |
| 只把 `<details>` 内容换成多列文本 | 否决 | 用户要的是**弹窗**；纯文本仍然给不了海报缩略图 |
| 另写一套「时间 + 片名 + 影院」的取值链 | 否决 | 违反「口径单一来源」，且会与分享图片 / 分享文案各印一套 |
| 删掉 `describeSavedPlan().details`（连同其单测） | 否决 | 它与本次诉求无关，删它只是扩大改动面；tooltip 保留无害 |

## 验收标准

1. 「已保存方案」里点「查看场次」→ 弹出 `role=dialog`，标题 = 方案名；内容按日期分节，
   每场显示：起止时间（有效结束，含映后谈）/ 英文名 · 中文名 / 影院短名 · CODE / GV 标记 / 备注（有则显示）/ 海报缩略图。
2. 已不在排期的 code 在弹层里单独列出（`N 场已不在当前排期：…`），不静默消失。
3. 方案里**没有任何有效场次**时，弹层给「已不在当前排期」提示，而不是空白。
4. `npm run verify:ui -- parity-agenda --project=desktop-chromium` 全绿。
5. `npm test` 全绿（`poster.test.ts` / `agenda-parity.test.ts` 不回归）。
