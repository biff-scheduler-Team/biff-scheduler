# PLAN 2026-09-10 01:06:48 — GV 映后谈「两张拼接卡」:可单独放弃,转场按保留卡算

> 需求(用户原话):「GV 时长 我看你直接把时长做进去了 能不能用两张卡片拼接的方式来做这种交互呢 默认选中的时候就是两张卡片 有的人会放弃映后谈 然后转场时间也要按照用户选的单卡片来算 这样也是可以的交互」。
> AskUserQuestion 澄清:① 网格卡 + 行程行**都做**;② 记忆粒度 = **全局默认 + 单场覆盖**。
> 本文件 = 本需求唯一规划文档。

## 现状(代码/数据事实)

- schedule.json 9 场 GV(`is_gv:true`)的 `end_time` 均已把映后 +25min 直接算进槽位(如 003 正片 95min,槽位 14:10–16:10=120min;已脚本核对 9 场全部恰好 +25;非 GV 场差值 = 0)。
- `duration_min` 只存正片。冲突(`conflict.ts` slots)、网格紧转场(`markTightPairs`)、行程 gapNote、行程质量分(`scorePlanRows`)、抢票清单、.ics 导出**全部按 end_time(含谈)计算** —— 没有任何"放弃映后谈"的选项。
- `PlanEntry`(plan Map,key=code)与 `Settings`(本地)均无 talk 概念;云端 D1 `user_plan` 无此字段。

## 方案

### 语义(单一数据源,新 `src/gv.ts`)
- **映后谈时长按数据推导**(不新加字段):`gvTalkMin(s) = is_gv ? max(0, 槽位分钟 − duration_min) : 0`。真实排期若某场没把谈后含进 end_time → 自动 0 → 该场不拆、不显示开关,向前兼容。
- 有效结束:含谈 = `end_time`;放弃 = 正片结束(`start + duration`)。
- 每场三态覆写:`store.gvTalk: Map<code, boolean>`(undefined = 跟随全局),**本地 localStorage `biff.gvtalk.v1`** —— 与 Settings 同级(settings 本就不同步云端),避免动 D1 表 + 远程迁移 + functions 契约(评估过加列方案,收益低、需先迁移再发版,否决)。
- 全局默认:`Settings.gvTalkOn: boolean` 默认 **true(含映后)**;`loadSettings` 缺省合并保默认。

### 网格卡 = 正片卡 + 映后谈块(拼接),src/grid.ts
- GV 且 talk>0:主卡宽度缩到**正片段**;右缘紧贴追加一块独立 talk 块(绝对定位,同高同状态):`left = 卡左 + 正片宽`,块宽 = `talkMin × 2.2px`,视觉拼接。
- talk 块内容:两行小字「映后 +25′」/ 谈段时间;样式:细斜纹底 + 描边,未选中=中性、选中含谈=`in-plan` 同款优先级底色(两张卡一起选中)、**放弃后 = 虚线 + ✕ + 降透明度**(仍占槽位,表示"物理存在但我不到场")。
- 点击语义(事件委托,mian.ts,`[data-talk]` 分支优先于整卡):
  - 场次未在当前方案 → 直接加入(maybe 默认)+ 覆写 false = **一枪"只要正片"**;
  - 已在当前方案 → 翻转该场覆写(含↔放弃),**不删除场次**;
  - tooltip 随状态给出当前含义。
- `markTightPairs` 判定用**有效结束**(放弃谈的场按正片末算);卡与 talk 块同步淡底色 + data-tip。

### 行程行,src/agenda.ts
- 时间首行 bold 显示**有效区间**(含谈=slot end / 放弃=正片末);时长行 `95min` 旁追加说明。
- GV 行(谈>0)加一枚小开关胶囊(button,`data-act="gv-talk"`):「✓ 含映后25′」/「✕ 放弃映后谈」,翻转即重算。
- `gapNote` 上一场用**其有效结束**算间隔。
- 冲突行态/`slot-hit`/`hour-dim` 沿用,翻转后 renderAll 全量重算。

### 全局默认,src/main.ts 设置弹层
- 设置加一项「GV 场默认映后谈:参加 / 不参加(逐场可改)」→ `setSettings({gvTalkOn})`;hint 说明仅对未单设的场生效。

### 传导口径(全部吃"有效结束")
- `main.ts computeConflictsForCurrentGroup` slot.end = 有效结束(放弃谈 → 不再与后场冲突,即时消红)。
- `engine.ts scorePlanRows` 加可选 `endOf(s)` 参数(默认原逻辑=含谈,引擎自动排片不动,其保守解在放弃谈后只会更宽松,安全);行程侧实时分传有效结束。
- `ics.ts buildIcs` 加 `talkOf(code)` 参数:DTEND 用有效结束;描述动态:「正片95min+映后25min」/「95min 正片 · 已放弃映后谈」。
- 抢票顺位清单行内结束时间同口径,GV 标记 `(GV·含映后)` / `(GV·仅正片)`。

### 文案同步
- `badges.ts` gv title、`legend.ts` durChip tip 与总览/图例里「+25min 计入结束时间」类文案 → 改为「映后谈可在卡片/行程里单独放弃;放弃后该场按正片结束算转场」。

## 验收
1. 网格 GV 场两段拼接;点正片=整场选中(两张同 tint);点谈段=只加正片/翻转让弃;放弃的块虚线+✕。
2. 放弃后:该场与紧邻下一场的冲突/紧转场按正片末重算(如 003 放弃后 15:45 结束 → 与 005 16:30 不再冲突标红则消);行程行区间、gapNote、质量分、ics DTEND 同步。
3. 设置「默认不参加」后,新加 GV 场默认单卡;未单设的场跟随,已单设的场不跟随。
4. localStorage 刷新后偏好仍在(`biff.gvtalk.v1` / `biff.settings.v1`);云端 plan 不受影响。
5. `npm run typecheck` + `vite build` 通过;一次性 http.server + 无头截图自检(不起 dev server)。
6. 非 GV 场、talk=0 场完全无变化。
