# PLAN-20260928120415 — 红黑榜贴纸:带「撤销」的提示会自己消失

## 目标

用户原话:

> 都要 然后这个一直都不消失"《蓦然回首》的贴纸收回暂存区了。"

1. **「都要」** —— 收下上一轮列出的三个收敛项(鼠标 slop 4→8 / 暂存区按钮补 `movedRef` 守卫 /
   撤销提示 3s→5s)。
2. **bug** —— 带「撤销」按钮的那条提示**永不自动消失**,一直钉在屏幕底部。

## 现状(代码事实,非推测)

- `node_modules/@react-spectrum/s2/src/Toast.tsx:132-136`:
  ```ts
  // Minimum time of 5s from https://spectrum.adobe.com/page/toast/#Auto-dismissible
  // Actionable toasts cannot be auto dismissed. That would fail WCAG SC 2.2.1.
  let timeout =
    options.timeout && !options.actionLabel ? Math.max(options.timeout, 5000) : undefined;
  ```
  → 带 `actionLabel` 时 `timeout` **恒为 `undefined`**,`react-stately` 的 `ToastQueue.add`
  便不给内部 `Timer`(`useToastState.mjs:65`),队列永不自动关闭。
  **这是 S2 按无障碍规范(SC 2.2.1)做的选择**,不是它的 bug —— 是我们这层只兜了「不传
  `timeout`」,没兜「带 `actionLabel`」。
- 全仓带 `actionLabel` 的调用只有 **2 处**,都在 `RedBlackPage.tsx`(`:497` / `:577`),且都写了
  `timeout: 3000` —— 该字段在 action 场景被 S2 完全忽略,**写 3000 是误导**。
- `react-stately/dist/private/toast/useToastState.mjs:73-80`:`close(key)` 只在 `index >= 0`
  时动手 → 对已关闭 / 未知 key **幂等**,手动补定时器安全。
- ⚠ **`e2e/react/redblack.spec.ts` 在本轮期间处于他人的在途改动中**(新增 `quiet()`、
  `aboveGrid` 重写、`expect.poll(hitSelf)` 等「2026-09-28 CI 假红」修复,尚未提交)。
  按 §7,本轮**不动该文件**;我一度对它做过的所有改动**已全部撤净**(可核对:
  `git diff HEAD -- e2e/react/redblack.spec.ts | grep -c 20260928120415` 与
  `grep -c 暂存区按钮上拖一小段` 均为 `0`)。

## 方案取舍

| 备选 | 结论 | 理由 |
|---|---|---|
| 单击收回 → 双击收回 | 否决 | 判据问题在 `pointerdown→pointerup` 之间,与点几次无关;触发面更窄但误触方式更糟 |
| 干脆去掉 `actionLabel`(不给撤销) | 否决 | 收回是**丢信息**动作(位置一起丢),撤销出口有价值 |
| 在 `RedBlackPage` 两处调用点各写 `setTimeout(close, …)` | 否决 | 同一口径写两份;将来任何新增 action 提示都会复发同一个 bug |
| **在 `toast.ts` 统一补收口定时器** | 采纳 | 一处兜底,30+ 调用点零改动 |
| action 场景尊重调用方给的 `timeout` | 否决 | S2 在 action 场景**忽略**它,我们再尊重就等于「同一字段两套语义」;统一以 `DEFAULT_TOAST_TIMEOUT` 为准 |
| 鼠标阈值 4 → 8 | **采纳** | 4px 比系统双击容差还小,「点一下收回」的自然位移会先被判成拖。⚠ 附带风险已写进常量注释:再往上放宽要先改「跨片拖拽」那条 E2E(它的位移余量按 4px 设计) |
| 悬停暂停计时 | 不做 | 要复刻 S2 的 `Timer` 语义,收益低于复杂度 |

## 实测记录(2026-09-28,边做边证)

### ① 「撤销提示永不消失」—— 先红后绿成立

- **先红**(改 `toast.ts` 之前):新增用例失败,失败值 `expected +0 to be 1`(到点后 `close`
  从未被调用)。
- **后绿**(补收口定时器后):4 tests 全绿。

### ② 「暂存区按钮上拖一小段会误贴一枚」—— **实测未复现**,守卫降级为防御

原假设:`pointerup` 之后浏览器补发的那次 click 会打在按钮上,于是「拖了一小段」变成「贴一枚」。

实测(桌面 Chromium / 移动 Chromium / 移动 WebKit,三项目):把守卫摘掉(`detail` 恒传 0)
用例**仍然绿**;而且第一版用例的 `toHaveCount(0)` 是**即时**断言,会在「补发的 click 还没被
处理」时就成立(1.1s 就绿 —— 假绿)。补上「等过 1200ms 防抖上报窗口」+「断言写接口零调用」+
「阳性对照(同位置纯点击确实贴得出来)」之后,仍然绿。

结论:当前 `beginDrag::onMove` 越线那一刻的 `event.preventDefault()` 已经能压掉补发的 click。
`placeByTap` 因此**不是 bug 修复**,而是**不依赖那行副作用的保险**(① 补发 click 属各引擎
实现,跨引擎不该赌;② 谁删掉那行 `preventDefault`,行为靠它守住)。注释已按此口径写明。

> 顺带实测:`.rb-dot`(画布上那枚)那一侧摘掉守卫、跑既有用例
> 「拖一下微调位置不算单击」**也仍是绿的** —— 同一原因。该侧守卫(HEAD 已有)保持不动。

### ③ 阈值与「跨片拖拽」用例失败率的关系 —— **与本次改动无关**(对照组结论)

起因:跑红黑榜 spec 时撞上 `跨片拖拽:别片的张贴区一枚都不会多` 偶发失败(报「这张卡没亮」)。
用四格对照定位(每格 `--repeat-each=8`,桌面 Chromium):

| 组合 | 结果 |
|---|---|
| HEAD 用例 + HEAD 源码 | **8 / 8 绿** |
| 别人的在途用例 + HEAD 源码 | 4 / 8 失败 |
| 别人的在途用例 + 我的源码(阈值 4px) | 4 / 8 失败 |
| 别人的在途用例 + 我的源码(阈值 8px) | 4 / 8 失败 |

→ 后三格**完全一致**:失败由**他人在途的用例改动**引起(他们的 `quiet()` 会把手移到
`(2,2)` 再等提示条退场,而 S2 提示条进出场走 View Transitions,快照那几帧 `pointerdown`
会落在 `<html>` 上 —— 探针实测失败那一拍 `.rb-ghost` 数为 0,即手势压根没起),与阈值、
toast、`placeByTap` 都无关。

⚠ **过程中的一次误判**:我先只比了「HEAD 用例 + HEAD 源码」与「我的用例 + 我的源码」,
把 8/8 → 4/8 读成「阈值 4→8 是我的锅」,还据此把阈值回退到 4px;补上第 3、4 格对照后才
发现回退到 4px 同样 4/8 失败 —— 差的不是阈值,是那个文件里的他人在途改动。
**结论:阈值保持 8px。**

### ④ 由此产生的两条纪律(已写进注释,供后来人)

- `e2e/react/redblack.spec.ts` 的「跨片拖拽」用例,起手到第一个落点的位移 = 「贴纸位置 → 画布
  中心」,而贴纸是**随机落点** —— 再往上放宽阈值就有翻车风险,改阈值要连它一起改。
- 工作区多会话并行时,**动 E2E 之前先看 `git diff HEAD -- <spec>`**:那个文件可能正被别人改着。
