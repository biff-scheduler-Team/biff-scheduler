# PLAN-20260910121020 · 影片详情弹层「加入/移除」按钮点完没有反馈

## 1. 现象

影片详情弹层(网格卡 ⓘ / 影片库「详情 ⓘ」)里每场右侧的主操作按钮:

1. 点「加入 A 方案」→ **按钮自己一动不动**(文字、配色都没变),只有背后的网格/行程变了 → 像「点了没反应」;
2. 关掉重开详情,按钮已变成「已加入 · 点击移除」→ 再点它,同样一动不动(数据其实已经移除),仍「只有结果的变化」。

## 2. 根因

`src/modal.ts` 的 `showFilmModal()` 是**一次性渲染**:每行的按钮文案 + 变体类在渲染那一刻由
`ctx.slots.get(s.code)` 算出来,之后再也不更新。点击只做了一件事:

```ts
btn.addEventListener("click", () => ctx.toggle(filmNodeKey(...), code));
// ctx.toggle → toggleScreening → commit() → notify() → renderAll()
```

而 `renderAll()` 只重建 **chips / 网格 / 行程 / 角标**;弹层挂在 `#modal-root` 下,**不在任何重建范围内**
→ 按钮永远是开弹层那一刻的样子。

附带一个更隐蔽的坑:`FilmModalCtx.slots` 是**开弹层时捕获的 Map 引用**,而 `state.ts` 的
`rebuildIndex()` 是 `store.slotIndex = idx`(**整体换新 Map**,不是就地清空/填充)——
所以即便有人想「照着 ctx.slots 手动重绘」,读到的也是旧快照,照样画错。实时查询只能走 `slotOf(code)`。

## 3. 方案

`src/modal.ts`

- 新增 `actState(code, group)`:**按钮三态(文案 + 完整类名)的唯一来源**,初渲与点击后重绘共用一份口径。
  - 已加入当前方案 → 绿(与网格「已选」同一套语言:`border-ok` + `color-mix(ok 12%)` 浅绿底),
    **hover 转红**(`border-biff / bg-biff-soft / text-biff`)= 「点了就是移除」的意图预告;
  - 已在另一组 → 中性白底 + `text-ink-2`,hover 转红;
  - 未加入 → 红渐变主按钮,`hover:brightness-110`(原来是 1.05,几乎看不出);
  - 三态统一加 `transition-[…] duration-[120ms]` + `active:translate-y-px`(按下有位移回执)。
- `showFilmModal()`:行按钮改为先建后 `paintRows()` 上色;点击后 `paintRows()` + `wish.draw()`
  (刷新「已选 N 场」计数)+ 该行 `flash` 闪一下(复用既有 `biff-flash` 动画,做「点到了」的回执)。
- **删掉 `FilmModalCtx.slots`**:改为一律走 `slotOf(code)` 实时查询(避免上文的旧 Map 快照陷阱)。
- `buildWishRow()` 由「返回元素」改为「返回 `{ row, draw }`」,让外部能在场次增删后刷新计数文案。
- **顺手对齐一处「文案与行为不符」**:「已在另一组」原写「改入 A 方案」,但 `toggleScreening` 对
  已在该场的 code 是**移出**(一场只属于一个方案),点了并不会搬过去。重绘修好后按钮会当场翻成
  「加入 A 方案」,两步可见 → 文案改为「点击移出」并补 `title` 说明,不再许诺一步搬运。

`src/main.ts`

- `filmModalCtx()` 去掉 `slots: store.slotIndex`(接口已删该字段)。

## 4. 不改的东西

- 数据层(`store.picks` / `slotIndex` / `toggleScreening`)不碰 —— 本次纯粹是「弹层按钮没重绘」。
- 弹层结构 / 视觉骨架 / 场次行布局不动。
- 网格卡、行程行、影片库列表的重绘链路本来就正常,不动。

## 5. 验收

1. 详情弹层点「加入 A 方案」→ 按钮**立刻**变绿「已加入 · 点击移除」,该行闪一下,「已选 N 场」计数 +1。
2. 再点「已加入 · 点击移除」→ 立刻变回红渐变「加入 A 方案」,计数 −1。
3. 在 B 方案下打开同一部片(该场在 A)→ 按钮显示「已在 A 组 · **点击移出**」(文案已对齐真实语义:
   一场只属于一个方案,`toggleScreening` 对「已在另一组」是移出,不是搬运)→ 点它变「加入 B 方案」,
   再点一次才是改入 B(两步现在都看得见)。
4. hover 任一态都有明显变化(已加入态 hover 转红);按下有轻微位移。
5. `npm run typecheck` 通过;部署后线上重复 1~3。
