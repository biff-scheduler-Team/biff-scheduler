# PLAN 2026-09-10 16:51:47 — 「影片库」与「我的选片」合并为一个左右双栏弹窗(共用影片行组件)

> 需求(用户原话):「我的选片 里面影片的展示机制 图标化 等等 没有和影片库保持一致」;
> 追问后用户给出方案:「影片库和我的选片做成一个弹窗 左右两边是不是好点呢? 这样也能公用组件」。
> 本文件 = 本需求唯一规划文档。

## 1. 现状(代码事实,HEAD 443875f)

两个**独立弹窗**、两套**各自手写的影片行**,于是同一部片在两处长得完全不一样:

| 维度 | 影片库 `openLibrary` | 我的选片 `openMyPicks` |
|---|---|---|
| 头行首元素 | `▶` 折叠箭头(点击展开) | 只读「档位章」(实心色块) |
| 档位 | 行内三选 seg(`buildWishSeg`,可改档) | 无控件,只展示 |
| 头行徽章 | `N 场` + `A 已选 N` | `已排 N 场`/`未排场` + `可选 N 场`/`暂无排期` |
| 展开场次 | `n.shows` 全部场次 | 只列 `rec.picks`(已排场次) |
| 场次行 | `code` 章 + 日期时间 + **影院官方代码章** + 时长 + GV/等级/字幕/页码徽章 + `定位 ▸` + **加入/移出三态按钮** | `code` 章 + 方案章 + 日期时间 + 影院**短名文本** + `定位 ▸`(无代码章/时长/徽章/加入按钮) |
| 行尾 | `资料 ⓘ` | `资料 ⓘ` + `✕ 整片移除` |

根因:`library.ts` 里 `openLibrary` 与 `openMyPicks` 各写了一份行构造(`head` / `ops` / 场次行),
`buildFilmList` 虽然同源,但**渲染层没有收口**,于是「图标化」在两条分支上各走各的。

## 2. 设计决策

1. **合并为一个弹窗,左右双栏**(用户指定):
   - 标题「影片库 · 我的选片」,宽度新增 `xl`(1280px);
   - 左栏 = 影片库(`flex-1`,搜索 + 单元 chips + 计数 + 列表);右栏 = 我的选片(固定 480px,计数 + 档位 chips + 列表);
   - 窄屏(< 1100px)自动上下堆叠,各自保留滚动容器;
   - 宽度定死的依据:**两栏都要放得下「场次行」那套完整徽章行** —— `176px 时间列 + 影院代码章 + 时长 +
     特性徽章 + 定位 ▸ + 三态按钮` 的最小宽度约 440px,480px 右栏 + 左栏最窄 536px 都在安全区。
2. **渲染层收口 —— 一份 `filmRow()` + 一份 `showRow()`**,两个面板共用:
   - 头行统一:`▶` 折叠箭头 + 片名/豆瓣章/原始片名/单元信息 + `[档位三选 seg][场次徽章][已排徽章][资料 ⓘ]`;
   - 场次行统一:影片库那套完整版(`code` 章 + 日期时间 + 影院官方代码章 + 时长 + 特性徽章 + `定位 ▸` + 加入/移出三态按钮);
   - 「我的选片」只多一枚 `✕ 移除` 按钮,不再有第二套行结构。
3. **档位控件统一为三选 seg** —— 删掉「我的选片」的只读档位章(seg 的 on 态本身就是档位指示,
   且顺带补上「在选片面板里直接改档」的能力,与 `pick.ts` 的「三选唯一语义」对齐)。
4. **徽章口径统一**:`N 场`(已发布场次数,无则「暂无排期」)+ `已排 N 场`(A+B 合计投影,> 0 才显示);
   「我的选片」面板在 `已排 0` 时补一枚 `未排场`(该片是选片但还没落场)。旧 `A 已选 N` 由 `已排 N 场`
   取代(A/B 细分已在展开后的三态按钮上逐场给出,不再重复)。
5. **展开态各自独立**:左栏默认全折叠(250 部,全展开不可用);右栏默认展开(选片通常 < 30 部,
   展开才看得到「已排场次」这一核心信息)。机制(箭头 + 点击)完全一致。
6. **场次口径**:「我的选片」面板展开仍**只列已排场次**(用户确认),不列全部可选场次。
7. **入口按钮不动**:顶栏「影片库」/「我的选片」两个按钮都开这**同一个**弹窗(保留 `#my-picks-count` 角标)。

## 4. 边界与风险

- **Tailwind v4 只生成源码里完整出现的字面量类**:新增 `w-[1280px]` / `min-[1100px]:` / `max-[1099px]:` /
  `min-w-[150px]` / `content-start` 等均为字面量,构建后 `grep` 产物 CSS 核对命中。
- **弹层内改状态必须就地重绘**(CONVENTIONS §二):三选 / 加入移出 / 整片移除 / 展开折叠全部走
  本弹窗自己的 `render()`,并保存-恢复**两个**滚动容器的 `scrollTop`。
- **弹层栈安全**:`openEngineDialog(..., fromLibrary = true)` —— 无片单模式里的「← 返回影片库打标」
  只 `closeModal()`,不再叠第二层。
- **单一数据源不变**:本需求只动渲染层,`store.picks` / `slotIndex` / `setWish` / `toggleScreening` /
  `removePick` 一行不改。

## 5. 验收标准

1. `npm run typecheck` + `npm run build` 通过。
2. 顶栏「影片库」「我的选片」任一入口 → 同一个左右双栏弹窗。
3. 同一部片在两个面板里:头行结构、折叠箭头、三选 seg、场次行(影院代码章 / 时长 / 特性徽章 /
   定位 ▸ / 加入按钮)完全一致;「我的选片」面板仅多一枚 `✕ 移除`。
4. 在「我的选片」面板改档位 → 左栏同行 seg 与甘特色点同步(同一份 `picks`)。
5. 在任一面板展开行、点「加入/移出」→ 两栏计数与按钮态同步,滚动位置不跳回顶部。
6. 窄屏(≈ 800px)双栏自动堆叠,不溢出。
