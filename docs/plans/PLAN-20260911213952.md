# PLAN 2026-09-11 21:39:52 — 日期口径统一为 OCT 写法 + 「我的选片」日期筛选支持多选

> 需求(用户原话)：「时间表示不统一 改成 OCT 这种 和甘特用一样的 然后选片中日期可以多选」。

## 1. 问题

**① 日期写法两套并存**:同一屏里「甘特图日期条」印 `OCT 8`(官方 Schedule by Date 写法),
而网格标题 / 选片日期筛选 / 行程日期头 / 分享文案仍印 `10/8 周四` 这类数字写法 —— 同一天两种表达。

**② 选片日期筛选是单选**:`library.ts` 的 `dateFilter: string | null` 一次只能看一天,
而看片行程天然是「挑几天集中排」,单选逼用户一天一天切。

## 2. 改动

### 2.1 日期口径统一(单一来源 `util.ts::dateInfo`)

| 位置 | 改动 |
|---|---|
| `util.ts::dateInfo` | 删掉并存的 `en` 字段;**`label` 直接改为 OCT 写法**(`OCT 8`,日不补零),与官方排期页一致;`weekday` 不变(中文星期作为附带信息,不参与日期写法) |
| `main.ts::renderChips` | 顶栏日期条由 `en` 改取 `label`(值不变,只是字段收口) |
| 其余全部调用点 | `agenda.ts` / `library.ts`(节头 + 日期 chips)/ `main.ts`(网格标题)/ `row.ts` / `share.ts` **无需改代码** —— 它们本就取 `label`/`weekday`,口径随单源一起变成 `OCT 8 周四` |

> 关键取舍:`dateInfo` 只留**一个**日期字符串字段。留两个(`label` 数字 + `en` OCT)正是「两套写法」的病根,
> 删掉 `en` 后类型层面就不可能出现第二种写法。

### 2.2 选片日期多选(`library.ts`,单文件)

| 位置 | 改动 |
|---|---|
| 状态 | `let dateFilter: string \| null` → `const dateSel = new Set<string>()`(**空集 = 全部日期**) |
| `showsInPicks` / `paintPick` 影片过滤 | `dateSel.size === 0 \|\| dateSel.has(s.date)` / `.some((s) => dateSel.has(s.date))` |
| 日期 chips 渲染 | 「全部 N 天」= 空集时高亮;每天 chip 按 `dateSel.has(d)` 高亮;tooltip 分「已选 → 再点取消该天」/「未选 → 加上该天的场次(可多选)」 |
| chips 点击 | 空串(「全部」)= `clear()`;已选天 = `delete`(其余天保留);未选天 = `add`(累加) |
| 失效日期剔除 | 已选日期不再有任何**可选**场次(选片移除 / 换档)→ 从集合里 `delete`,避免「筛了却是空列表」 |
| `goPickShows` | 跳转前 `dateSel.clear()`(原 `dateFilter = null`) |

## 3. 不做的事

* 不动**顶栏日期条**(甘特图日期条)的交互 —— 它仍是「切到某一天」的单选导航,与选片 tab 的**筛选**语义不同。
* 不动 `.ics` / 分享文案的**时间**口径(仍是 `HH:MM`,24+ 时制),本次只改**日期**写法。
* 不引入「日期区间选择器」—— 多选 chips 已覆盖「挑几天」的用法,再加控件是过度设计。
