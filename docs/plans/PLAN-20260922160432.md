# PLAN-20260922160432 — 红黑榜：刚贴的那一枚闪一下；单击就收回

## 目标

用户 2026-09-22 提出的两条交互：

> 在贴贴纸动作没有完成的时候 自己的那一张贴纸高亮 边缘闪烁 贴完后再渲染和别的贴纸一样的样式 ，
> 以及重贴的时候(直接收回贴纸)你觉得这样的交互怎么样

以及随后的拍板：

> 1 和 2 都做 1 可以推翻自己三小时之前的决定 做完渲染我看看效果

**读法（我按这个理解实现的，若与你的本意不符请纠正）**：① 指**贴下去的那一刻**——那枚贴纸先闪一下，
让用户知道它落在哪;「贴完之后」与别人的贴纸**逐字一致**;② 指**单击已贴的那一枚即收回暂存区**。

## 范围

**做：**

1. **刚贴下的那一枚闪描边**（`RedBlackPage.tsx` 的 `freshKey` + `RbCard` 的动效）：
   `data-rb-fresh` 挂 `FRESH_MS = 2400`（= 3 × 800ms）后连描边一起撤掉，之后与别人的完全一致；
   WAAPI 只闪**描边**、`prefers-reduced-motion` 下退化成静态描边。
2. **单击我贴的那一枚 → 收回暂存区**：与「拖出画布」共用 `takeBack()`（文案与落库口径只此一处）；
   收回后暂存区按钮重新可用，并向上报一份「整份替换」的空表。
3. **顺手补上 a11y**：那枚贴纸从 `<span role="img">` 改成 `<button type="button">` ——
   它现在可单击，把点击处理挂在非交互语义上本来就是缺陷；顺带让键盘也能收回。
4. **拖拽与单击的区分**：`pointerup` 之后浏览器还会补发一次 `click`，不做区分的话「微调位置」会变成「撤销」。
   用 `movedRef`（`pointermove` 越过阈值即置位、下一次 `pointerdown` 复位）把它吃掉；
   阈值按指针类型分档（鼠标 4px / 触屏 10px）——手指抖得多，4px 在触屏上几乎必然越过。
5. **订正两处过期注释**：文件头「一部片红 / 黑**各一枚**（同框双色并存）」早与 `MAX_PER_FILM = 1` 矛盾；
   「**单击**就取下」是设计意图但**从未实现**——这一轮把它实现了。

**不做：**

- **不动「贴纸完全拉平」的外形口径**：形状 / 尺寸 / 实心度一字未改。本轮推翻的只是
  「**不加任何『这枚是你的』的视觉标识**」里 **常驻** 那一半——闪一下是**反馈**，不是身份，
  而且**有界**（2.4s 后连描边一起去掉，不做 infinite）。
- **不动 canvas 层与渲染口径**（`PLAN-20260922145815` 的成果）：闪的是 DOM 上那一枚，
  群点是画出来的像素、没有元素，本来也动不了；不做无限动画（那会一直占着合成层持续重绘）。
- **不动 `biff.redblack.*` 契约与拖拽逻辑**（只在「算不算点」上加了一个阈值分档）。
- **不给「待贴」状态加动效**：暂存区按钮的亮 / 淡已经在表达它（2026-09-16 用户「太占空间」）。
  若做，也只能给**刚标记过的那一张**，不能按 `canPlace` 状态驱动——否则连着标记十部会十张卡一起闪。

## 方案取舍

| 备选 | 结论 | 理由 |
|---|---|---|
| 「边缘**闪烁**」做成 infinite 循环 | 否决 | 无限动画会让元素持续占着合成层、持续重绘，正好抵消同一天刚省下来的渲染；而且闪烁对动效敏感人群不友好 |
| 一次性 3×800ms 描边明暗（照 `ScheduleGantt::flashScreenings` 的既有手法） | **采纳** | 有界、只动描边不动 opacity / 尺寸；与「上报防抖 1200ms + 一次重拉」同拍 |
| 闪 body（opacity / 缩放） | 否决 | 会让人读成「这枚贴纸自己在闪」而不是「它被放到了这里」（仓库既有注释里踩过同一个坑） |
| 常驻给「我贴的那一枚」一个标识 | 否决 | 与本轮「贴完即与别人一致」冲突，且用户要的是「知道它落在哪」这一次性需求 |
| 单击收回（用户口径，也是文件头早写下的） | **采纳** | 最短路径；原来只有「拖出画布」这条相当隐蔽的手势 |
| 单击收回前先弹确认 | 否决 | 收回是**可逆**的（再点红 / 黑就回来）；仓库给「点掉一场」上确认弹层是因为那一下**不可逆**。这里改用 toast 交代 |
| 用 `<span role="img">` + onClick | 否决 | 非交互语义上挂点击是 a11y 缺陷；改 `<button>` 顺带把键盘收回也给了 |
| 拖拽阈值一律 4px | 否决 | 触屏上手指抖一下就越过，于是「想单击收回」会变成「挪了个位置」 |

## 验收标准

1. 贴下一枚 → 那枚有 `data-rb-fresh`、描边为实线；**2.4s 后描边消失、与别人的贴纸完全一致**（不是常驻标识）。
2. 单击那枚贴纸 → 收回到暂存区（画布空、提示文字回来、暂存区按钮重新亮起），
   且上报变成**整份替换的空表**（服务端不再替我留着那一票）。
3. **拖一下（10px，松手点仍在这枚贴纸上）不会被顺手收走** —— 这是本轮引入的主要风险，
   必须有能变红的断言守着（已实测：去掉 `movedRef` 守护后该断言红）。
4. `prefers-reduced-motion: reduce` 下不做明暗起伏，只留静态描边。
5. 收口命令：`npm run verify:quick` + `npx playwright test -c playwright.react.config.ts e2e/react/redblack.spec.ts e2e/react/smoke.spec.ts` 全绿。
