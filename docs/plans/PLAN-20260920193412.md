# PLAN-20260920193412 — 图表的解释性文案收进右上角 ⓘ

## 目标

用户原话：

> 太多解释性文案了 全部放到图的右上角的 tooltip 里面吧 比如这种"无评分的片子单列一档 —— 不是 0 分。"

把**每张图下面那行口径小字**（`ChartFrame` 的 `footnote`）从可见文案改成**图表右上角一个 ⓘ**，
点开才显示 —— 图自己能说话，解释按需再取。

## 范围

**做：**

- `ChartFrame`：`footnote` 从「画布下方的 `figcaption`」改为「画布右上角的 `<details>` 气泡」。
  用原生 `<details>` 而不是纯 CSS `:hover`：这一页是**现场手机在看**，点击是手机上唯一可靠的打开方式，
  而 `<details>` 天然带键盘可达与 toggle 语义，不需要自造弹层。
- `rush-analysis.css`：`.ra-chart-canvas` 加 `position: relative` 作为定位锚；`.ra-chart-note` 换成
  `.ra-note` / `.ra-note-body`（颜色全部走既有 token，不新增视觉语言）。
- 「还没有人贴过红黑榜」这一条**不进 ⓘ**：它是**状态**不是口径解释，藏起来会让人以为图坏了 ——
  改为在红黑票那一格渲染可见空态文案（原先是画一张空环 + 图注）。
- E2E：`rush-analysis.spec.ts` 里「『类型暂缺』必须写在页面上」这条断言改为**先点开 ⓘ 再断言**；
  另新增一条回归断言：**图注默认不可见、点 ⓘ 后可见**（本次改动的守门人）。

**不做：**

- **不动 `ra-hint`**（每组标题下那句）：它们多数带**数字或状态**（「我排进行程的 12 部片 / 40 场」、
  「本届 327 部片目的构成」），是这组的结论摘要而不是口径解释；用户给的反例也全部来自图注。
  若这些也要一并收走，说一声即可（那是另一件事：它们不属于任何一张图）。
- 不改任何统计口径、图表形态、数据契约。
- 不删本轮发现的**死代码** `RushPortraitSection.tsx` / `RushCrowdSection.tsx`（第 4 轮精简后已无人引用，
  全仓只有它们自己出现）。它们是另一件事，单独提出来确认再删。

## 方案取舍

| 备选 | 结论 | 理由 |
|---|---|---|
| 保留 `<figcaption>`、只把文字缩短 | 否决 | 用户要的是「不占版面」，缩短仍占一行 |
| 纯 CSS `:hover` 气泡（不点击） | 否决 | 手机没有 hover；这一页的主要读者在现场用手机 |
| 自写 `<button>` + React `open` state | 否决 | 为一个说明气泡引入状态与「点外面关闭」的收尾逻辑，而 `<details>` 原生就给全了 |
| Spectrum S2 `Tooltip` | 否决 | 触屏上同样不可靠；且内容懒渲染，E2E 断言不到 |
| **原生 `<details>` 放画布右上角** | **采纳** | 点击 / 键盘都可达，内容在 DOM 里（可断言），零新增依赖与状态 |
| 空态图注也一起收进 ⓘ | 否决 | 状态提示藏起来 = 让人以为图坏了 |

## 验收标准

1. 分析页每张图下方**不再有可见的口径小字**；图右上角有一个 ⓘ，点开显示原来的那段说明。
2. 红黑票没有票时给出**可见**的空态文案（不是一张空环 + 藏起来的说明）。
3. E2E：`rush-analysis.spec.ts` 全绿，其中「点 ⓘ 才看到说明」是新加的那条。
4. `npm run typecheck` 通过；`check:repo` / `check:test-map` 通过。
5. 回写文档：本 PLAN；`PLAN.md` 文档头一行「最后更新」。
