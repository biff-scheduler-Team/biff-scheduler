# PLAN-20260928101634 — 管理后台：权限探测不再打断操作 + 数据体检从概览里拆出来

## 目标

用户 2026-09-28 原话：

> admin 页面总是一下在刷新确认权限 每次一刷新 这个过程 中就无法操作
> 第二点 就是数据体检（聚合对账） 太长了 请你想办法解决下

拆成两件事：

1. **「一直在刷新确认权限、那期间不能操作」** —— 复现出来的机制是：
   `account-sync` 每 20s（外加 `focus` / `online`）跑一次 `syncAccount()`，
   它每轮都会 `setStatus("syncing")` → `emit()` → `AdminPage` 的 `onAccountChange` 监听 → `probe()`；
   而 `probe()` 一进来就 `setGate("loading")` —— **整屏（规模图、数据总览表、明细分页、滚动位置）
   被拆掉重新挂载**。用户看到的就是「每 20 秒回到『正在确认权限…』，这中间点什么都白点」。
   ⚠ 权限是**主体**的函数：白名单在服务端写死（`admin.ts::ADMIN_SUBJECTS`），
   同一个主体 20 秒内反复问，答案不会变 —— 这些请求 100% 是浪费，代价却是打断操作。

2. **「数据体检（聚合对账）太长」** —— 对账挂在 `GET /api/admin/overview` 的 `Promise.all` 里
   （`admin-read.ts:251`），而它要对五张贡献表各做一次**全表 GROUP BY**（`stat-audit.ts`，10 条查询）。
   于是整屏（规模 / 数据总览 / 账号与内容）都被这一项拖住 —— 最慢的那一步决定了整页能不能看。

## 范围

**做:**

1. **`apps/web/src/pages/AdminPage.tsx` — 权限探测去抖 + 不再拆屏**
   - `onAccountChange` 回调里**按身份判重**：`accountState.account?.user.id ?? "guest"` 没变就直接返回
     （例行 `syncing`/`synced` 不再触发探测）；变了（刚登录 / 刚登出）仍然立刻重探。
   - `probe()` **不再把 gate 打回 `loading`**：首屏之外的探测是静默的，用按钮文案
     （「正在确认…」）表达进行中，而不是把内容换成一个 loading 段落。
2. **`apps/api/src/admin-read.ts` — 概览不再包含对账**：`AdminOverview` 去掉 `audit` 字段与
   `Promise.all` 里那一项（`stat-audit.ts` 的算法**一字不动**）。
3. **`apps/api/src/index.ts` — 新增 `GET /api/admin/audit`**：直接把 `auditContributions()` 的结果回出去。
   它天然继承 `/api/admin/*` 的两层门禁（`requireIdentity` + 名单）。
4. **`apps/web/src/admin-api.ts`** — `AdminOverview` 去掉 `audit`；新增 `loadAdminAudit()`。
5. **`apps/web/src/pages/AdminPage.tsx` — 体检变成独立的 `AdminAuditPanel`**：
   自己的加载态 / 失败态 / 「重新体检」按钮；结果在**本次会话内缓存**（切 tab 回来不重跑全表扫描），
   并显示上次体检时间。
6. **测试**：
   - `apps/api/tests/admin-read.test.ts`：加上「概览响应里**没有** `audit`」这条契约断言；
     原有的对账断言本就与 `stat-audit.test.ts` 重复，删掉重复的那条。
   - `apps/api/tests/admin-audit-route.test.ts`（新）：`/api/admin/audit` 的 HTTP 边界 ——
     未登录 401 / 非管理员 403 / 管理员 200 且能报出人为漂移（**新路由没绕过门禁**）。
   - `e2e/react/admin.spec.ts`：① 概览与体检分开 stub；② ★ 体检请求**挂住不返回**时，
     概览的「数据总览」与「账号与内容」照样渲染（这就是「太长了」的回归测试）；
     ③ ★ 派发一次 `focus`（=`account-sync` 例行同步的真实触发路径）后，`/api/admin/whoami`
     **仍是 1 次**、且页面**不再出现**「正在确认权限…」。

**不做:**

- ❌ 不改对账算法（`stat-audit.ts`）—— 它要报的是真值，慢是它的成本，不是它的 bug。
- ❌ 不做服务端缓存 / 定时预计算：Workers 无状态，要落 KV 或 D1 表，为一个月度体检引入一套
  存储 + 失效口径，成本远大于收益（且「结果多旧」这件事会变得没人说得清）。
- ❌ 不动 `account-sync.ts` 的 20s 例行同步 —— 那是片单同步要用的，问题在管理页**被它牵动**。
- ❌ 不改 `probeAdmin()` 的三态语义与门禁（服务端仍是唯一安全边界，前端不抄白名单）。
- ❌ 不改 `biff.*` 数据结构、不动在途改动（`AGENTS.md`、`apps/web/vite.config.ts`、
  `docs/DEVELOPMENT-STANDARDS.md`、`apps/web/mock/`、`apps/web/public/mock-redblack.html` 只用不改、不提交）。

## 方案取舍

| 备选 | 结论 | 理由 |
|---|---|---|
| 权限探测改「只在身份变了才问」 | **采纳** | 权限是主体的函数（白名单静态），主体不变答案不变 —— 例行同步触发的那次必然是浪费 |
| 探测期间用 `loading` 遮罩但保留 DOM（`aria-busy` + 覆盖层） | 否决 | 遮罩同样让人「点不了」，只是把「不能操作」画得更明显；真正该做的是**根本不要重探** |
| 每次探测都静默、完全不显示进行中 | 否决 | 手动「重新确认 / 重试」按钮需要反馈，否则点了没反应像坏了（按钮文案承担它） |
| 对账留在 `/overview`，只是前端延后渲染 | 否决 | 慢的是**服务端那条查询**：它会占住整个 `Promise.all`，前端怎么渲染都还是要等 |
| 对账拆成 `/api/admin/audit` | **采纳** | 概览（轻查询）先出来，体检自己转自己的；两条路径各回各的形状，前端不再耦合 |
| 服务端缓存对账结果（KV / D1 表 + TTL） | 否决 | 多一套存储与失效口径，且「缓存多旧」要额外解释；管理端低频，收益不抵复杂度 |
| 前端会话内缓存体检结果 | **采纳** | 切 tab 会重新挂载组件 —— 不缓存等于每次重进概览都重跑一次全表扫描（「太长了」原样复发） |
| 体检改成「必须手动点开始」 | 否决 | 体检的意义就是**不用人想起它**；改成手动会让它变成永远不会被看的一屏（自动跑 + 独立加载已够） |

## 验收标准

1. `GET /api/admin/overview` 的响应**不含** `audit`（单测断言 + 路由测试）。
2. `GET /api/admin/audit`：未登录 401、非管理员 403、管理员 200 且能报出人为制造的漂移。
3. E2E：体检接口**永不返回**时，概览的「数据总览」「账号与内容」仍然渲染，
   页面不出现「概览加载失败」；体检面板自己是「正在体检…」。
4. E2E：概览渲染后派发一次 `focus`，`/api/admin/whoami` 请求数**保持 1**，
   且全页不出现「正在确认权限…」；「数据总览」标题始终在（没被拆屏）。
5. 收口命令：`npm run verify:quick` 全绿；
   `npx playwright test -c playwright.react.config.ts e2e/react/admin.spec.ts --project=desktop-chromium` 全绿。

## 修订记录

- 2026-09-28 修订 1（code review）：`main.tsx` 用 `<StrictMode>`，dev 下 effect 跑两次 ——
  体检是整页最贵的请求，会**并发跑两遍全表扫描**，正好抵消这一轮要修的东西。补在途请求合并

  身份不变就不再自动重探 → 名单变更不会自己反映到已打开的页面（门禁在服务端，不是安全口子）。
