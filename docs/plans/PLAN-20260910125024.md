# PLAN-20260910125024 · 影厅行标签截断 → 引入 `short` 短名

## 1. 需求

「电影院名字 B1 B2 B3 全部显示成 Busan Cinema ....」—— 甘特图粘性影厅列（`grid.ts`）里
B1 / B2 / B3 三行标签看起来一模一样。

## 2. 根因

不是数据问题（`venues.json` 里三个厅名字各不相同），是**渲染层的截断**：

| 项 | 值 |
|---|---|
| 影厅列宽 `LABEL_W` | 148px |
| 内边距 | `px-[10px]` × 2 = 20px |
| 官方代码 chip（`B1`） | ≈ 21px |
| 行内 gap | 5px |
| **留给名字的宽度** | **≈ 102px** |
| `Busan Cinema Center Cinema 1` @12px semibold | ≈ 178px → **必被截断** |

且名字的**区分性字词全在末尾**（`… Cinema 1` / `… Cinema 2` / `… Cinematheque`），
`truncate` 从左往右裁，于是三家 BCC 影厅（b1/b2/b3/bd/bh/bt）在列里全成了
`Busan Cinema …`；CGV 7 厅（`CGV Centum City 1..7`）、LOTTE 8 厅、MEGABOX 4 厅同理。

## 3. 设计决策

| 项 | 决策 | 理由 |
|---|---|---|
| 载体 | `venues.json` 每厅加 `short` 字段（数据驱动，不在前端做字符串裁剪） | 换年份只需改数据；前端做「掐前缀」在 2026 新增影院时必然漏 |
| 命名法 | `<影院品牌> <厅名>`，**去掉与品牌重复的城市词**（`CGV 1` / `LOTTE 10` / `MEGABOX 1`） | 城市词在品牌里已隐含（CGV = Centum City、MEGABOX = Busan），去掉无损信息；不这么压最长一条 107px 放不下 |
| 长度预算 | 实测 ≤ 98px（12px semibold，Chromium + 本机字体栈） | 见 §7 实测：29 条全部零截断 |
| 不动的 | `LABEL_W` 148px / 字号 12px / `truncate` | 改列宽会挤压时间轴，且并行会话的缩放锚点换算依赖 `LABEL_W`（`ROW_BASE_CLS` 里还有一份硬编码 148px 必须同值） |
| 全名去哪 | tooltip（`venueTip`）+ ⓘ 说明弹层 + ICS `LOCATION` | 详情层给全名，紧凑层给短名 |
| 单一来源 | `tools/extract_schedule.py::VENUE_NAME` 加第 5 元素 `short` | 否则下次重跑 PDF 管线会把 `short` 冲掉 |

## 4. 改动清单

### `tools/extract_schedule.py`
- `VENUE_NAME` 值类型 `tuple[str,str,str,str]` → `tuple[str,str,str,str,str]`（追加 `short`）；
  29 条全部补齐。`build_venues()` 解包 5 元组 + 写出 `"short"`。
- `extract_schedule.py:495` 的 `venue_display` 仍取 `[0]`（全名），**不变**。

### `public/venues.json`
- 29 个厅逐个补 `"short"`（与 `VENUE_NAME` 同值）。

### `src/types.ts`
- `Venue` 加 `short?: string`（可选 → 旧 JSON / 手工数据仍合法，取用点一律带全名兜底）。

### `src/legend.ts`
- 新增 `venueShort(v: Venue): string` —— `v.short ?? v.name`，唯一取用口。
- 文件头注释第 4 行「场馆行只显示英文全名」→ 改为短名/全名分层口径。
- ⓘ 说明弹层「影院与官方代码」表：`影厅(本工具行标签)` 列改为
  **短名（粗）+ 全名 · 韩名（次级灰）**，让用户能把列里看到的短名对回官方全名。

### `src/grid.ts`
- 场馆行标签 `venue.name` → `venueShort(venue)`（`dataset.tip` 仍走 `venueTip` 全名）。

### `src/library.ts`
- `enginePickRow()`（`:728`）与选片总览场次行（`:964`）两处 `truncate` 的
  `s.venue_display` → `ctx.cat.venueById.get(s.venue_id)?.short ?? s.venue_display`。

### `docs/CONVENTIONS.md`
- §三 venue 条补一句 `short` 契约（取用口 / 兜底 / 全名去向）。

## 7. 实现纪要（2026-09-10 12:5x）

**第一版命名法被实测否掉了。** 先按「缩写品牌 + 全厅名」（`BCC Cinematheque` / `CGV Centum IMAX` /
`MEGABOX Busan 1` / `LOTTE Centum 10`）落数据，然后用 playwright-core + 本机缓存 Chromium
**复刻 LABEL_BOX 结构做无服务器量测**（`setContent` + `clientWidth` vs `scrollWidth`，不依赖 dev server）：

```
✗ 截断  CX  CGV Centum IMAX   可用 101px / 需要 107px  超 6.0px
✗ 截断  L10 LOTTE Centum 10   可用  98px / 需要 101px  超 3.0px
✗ 截断  M1  MEGABOX Busan 1   可用 101px / 需要 107px  超 6.0px   ← M2/M3/M4 同样，四行又会糊成一串
```

关键发现：**可用宽度不是固定的 102px，而是随代码 chip 宽度浮动**（2 字符码 `B1`/`M1` ≈ 101~103px，
3 字符码 `L10`/`BCM` ≈ 98px），且 chip 越宽留给名字的越少 —— 光靠「≤16 字符」的经验值不够，必须实测。

改「品牌 + 厅号」（去掉与品牌重复的城市词）后：**29 条全部通过，0 截断**，最长 `BCC BIFF Theatre` 98px / 可用 101px。
`B3` 因 `Cinematheque`（103px，恰好等于可用宽度、零余量）改为 `Cinematek`（시네마테크 的常用罗马字）。

**副作用自查**：城市词去掉后信息是否丢？不丢 —— 品牌已隐含城市（CGV = Centum City、MEGABOX = Busan），
且行按分区聚合、代码前缀（C/L/M）同义；全名在行 hover tooltip 与 ⓘ 弹层「代码 → 行标签 → 官方全名」表里可溯源。

**验证**：`npm run typecheck` 通过（含并行会话在途的缩放改动）；`public/venues.json` 29 条 short 去重后仍 29 条。
