# PLAN-20260920204603 — 修掉 CI 上 3 个稳定红：活动场次日期写法漂移没跟着改 E2E

## 目标

CI（main push，`b40baab`）E2E 报 `3 failed / 2 flaky / 415 passed`，3 个红**同一个用例、三个浏览器全红**：

> `[desktop-chromium] / [mobile-chromium] / [mobile-webkit] › e2e/react/review-library.spec.ts:4:1 › screening detail links retain the exact show through refresh`
> `Expected substring: "October 7 (Wed) After the 19:00 Screening"`

本地复现（`npx playwright test -c playwright.react.config.ts e2e/react/review-library.spec.ts --project=desktop-chromium`）确认失败点是 **:21**：

- 期望 `October 7 (Wed) After the 19:00 Screening`
- 实际 `官网原文：Oct 7 (Wed) After the 19:00 Screening`
  （`apps/web/public/festival-extras.json:237` 的 `dateText` 已是 `"Oct 7 (Wed) ..."`）

即**数据先漂移、E2E 的字面期望没跟着改**；单测 `apps/web/tests/film-details.test.ts:38` 早已按新写法
（`"Oct 7 (Wed) After the 19:00 Screening"`）钉住同一口径，只有这条 E2E 漏了。
这条红已被 `PLAN-20260920161837` 的「修订 4」记为既有红、「另行处理」——本 PLAN 就是那次另行处理。

## 范围

**做：**

- 把 `e2e/react/review-library.spec.ts:21` 的字面期望对齐已发货数据（`Oct 7 (Wed) ...`），
  并加一行注释说明它与会漂移的来源（同 `film-details.test.ts` 同一处口径）。
- 本地把该 spec 在 **desktop-chromium / mobile-chromium / mobile-webkit** 三个 project 上跑绿。

**不做：**

- 不改 `festival-extras.json`（数据是对的，官网当天就写 `Oct 7`），也不改 `FilmDialog.tsx` 的渲染。
- 不改 `:24`（mobile-webkit）与 `redblack.spec.ts:54` 两条 **flaky** —— CI 重试即过，本地 `--repeat-each=6`
  跑 `review-library` 全量 30 次也**未复现** `:24`，无证据不下判断，另案观察。
- 不把断言改成「只匹配 `After the 19:00 Screening`」这类更松的子串（那是削弱断言，不是修红）。

## 方案取舍

| 备选 | 结论 | 理由 |
|---|---|---|
| 改 `public/festival-extras.json` 回 `October` | 否决 | 数据是重抓产物，官网就是 `Oct 7`；改数据等于把「最新事实」改回旧的 |
| E2E 期望从 `festival-extras.json` 里读 `dateText` | 否决 | 会让这条断言变成「渲染 == 数据源」的自证；仓库既有口径（`film-details.test.ts`）就是钉字面量，保持一处一致 |
| 改成松子串（只断 `After the 19:00 Screening`） | 否决 | 削弱断言，且下次漂移依然发现不了 |
| **对齐字面期望到当前数据** | **采纳** | 断言写「当前实际行为」（AGENTS.md §3）；漂移代价小且可见 |

## 验收标准

1. `npx playwright test -c playwright.react.config.ts e2e/react/review-library.spec.ts`
   在 desktop-chromium / mobile-chromium / mobile-webkit 上全绿（本地已复现：改动前 3 红，改动后全绿）。
2. 期望串与 `apps/web/tests/film-details.test.ts:38` 的 `dateText` 字面一致，不再出现两处口径。
