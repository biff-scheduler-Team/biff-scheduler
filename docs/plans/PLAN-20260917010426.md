# PLAN-20260917010426 — 豆瓣映射取用口径收成一处（有场次按 code、无场次按 `f###`）

## 目标

用户原话：

> 把豆瓣 ↗ 改成 [弹层那颗「在豆瓣打开」按钮] 这个在豆瓣打开这个按钮后面的逻辑可以吗?
>
> 弹层/行程卡一定有场次 的就直接跳转 然后没有就跳转 只改接口的逻辑 不用改样式

澄清后（用户从选项里选定）：**只统一「取哪一条豆瓣映射」的口径，不碰文案、不碰样式**；
三个入口（资料弹层 / 行程场次卡 / 影片库卡）一起改。

### 现状（代码事实，行号已核）

`href` 本身早就是单一口径 —— `util.ts:299-307 doubanUrlOf()`：映射有 `douban_url` 就用条目页，
否则按中文名（空则英文名）搜 `douban.com/search?q=`。4 个入口都走它，没有分叉。

**分叉在「先取哪一条映射」这一步**，同一个意图写了 5 份：

| # | 位置 | 表达式 |
|---|---|---|
| 1 | `apps/web/src/app/model.ts:43`（有场次的片节点） | `mappings.get(s.code)` |
| 2 | `apps/web/src/app/model.ts:68`（纯目录片节点） | `mappings.get(f.id)` |
| 3 | `apps/web/src/pages/LibraryPage.tsx:51` | `film.map ?? store.mappings.get(film.cats[0]?.id ?? "")` |
| 4 | `apps/web/src/components/ScreeningCard.tsx:223 / 299 / 303` | 三处 `store.mappings.get(s.code)` |
| 5 | `apps/web/src/components/ScreeningInfoPopover.tsx:48` | `store.mappings.get(s.code)` |
| 6 | `apps/web/src/pages/FilmDialog.tsx:81-83` | `anchor.code ? get(anchor.code) : film?.map ?? get(film?.cats[0]?.id)` |

3 与 6 有「code 未命中 → 退回目录片 id」这条腿，1/2/4/5 没有 —— **同一部片，影片库卡片能直达条目页，
弹层/行程卡却掉进搜索结果页**。这类分叉只会在映射产物缺某一类键时静默出现，所以要么一处实现，要么早晚踩。

### 产物实测（本次重构「零行为变化」的依据）

- `public/douban.json`：852 条映射 = **632 个场次 code + 220 个目录片 `f###`**，852 条都带 `douban_url`。
- `public/schedule.json`：792 场次。逐场次对账：

| 情况 | 场次数 |
|---|---|
| 场次 code 与所属目录片 `f###` **同时**命中 | 632 |
| 只有一侧命中 | **0 / 0** |
| 两侧都没有（该片没匹配上豆瓣） | 160 |

→ 当前产物下，两种取值链结果**逐条相同**，本次纯属口径收敛。这条对账写进测试，数据换版时会自己红。
（上表只算了**公开排期**；P&I 那份见「修订 1」。）

## 范围

**做：**

1. `apps/web/src/util.ts` 新增 `doubanMappingOf(mappings, {code, filmId})` —— 唯一取用口：
   - ① 有场次 → 按场次 code 查（与映射产物同键）；
   - ② 没有场次（纯目录片）/ code 未命中 → 按目录片 id（`f###`）查；
   - ③ 都没有 → `undefined`，调用方交给 `doubanUrlOf` 退搜索。
2. 上面表里 6 处全部改走它：`model.ts` 两处（片节点 `map` 字段本身收敛成统一口径）、
   `LibraryPage.tsx`、`ScreeningCard.tsx`（三处查一次，`score` / `href` / `title` 共用）、
   `ScreeningInfoPopover.tsx`、`FilmDialog.tsx`。
3. 回归测试：
   - `apps/web/tests/film-score.test.ts`：`doubanMappingOf` 的纯逻辑用例
     （code 命中优先 / code 未命中退 `f###` / 两侧皆无 → `undefined` / 纯目录片只给 `filmId`）。
   - `apps/web/tests/model-parity.test.ts`：**产物对账** —— 逐场次断言「code 腿」与「`f###` 腿」
     同真同假（不一致的场次列表必须为空），并断言 `buildFilms()` 出来的每个片节点 `map`
     与统一口径一致。

**不做：**

- **不改文案**：`豆瓣 ↗`、`在豆瓣打开` 原样。
- **不改样式**：不加按钮、不动 `.douban-jump` / `.preview-douban`。
- **不改 `doubanUrlOf`** 的搜索兜底口径。
- **不动 `FilmDialog` 里那对「中文搜索 / 英文搜索」** —— `util.ts:298` 注释已明示那是**另一条口径**
  （让用户自己选搜哪个名字）。
- **不顺手改造 `.title_cn` 那一类调用点**（`AgendaPage` / `DiscussionsPage` / `ics.ts` / `poster.ts` /
  `share.ts` / `schedule-search.ts` 等）：它们只取展示用中文名、不产出外跳链接，不在本次口径内。
- **不动 `legacy/`**（只读回退件，本次不是 P0 修复）。
- **不改 `scripts/test-map.json`**：`apps/web/src/util.ts` 本就没登记（`apps/web/src/app/` 命中
  `shell` 规则、`LibraryPage`/`ScreeningCard`/`FilmDialog` 各有规则），本轮不顺手扩表 ——
  扩表要连带重生成 `docs/TEST-MAP.md` 的区块，属另一件事。
- **不推送**（本机 §0 约定：本地验收 + 用户明确说「可以推」再 push）。

## 方案取舍

| 备选 | 结论 | 理由 |
|---|---|---|
| 新增 `doubanMappingOf(mappings, {code, filmId})`（本方案） | 采纳 | 参数只收「场次 code + 目录片 id」两项，调用方手上有什么传什么；回落链只此一处 |
| 把回落链塞进 `doubanUrlOf` | 否决 | `doubanUrlOf` 的入参是「片名 + 一条映射」，让它回头去查 `Map` 会把「取映射」和「拼 URL」两件事耦成一坨，且 4 个调用方都得改签名 |
| 只给弹层/行程卡各补一份 `?? mappings.get(cats[0].id)` | 否决 | 治三处漏一处（`FilmDialog` 也是同一意图的第四份写法），且这正是红线 5「同一口径写第二份实现」 |
| 保持现状，只加注释说明两种写法等价 | 否决 | 等价只在**当前产物**下成立（已实测），产物换版就会静默分叉 —— 注释拦不住 |
| 传整个 `Map` + 整个 `Screening` 给函数 | 否决 | 函数会忍不住再算 filmId（要重做 `filmInfoOf` 的命中规则），等于把第二份 `filmNodeKey` 塞进 util |
