# PLAN-20260913180837 — 移除行程最后一场不再连带删掉选片

## 目标

用户报（2026-09-13）：**一部片只排了一个场次时，在行程里把它移出，整部片会从「我的选片」里消失**，
用户怀疑是自己操作有误。

复现确认（读码，非猜测）：`apps/web/src/state.ts`

- `toggleScreening()`（网格整卡点选 / 场次卡「移出行程」）与 `removeScreening()`（行程行 ✕）
  在**移出后 `picks` 变空且无备注**时走 `isOrphan()` 分支，直接 `commit(key)` **把整条记录删掉**；
- 而同一份数据的另外三处口径都承诺「移除场次 ≠ 取消选片」：
  - `types.ts::PickEntry` 注释：「从行程里移除某一场只动 picks，记录保留（选片意向不丢）」；
  - `InfoDialogs.tsx` 帮助「我的行程 ✕」：「只移出这一场，选片保留 —— 该片仍留在『我的选片』里并标注『未排场』」；
  - `ScreeningCard` 卡片按钮 tooltip（legacy 文案同源）：「点击移出（影片仍留在『我的选片』，标注『未排场』）」。

结论：**不是用户操作有误，是 `isOrphan()` 这条「最后一场就整条删」的例外与全站承诺相左。**

修复口径：**移除某一场只动 `picks`，任何情况下都不删记录**；`picks` 为空 = 合法的「已选未排场」态
（与 `addPickFilm()` 建出的空记录同构）。要连选片一起移除，走「移除影片」（`removePick()`）。

## 范围

**做：**

- `apps/web/src/state.ts`
  - `toggleScreening()`：移出后不再判 `isOrphan()`，一律 `commit(key, {...cur, picks})`。
  - `removeScreening()`：同上（该函数 React 侧无调用点，但它是 state 公开 API、legacy 侧在用，口径必须一致）。
  - 两处注释改为写明新口径 + 为什么（否则下一个人又会「顺手清空壳」）。
- `apps/web/src/pages/LibraryPage.tsx`：选片卡状态行 `picks.length === 0` 时显示「未排场」
  （原来渲染「已排 0 场」）—— 让用户**看得见**「片还在，只是没排场」，与帮助文案逐字对齐。
- 回归测试（先红后绿）
  - 新增 `apps/web/tests/state-picks.test.ts`：锁「移出最后一场 → 记录保留 / 场次索引清空 / 顺位 prune /
    `removePick()` 仍是真删」。
  - `e2e/react/parity-library.spec.ts`：加一条「只排一场的片，在选片里点『移出场次』后卡片仍在、storage 仍是空 picks 记录」。

**不做：**

- **不动 `clearScreeningSlots()` / `replaceScreenings()` 的 `isOrphan()` 分支**：这两处是**批量**动作，
  且已经在 UI 上**明示**「有备注的影片会保留，其他空记录会删除」（设置弹层清空确认文案 / .ics「替换」档），
  属于已披露的另一条口径，不属本次 bug。（本次只把 `clearScreeningSlots()` 那句与实现相左的
  「选片意向保留」注释改成与 UI 一致，避免下一个人照注释改代码。）
- 不给移除场次加 confirm 弹窗：口径是「选片保留」，没有破坏性后果，加弹窗只是噪声。
- 不改 `addPickFilm()` / `removePick()` 语义，不改 `biff.picks.v2` 结构（无需迁移）。
- 不改 `biff.ranks.v1` 的 prune 行为（场次没了顺位就该清）。
- 不动 legacy 快照 `legacy/src/*` 与 `e2e/react/fixtures/legacy-state.ts.txt`：它们是**历史实现留档**，
  只作为兼容性对照，不得跟着改（改了就不再是「旧版行为」）。

## 方案取舍

| 备选 | 结论 | 理由 |
|---|---|---|
| 保持现状（最后一场整条删） | 否决 | 与 `types.ts` / 帮助文案 / 卡片 tooltip 三处承诺冲突；用户只是点错一下，丢的是**选片意向**（不可从 UI 看出是被删还是没排） |
| 最后一场时弹 confirm 再删 | 否决 | 让用户为「一个本不该发生的破坏」买单；且帮助文案已承诺不删 |
| 移除场次一律保留记录（空 = 未排场） | **采纳** | 与既有承诺一致、与 `addPickFilm()` 空记录同构、实现最简（删掉一个分支） |
| 顺手把 `clearScreeningSlots()` / `replaceScreenings()` 也改成保留 | 否决 | 那两处 UI 已明示会删空记录，属另一条已拍板口径；本次混进来会变成「一次提交两件事」 |
| 选片卡 0 场时显示「已排 0 场」 | 否决 | 用户看不懂是「没排场」还是「数据丢了」；帮助文案写的是「未排场」 |

## 验收标准

1. 一部片只有 1 个场次、无备注：在「我的选片」/「我的行程」点「移出行程」后
   —— 该场次从行程消失，但影片卡**仍在「我的选片」**，状态行显示「共 N 场，未排场」；
   `biff.picks.v2` 里该记录仍在（`picks: []`）。
2. 该片有备注时：移出最后一场后备注**原样保留**（不得连备注一起丢）。
3. 多场影片移出一场：其余场次与备注不动。
4. 移出后 `store.slotIndex` / `allCodes()` 不含该 code；该 code 的抢票顺位被 prune（`biff.ranks.v1` 不再含它）。
5. 「移除影片」（`removePick()`）仍能整片删除（含备注与全部场次）——「要真删」有出口。
6. `npm run verify` 全绿；`e2e/react/parity-library.spec.ts`（chromium 单浏览器）全绿。

## 备注

- 无数据迁移：空记录本来就是 `PickEntry` 的合法态（`addPickFilm()` 从 2026-09-11 起就产出它）。
- 副作用提示：网格整卡点选「加了又取消」现在会留下一部「未排场」的片（这正是帮助文案承诺的行为，
  且「移除影片」一键可清）。
