# PLAN-20260910103600 · 「我的行程」与「我的选片」合并为单一数据源（一部片一条记录）

## 1. 需求

> 我的行程和我的选片好像是两套数据 请你统一成一套数据。

用户已确认两点口径：

1. **统一方向 = 一部片一条记录（真·一套数据）**：唯一数据源是「影片记录」`{档位, 已选场次[], 备注}`。
   「我的选片」（按片看）与「我的行程」（按场次看）变成**同一份数据的两个视图**。
2. **移除联动 = 仍算选片**：在「我的行程」里移除某一场后，这部片**仍留在「我的选片」**里（保留选片意向，标注「未排场」）。

## 2. 现状（根因）

现在确实有**两套互不相干的数据**：

| 视图 | 数据 | 存储 | 粒度 | 云同步 |
| --- | --- | --- | --- | --- |
| 我的选片 | `state.wish: Map<filmNodeKey, Priority>` | `biff.wish.v1` | **影片级**（`cat:f001` / `sched:片名`） | ❌ 从不落 D1 |
| 我的行程 | `store.plan: Map<code, PlanEntry>` | `biff.plan.v1` + D1 `user_plan` | **场次级**（3 位 code）→ A/B + 档位 + 备注 | ✅ |

**根因**：两边**各存了一份「档位」**，且「是否选中」也存在两处。

- 加入行程时从 `wish` 继承一次档位，之后各自独立 → 影片库标「必看」、行程行改「随缘」，我的选片里它还是「必看」。
- 行程行 ✕ 移出场次 → `wish` 一字未动，我的选片里那部片照样在。
- 反向：影片库打标 → 行程里什么都没有（对没排期的片是合理的，但用户看到的是「两套账」）。

`legend.ts` §7 甚至把这个分裂写成了产品说明（「注意区分两层『档位』…两者同色系、互不影响」）—— 本次需求正是要废掉这条口径。

## 3. 方案

### 3.1 数据模型（`types.ts`）

删 `PlanEntry`，新增：

```ts
export interface PickSlot { code: string; group: Group; }   // 场次级：选了哪一场 + 归属方案
export interface PickEntry {
  key: string;                  // filmNodeKey：cat:<id> | sched:<片名小写>
  priority: Priority | null;    // 影片级档位（全站唯一一份）；null = 未设档位
  picks: PickSlot[];            // 已选场次（可空 = 已打标/已选中但未排场）
  note: string;                 // 备注（影片级）
}
```

- **档位只有一份，在影片级**。行程行的三段 seg 改的是**该片档位**（该片所有场次同步）—— 语义统一，两边永不打架。
- `group` 仍留在**场次级**：同一部片的两场可以分别放进 A / B 方案（排片策略需要）。
- `priority = null` 保留：网格里点选一部**未打标**的片 → 记录被建出来但档位未设（沿用 `6a3c9de` 「新加入不再默认备选」的口径），「我的选片」里归到「未设」。

### 3.2 状态层（`state.ts`）

- `wish` + `store.plan` → **`store.picks: Map<filmNodeKey, PickEntry>`**。
- 派生索引 `slotIndex: Map<code, { key, group }>`（每次变更重建），供网格 / 行程 / 弹层 O(1) 查「这场选没选、在哪个方案」。
- 入口收敛：
  | 函数 | 语义 |
  | --- | --- |
  | `setWish(key, p)` | 设/清**影片档位**；`p=null` 且 `picks` 为空 → 删记录 |
  | `toggleScreening(key, code, group)` | 网格点选：加/删该场（记录不存在则建，档位 `null`） |
  | `removeScreening(code)` | 行程行 ✕：只删该场，**记录保留**（需求 2） |
  | `setPriorityOfCode(code, p)` | 行程行 seg：按 code 反查影片 key → 改**影片档位**（该片 N 场同步） |
  | `flipGroup(code)` | 翻转该场方案 |
  | `replaceGroup(g, picks)` | 智能排片「采纳」：整组替换（含档位） |
  | `removePick(key)` | 整片移除（记录 + 其全部场次） |
  | `clearScreeningSlots()` | 清空全部已排场次（A+B），保留打标 |
- 持久化：`biff.picks.v2`（单一 localStorage key）。**旧 `biff.wish.v1` / `biff.plan.v1` 一次性迁移**（见 §4）。

### 3.3 视图层

| 文件 | 改动 |
| --- | --- |
| `grid.ts` | `ctx.plan` → `slotGroup(code)`（是否已选 + 方案）；`wishOf(s)` 改读 `picks.get(key).priority`；紧转场 / 冲突循环按 `slotIndex` 取当前方案场次 |
| `agenda.ts` | 按当前方案从 `picks` 展开场次行；行内 seg 读**影片档位**，title 注明「改该片档位（该片 N 场同步）」；✕ 文案改「移出该场（保留选片）」 |
| `library.ts` | 影片库行三选读 `picks.get(key)?.priority`；「A 已选 N」按 `picks` 统计；**「我的选片」总览 = 全部记录**（不再只列已打标），chips 增「未设」，每行可直接改档位 + 整片移除，场次行保留「定位 ▸」 |
| `modal.ts` | 详情弹层「我的选片」行改读影片档位；同片场次行 toggle 走 `toggleScreening` |
| `main.ts` | 网格点选 / GV 一枪「只要正片」走 `toggleScreening`；质量分与抢票顺位读影片档位；顶栏计数 = 影片记录数；设置里「清空」改「清空全部已排场次(A+B)」 |
| `ics.ts` | `pickEntries(picks, cat, which)` 从 `picks` 展开为 `{code, group, priority, note}` 行 |
| `legend.ts` | §7 重写：删「两层档位互不影响」口径，改为「一部片一条记录，档位在影片级，行程行改的是该片档位」 |
| `index.html` | 顶栏「我的选片」按钮 title 改写（不再是「在影片库打标」） |

### 3.4 云端（D1 单表）

`wish` 从来没落过云，合并后它就是主数据 —— 必须同步。

- 新迁移 `migrations/0003_user_pick.sql`：建 `user_pick(user_id, film_key, priority, note, picks JSON, ...)`，主键 `(user_id, film_key)`。
  **保留 `user_plan` 表不删**（数据不丢，万一要回查）；只停用其 API。
- 新 Functions：`functions/api/pick.js`（GET 列表）、`functions/api/pick/[key].js`（PUT upsert / DELETE），key 走 `decodeURIComponent`（`sched:` 键含中文）。
- 删除 `functions/api/plan.js` / `functions/api/plan/[code].js`（不再有场次级入口）。
- `api.ts`：`getPick` / `putPick` / `deletePick`，删 `getPlan` / `putPlan` / `deletePlan`。
- `syncFromCloud()` 改为云端为准合并 `user_pick`，仅本地有的记录回推（沿用原逻辑）。

## 4. 迁移（老数据 → 新模型）

`boot()` 顺序调整为**先 `loadCatalog()` 再迁移**（迁移要用 `filmNodeKey(cat, s)`）：

1. 读 `biff.picks.v2`；有 → 直接用。
2. 无 → 从 `biff.plan.v1` + `biff.wish.v1` 合成：
   - `plan` 每条 `{code, group, priority, note}`：`key = filmNodeKey(cat, byCode.get(code))` → 追加 `picks: {code, group}`；档位取该 key 第一个非 null 值。
   - `wish` 每条 `{key, priority}`：并进同一条记录的档位。
3. 写 `biff.picks.v2`；**旧 key 不删**（只读忽略，留作回退）。
4. 首次 `syncFromCloud()`：云端 `user_pick` 为空 → 走既有 `localOnly` 回推，本地记录全部上云。

## 5. 不做

- 不动网格卡的视觉（档位色点仍只读展示影片档位；红绿灯底色与档位仍正交）。
- 不动 `.ics` 导出格式、质量分权重、抢票顺位排序口径。
- 不给「备注」加编辑 UI（现状即无入口，字段原样保留）。
- 不做多人 / 账号体系。

## 6. 验收

- 影片库把《X》标「必看」→ 我的选片出现《X》→ 网格点选《X》某场 → 我的行程出现该场，档位「必看」。
- 行程行把该场改成「随缘」→ **我的选片里《X》同步显示「随缘」**（这是本次需求的核心断言）。
- 行程行 ✕ 移出该场 → 我的行程少一场；**我的选片里《X》仍在**，标注「未排场」。
- 我的选片里「✕ 整片移除」→ 记录与其全部场次一起消失。
- 未打标直接点选场次 → 记录档位「未设」，质量分不计入。
- `npm run build`（tsc + vite）无错；线上 `curl -sL https://biff-scheduler.pages.dev/` 产物含新 bundle。
- 需先 `npm run migrate:remote` 应用 0003（否则 `/api/pick` 500 → 降级纯本地）。
