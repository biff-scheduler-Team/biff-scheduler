# PLAN-20260913183205 — 影片卡「豆瓣」外链移到操作行最右端

## 目标

用户报（2026-09-13，附「我的选片」卡片截图）：卡片底部操作行里，`豆瓣` 夹在
`查看场次` 与 `资料` 两个按钮中间 —— 它是个纯文本外链（S2 `Link`，带下划线），
和左右两侧的圆角矩形按钮（S2 `ActionButton`）视觉不同源，看起来像没做完。
随后用户明确要求：**把「豆瓣」这个选项放到最右边。**

采用口径：**「豆瓣」移到操作行最后一位，并靠右贴齐行右端**（`margin-left: auto`），
即「主操作按钮靠左成组，外链单独靠右」，两件事一次做完。

## 范围

**做：**

- `apps/web/src/pages/LibraryPage.tsx`：`FilmCard` 的 `.film-actions` 里把 `<Link>豆瓣</Link>`
  从 `查看场次` 与 `资料` 之间**移到 `资料` 之后**（成为该行最后一个子元素）。
- `apps/web/src/style.css`：`.film-actions > a { margin-left: auto; }`
  —— 让外链靠右贴齐行右端（与 `agenda-parity.css::.venue-map-link` 同一手法：行内主内容靠左、外链 `margin-left:auto` 顶到右边）。
- 回归测试：`e2e/react/parity-library.spec.ts` 加一条 —— 断言「豆瓣」是操作行最后一个子元素，
  且其右边缘与操作行右边缘对齐（`getBoundingClientRect` 比对，容差 2px）。

**不做：**

- **不改「豆瓣」的元素类型 / 视觉样式**：它仍是 S2 `Link`（真 `<a href>`，可中键新窗口、可复制链接地址）。
  本次不把它做成圆角矩形按钮 —— 用户第一条反馈是「没在圆角矩形里」，但紧接着的要求是「放到最右边」，
  以「靠右独立成一项」回应视觉突兀；是否要再改成按钮形态等用户看到效果再说。
- 不改 `apps/web/src/pages/FilmDialog.tsx` 里的 `在豆瓣查看` / `中文搜索` / `英文搜索`：
  那是弹层内的行内链接组，与本次卡片操作行不是同一处。
- 不改 `ScreeningInfoPopover` 的 `.preview-full.preview-douban`（弹层里已经是圆角按钮形态，无需动）。
- 不引入任何依赖、不动数据契约（无 `biff.*` 变更、无迁移）。

## 方案取舍

| 备选 | 结论 | 理由 |
|---|---|---|
| 只把它移到 `资料` 之后（左对齐成组） | 否决 | 用户说的是「最右边」；卡片很宽时，紧跟按钮组仍是「挤在按钮堆里」，没解决第一条反馈的突兀感 |
| 移到末位 + `margin-left: auto` 靠右贴齐 | **采纳** | 一次满足「最右边」；主操作靠左、外链靠右是常见卡片布局；与仓库既有 `.venue-map-link` 手法一致 |
| 把它改成 `ActionButton`（圆角矩形，视觉与兄弟按钮一致） | 否决 | 会丢掉 `<a href>` 语义（中键新窗口 / 复制链接地址 / 右键菜单），为纯视觉一致性付语义代价；且与用户最新要求（挪到右边）不同 |
| 给 S2 `Link` 套一层圆角背景（`styles` 自定义样式） | 否决 | 等于把 S2 `ActionButton` 的样式再实现一份，违反「口径单一来源」 |
| 顺手统一弹层里的豆瓣链接 | 否决 | 一次提交只做一件事 |

## 验收标准

1. 「影片库」/「我的选片」的影片卡底部操作行顺序为：`加入我的选片 / 已在选片，去排场次 / 移除影片`、`查看场次`、`资料`、`豆瓣（豆瓣搜索）`。
2. 「豆瓣」右边缘与 `.film-actions` 右边缘对齐（容差 2px）—— 即贴齐卡片内容区右侧，而不是紧跟 `资料`。
3. 链接行为不变：`href` 指向豆瓣条目或豆瓣搜索、`target="_blank"`、`rel="noopener noreferrer"`。
4. 窄屏（≤768px）换行时「豆瓣」仍落在行右端，不遮挡其他按钮。
5. `npm run verify:ui -- parity-library --project=desktop-chromium` 全绿（含新增用例）。

## 备注

- 无数据迁移、无 `biff.*` 结构变更。
- 该行只有「豆瓣」一个 `<a>`，`.film-actions > a` 选择器不会误伤其他元素。
