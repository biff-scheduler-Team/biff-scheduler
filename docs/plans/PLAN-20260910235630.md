# PLAN 2026-09-10 23:56:30 — 片单彻底本地化（D1 只留豆瓣映射）+ 清空入口 + 堵旧 key 复活

> 需求(用户原话):「现在还需要 D1 吗 我之前不是说存 LocalStorage 吗」
> → 用户拍板:**「D1 保留,但是片单信息存 LocalStorage」「D1 保留,豆瓣也会保留」**。
> 前置:`PLAN-20260910235000`(适配与样式收敛)。
> 本文件 = 本需求唯一规划文档。

## 1. 现状(代码事实)

| 数据 | 存放 | 说明 |
|---|---|---|
| 选片 + 排片(`store.picks`) | **localStorage `biff.picks.v2` + D1 `user_pick`(双写)** | `commit()` → `saveLocal()` + `pushCloud()` |
| 设置 / GV 覆写 / AI 配置与日期 | localStorage | 本来就在本地 |
| **豆瓣映射** | **仅 D1 `douban_map`** | `store.mappings` 只在 `syncFromCloud()` 里从 D1 灌,本地零兜底 |
| 旧版 plan / wish | localStorage `biff.plan.v1` / `biff.wish.v1` | **迁移后故意不删** → 第二个「数据复活」源 |

**「部署后又出现默认行程/排片」的根因链**(上一轮已定位):
1. `syncFromCloud()` 是**云端为准**(`merged.set(r.film_key, …)` 覆盖本地同 key);
2. 设置里的「清空」只清场次、保留档位,且 D1 行仍在;
3. 每次部署换 origin(localStorage 空)但 D1 是同一个 → 同步回来;
4. `pushCloud()` 开头 `if (!store.online) return` → 离线期间的清空只落本地,下次被云端覆盖。

## 2. 决策

1. **片单(`user_pick`)彻底退役**:前端不再读写云端片单 —— `commit()` 只落 localStorage,
   删除 `pushCloud()` / `api.getPick|putPick|deletePick` / `functions/api/pick*`。
   → **「数据复活」从机制上根除**(没有云端权威源,就不可能覆盖本地)。
2. **D1 保留,只服务豆瓣映射**:`douban_map` + `/api/mapping` 不动;`wrangler.toml` 的 D1 绑定保留。
   ⚠ 映射仍是**仅云端**,离线粘贴回填不落本地 —— 本轮**不改**(用户选择保留 D1),作为已知限制写进文档。
3. **`store.online` → `store.mappingOnline`**:语义收窄为「豆瓣映射云端是否可达」,顶栏状态点文案同步改。
4. **新增「清空全部(选片 + 排片)」**:`clearAllPicks()` 对每个 key 走 `commit(key)`(纯本地删),
   设置里给出明确写「选片 + 排片一起清空」的危险操作 —— 补上现在**根本没有**的清空入口。
5. **堵旧 key 复活**:`migrateLegacy()` 迁移成功后**删除** `biff.plan.v1` / `biff.wish.v1`
   (并写 `biff.migrated.v1` 标记)。原「迁移后不删,留作回退」的理由(怕新结构出问题)已随
   「片单本地化 + 有清空入口」失效,留着反而是复活源。
6. `user_pick` / `user_plan` 两张表**保留不删**(与 0003 对 `user_plan` 的处理一致:数据不丢、只撤 API 入口)。

## 4. 边界与风险

- **数据不迁移**:D1 里现存的 `user_pick` 行**刻意不导入**本地 —— 那正是用户反复手动清掉的那批数据。
  旧行留在表里(无 API 入口),需要时用 `wrangler d1 execute` 查/删。
- **旧部署的缓存前端**仍可能打 `/api/pick` → 404 → `req()` 返回 null → 降级本地(无害)。
- **映射仍仅云端**:离线时「保存映射」会失败(按钮显示「保存失败(离线?)」),这是既有行为,本轮不动。
- **多设备同步消失**:片单不再跨设备。单用户单设备是既定定位,已在文档写明。
- 不改 `wrangler.toml` 的 D1 绑定与 `migrations/`;`migrate:remote` 脚本保留。

## 5. 验收标准

1. `npm run typecheck` / `npm run lint` / `npm run build` 全绿。
2. `src/` 内不再出现 `getPick` / `putPick` / `deletePick` / `pushCloud` / `syncFromCloud`(grep 复核)。
3. `functions/api/` 只剩 `mapping.js` 与 `mapping/[code].js`。
4. 产物 JS 不含 `/api/pick` 字符串。
5. 部署后:清空选片/排片 → 刷新 → **不再复活**;豆瓣映射仍能保存/读取。
