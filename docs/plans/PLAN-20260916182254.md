`P&I(Press & Industry) Screenings` 粉底标题下 —— 记者/业界场,不印场次编号、不对外售票,
官网排期页与影片介绍页都不列它们。2026-09-14 已把它们**排除**出公开产物。

在「设置」里给一个勾选项,勾上才纳入排片表 / 影片库 / 行程 / 冲突 / 导出等全部视图。

## 范围

**做:**

1. **数据侧**:`tools/extract_schedule.py` 加 `--include-pni`(默认**关**,不传参 = 行为与今天逐字节相同);
   开启时无编号格子不再跳过,产出行带 `pni: true`,并给一个**一眼可辨非官方**的 code。
2. **产物侧**:P&I 场次走**独立文件** `apps/web/public/pni.json`
   (含 `screenings` + 它用到的两个厅 `bd` / `c7`),**公开 `schedule.json` / `venues.json` 一个字节都不动**。
3. **前端**:`Settings.showPni`(默认 `false`)+ 设置弹层勾选项;
   勾上后 P&I 场次进入所有视图,取消即完全消失。
4. **回归测试**:纯逻辑单测 + 一条 E2E(勾选 → 出现;取消 → 消失)+ 公开产物哨兵**保留原样**。

**不做:**

- 不改公开 `schedule.json` / `venues.json` 的口径(哨兵不重写,只**追加**一条「P&I 不在公开产物里」)。
- 不为 P&I 场次写票务(不对外售票)/ 讨论 / 同场人数 / ICS 的特殊分支 —— 它们与普通场次同一套逻辑。
- 不引入新依赖;不动 `legacy/`。
- 不动 `data/schedule-2026.json`(那是册子中间产物,不是站点读的那份)。

## 方案取舍

| 备选 | 结论 | 理由 |
|---|---|---|
| **A. 直接把 P&I 混进 `public/schedule.json`,前端按设置过滤** | 否决 | 公开产物从此含 P&I;`catalogue-data.test.ts` 那条哨兵(2026-09-14 刚立的)得推翻重写 —— 等于把刚钉死、且踩过坑的口径再打开一次 |
| **B. 独立文件 `pni.json` + 启动时并行拉取,`derive()` 按开关同步合入** | **采纳** | 公开产物零变化(哨兵原样);异步只发生一次(bootstrap),开关切换是纯同步重算,无需重载 JSON、无需重启视图 |
| C. 开关打开时才 fetch `pni.json` | 否决 | 组件里要多一条异步状态机(加载中/失败),而 `derive()` 是同步的;收益只是省一次 ~10KB 请求 |
| 复用旧的 `X<页><序>` 合成号 | 否决 | 2026-09-14 的教训(伪装官方号,用户在册子上找不到);本次 code 用 `PI-<厅>-<序号>` 显式前缀 |
| 把 P&I 塞进 `venues.json`,靠设置过滤 | 否决 | `venues.json` 是公开在场馆表(ICS LOCATION / 图例口径都读它),混进去等于又改公开口径 |

### code 形态

`PI-BD-01` / `PI-C7-12`:`PI-` 前缀一眼表明**非官方编号**,`BD`/`C7` 是册子列号,序号按该列自上而下递增。
不占用三位数字空间(官网/册子官方号恒为 `\d{3}` 或 `901-942`),不与既有哨兵的 `^X` 规则冲突。

## 修订 1(2026-09-16,实施时查证后订正)

**触发**:动手时发现「源文件」与「验收数字」两处写错,另有两条口径按实测收紧。

1. **源文件认错了**。`~/Downloads/2025_BIFF_Ticket_Catalogue_web.pdf` 文件名与**内容都是 2025 届**
   —— 日标签实测 `17 WED` / `25 THU` / `26 FRI`(= 2025-09-17 ~ 09-26),解析出「公开 662 场 +
   P&I 36 场 + BAFA 1 场 = 699」,与 SKILL 记录的 2025 自检基线逐项吻合(GV 347、`dur_missing` 1、
   多值 subs 4 场 `028/029/109/268`)。**2026 册子**(第 31 届)实测在
   `~/Library/Containers/com.tencent.xinWeChat/.../msg/file/2026-09/2026_BIFF_Ticket_Catalogue_0910ver.pdf`。
2. **月份必须传 10**。第 31 届档期是 **2026-10-06 ~ 10-15**;册子只印「日号」(6..15),月份全靠 `--month`。
   传 9 会让册子侧整批落到 9 月,与官网骨架全面错位 —— 实测报出 **639 条假冲突**。
3. **开关形态改为 `--pni-out <path>`**(不是原计划的 `--include-pni`):只在给了输出路径时解析、
   收口,**不给时行为与今天逐字节相同**(实测 `P&I 0 场 / skipped 37`)。
4. **判据是「列归属」不是「有没有编号」**。2026 届「无编号但不在 P&I 列」的场次有 **2 条**
   (`Forum BIFF 2026 The Future of AI Cinema` @ BCM、`BAFA 2026 毕业典礼` @ B2),它们**已经在公开
   排期里**(官网另有编号那条)—— 按「无编号」收就会与公开产物**重复**。故常量 `PNI_VENUES = {BD, C7}`。
5. **实际数字**:P&I 共 **37 场**(BD 20 / CGV 7 17),分布在 10/07–10/11;公开产物仍 **792 场**、
   venues 仍 30 个、`--strict` 未登记冲突 **0**。
6. **新增幂等语义**(`merge_schedule.py`)：「合并结果与现有产物逐条相同」时**沿用原 `generated_at`**。
   否则每次重放都前进版本号,而 `build_changelog.py` 按「场次差异」算,两版一致 → 不写 changelog →
   `catalogue-data.test.ts` 的「版本号与排期生成时间一致」必红。重放不该让用户看到假的「数据已更新」。
