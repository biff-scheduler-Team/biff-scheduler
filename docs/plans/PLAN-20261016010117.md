# PLAN-20261016010117 — 部署核对不能被**别人的**本地 dist 判成「未核实」

## 目标

`npm run verify:deploy` 是 §6 交付口径里唯一那条「一行结论」的证据来源，它必须只在**证据成立**时给结论。
本轮修它的一处**假阴性**：多会话共用工作区里，`apps/web/dist` 常常是**并行会话刚构建的那一份**，
脚本拿它的入口 hash 与线上比对，于是「自己那笔已经上线」被判成「上线未核实」——同一个坑这轮已踩到两次
（另一次是 `--sha HEAD` 被别人的提交带走，已在前一轮修完并写进 §2.5）。

## 现状（代码事实，不是推测）

- `scripts/verify-deploy.mjs` 的 hash 判据取 `expectedHash ?? localHash()`；`localHash()` **只读
  `apps/web/dist/index.html`**，对「这份 dist 是谁的」一无所知。
- `apps/web/dist/version.json` **已经记着构建身份**（`{sha, branch, builtAt}`，由
  `scripts/prepare-cloudflare.mjs` 在 build 后写入）—— 归属信息本来就在手边，只是没被读。
- 本地 dist 是**构建产物**：可能不存在（没构建过），也可能属于**别人**的提交。

## 范围

**做：**

1. `localHash()` → `localBuild()`：同时读 `index.html` 与 `version.json`，返回
   `{ hash, sha }`；读不到（没构建过）返回 `null` —— **仍然不算失败**（判据缺席 ≠ 判据不成立）。
2. 新增纯函数 `localBelongsTo(local, wantSha)`，把「能不能拿这份 dist 的 hash 当判据」这件事**独立出来**：
   - 没有本地 dist → `false`；
   - 没传 `--sha`（无从谈起）→ `true`；
   - dist 没带 sha（引入 `version.json` 之前的旧产物，无从判断归属）→ `true`；
   - 两者都有且不等 → `false`。
3. 归属不符时：**不**参与 hash 比对，并打一行 `·` 说明（`本地 dist 属于 <sha>(≠ 期望 <sha>)…`）——
   与文件既有的「不静默降级」一致：判据缺席必须**说出来**，而不是悄悄少判一条。
4. 自检补 5 条用例（`localBelongsTo` 的五种输入），并说明文件头「本地 dist 只在归属正确时才算判据」。

**不做：**

- 不改判据强度顺序、不改 `--hash` / `--sha` / `--new` 的语义与退出码。
- 不碰 `apps/web/dist`（它是构建产物，不改、不删、不提交）。
- 不把「归属不符」判成**失败**：那不是核对失败，只是这条判据不适用。
- 不动 `scripts/prepare-cloudflare.mjs`（`version.json` 的写入方式不变）。

## 方案取舍

| 备选 | 结论 | 理由 |
|---|---|---|
| 归属不符 → `exit 1`（判失败） | 否决 | 那是**判据不适用**，不是「上线未核实」；把它算失败只会制造新一类假红 |
| 归属不符 → 静默跳过 hash 比对 | 否决 | 正是本文件要防的「静默降级」（上一版 `--hash` 漏参就是这么栽的）——所以要打 `·` 一行 |
| 「最近一次 git 提交 == dist.sha」来判断归属 | 否决 | 工作树可能脏、HEAD 在共用区会被带走；`version.json` 是 build 期写死的身份，比推断可靠 |
| dist 没带 sha 就当「不是我的」 | 否决 | 那会把「自己刚构建但版本较早」也判掉，假阴性换了个方向 |
| 归属判断就写在 `main()` 里（不抽函数） | 否决 | 抽出来才能进 `--self-test` —— §3「bug 修复必须带回归测试」，而这个脚本的自检就是它的测试面 |

## 验收标准

1. `node scripts/verify-deploy.mjs --self-test` → **19/19 通过**（原 14 条 + 新增 5 条归属用例）；
   5 条新用例中「dist 属于别人的提交时不采用」正是本 bug 的回归用例。
2. 局部实测（临时目录造 `dist`，不碰仓库产物）：
   - `version.json` 的 sha ≠ `--sha` 传的值 → 打印 `· 本地 dist 属于 …不参与 hash 比对`，且**不**因 hash 判失败；
   - sha 相同 → 照旧参与 hash 比对。
3. `npm run check:ci` 全绿（脚本改动不进 `apps/` / `packages/`，按 §2 该提交的 E2E job 本就不启动）。
4. 结论口径不变：仍输出 `verify-deploy:✓ 上线已核实 —— …` 一行。
