# PLAN-20260920193032 — 「抢票分析」页更名为「数据分析」

## 目标

用户原话：

> 抢票分析 不要叫这个名字 叫数据分析吧

把这一页的**用户可见名称**从「抢票分析」改为「数据分析」：导航项、页面标题、以及区域无障碍名。

## 范围

**做：**

- 导航项（`/rush-analysis`，位置不动 —— 仍在「抢票」之后）显示名 → 「数据分析」。
- 页面 `<h1>` 与 `.ra-page` 的两处 `aria-label` → 「数据分析」。
- 同步两处 E2E 断言：`rush-analysis.spec.ts`（导航位置 + 标题）、`screening-social.spec.ts`（导航整体顺序快照）。
- 代码注释里**指代这一页**的「抢票分析」一并同步（web 侧 + `scripts/test-map.json` 的 note）。
- 新增一条断言：**导航名与页面标题必须同一个字符串** —— 把「改一处漏一处」变成机械约束。

**不做：**

- **不改路由 `/rush-analysis`**：路径是契约（书签 / PWA 预缓存 / TEST-MAP 规则 / 多个 spec 引用），用户只说名字；改路径只有破坏没有收益。
- **不改模块代号**：`RushAnalysisPage.tsx` / `rush-analysis.ts` / TEST-MAP 的 `rush-analysis` id、
  API 侧「抢票分析模块」自述与 `tickets` 表 —— 它们描述的是**采集与聚合模块**（抢票结果的读写），不是页面名。
- **不动历史文档**：`docs/plans/*.md`（含用户当时的原话）保持原样；`PLAN.md` 只更新文档头一行「最后更新」。
- 不改任何统计口径、视觉与数据契约。

## 方案取舍

| 备选 | 结论 | 理由 |
|---|---|---|
| 名字与路径一起改成 `/data-analysis` | 否决 | 路径是书签 / PWA 缓存 / 测试映射的契约；用户只说名字 |
| 页面名抽成单一常量（`App.tsx` 与 Page 同源） | 否决 | 为一个字符串新增模块不值：`App.tsx` 若静态引用 `rush-analysis.ts` 会把这份纯逻辑拉进首屏包；而 E2E 已同时钉住两处，再用一条断言防漂移更轻 |
| 只改 `<h1>`、导航保持旧名 | 否决 | 导航与标题不一致是典型的漂移形态 |
| **改显示名 + 同步断言 + 一致性断言** | **采纳** | 改动最小，且「两处名字必须相同」由测试守住 |

## 验收标准

1. 导航里该项显示「数据分析」，`/rush-analysis` 的 `<h1>` 也是「数据分析」，两者字符串相等。
2. `apps/web` 内**用户可见文案**不再出现「抢票分析」。
3. `npm run typecheck` 通过；`rush-analysis` 与 `screening-social` 两个 spec 在 desktop-chromium 全绿。
4. 路由仍是 `/rush-analysis`；`scripts/test-map.json` 的 `rush-analysis` id 未变。
5. 回写文档：本 PLAN；`PLAN.md` 文档头一行「最后更新」。
