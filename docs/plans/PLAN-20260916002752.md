### 两轮口径澄清（我追问后的确认）

| 问题 | 用户答复 | 落地 |
|---|---|---|
| 载体：Markdown 表格还是纯文本？ | 第二次给出**纯文本缩进块**样例 | 不用 `\|` / `**` / `<br>`，维持微信纯文本硬约束 |
| CODE 去留？（首轮样例里没有 CODE） | 「还是提升 CODE 优先级」 | CODE **保留在行首**，不退回影院行尾 |

### 拆成三件事

1. **版式**：两行一场 → **三行缩进块**（`CODE  时间  英文名` / `中文名` / `影院 · 状态`），
   续行缩进到**英文名的起始列**。
2. **去 emoji**：`🎬` `📅` `📍` `📝` `⭐` 全部去掉；`↳` 保留（箭头符号，非 emoji，各端等宽）。
3. **状态列**：顺位 `顺位 N` → **`主选`（第 1）/ `备选②③…`（第 2 起，带圈数字）**；
   GV `含映后谈` → **`映后`**（`仅正片` / `GV` 不变）。

**不做（与「做」同等重要）：**

- **不改 `.ics`**（机器读的出口，信息取舍本就不同）。
- **不改分享图片 `poster.ts` 的画法**（只跟着 `gvMark` 文案变短；海报是单行标题，不做缩进块）。
- **不动 `legacy/`**（只读回退件，sha256 冻结）。
- **不动 `biff.*` 数据契约**（无迁移）。
- **不改批次分节版式** —— 节头仍是 `【第 1 批 · 9/17 14:00 KST / 北京 13:00】`。
- 不上 `verify:full`（三浏览器 5–9 min）。

## 方案取舍

| 备选 | 结论 | 理由 |
|---|---|---|
| 照用户首轮贴的 Markdown 表格输出 | **否决** | 微信不渲染 Markdown —— `\|` 与 `**` 会原样印出来，等于把排版噪声发给朋友；用户第二轮改口给了纯文本缩进样例 |
| 续行缩进写死空格数（如 13） | **否决** | 跨午夜场时间串多出「次日 」，写死会在那些块里错位；按**实际首行前缀宽度**算 |
| 续行只缩进 CODE 宽度（5 空格） | **否决** | 与用户样例不符 —— 样例的续行与**英文名**左对齐（13 空格 = 时间串 + 2） |
| 顺位继续印「顺位 N」 | **否决** | 用户样例明确 `主选` / `备选②`；且「顺位 1」对分工没信息量 |
| 备选沿用上一版单行 `↳ 备选 CODE  时间  片名  影院 · 顺位 N` | **否决** | 与主选块同构（三行缩进）才看得出「这是同一组的两套方案」 |
| `gvMark` 只改分享文案，弹层 / 海报另留一份文案 | **否决** | 同一语义两个口径必然漂移；三处一起变（`含映后谈` → `映后`） |
| 日期分节头保留「· N 场」 | **否决** | 用户样例 = `OCT 7 · 周三`；场次数已由概要行「共 N 场」给出 |
| 缩进块里保留 `📍` 前缀做视觉锚点 | **否决** | 用户明确「去掉 EMOJI」，且缩进本身已表达层级 |

## 验收标准

1. 不勾选任何选项时，分享文案 = `BIFF 2026 看片计划` / `OCT 8–OCT 9 · 共 2 场 / 2 部` / 分隔线 /
   `【OCT 8 · 周四】` / 三行缩进块，**通篇没有任何 emoji**。
2. 勾选「带上顺位」后：主选场次影院行尾 `· 主选`（同组第 2 起 `· 备选②`），
   同组备选另起一块（前缀 `    ↳ `），跨午夜场续行仍与英文名左对齐。
3. `npm test` 全绿（含新增用例）；`npm run verify` 全绿。
4. 受影响 E2E（`rush` / `parity-agenda`）桌面端全绿，贴出计数。
5. 推送 `origin/main`。
