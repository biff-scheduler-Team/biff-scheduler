# PLAN 2026-09-10 08:59:13 — 甘特卡「满高泳道」:上下留白 6px → 2px

> 需求(用户原话):「甘特图中的卡片 和甘特图时间的上下左右边缘都有空隙 这是设计吗 ?有更好的样式吗」。
> AskUserQuestion 澄清结论:方向 = **满高泳道**(卡片上下 1~2px 几乎顶满行,最紧凑;靠行分隔线区分场馆)。
> 本文件 = 本需求唯一规划文档。

## 现状(代码事实,HEAD 83ec2ad + 工作区在途)

- `src/grid.ts`:`ROW_H = 92`;卡片 `top: 6px`、`height: ROW_H - 12`(= 80px)→ **上下各 6px 空隙**。
- 左右:`left = 起点px + 2`、`width = 时长px - 4` → **左右各 2px 空隙**(防卡片边框与整点/半点刻度竖线叠成粗线)。
- GV 映后谈拼接块(`appendCard` talk 分支)沿用同几何:`top: 6px`、`height: ROW_H - 12` → 与主卡严格同高同顶,拼接不错位。
- 行分隔:`ROW_BASE_CLS` 行上 `border-t border-line-faint`(#f4f4f4,最淡一档)。
- 结论:上下 6px / 左右 2px **均为刻意设计**(给 hover 阴影、红圈联动高亮留投射空间);本需求只收上下,左右保持。
- **工作区注意**:并行需求(GV 拼接卡 + 红绿灯底色,PLAN-20260910010232 / 010648 / 011409;图例虚线下划线 PLAN-011607;日期 chips 挪位 PLAN-012009)改动仍在工作区未提交,`npm run typecheck` **已归零**(全部接线完成)。`src/grid.ts` 被并行需求改动 170 行 → 本需求改动无法按文件粒度与并行需求拆分,统一提交。

## 方案

- 新增常量 `CARD_INSET_Y = 2`(卡片上下留白,唯一来源),卡片与 talk 块几何均由它推导 —— 避免两处魔法数各写各的。
- 卡片 / talk 块:`top` 6 → `CARD_INSET_Y`(2px);`height` `ROW_H - 12` → `ROW_H - CARD_INSET_Y * 2`(= 88px)。
- **左右 2px 不动**(防刻度线粘连,与时间语义无关)。
- **行分隔线 `border-line-faint` → `border-line-soft`**:满高后相邻两行卡片间距由 13px 缩到 5px,最淡的 faint 已撑不起"区分场馆"的职责(用户选择本方案的动机之一即"靠行分隔线区分场馆"),配套提到 soft(#eaeaea)。
- `ROW_H = 92` 不变(行高、now 线、tracks 高度等全部依赖它,不动)。
- 卡片圆角 5px、内边距、字号一律不动。

## 改动清单

- `src/grid.ts`:
  1. 顶部常量区新增 `const CARD_INSET_Y = 2;`(带注释:满高泳道)。
  2. 行类:`border-t border-line-faint` → `border-t border-line-soft`(1 处)。
  3. `card.style.top = "6px"` → `` `${CARD_INSET_Y}px` ``;`card.style.height = `${ROW_H - 12}px`` → `` `${ROW_H - CARD_INSET_Y * 2}px` ``。
  4. talk 块:`talkEl.style.top = "6px"` → 同 3;`talkEl.style.height = ROW_H - 12` → 同 3。
