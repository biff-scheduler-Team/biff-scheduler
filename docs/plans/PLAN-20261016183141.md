# PLAN-20261016183141 — 让「只改 e2e spec」的提交在 CI 上真的跑到那个 spec

## 目标

> 上一轮问：要不要把这个 test-map 缺口一并修掉？（不修的话，本轮修复在 CI 上永远验不出来）
> 用户回：**「1.修复 2.推送 main」**

2026-10-16 实测（run 38884776014，PR #37）：`fix/e2e-ci-reds` 这轮改的是 `e2e/react/parity-library.spec.ts`
的**测法**，PR 上的 E2E job 只跑了一条 —— 而它跑的是 `smoke`：

```
必跑 spec:e2e/react/smoke.spec.ts
1 passed (4.2s)
```

`scripts/test-map.json` 的 21 条 rules 全是 `apps/` 源码路径，`always` 只有 `smoke` ——
于是**只改测试的提交谁也命中不了**：改动没被执行，绿灯是空的。

同一个缺口在 `main` 侧还有另一半：`ci.yml` 的 e2e job 只在改动含 `apps/` 或 `packages/` 时启动，
只改 `e2e/` 的提交在 main 上**整条 job 都不跑**。

## 范围

**做：**
1. `scripts/test-map.json` 加 `selfSpecPrefixes: ["e2e/react/"]`（**不**在 `allOn` 里手工枚举共享件 —— 见取舍表）。
2. `scripts/affected-specs.mjs` 认 `selfSpecPrefixes`：该目录里改 `<名>.spec.ts` → 至少跑 `<名>` 自己；同名 spec 不存在时**报警而不是静默**；改该目录里**任何非 spec 文件**（共享件 / 子目录）→ 退全量。
3. `.github/workflows/ci.yml`：`push` 的 e2e 启动条件加 `e2e/`（main 侧那半个缺口）。
4. 回归测试 `tests/affected-specs.test.ts`（先红后绿，4 例）。
5. `docs/TEST-MAP.md` 重生成 + 补一段说明。

**不做：**
- 不动 `allOn` 里既有的全局件名单（`playwright.react.config.ts` 等），也不把 e2e 启动条件改成「读 allOn」——那是另一个缺口，不在本轮。
- 不动三浏览器档位（§8 红线 16）。
- 不改任何生产代码 / 既有 spec 的断言。

## 方案取舍

| 备选 | 结论 | 理由 |
|---|---|---|
| 在 `test-map.json` 里为 31 个 spec 各写一条 `{paths:[<spec 自身>], specs:[自己]}` | 否决 | 31 条要手写、会漏、且新增 spec 时没人记得补 —— 规则本可以自己从路径推出来 |
| 代码里硬编码 `e2e/react/` 前缀 | 否决 | 前缀属于「映射口径」，该留在 `test-map.json`（唯一来源），代码只负责执行口径 |
| `selfSpecPrefixes` 字段 + 代码执行 | **采纳** | 口径仍在 json；新增 spec 自动获得「改自己就跑自己」，无需维护 |
| 共享件（`helpers.ts` / `fixtures/`）写进 `allOn` 白名单 | 否决（code review 第 1 轮改口） | 靠枚举防不住「新增一个 fixture」—— 没人会记得回来补，于是**静默漏跑**，正是本轮要修的毛病换个地方复发。改由 `selfSpecPrefixes` 一并推出：该目录里非 `.spec.ts` 的文件即共享件，影响面未知 → 全量 |
| 前馈：改 `e2e/` 在 main 上也跑全量 | **采纳** | main 侧没有「受影响 spec」这条路径，只能全量；代价是 5–9 min |
| 顺带把 `playwright.react.config.ts` 等也加进 `ci.yml` 启动条件 | 否决 | 收窄范围；它们是既有缺口，与本轮的「改测试没人验」不是同一件事 |

## 验收标准

1. `CI=1 npx vitest run tests/affected-specs.test.ts` → **4 passed**（修复前 3 failed）。
2. `node scripts/affected-specs.mjs --files e2e/react/parity-library.spec.ts` → 输出含 `parity-library`（修复前只有 `smoke`）。
3. `node scripts/affected-specs.mjs --files e2e/react/helpers.ts` → 全量（31 条）。
4. `npm run check:ci` 绿（`check:repo` + `check:test-map` 的 md↔json 同步断言）。
5. 未提交改动经 SKILL `code-review-skill` 审查（§4），结论修完后提交。
