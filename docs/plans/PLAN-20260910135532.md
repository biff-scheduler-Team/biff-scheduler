# PLAN-20260910135532 — 智能排片接入 LLM:填入 API Key 后排片(隐藏主 Prompt + 用户自定义 Prompt + 本地保密)

## 背景 / 用户诉求

> 智能排片支持填入 APIKEY 后排片。请你提供一个主 Prompt(隐藏)和用户自定义的 Prompt 区域,
> 并且提示用户 APIKEY 只存在本地、不会存在服务器、完全保密,请用户放心。先写一个 PLAN。

现状:`src/engine.ts` 的「智能排片」是**纯本地确定性求解**(must 全覆盖 DFS + maybe 贪心填空),
零联网、零 key、可解释,已能产出 A/B 方案 + 评分 + 未纳入原因。本轮**不替换它**,而是**并列增加一个 AI 模式**:
用户在弹层里填入自己的模型 API Key,由浏览器直连模型服务商,让 LLM 在**同一套硬约束**下给出选场建议。

## 一、核心设计决策(先定死,避免实现跑偏)

### 1. 隐私承诺必须「技术上为真」

用户要的「只存本地、不上服务器」不能只是文案。落地方案 = **浏览器直连**:

```
浏览器 ──(带用户自己的 key)──▶ 用户填写的 baseURL(模型服务商)
   │
   └──(只发 picks/mapping,永不携带 key)──▶ biff-scheduler.pages.dev/api/*
```

硬性约束(写进 `docs/CONVENTIONS.md`):

- **不新增任何服务端代理**(Functions 里不得出现转发 LLM 的 endpoint)—— 一旦有代理,key 就「经手服务器」,承诺即假。
- key 只落 `localStorage["biff.ai.v1"]`,**单独一个 LS 键**,不并入 `biff.settings.v1`:
  ① 便于「一键清除」语义干净;② 不会被设置项的任何序列化/导出顺手带走。
- 代码里**不存在**把 key 拼进任何本站请求的路径(`api.ts` 一行不改)。
- 不在 `title` / `placeholder` / `console` / DOM 属性里回显完整 key;UI 只显示末 4 位(`sk-…a1b2`)。
- 输入框 `type="password"` + 「显示/隐藏」切换。

**文案如实说明,不过度承诺**:localStorage 是明文,同源脚本可读 —— 提示里写「Key 只保存在你这台设备的浏览器里;
请勿在公用电脑上保存;可随时点『清除 Key』」,不写「已加密」。

### 2. 协议:OpenAI 兼容 Chat Completions(可配置三件套)

`baseURL` + `model` + `apiKey` 三项全可配,预置常见服务商快捷项,避免锁死一家:

| 预设 | baseURL | 默认 model |
|---|---|---|
| DeepSeek(默认推荐) | `https://api.deepseek.com/v1` | `deepseek-chat` |
| OpenAI | `https://api.openai.com/v1` | `gpt-4o-mini` |
| Moonshot | `https://api.moonshot.cn/v1` | `moonshot-v1-8k` |
| 硅基流动 | `https://api.siliconflow.cn/v1` | `deepseek-ai/DeepSeek-V3` |
| 自定义 | 手填 | 手填 |

请求形态固定:`POST {baseURL}/chat/completions`,`Authorization: Bearer <key>`,body = `{model, messages, temperature: 0.2, response_format?}`。
(`response_format: {type:"json_object"}` 仅在预设里标注支持的厂商开启,其余靠容错提取兜底。)

### 3. 主 Prompt(隐藏)—— 不进 UI、不可编辑

编译进 JS 的常量 `src/ai.ts::SYSTEM_PROMPT`,UI 只展示「规则摘要」不给全文。全文如下:

```text
你是电影节排片助手,为一位观众在**硬约束**下挑选场次。

【输入】两条清单:
1) 影片清单 films[]:{key, 中文名, 原始片名, 档位 priority(must=必看 / maybe=备选 / wild=随缘), 豆瓣评分 rating}
2) 场次清单 screenings[]:{code(唯一,6 位内), film_key, 日期 date(YYYY-MM-DD), 开始 start(HH:MM),
   结束 end(可能写作「次日 05:35」= 跨午夜), 影厅 venue, 是否含映后谈 gv}
环境约束 env:{跨影院转场缓冲 transitMin 分钟, 日期范围}

【硬约束 —— 任何情况下不得违反】
C1 每部影片最多选 1 场。
C2 同一天内,任意两场不得时间重叠;若两场影厅不同,前一场结束后必须再留出 transitMin 分钟转场。
   跨午夜的场次按「次日」理解(如 23:59–次日 05:35 会占用次日凌晨)。
C3 只能使用场次清单里出现过的 code,禁止编造、禁止改写。
C4 优先级:must 必须尽力全覆盖(实在排不下才可放弃,并在 dropped 里说明);maybe 在硬约束内尽量多排;
   wild 只在完全不影响 must/maybe 时才考虑。
C5 一部影片若有多场可选,优先选 gv=true 的场次,其次选时间更早的场次。

【输出】**只输出一个 JSON 对象,不要任何解释文字、不要 Markdown 围栏**:
{
  "picks": ["<code>", ...],
  "dropped": [{"key": "<影片 key>", "why": "<不超过 20 字的放弃原因>"}],
  "note": "<不超过 60 字的整体策略说明>"
}
picks 按日期与开始时间升序排列。若某档位影片无法排入,dropped 必须给出原因。
```

用户自定义偏好作为**独立的一条 user 消息**注入,外层包一段守卫说明,使其无法覆盖硬约束:

```text
【用户的附加偏好 —— 请在上述硬约束内尽量满足;若与硬约束冲突,以硬约束为准】
<用户输入原文>
```

### 4. 数据打包(控 token)

只送**已定档(priority ≠ null)**的影片 —— 与本地引擎口径一致(`openEngineDialog` 已如此过滤)。
基线 20–60 部片 × 均 3 场 ≈ 60–180 场,可控。字段精简:

- 影片:`key, zh, orig, priority, rating, unit`
- 场次:`code, film_key, date, start, end(显示口径 —— 走 `fmtEndClock`,避免把 `29:35` 丢给模型), venue, gv`
- 环境:`transitMin`、日期范围、`gvTalkMin`(默认映后时长)

**超限截断**:序列化后 > 120,000 字符时,按 `wild → maybe` 顺序丢片,`must` 永不丢;弹层明示「本次仅送 N 部」。

## 二、UI 落点

`智能排片 ▸` 弹层(现 `library.ts::openEngineDialog`)顶部加**分段控件**:`本地引擎` / `AI 排片`。

- **默认停在「本地引擎」** —— 零配置永远可用,不因新增 AI 而破坏现有路径。
- 切到 **AI 排片** 后两种态(弹层内**就地重绘**,遵守约定 9「弹层内改状态必须自己重绘」):

**态 A · 未配置 Key**

```
┌ AI 排片 · 需要你自己的模型 API Key ────────────────────┐
│ 服务商 [DeepSeek ▾]   Base URL [https://api.deepseek.com/v1] │
│ 模型   [deepseek-chat]                                     │
│ API Key [••••••••••••••] [显示]                            │
│                                                            │
│ 🔒 隐私说明                                                 │
│ · Key 只保存在**你这台设备的浏览器**(localStorage),不上传本站服务器 │
│ · 排片请求由浏览器**直连**你填写的模型服务商,本站不经手            │
│ · 明文存储,公用电脑请勿保存;可随时「清除 Key」                   │
│                                  [ 保存到本机 ]              │
└────────────────────────────────────────────────────────────┘
```

**态 B · 已配置**

```
✓ 已配置 · DeepSeek · deepseek-chat · sk-…a1b2    [更换] [清除 Key]

用户自定义偏好(可选)
┌────────────────────────────────────────────────────────────┐
│ 例:尽量把场次集中在 BCC;早上不看片;不接受午夜场;优先带 GV 的场   │
└────────────────────────────────────────────────────────────┘
在硬约束(不重叠 / 跨馆转场 / 每片一场)内尽量满足   ·  12/500 字

[ 开始 AI 排片 ]   ← 请求中变「生成中…(点击中断)」,走 AbortController
```

**结果态**:归一化成 `{picks, dropped, note}` → 本地校验 → 复用现有方案卡视觉逐行渲染
(日期分组 / 时间深色 / 影院次级灰 / 档位色点)+ 「采纳为 A 方案 / 采纳为 B 方案」→ 走 `state.replaceGroup()`。
未采纳/被剔除的场次以浅红卡列出原因。同时展示 `note`(模型的一句话策略说明)与原始返回的可折叠文本(便于排查)。

**设置弹层**(`main.ts::openSettings`)追加一节只读状态:`AI 排片 Key:已配置(…a1b2) / 未配置` + 「清除 Key」。
**不在设置里填 Key** —— 配置入口只留在智能排片弹层(上下文更自然,也降低误触)。

## 三、输出校验(不信任模型)

1. 容错提取首个**括号平衡**的 JSON(剥 ```json 围栏、忽略前后废话)。
2. 逐条校验:`code` 必须存在于 `cat.byCode`;同片去重(保留首个);**同片最多 1 场**。
3. 再跑一遍**本地冲突检测** —— 复用 `gv.ts::effEndMin` + `talkOnOf` 的有效结束口径,与 `engine.ts::blocks` 同判据,
   剔除违规场次。**不信任模型的自我约束**(否则方案一进网格就红一片,与「映后时长可配置」那次踩的坑同源)。
4. 结果卡片明示「已自动剔除 N 场(无效 code / 时段冲突)」。
5. 校验后 picks 为空 → 「AI 未给出可用场次」,附原始文本。

**采纳出口唯一**:`replaceGroup(g, picks)` —— 与本地引擎同一出口,保证「选片只有一张表」的数据契约不被绕开。

## 五、验收标准

1. `npm run typecheck` 通过。
2. **无头交互断言**(playwright-core + 本机缓存 chromium + 临时 `python -m http.server` 对 `dist/`,用完 `pkill`;
   见 SKILL `web-ui-headless-interaction-qa`):
   - 打开智能排片 → 切「AI 排片」→ 出现配置区 + 隐私文案;
   - 填假 key 保存 → 出现「已配置 · …末 4 位」+ 自定义 Prompt 区,`localStorage["biff.ai.v1"]` 有值且**含 userPrompt**;
   - **隐私断言(可自动化)**:用 `page.route` 拦全部请求 —— 断言 ① 不存在发往 `/api/*` 的请求携带 key;
     ② LLM 请求 URL 的主机 == 用户填的 baseURL;③ 请求 body 里不含 key(只在 header);
   - mock 一个合法 JSON 响应 → 结果卡出现 → 点「采纳为 A 方案」→ `store.picks` 里出现对应 code 且档位正确;
   - 「清除 Key」→ LS 键被删、UI 回到未配置态。
   - **绝不**在测试里使用真实 key,不打真实服务商。
3. 线上只跑**只读**断言(约定:不点会写接口的按钮)。
4. 失败路径人工可复现:401/403/404/CORS/超时/非法 JSON 六类各给出可读文案(用 mock 状态码覆盖)。

## 六、边界与风险

- **CORS**:部分服务商不允许浏览器直连 → 明确报错文案(「该服务商不允许浏览器直连,请换一家或自建网关」),
  **不引入本站代理**。这是本方案的固有边界,须如实告知用户。
- **模型幻觉 code** → 白名单校验兜底(第三节)。
- **token 超限** → 第四节截断策略 + UI 明示。
- **key 明文存 localStorage** → UI 如实说明,不宣称加密。
- **`library.ts` / `main.ts` / `legend.ts` 是并行会话热点文件**(约定 5):实现后提交按 SKILL
  `parallel-agent-safe-commit` 只带自己 hunk;若有在途改动走隔离 worktree,构建后 `grep` 产物确认新类名命中。
- **P0 不做流式**:一次性返回 + 可中断 + 生成中态即可;流式(SSE 增量渲染)列 P1。

## 附:主 Prompt 的设计取舍(为什么这么写)

- **不要求模型回片名/时间**,只要 code —— 幻觉面最小,前端按 code 反查权威数据。
- **跨午夜显式说明**:模型对「29:35」几乎必然理解错,故打包时已换成「次日 05:35」文本并额外提示。
- **把硬约束写成 C1–C5 编号**,便于模型自查,也便于我们把校验失败原因映射回具体条款。
- **强制 `dropped` 带原因**:与本地引擎的「未纳入原因」体验对齐,不让 must 静默消失。
- **`temperature: 0.2`**:排片是约束求解,不是创作。
- **用户偏好单列一条 user 消息 + 守卫句**:既满足「用户自定义 Prompt 区域」,又不让用户无意中破坏 JSON 契约。
