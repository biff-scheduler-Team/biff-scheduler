# PLAN-20260915233816 — 讨论区（方格墙聚合 + 行程内讨论定位）

## 目标

用户原话（逐字保留）：

> 在我的行程和建议后面 加上一个模块 叫做讨论区 把讨论区的集合放到那边去 然后现在行程中的讨论会直接定位到这个区域的这个帖子 帖子的布局参考小红书的那种一个个方格的

### 拆成三件事

1. **新增顶层模块「讨论区」** —— 排在导航「我的行程」「建议」**之后**。
2. **把讨论的集合挪过去** —— 讨论区是**全站帖子墙**（不再只能从某一个场次的卡片里看到）。
3. **行程里的「讨论 N」改成「定位」** —— 点它跳到讨论区，滚动到该场次的帖子并高亮，
   而不是像现在这样就地弹一个只含单场讨论的弹层。
4. **帖子的排布参考小红书** —— 一个个方格的网格墙。

### 对本轮实现的解读（有歧义处先写明，实现按此走）

| 原文 | 解读 | 依据 |
|---|---|---|
| 「在我的行程和建议后面」 | 导航项列表末尾追加（排片表 / 影片库 / 我的选片 / 我的行程 / 建议 / **讨论区**） | 「A 和 B 后面」= A、B 两者之后 |
| 「这个区域的这个帖子」 | 行程里的入口是**场次级**（只有「讨论 N」，不带单帖 id），所以定位的粒度 = **该场次的全部帖子**：滚动到该场第一条 + 该场所有格子加高亮 | `DiscussionEntry` 拿不到 post id；换成按 post id 定位要另做一张 id 索引，收益不抵成本 |
| 「一个个方格」 | CSS Grid `auto-fill` 方格墙（等宽格、按行阅读） | 见「方案取舍」 |

## 范围

**做：**

1. **后端聚合读**：`GET /api/discussions`（`edition` 收窄 + 游标分页，公开读；登录时回 `myReactions`）。
   与单场讨论**共用一份实现**（`listScreeningPosts` 抽出 `listPosts`，`code` 可空），游标 / 反应聚合口径不另写第二份。
2. **前端数据层**：`screening-discussion.ts` 增 `fetchDiscussionBoard(cursor)`（复用 `api()`）。
3. **新页面 `DiscussionsPage.tsx` + 路由 `/discussions`**：方格墙，每格 = 一条帖子
   （分类 tag / 正文摘要 / 片名 / 场次时间 / 作者 / 时间 / 已有反应数 / 「进入讨论」）。
4. **定位**：URL `?focus=<code>`；进入时把该场次的格子高亮，滚动到首条，顶部给一条可清除的定位条。
   若该场次的帖子不在已加载分页里，定位条提示「继续加载更多」。
5. **行程场次卡的「讨论 N」改为跳转**：`/discussions?focus=<code>`，不再就地弹层。
6. **导航 / 路由接入**：`App.tsx` 的 `nav` 追加「讨论区」；`fullPage` 正则纳入 `/discussions`；`main.tsx` 加路由。
7. 样式追加进既有 `screening-social.css`（**不新建 css 文件、不动 `style.css`**）。
8. E2E `screening-social` 同步改造 + `scripts/test-map.json` 登记新页面 + 重生成 `docs/TEST-MAP.md`。

**不做（与「做」同等重要）：**

- **不改任何 `biff.*` 本地数据键** —— 讨论仍是服务端 UGC，本轮不动片单契约。
- **不新增数据表 / 迁移** —— `screening_post` / `screening_reaction` 原样复用。
- **不给讨论区加独立的发帖入口** —— 帖子必须挂在某个场次上（接口契约如此），发帖 / 反应 / 删除仍走既有
  `ScreeningDiscussionDialog`（从格子上的「进入讨论」打开）。**不为了这轮把发帖门闸搬出弹层**。
- **不做真·瀑布流（masonry）**、不做图片 / 富文本 / 楼中楼回复、不改分类白名单。
- **不动 `style.css`**（命中 TEST-MAP `allOn`，会触发三浏览器全量 E2E）。
- **legacy 侧不做任何入口**（`legacy/` 只接 P0）。
- **本轮不推送** —— 本地跑通 + 起 dev server 交用户验收，用户确认后才推。

## 方案取舍

| 备选 | 结论 | 理由 |
|---|---|---|
| 复用 `/api/screenings/:code/discussion` 逐场次拼出全站列表 | **否决** | 要 N 个请求且拿不到「全站时间倒序」；聚合读必须是一次游标分页 |
| 讨论区直接读 D1 新表 / 新视图 | **否决** | 同一份数据两个读口径 = 漂移；抽 `listPosts(code: string \| null)` 一处实现 |
| 方格墙用 CSS `columns` 做真瀑布流 | **否决** | DOM 顺序变「按列」→ 键盘 tab 与读屏顺序跳列；也用不上「方格」的字面意思。改用 `grid-template-columns: repeat(auto-fill, minmax(…))`，按行阅读 |
| 方格墙用 JS 测高做瀑布流 | **否决** | 引入 ResizeObserver + 重排，收益仅是视觉；方格墙已满足「一个个方格」 |
| 行程里保留「就地弹层」并**额外**给一个定位入口 | **否决** | 用户明确要「直接定位到这个区域」；两套入口 = 讨论有两处家，与「集合挪过去」相悖 |
| 定位参数带 post id（`?focus=<postId>`） | **否决** | 行程入口只有场次 code，没有 post id；为此新增 id 索引不划算。若要精确定位单帖，日后从讨论区内部跳转再加 |
| 讨论区加独立顶部发帖框 | **否决** | 接口要求帖子必须挂场次；无场次的发帖框要么假、要么得改接口与表结构 |
| 新建 `discussion-board.css` | **否决** | 讨论相关样式已集中在 `screening-social.css` 且已登记 test-map；新开文件只会让「讨论的样式」有两个落点 |
| 未登录也能在讨论区发帖 | **否决** | 与既有门闸一致：公开读、登录写 |

## 验收标准

1. 顶栏导航出现「讨论区」，且排在「我的行程」「建议」之后；点它进入 `/discussions`，页面为方格墙。
2. `/discussions` 展示**全部场次**的帖子（不再局限于某一场），按时间倒序，可「加载更多」翻页。
3. 行程页点任一场次卡上的「讨论 N」→ 跳到 `/discussions?focus=<code>`，该场次的格子带高亮 class，
   页面滚动到该场次第一条；顶部定位条可清除（清除后高亮消失）。
4. 格子上的「进入讨论」打开既有 `ScreeningDiscussionDialog`（分类发帖 / emoji 反应 / 作者删除 / 社区提醒**全部不变**）。
5. 未登录点「进入讨论」里的发帖仍被挡到登录面板（门闸未松动）。
6. `npm run verify:quick` 全绿；`npm run verify:ui -- e2e/react/screening-social.spec.ts --project=desktop-chromium` 通过（贴出计数与断言汇总）。
7. 本地 dev server 可交互，交用户本地验收；**未获用户确认前不推送**。
