# PLAN-20260916142713 — 活动场次（Actors' House / Master Class / Cine Class / Special Talk）中文译名落进数据管线

## 目标

> 用户原话：「这个可以翻译然后放到我的网站上吗 还有Actors’ House: RYU Seung-ryong这种只有英文的 能不能也翻译成中文吗?」

把站上**只有英文名**的活动类场次补上中文名，让网格卡 / 行程 / 复制清单 / ICS 都显示中文。

## 现状（代码事实，2026-09-16 核对）

- **显示链路已就绪，前端零改动**：`apps/web/src/util.ts:128-142`
  `bilingualTitle(en, zh)` → `displayTitle()` = 「**英文名 · 中文名**」（英文在前）。
  所以只要数据里 `title_zh` 非空就自动显示中文，不需要动任何组件。
- **中文名唯一生成点是抓取脚本**：`tools/scrape_biff_web.py:494-548`
  `title_zh = build_title_index(films.json + data/title-alias-2026.json).get(片名)` ——
  按【影片目录】反查；活动场次不在目录里 → **恒为空**；且每轮重抓都从 `title_zh = ""` 起算。
  ⇒ **直接手改 `apps/web/public/schedule.json` 会在下次重抓时被冲掉**。
- **现有 `data/title-alias-2026.json` 不能复用**：`_note` 写明它的语义是
  「官网**片名** → 目录中文名」，值必须与 `data/films-catalog-2026.json` 的 `title_zh` 一致
  才能命中；活动名塞进去会污染该表语义，且 `tools/build_films_2026.py` 会直查它。
- **待补清单**（`apps/web/public/schedule.json`，42 条带 tags 场次中 `title_zh` 为空的）：

## 方案取舍

| 备选 | 结论 | 理由 |
|---|---|---|
| 前端硬编码 `code → 中文名` 映射 | 否决 | 违反「口径单一来源」，数据变一次就要改代码 |
| 塞进 `data/title-alias-2026.json` | 否决 | 语义冲突（该表值 = 目录中文名），且被 build_films 直查 |
| 只手改 `apps/web/public/schedule.json` | 否决 | 是抓取产物，下次重抓即丢（见上） |
| **新建 `data/event-titles-2026.json` + `scrape_biff_web.py` 兜底查表** | **采纳** | 人工表独立于片名表；重抓不丢；前端零改动；日后加活动只加一行 |

落点：
1. `data/event-titles-2026.json`：`{ "_note": …, "_why": …, "events": { "<官网活动英文名(归一化后可匹配)>": "<中文名>" } }`
2. `tools/scrape_biff_web.py`：在目录反查之后追加一层兜底
   （`title_zh = 目录命中 || 活动表命中 || ""`），命中时打 stderr 统计，与现有 `estimated` 自检同风格。
3. 重跑抓取 + `tools/merge_schedule.py` 生成 `apps/web/public/schedule.json`。
