# PLAN-20260922142903 — 红黑榜：贴纸外观拉平、全局统计为主、新增「只看我贴过」

## 目标

用户 2026-09-22 基于实际使用提出三点观察，逐条对应的复盘结论与拍板口径如下。

> 1. 「别人贴的 和我自己贴的 贴纸长得不一样?」
> 2. 「上面的统计数据应该显示全局的 然后自己的应该有什么其他的显示逻辑?」
> 3. 「现在最多只显示 16 枚吗? 为啥会这样」

**复盘结论**：① 是**刻意设计**（`.rb-dot--crowd` 18px / opacity 0.62 / 只读，`.rb-dot` 26px / 实心 / 可拖），
但页面上没有任何图例传达这件事，用户第一反应是「这俩不是一个东西」；② 顶部三格 `标记看过/还能贴/已贴`
**全是个人进度**，而全站总票数 `totals.total` 已算出却只用于判断「榜空不空」，一个字都没显示 —— 真缺口；
③ `CROWD_CAP = 16` 的存在有两层原因（性能 + **服务端只返回聚合计数、拿不到每一票的坐标**），
本期顺带修掉一个真 bug：`Math.round` 会把少数派颜色整个抹掉（1 红 / 100 黑 → 画布上无红点）。

**本期要达成的结果**：贴纸外观拉平（只靠「能不能拖」区分）；顶部统计以全局为主、我的收成一行小字；
新增「只看我贴过」筛选；16 枚从「最多显示 16 枚」改成「16 枚代表全部票数」。

## 范围

**做:**

1. **贴纸外观拉平**（`apps/web/src/pages/redblack-parity.css`）
   - `.rb-dot--crowd` 去掉 `width/height: 18px` 与 `opacity: 0.62`，尺寸/实心度与 `.rb-dot` 一致
   - **只保留** `cursor: default` 与 `pointer-events: none`（后者是硬约束：否则挡住拖拽落点命中测试）

2. **修比例失真 + 溢出数量**（`apps/web/src/redblack.ts::crowdStickers`）
   - 红黑**都 > 0** 时，`reds` 夹在 `[1, shown - 1]` —— 少数派颜色至少留 1 枚
   - 同时返回溢出数 `overflow = counts.total - shown`（供画布画「+N」）

3. **画布「+N」溢出角标**（`apps/web/src/pages/RedBlackPage.tsx` + css）
   - `overflow > 0` 时渲染一枚独立 class 的角标（**不用** `.rb-dot--crowd`，避免污染现有 e2e 的计数断言）

4. **hero 统计改「全局为主 + 我的一行小字」**（`RedBlackPage.tsx` + css）
   - 大字：全站总票数（含红 / 黑拆分）
   - 一行小字：我的 —— 标记 x / 已贴 y / 还能贴 z
   - `totals.total` 继续兼作「榜是否为空」的判据

5. **新增「只看我贴过」筛选**（`RedBlackPage.tsx`）
   - 独立 URL 参数 `only=mine`（与 `sort` **正交**，不做成第四档排序）

6. **颜色 token 收敛**（`redblack-parity.css`）
   - `#cf3b52` / `#2f2f36` 现散在 `.rb-src--*`、`.rb-dot--*`、`.rb-ghost--*` 三组共 6 处，
     提成 `--rb-red` / `--rb-black`（`AGENTS.md §5`：颜色 token 只允许一处实现）

7. **测试**（先红后绿）
   - `apps/web/tests/redblack.test.ts`：`crowdStickers` 的比例边界（1红100黑 / 100红1黑 / 纯色）+ 溢出数
   - `e2e/react/redblack.spec.ts`：「+N」角标、只看我贴过筛选、拉平后 crowd 点仍不可拖

**不做:**

- **不改 `apps/api`** —— 显示「全站参与人数」需要改 `film-vote-store.ts::readVoteCounts`，
  属「涉及 `apps/api`」类改动，按 `AGENTS.md §4.5` 必须走 PR；本期只用现成的 red/black 计数。
- **不改 `CROWD_CAP = 16` 的数值**（已拍板：修失真 + 加角标，而不是提高上限）。
- **不加任何「这枚是你的」的额外视觉标识** —— 用户口径：只靠**拖动 / 收回重贴**操作即可。
- **不改拖拽逻辑、`StickerBoard` 模型、`biff.redblack.*` localStorage 契约**（§5：key 只增不改）。
- **不动 `RushCrowdPanel` / 数据分析页**（那里的红黑票口径另有来源，见 `PLAN-20260920203010`）。
- **不碰 `apps/web/src/app/App.tsx`、`e2e/react/share-export.spec.ts`** —— 二者是**他人在途改动**

## 方案取舍

| 备选 | 结论 | 理由 |
|---|---|---|
| 保持 18px / 0.62 的区分 + 加图例说明 | 否决 | 用户 2026-09-22 明确选「完全拉平」，图例随之失去意义 |
| 拉平后给我贴的那枚加角标 / hover 高亮 | 否决 | 用户口径：靠拖动与收回重贴即可，不要额外标识 |
| 提高 `CROWD_CAP` 到 24 / 32 | 否决 | 不解决「16 被误读成真实票数」，只让画布更吵、DOM 更多 |
| 修比例失真 + 「+N」角标 | **采纳** | 让 16 枚代表"全部票数"的语义成立；少数派颜色不再消失 |
| 「只看我贴过」做成第四档排序 | 否决 | 筛选与排序是两种语义，塞进 `sort` 会让「重新排序 / 顺序冻结」逻辑纠缠 |
| 「只看我贴过」用独立参数 `only=mine` | **采纳** | 与 `sort` 正交、可分享、不触碰现有排序快照机制 |

## 验收标准

1. 1 红 / 100 黑 的影片，画布上**至少 1 枚红点**；100 红 / 1 黑 反向同理；纯色（0 红 / N 黑）不误留另一色。
2. 票数 > 16 时画布出现「+N」角标，`N = 总票数 − 16`；票数 ≤ 16 时不出现。
3. crowd 点与我贴的点**同尺寸、同实心**；crowd 点仍**不可拖**（`pointer-events: none`），
   拖拽落点命中测试不受影响（e2e 的「拖进画布」路径仍通）。
4. hero 大字是全站总票数（红 / 黑拆分可见）；「我的」收成一行小字：标记 x / 已贴 y / 还能贴 z。
5. 勾选「只看我贴过」→ 只列我贴过贴纸的片；取消 → 恢复全量；参数进 URL 且可分享。
6. 回归测试**先红后绿**（红的那次要贴失败值）；收口命令：
   `npm run verify:quick` + `npx playwright test -c playwright.react.config.ts e2e/react/redblack.spec.ts --project=desktop-chromium` 全绿。

## 修订 1（2026-09-22）「有新贴纸 · 重新排序」只在数量变化时才提示

用户原话：

> 红黑榜的刷新只需要在数量变化才需要提示"有新贴纸 重新排序"

**根因**：顺序冻结的提示判据 `orderStale` 拿的是 `votes` 的**对象引用**（`orderRef.current !== votes`）。
每次重拉票数都会得到**新对象**，即便数字一模一样也会被判成「有新贴纸」，提示白亮一次 ——
用户看到的就是「莫名提示重排」。

**改法**：判据换成 `crowdSignature(crowd)`（`redblack.ts`）—— 只串排序真正看的那三个数
（`total` / `red` / `black`）并按 key 排一次，比较字符串值；`RedBlackPage.tsx` 的 `orderKey`
由 `useMemo(() => votes, [votes])` 改为 `useMemo(() => crowdSignature(crowd), [crowd])`。

**验收**：

- `apps/web/tests/redblack.test.ts::crowdSignature`：内容相同 → 签名相同；数量变 / 红黑互换 / 增删片 → 签名变；
  条目换序 → 签名不变（52 passed）。
- `e2e/react/redblack.spec.ts`「重拉同一份票数不算「有新贴纸」」：读接口固定返回同份票数，
  贴一枚触发重拉后 `data-rb-stale` 不再亮起。
