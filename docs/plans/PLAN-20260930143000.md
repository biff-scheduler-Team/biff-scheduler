# PLAN-20260930143000 — 红黑榜卡片重排（信息列两端对齐 + 按钮/海报/胶囊统一）

## 目标
> 用户原话：「请重构当前卡片组件的 UI 布局与样式设计，解决目前散乱、缺乏视知觉秩序的问题」
> 「注意：不要改动既有的 UI 基础结构和业务逻辑代码」

红黑榜 `.rb-card` 的信息列目前是「居中堆叠」：海报 / 片名 / 数字 / 红黑按钮全部浮在列中间，
列底空着 30~40px，按钮悬在半空，卡片读不出上下关系。红 / 黑两枚按钮又是**相反方向歪斜的
不规则形状**（−4° / +4° 的 blob），两张卡并排时看起来更像随手撒的，而不是一组取舍。

## 范围
**做（全部落在 `apps/web/src/pages/redblack-parity.css`，一个文件）：**
- `.rb-card-info`：grid 居中 → **flex 纵向 + `justify-content: space-between`**，
  海报 / 片名在上、红黑按钮落在列的下缘（与右边画布下缘齐平）。
- `.rb-poster`：固定**宽高比 2:3**（`aspect-ratio`，宽 58 / 窄屏 48），圆角 8 → 10，加轻微阴影。
- `.rb-title`：显式 `font-weight: 700`（不再依赖 UA 默认，层次不因全局重置而塌）。
- `.rb-chip`：内边距 2/8 → **3/10**、加 `font-variant-numeric: tabular-nums`（数字对齐）。
- `.rb-src`（红 / 黑）：32 → **36 圆**（去歪斜、去 blob 圆角），统一 `transition` + `:active` 按压缩放，
  补 `:focus-visible` 描边；暂存区间距 8 → 12。
- `.rb-talk`：角距 16 → **12**。
- 窄屏 `@media (max-width: 560px)` 里的 `.rb-poster` 跟着改成只给宽度（高度由比例推）。

**不做（明确否决，避免返工）：**
- **不改 JSX**：类名、`data-rb-*` 契约、DOM 顺序、事件处理一律不动（用户要求 + E2E 按类名断言）。
- **不引 Tailwind 工具类**：红黑榜整页是「一个页面一份 CSS + 既有 token」的口径（AGENTS §5
  「口径单一来源」），混一套工具类进同一张卡等于两套色源 / 两套字阶；用户给的
  `aspect-[2/3]` / `text-lg` 这类写法在本仓库是**禁用**的任意值写法，故只取**设计意图**，在 CSS 里实现。
- 不改 `.rb-card` 的 padding / gap（14px）：它决定画布有多宽，且窄屏那条
  `contain-intrinsic-size` 的估算是按这套值校准的（改了要重测滚动条抖动，与本症状无关）。
- 不改 `.rb-canvas` 的 `min-height`（228，卡片高度的唯一杠杆）、不改贴纸分布（上一轮刚调过）。
- 不改「已贴出 / 未标记」两个状态的**语义与开关**（`data-rb-spent` / `disabled`）。

## 方案取舍
| 备选 | 结论 | 理由 |
|---|---|---|
| 信息列 grid 居中 → flex `space-between` | 采纳 | 只有它能同时做到「固定宽度」与「按钮沉到底」，且不碰 DOM |
| 直接改用 Tailwind 类名重写卡片 | 否决 | 与既有 CSS 口径重复（两套色源）、`text-[Npx]` 类任意值被 AGENTS §5 明令禁止 |
| 给信息列加 `align-items: stretch`（"标准 flex"） | 否决 | 会把 `.rb-poster-box` 撑到 128px 宽，而右上角评分角标是相对**这个盒子**右缘定位的 —— 评分会飘到列的最右边 |
| 海报显式写两处 height（宽 / 窄屏） | 否决 | `aspect-ratio` 一处表达比例，少一个会忘改的地方 |
| 把 `gap` 4 → 8（用户提到的 `gap-2`） | 否决 | 4 本身就是 4 的倍数；而列高进窄屏的 `contain-intrinsic-size` 估算，改了要重测。`space-between` 在宽屏本来就会把多出来的十几像素分给这几条缝 |
| 改红黑按钮为胶囊（`flex-1 py-1.5`） | 否决 | 列宽 128 里两个胶囊会把「贴纸」读成「表单按钮」；圆形 + 36px 既统一又保住贴纸手感 |

## 修订 1（2026-09-30，用户：「贴纸区 和影片信息区稍微调整下 加大贴纸区 然后减少两者之间的空白」）

同一个交付物（卡片版面），故在此追加而不是新开 PLAN。

**症状与成因**：用户看到的「空白」不是那 14px 的缝，而是 **「列宽 − 左列真实内容宽 + 缝」**。
左列最宽的内容是那颗数字胶囊（三位数票时实测 **94px**），列宽 128 时它右边空着 34px，
再加 14px 缝 = **48px 空档**。

**改动**（仍只动 `redblack-parity.css`）：
- `.rb-card` 的 `grid-template-columns: 128px → 108px`、`gap: 14px → 8px`。
  画布 **553 → 579（+26px）**，空档 **48 → 22px（−54%）**。

**实测代价**（playwright / 1512 宽 / 60 张卡）：片名折行 0/60 → **3/60**，
英文名多折一行 7/60 → **10/60**，卡片高度不变（仍是 258）。**108 是下界**：
胶囊 `white-space: nowrap`，列宽小于它的 94px 就会溢出到缝里、压到画布上。

**明确不做**：不动 `.rb-canvas` 的 `min-height`（228）。加高是「贴纸区变大」的另一条杠杆，
但它按卡片等高付费（一屏少半张卡），用户这次的理由是「空白太多」，先只做**不吃高度**的那一半；
要再加高是一行的事，留给他点单。

## 验收标准
1. 卡片在宽屏下读得出「上：影片信息 / 下：红黑两枚按钮」两段，按钮与画布下缘齐平。
2. 红 / 黑两枚按钮**同尺寸正圆、同一水平线**，无歪斜；两者都是实底色（红 `--rb-red` / 黑 `--rb-black`）。
3. `.rb-poster-score` 仍贴海报右上角、`.rb-mark` 仍贴海报左下角（E2E `spec:124-128` 守着）。
4. 卡片高度不变（仍由 `.rb-canvas` 的 `min-height: 228` 决定）—— 宽屏实测信息列内容 ≈ 215 < 228。
5. `npm run verify:quick` 与 `redblack.spec.ts`（桌面 chromium）全绿。
