# PLAN 2026-09-10 01:14:09 — Open Talk 等描边徽章文字贴边:内边距与 KE/GV 统一

> 需求(用户原话):「OPENTALK 的 O 和 K 都贴到卡片边缘了 和这两个 KE GV组件不统一」。
> 本文件 = 本需求唯一规划文档。

## 现状(代码事实,HEAD d5b5d05 + 工作区在途)

- `src/badges.ts` `BADGE_DEFS` 四枚徽章:`gv`/`masterclass` 为实心(`px-1 py-px`),`premiere`/`open_talk` 为描边但 **`px-0` 且无 `py-px`** → 文字与 1px 边框零间距。
  - `premiere` label「首映」中文两字,贴边不明显;
  - `open_talk` label「Open Talk」,两端字母 O / K 直贴左右边框,肉眼即「贴边」。
- 同行参照:等级/字幕(KE)/页码 chip(`legend.ts` CHIP_BASE = `px-[3px] py-px border`)与 GV(`px-1 py-px`)均有水平内边距 → 描边徽章观感与它们不统一。
- 渲染单点:`badgeEl(key)` 全部入口共用(grid 卡徽章行 / agenda 行 / 影片库行 / 详情弹层 / 图例 demo)→ 只改注册表 `cls` 一处全量生效。
- **工作区注意**:另一并行需求(GV 拼接卡 + 红绿灯底色,PLAN-20260910010232 / PLAN-20260910010648)实现仍在工作区未提交,`src/main.ts` 尚缺 `GridCtx.gvTalkOf` → 当前 `npm run typecheck` 报 1 错(main.ts:119),**整体 build/deploy 被阻塞,与本需求无关**;本需求不碰那些文件。

## 方案

- `premiere` / `open_talk` 的 `cls`:`px-0` → `px-[3px]`,并补 `py-px` —— 与 CHIP_BASE(KE/等级/页码)同值,描边徽章与同排 chip 视觉同族(描边类归 KE 口径,不跟实心 GV 的 px-1)。
- 不改字号/字重/圆角/描边色;不新增字段。

## 改动清单

- `src/badges.ts` BADGE_DEFS 两行:
  - `premiere` cls: `px-[3px] py-px text-biff bg-card border border-biff`
  - `open_talk` cls: `px-[3px] py-px text-ink bg-card border border-ink`

## 验收

1. `npm run typecheck` 错误集合与改动前一致(仅并行在途的 main.ts:119 既有错,本需求不新增)。
2. `npx vite build`(绕过被阻塞的 typecheck 步骤)通过;dist CSS 含新 utility,产物可打包。
3. 视觉:Open Talk 徽章文字与边框留 3px 空隙,O/K 不再压线,与同排 KE/GV 协调。

- commit 仅含 `src/badges.ts` + 本 PLAN(不 stage 并行在途文件)。
- push main;deploy 受并行在途 typecheck 错误阻塞 → 与并行需求收尾后统一部署。
