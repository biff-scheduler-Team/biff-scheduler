## 2. 决策

### 2.1 删到什么深度
按用户既有偏好(**移除不想要的功能,而非留 stub / 保留死代码**),本次**连实现一起删**:

1. **UI**:去掉分段控件与本地引擎面板 → 弹层直接是 AI 面板;标题统一 `智能排片 · AI 建议行程`。
2. **`library.ts` 死代码**:`ENGINE_MODES`、`engineRuleBar`、`enginePlansPanel`、`enginePlanBox`、`engineDropSection`、`adoptPlan` 全删(仅被本地引擎调用)。
3. **`engine.ts` 本地求解器**:`suggestPlans` / `mustSolutions` / `buildPlan` / `blocks` / `fits` /
   `blockersOf` / `bestFit` / `maybeWeight` / `describeDrop` / `sortShows` / `Placed` / `planScore` 全删;
   仅本地引擎用的类型也删:`EnginePlan` / `EnginePick` / `EngineDrop` / `DropKind` / `DROP_LABEL` /
   `EngineInput` / `PlanScore` / `PlanScoreParts`。

### 2.2 保留什么(以及为什么)
| 保留 | 理由 |
| --- | --- |
| `scorePlanRows` / `SCORE_W` / `ScoredRow` / `ScoreBreakdown` | 「我的行程」质量分药丸(`main.ts:348`),与排片建议无关 |
| `EngineFilm` | AI 打包入参(`ai.ts:171,498` + `library.ts:503` 都在用),只是名字带 Engine |
| `groupByDate` / `enginePickRow` | AI 结果卡在用(`library.ts:871,874`);**改类型为 `AiPlanPick`**,并把 `enginePickRow` 更名 `aiPickRow`(它已只服务 AI) |

### 2.3 不做的(明确划界)
- **不重命名 `engine.ts` 文件**。它现在只剩质量分 + 共享类型,名字略失准;但 `library.ts` / `main.ts`
  正被**并行会话**写入(`venueShort` 影厅短名 + 甘特缩放),改模块路径会给对方的在途工作副本
  留下失效 import。改文件名收益小、协调成本高 → 只在文件头注释里讲清楚,**并留作可选后续**。
- **不动质量分算法**。删本地引擎不改 `scorePlanRows` 一个字符 —— 否则「我的行程」分数会漂移,
  与本次需求无关。

## 5. 风险与并行会话处置

- **并行会话在途**:`src/library.ts`(+14,`venueLabelOf`)、`src/main.ts`(+38,甘特缩放)、
  `src/legend.ts`(+22)、`src/grid.ts`、`src/types.ts`、`public/venues.json`、`tools/extract_schedule.py`。
  本次要改的 `library.ts` / `main.ts` / `legend.ts` **与对方重叠** → 提交按 SKILL
  **`parallel-agent-safe-commit`**:同文件多处改动**串行 Edit**,提交前用 blob 手术只带自己 hunk,
  dry-run 三重断言(我的标记全在 / 对方标记全不在 / orphan lines = 0)。
- **部署走隔离 worktree**:共享树压着对方在途改动,`npm run deploy` 读磁盘源码 → 必须
  `git worktree add --detach` + 软链 `node_modules`,在隔离树里 build & deploy。
- **删除类改动的主要风险是「删漏」与「删多」**:删漏 → `tsc` 报未用 import;删多 → `tsc` 报缺类型。
  两者都由 typecheck 兜住,所以**必须先跑 typecheck 再提交**。
