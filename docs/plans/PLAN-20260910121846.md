# PLAN 2026-09-10 12:18:46 — 午夜场跨天:统一 24+ 时制(数据侧归一 + 显示层「次日」)

> 需求(用户原话):「如果有午夜场跨天 怎么办呢?」→ 决策:**数据侧 24+ 时制**,写 PLAN 后直接实现。
> 本文件 = 本需求唯一规划文档(每次需求独立建 PLAN,不再通读 PLAN.md)。

## 背景(排查结论,已实测)

真数据里就有:2025 册子(699 场)含 **4 场 Midnight Passion 通宵场**,`23:59 → 次日 05:26~06:04`(5.6~6h):
`008`(09-18)、`081`(09-19)、`164`(09-20)、`244`(09-21)。

根因 = **信息在解析器出口被抹平**:`tools/extract_schedule.py:313-314` 内部已 `if end <= start: end += 24*60`,
但 `:482` 输出 `f"{(end_min//60)%24:02d}:{end_min%60:02d}"` 把 24h 溢出折回 → 前端拿到 `start_time:"23:59" / end_time:"05:35"`(`end < start`)。

实测崩点(esbuild 打包真实 `util/gv/conflict/ics` 跑探针 + 复制 `axisRangeFor`):

| # | 消费点 | 位置 | 现象 |
|---|--------|------|------|
| 1 | 轴界 | `grid.ts:40` | `last` 取到 335 被当日 22:44 盖过 → 轴止于 23:00,午夜场**完全在轴外** |
| 2 | 卡片几何 | `grid.ts:393-395` | `left=2877px`(轨道仅 2700px)、`width=−3316px` → 负值被忽略 → 卡片戳在轨道外 |
| 3 | 整点筛选 | `grid.ts:399-401` | 22/23/00 段全 false → 任何整点筛选都把午夜场 `hour-dim` |
| 4 | 冲突检测 | `conflict.ts:42` | 午夜场 `end` 最小,排序后 `b.start >= a.end` 立即 break → 0 对 |
| 5 | GV 映后谈 | `gv.ts:16` | `(335−1439)−dur < 0` → 归零 → 映后谈被吞、不拆卡 |
| 6 | ICS | `ics.ts:87` | `DTEND` 落在 `DTSTART` 前一天(负 18.4h)→ 非法事件 |

## 口径决定:24+ 时制

`end_time` 允许 ≥ `"24:00"`(如 `"29:35"` = 次日 05:35)。**算术与 ICS 进位天然正确**,只改显示层:

- `hmsToMin("29:35") = 1775` → 轴界 / 卡片宽度 / 排序 / `hourFilter` / `gvTalkMin` / 冲突 全部无需改动;
- `toUtcStamp` 走 `Date.UTC(y,m-1,d,h,min)`,JS 自动进位次日 —— 实测 `toUtcStamp("2025-09-18","29:35")` → `20250918T203500Z`,时长 5.6h ✅;
- 不选「前端归一化」(碰 7 个文件、漏一处即静默错,同 `subs` 多值那次);不选 `end_next_day` 新字段(等同归一化 + 1 字段)。

## 本次改动

### 1. 数据侧(2 处)

- **`tools/extract_schedule.py:482`**:去掉 `% 24` → `end_time` 输出 `"29:35"`;新增 `stats["cross_midnight"]` 计数 + 汇总打印(跨天场次一目了然)。
- **`src/data.ts` `loadCatalog()`**:加**唯一归一化闸门** —— 逐场检查 `hmsToMin(end_time) <= hmsToMin(start_time)` 时原地补 `+1440` 并写回 `end_time`。
  作用:① 与解析器同口径的兜底;② 手改 / 旧版 JSON 也能自愈(单点收口,所有消费方都读同一批对象)。

### 2. 显示层(`src/util.ts` 新增 4 个 helper,`fmtMinRange` 就地升级)

```ts
minToClock(min)      // 折回 24h 内:1775 → "05:35"
nextDayTag(min)      // min ≥ 1440 → "次日 ",否则 ""
fmtEndClock(min)     // nextDayTag + minToClock:1775 → "次日 05:35"
fmtMinRange(a, b)    // "23:59–次日 05:35";同日输出与旧实现**逐字节相同**(兼容既有调用)
```

`fmtMinRange` 是既有公共出口 → **`grid.ts:412`(普通卡)与 `modal.ts:242` 自动修好,无需改动**(`modal.ts` 正被并行会话编辑,刻意不碰)。
