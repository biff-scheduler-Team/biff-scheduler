# PLAN-20260923182810 — 红黑榜收回贴纸后画布残留（乐观撤销）

## 目标

用户原话：

> 红黑榜 收回贴纸之后 贴纸仍残留 然后过一段时间才刷新

## 现状（代码事实，带位置；不是推测）

「别人的贴纸」（画布上的只读小点）= `othersOf(counts, mine)`：

- `counts` = **服务端**聚合票数（`film-votes.ts::loadFilmVotes` → `/api/stats/film-votes`），
  **上报落地后才含我自己这一票**；
- `mine` = 本地 board 里我贴的那几枚（`redblack.ts::countsOf`）。

上报链路（`film-votes.ts:96-119`）：贴 / 收 → `scheduleFilmVotesPing` **1200ms 防抖** → POST
→ 成功后 `loadFilmVotes(true)` 重拉。

于是「收回」有一个 **≥1200ms + 一次网络往返** 的窗口：

| 时刻 | 本地 `mine` | 服务端 `counts` | `others = counts − mine` | 用户看到 |
|---|---|---|---|---|
| 收回前 | 1 枚 | 含我（N） | N−1 | DOM 1 枚 + 画布 N−1 枚 = N ✓ |
| **收回瞬间** | **0** | **仍含我（N，还没撤）** | **N** | DOM 0 枚 + 画布 **N** 枚 = **N** ← 「贴纸仍残留」 |
| 重拉之后 | 0 | N−1 | N−1 | N−1 ✓（「过一段时间才刷新」） |

根因：`othersOf` 用**本地当前票**（`mine`）当扣减基准，而它要扣的其实是
**「服务端那份 `counts` 里属于我的部分」** —— 这两者在「本地已变、服务端未变」的窗口里不相等，
而 `Math.max(0, …)` 的夹取只能兜住方向上的一半（贴上那半边），兜不住收回这半边。

⚠ 贴上方向有对称的 ±1 误差（贴一枚时 `others` 瞬时少画一枚别人的），同一处根因，一并修。

## 方案取舍

| 备选 | 结论 | 理由 |
|---|---|---|
| 收回时立即上报（去掉防抖） | 否决 | 仍要等一次 RTT，残留窗口只是变短不是消失；且拖拽落点也会触发上报 |
| 本地维护「待同步队列」 | 否决 | `film-votes.ts` 已定「整份替换」口径（断网重报即自愈），加队列等于第二套同步模型 |
| 引入 `synced`（**服务端已确认含我**的那份票）快照，扣减基准由 `mine` 换成 `synced` | **采纳** | 语义单一且可证：`counts` 里属于我的部分**就是** `synced`；两个方向同时修正，只在同步成功那一刻切换，无跳动 |

## 设计

1. **`film-votes.ts`** —— 新增内存态 `synced`（`FilmVoteCounts` 形状）：
   - `peekSyncedVotes()` / `adoptSyncedVotes(votes)`；
   - ping **成功后先** `adoptSyncedVotes(本次上报的那份)`（**不广播**），**再** `loadFilmVotes(true)`
     —— 后者自己广播，让新的 `counts` 与新的 `synced` 在**同一次** emit 里生效（否则会出现
     「贴纸先涨回一枚再降下去」的跳动）；
   - 上报失败一律不动 `synced`（本地保持乐观，下次成功时自愈）。
2. **`redblack.ts`** —— 新增纯函数 `reconcile(counts, serverMine, mine)`
   = `max(0, counts − serverMine) + mine`（每色独立夹取，防服务端已撤而本地仍以为含我时负数）。
3. **`RedBlackPage.tsx`**：
   - mount 时 `adoptSyncedVotes(votesOf(boot.board))` —— 同一设备的历史票，服务端那份本就含我；
     不这么做首屏会把它当「别人的票」多画一遍（**新增的状态必须有初值**）；
   - `filmCounts` 改为 reconcile 的产物，并带**引用缓存**（值不变则沿用旧对象）
     —— `RbCard` 是 `memo` 的，「每次重算都造新对象」会毁掉整轮性能修复（PLAN-20260922145815）；
   - 卡片 / hero / 分享图统一用 reconcile 后的 counts；**排序仍按服务端 `counts`**
     （顺序本来就冻结，且 `orderStale` 的判据不该被自己的一票触发）。
4. **画布与弹层不用改**：卡片内 `othersOf(counts, mine)` 在拿到 reconcile 后的 counts 时，
   结果恰为 `counts − synced` —— 原公式的位置不变，只换入参口径（口径单一来源，§5）。

## 明确不做

- ❌ 不改 1200ms 防抖与上报时序。
- ❌ 不动 `biff.*` 数据结构（`synced` 是内存态，不落盘、不进 localStorage）。
- ❌ 不改排序口径（`sortByCounts` / `orderKey` 仍看服务端计数）。
- ❌ 不动分享图的绘制与分节逻辑。

## 验收标准

1. 单测：`reconcile` 覆盖四态（服务端含我 / 未含我 × 我贴 / 我未贴）+ 负数夹取。
2. 单测：ping 成功后 `peekSyncedVotes()` 等于刚上报的那份；上报失败时不变。
3. E2E：`贴一枚 → 上报落地 → 单击收回`，**在防抖窗口内**断言 `data-rb-crowd` 立刻回落到
   收回前的值（旧实现会多出 1 枚 —— 先红后绿）。
4. 现有 `e2e/react/redblack.spec.ts` 全绿（尤其 134-156 / 319-355 那几条「服务端票数含我」的用例）。
