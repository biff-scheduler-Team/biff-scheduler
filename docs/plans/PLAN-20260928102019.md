# PLAN-20260928102019 — 红黑榜贴纸「操作链路」的性能与交互优化

## 目标

> 用户原话：「红黑榜 除了贴纸渲染本身 贴贴纸/移除贴纸这样的操作有什么可以优化的地方吗?性能和操作逻辑上」
> 追加指令：「全部都改」

渲染层（canvas 群点 + 三层 memo + `useInView` 视口按需 + sprite 缓存）已在
`PLAN-20260922145815` / `PLAN-20260928003736` 收过一轮。本轮**只动操作链路**：
一次「贴 / 收 / 换色 / 拖」从指针按下到落盘、上报、重渲染的全过程。

## 范围

**做**（12 条，编号沿用讨论清单）：

| # | 改动 | 落点 |
|---|---|---|
| ① | 拖拽落点判定去掉每帧 `document.elementFromPoint`，改源片画布 rect + 数学判定 | `RedBlackPage.tsx::beginDrag` |
| ② | 上报触发依赖从 `board` 对象换成「票的签名」——**拖位置不再触发上报** | `redblack.ts` + `RedBlackPage.tsx` |
| ③ | `reconciledCrowd` / `tallies` / `filmCounts` / `totals` / `visible` 的依赖同样改走票签名，拖位置不再打整轮重算 | `RedBlackPage.tsx` |
| ④ | 写盘分级：「挪位置」延到 rAF + `pagehide` 兜底；「贴 / 收 / 换色」保持同步立即写 | `redblack.ts` + `RedBlackPage.tsx` |
| ⑤ | `film-votes-ping` 直接返回最新聚合，前端省掉「上报成功再重拉」的那次 GET | `apps/api/src/index.ts` + `film-vote-store.ts` + `film-votes.ts` |
| ⑥ | 上报超 `MAX_VOTES_PER_PING` 改为**分批**，不再静默丢弃尾部的票 | `film-votes.ts` |
| ⑦ | 收回贴纸可**撤销**（Toast `actionLabel`，恢复原 id / 颜色 / 坐标） | `RedBlackPage.tsx` |
| ⑧ | 暂存区点**另一色** = 原地换色（保留位置），不再要求「先收回再重贴」 | `redblack.ts` + `RedBlackPage.tsx` + CSS |
| ⑨ | 多标签页同步：监听 `storage` 事件重读 board / watched | `RedBlackPage.tsx` |
| ⑩ | 上报失败给一次弱提示，不再完全静默 | `film-votes.ts` + `RedBlackPage.tsx` |
| ⑪ | 拖拽**落点预览**：画布内按真实相对坐标同步一枚半透明贴纸 | `RedBlackPage.tsx` + CSS |
| ⑫ | 小项：暂存区 `aria-disabled`、贴纸方向键微调、`freshKey` 单值 → `Set` | `RedBlackPage.tsx` |

**不做**：

- 贴纸**渲染本身**（`StickerCanvas` / `sticker-sprite` / `sticker-canvas-guard` /
  `use-in-view` / `shared-resize-observer`）—— 本轮一行不碰。
- 服务端**表结构 / 迁移**（⑤ 只改响应体，不加列）。
- 拖拽期的边缘自动滚动（单张卡画布高度有限，不需要）。
- 「一部一枚」的配额口径、「单击收回」「张贴区按片独立」三条既有交互口径**不变**。

## 方案取舍

| 备选 | 结论 | 理由 |
|---|---|---|
| ① 保留 `elementFromPoint`，只降频 | 否决 | 判据本来就只需要**源片自己那一块**画布的 rect；能降成一次矩形比较，没有理由留在全页 hit-test |
| ① 拖拽开始缓存**全部** 300 个画布 rect | 否决 | 只有「落点是不是源片画布」这一个问题要回答，缓存 300 个是白建 |
| ② 把 `board` 拆成「票」「坐标」两个 state | 否决 | 牵连 `RbCard` 的 prop 形状与既有测试；改依赖签名能达到同样效果，改动面小一个数量级 |
| ③ 让 `reconciledCrowd` 增量更新单 key | 否决 | 300 项 Map 重建是微秒级，不是瓶颈；只解决「拖动不该打整轮」这一点即可 |
| ④ 所有写盘都延后 | 否决 | 贴 / 收是语义操作，崩溃丢一次就是「贴了没了」；只有「挪位置」是装饰性写入，值得延后 |
| ⑤ 前端自己乐观拼 counts | 否决 | 会造出「我这一票算两遍」的第二套口径（与 `reconcile` 打架）；让服务端一次回全量最干净 |
| ⑧ 长按 / 右键换色 | 否决 | 触屏长按与拖拽起手冲突；且要新造一个手势。暂存区点另一色即可原地换色，零新交互 |
| ⑧ 单击贴纸弹「换色 / 收回」菜单 | 否决 | 改掉用户已定的「单击 = 收回」口径，且多一层弹层 |
| ⑦ 为「贴一枚」也加撤销 | 否决 | 贴已有 fresh 描边确认，且再点一下就收回；给它加撤销等于同一件事两个出口 |

## 实施结果（2026-09-28）

### 与原计划的偏差（都在实现期被代码推翻）

| # | 原计划 | 实际 | 为什么改 |
|---|---|---|---|
| ⑥ | 「改为**分批**上报」 | **累积前缀**分批 | 动手才读到 `replaceContributorVotes` 是「**整份替换**」语义 —— 切成互不相交的块会让后一块盖掉前一块，等于只发了最后一块（那正是原来 `slice(0, MAX)` 的隐患：超出的票**永远**不上报且完全静默）。所以第 k 批发 `[0, k × MAX)`，最后一批即全量 |
| ④ | 「挪位置延后写盘」 | 照做，但**收益近似为 0** | 一次写盘 = 全量 `JSON.stringify`（~15KB）+ 同步 `setItem`，量级 1ms 以下；而拖动松手是离散事件，本来也合并不到什么。保留它的真正价值是**把「装饰性写入」与「语义写入」分开**，不当性能收益宣传 |
| ⑫ | spent / aria / 键盘微调 / `freshKeys` | 照做，外加一处口径收紧 | 暂存区 `data-rb-spent` 的语义同步改成「只有**当前已贴的那一色**算 spent」—— 否则另一色会被读成「不能点」，而它恰恰是 ⑧ 的换色入口 |

### 一处返工（code review 第 1 轮发现）

落点预览最初用 `left` / `top` 百分比定位。那是**布局属性**，拖拽期间每帧写等于每帧触发一次 layout 重算 —— 正好抵消 ① 省下来的开销。改为负 `margin` 居中 + `transform: translate3d(px, …)`（只走合成层），并让它在创建时先 `display: none`（否则会在画布左上角闪一帧）。第 2 轮只看该增量，无新问题。
