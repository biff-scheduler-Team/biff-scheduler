## 方案取舍

| 备选 | 结论 | 理由 |
|---|---|---|
| **本地解析 `hours` 文本**(采纳) | 采纳 | 数据已在手上,零外部依赖、零配额;36/87 家有营业时间,其余落 `unknown` |
| 接 Places API 拿 `opening_hours` | 否决 | 只有 1,000 次/月免费、要跑 87 次/天;且 Naver 那批店在 Google 上多半没有条目 |
| 把营业状态烘进 `eats.json` | 否决 | 静态产物会过期 —— 今天写「营业中」明天就是错的 |
| 判定粒度:`open` / `closed` / `unknown` 三态(**采纳**) | 采纳 | 用户裁决「仅显示确定开着的」。认不出来的写法回 `unknown` 并被过滤掉,**不猜** |
| 时区用 `Intl` + `timeZone: "Asia/Seoul"` | 否决 | 韩国 1988 年起无夏令时,恒为 UTC+9;手算偏移比依赖 ICU 数据更可预测,也免掉单测环境差异 |
| 「营业中」用 `Picker`(全部/营业中) | 否决 | 这是布尔开关不是枚举;用 `ToggleButton` 与排片表日期条、FilterBar 同款 |
| 加 60 秒心跳刷新 `now` | 采纳(仅开关打开时) | 筛选关着时不该有形变;开着时跨过打烊时刻要能自己翻脸 |

### `hours` 实际写法(全 36 条已核对,解析器必须覆盖)

`11:00-21:00` / `24小时营业` / `17:30-2:30`、`11:00-4:00`、`10:00-1:00`(**跨午夜**) /
`10:00-19:00（周日休息）` / `8:00-21:30 · （周五周六休息）` / `12:00-23:00（10/6休息）` /
`周一到周五08:00-19:00 · 周末09:00 ~ 19:00`(一天内两段日程) /
`11:00-21:00 · 15:00-17:00休息 · 20:00LAST ORDER`(午休 + LAST ORDER) /
`07:30-24:00 · 13:00-15:00休息` / `周二-周日11:00-21:00` / `周一-周六 08:00-21:30` /
`周一到周五11:00-18:30 14:50 -16:00休息 · 周末节假日休息`。

### 判定规则(写进模块注释,是唯一口径)

1. 先扫 `M/D休息`:今天(釜山)是该日期 → `closed`。
2. `24小时营业` → `open`(**在日期休息之后判定**)。
3. 按 `·` 切段,每段抽「时间区间」与「星期限定」:
   - 区间**紧跟 `休息`** → 记为休息段(午休),不是营业窗口;
   - 段落里带星期限定(`周一到周五` / `周末` / `周二-周日`)且**不带 `休息`** → 这批窗口只在这些星期生效;
   - 段落**没有时间区间**又含 `休息`(或含 `休息` 且带星期词)→ 整日闭店条款;
   - 段落后仍有没归类的 `休息` → 认不出来,整条回 `unknown`(**保守兜底**)。
4. 闭店条款命中今天星期 → `closed`;条款里出现 `节假日` 而今天不是命中的周末 → `unknown`
   (韩国公休日无法离线枚举,10 月正好有开天节 / 韩文节)。
5. 跨午夜:结束时间 ≤ 开始时间时 `+24h`;判定时同时看「今天的窗口」和「昨天溢出到今天的窗口」。
6. 一个窗口都没有(空串、纯文字说明)→ `unknown`。
7. 今天没有任何生效窗口(**且**没被闭店条款命中)→ `closed`(日程只写了某几天 = 其余天不营业)。
