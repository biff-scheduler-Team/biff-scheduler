# PLAN-20261012105322 — 红黑榜搜索后 hero「全站」总览数字不该变化

## 目标

红黑榜页顶部「全站 / N 枚贴纸 / 红 X · 黑 Y」这块总览，输入场次编号搜索后数字会变化。

> 用户原话：「红黑榜输入编号搜索后 总览上面的这个数字会变化 "424 枚贴纸 红 289 · 黑 135"」

正确口径：「全站」= **整份榜单**（`boardFilms(films)`）的票数之和，与搜索词无关。
搜索只该缩减下面的卡片，不该动 hero。

## 范围

**做:**

- 修 `apps/web/src/pages/RedBlackPage.tsx`：`totals` 的全站红 / 黑改为按 `boardKeys`（整份榜单）+ `reconciledCrowd` 累加，而不是 `filmCounts`（只有当前搜索命中的那几部）。
- 同一处 bug 的连带项：`totals` 的「我的」三格（标记看过 / 已贴 / 还能贴）也来自 `tallies`，而 `tallies` 同样只覆盖 `sorted` —— 一并把 `tallies` 的口径改成整份榜单。
- 补一条 E2E 回归（`e2e/react/redblack.spec.ts`）：搜索前后 hero 全站数字逐字不变。

**不做:**

- 不动排序冻结（`orderRef` / `orderStale`）逻辑。
- 不动卡片内每部的红黑数字（那是「这一部」的口径，本来就该跟着卡片走）。
- 不动分享图（它已经在用全量的 `reconciledCrowd`）。

## 方案取舍

| 备选 | 结论 | 理由 |
|---|---|---|
| 全站数字改从 `reconciledCrowd` 按 `boardKeys` 累加 | 采纳 | `filmCounts` 是 `sorted`（搜索过滤后）派生的；`boardKeys` 就是整份榜单，口径与「分享图用全量」那条既有注释完全一致 |
| 直接 `reconciledCrowd.values()` 全量累加 | 否决 | 会把「不在当前榜单」（无排期的目录片 / 旧届残留）的票也算进 hero，与改版前「空搜索时」的数字不一致 —— 属于顺手改了另一件事 |
| 只修全站三格、不动 `tallies` | 否决 | `tallies` 同源同病：「我的」三格一样会随搜索缩水，只修一半等于留半个 bug |

## 验收标准

1. `e2e/react/redblack.spec.ts` 新增用例通过：输入编号搜索前后，`.rb-global-num` 与 `.rb-global-split` 逐字相同。
2. 未搜索时 hero 数字与改前一致（空搜索 = 整份榜单，本就相等）。
3. typecheck / lint 通过。
