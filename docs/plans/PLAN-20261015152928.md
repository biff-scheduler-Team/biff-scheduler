# PLAN-20261015152928 — 窄屏上把「榜单」页的 hero 收成一条

## 目标

> 用户原话（配移动端截图）：「这个榜单占移动端太多的内容了基本其他都不可见了」

截图是 390px 宽的手机：红底 hero（`划过就投` / **榜单** / 一句规则 / 全站 676 枚贴纸 红 475 · 黑 201 / 已贴 30）
在竖屏里占掉约三分之一以上的高度，栅格（真正的内容）整个被顶到首屏之外。

## 范围

**做**

- `apps/web/src/pages/redblack-parity.css`：给 `.rb-hero` 及其内部几块（`.rb-eyebrow` / `.rb-hero h1` /
  `.rb-lede` / `.rb-totals` / `.rb-stat-card` / `.rb-global-num`）加一条 `@media (max-width: 560px)` 覆盖：
  收紧内边距与间距、缩小标题与「全站」数字、把「全站卡片 + 已贴徽章」从竖排改成**一行横排**。
- `e2e/react/redblack.spec.ts`：加一条**高度预算**回归测试（390×844），先在旧样式上**红**、修完**绿**。

**不做**

- 不动任何文案、不删任何信息（`?` 完整规则、全站 / 红黑拆分 / 已贴 都保留）。
- 不动 `.rb-controls`（搜索框 / 排序 / 筛选那一排）——用户这一轮指的是那块红底 hero。
- 不动 JSX 结构（`.rb-global` / `.rb-global-num` / `.rb-global-split` 是 E2E 的机读契约，逐字保留）。
- 不动桌面端（≥ 561px 的版面一个像素都不变）。
- 不动热门榜（`.hb-masthead` 本来就是一行紧凑布局）。

## 方案取舍

| 备选 | 结论 | 理由 |
|---|---|---|
| 窄屏直接隐藏 hero（或折叠成一行标题） | 否决 | 全站票数 / 已贴数是这一页唯一的「榜有多大」的读数，藏起来等于换了个页面 |
| 把规则正文收进 `?`，窄屏不显示那句话 | 否决 | `?` 在 `.rb-lede` **内部**，隐藏正文会连入口一起藏掉；且首屏一句「怎么用」是必要的 |
| 只改 `@media`、结构与文案一个字不动 | **采纳** | 症状是「版面占得太高」，不是「信息不对」；纯 CSS 覆盖的回归面最小 |
| 顺手把 `.rb-controls` 也压一压 | 否决 | 超出本轮症状；搜索框是这一页第二重要的入口，压缩它要单独评估 |

## 验收标准

1. 390×844 下 `.rb-hero` 高度 **≤ 150px**（旧样式实测 **293.7px**，≈ 35% 可视高；修完实测 **138.3px**）。
2. 修复前这条测试**红**（实测 `Received: 293.734375`），修复后**绿**。
3. 桌面 1512×982 上 hero 与其他既有断言（`.rb-global-num` / `.rb-global-split` 的逐字断言）逐字不变。
4. `node scripts/affected-specs.mjs --files apps/web/src/pages/redblack-parity.css` 命中
   `e2e/react/redblack.spec.ts` → 按 §4.5 走 PR（推之前等用户确认）。
