# PLAN-20260923101147 — 红黑榜：张贴区按片独立 + 拖拽不再慢半拍

## 目标

> 发现问题1.从 A 电影张贴区的贴纸 移到 B 电影的 会直接被贴上 我认为应该贴纸张贴区应该是电影之间独立的
> 2.而且张贴贴纸和收回贴纸总有延迟

两件事：

1. **张贴区按片独立**。现在把《A》画布上那一枚拖到《B》的卡片上松手，`moveSticker` 会把《A》的票
   **搬到《B》头上**（`redblack.ts:314-326` 的跨片分支，且 aria-label 明文写着「拖动可挪位置或挪到别的片」）。
   口径改为：**一枚贴纸只属于它那一部电影的张贴区**，别片的画布不是落点。
2. **拖拽不再慢半拍**。`pointermove/pointerup` 挂在 `useEffect([drag])` 里 —— 要等 `setDrag` 触发的那次
   渲染提交、副作用跑完才生效，起手几帧的移动会被丢；而且每个 `pointermove` 都做两次
   `elementFromPoint()`（`canvasAt` + `cardAt`）并改一次 ghost 的 `transform`，300 张卡的页面上
   指针跑得比 ghost 快。这两个合起来就是「总有延迟」。

## 范围

**做：**

- `apps/web/src/redblack.ts`：`moveSticker` 去掉跨片能力（签名去掉 `toKey`），只改坐标。
- `apps/web/src/pages/RedBlackPage.tsx`：
  - 拖拽的「源影片」变成一等字段（`RbDrag.srcKey`），暂存区那两枚也带上自己的 `film.key`；
  - 落点不是本片画布 → 已贴的**收回暂存区**（沿用既有出口与文案），从暂存区拖出的**什么也不做**；
  - 拖拽高亮只落在**本片**卡片上（别片不再亮成落点，避免误导）；
  - 拖拽改成**同步挂监听 + rAF 合并**：`beginDrag` 里直接 `addEventListener`，不再经 `drag` state 与
    `useEffect`；`pointermove` 只记最后一个点，命中测试与 ghost 位移合并到一帧一次；
  - 去掉 `drag` state（它只被那个 effect 用，JSX 里根本没用）→ 拖拽起手少一次整页重渲染。
- 回归测试：单测改 `moveSticker` 口径 + 新增 E2E「跨片拖拽不落到别片」。

**不做：**

- 不动 `film-votes.ts` 的 1200ms 上报防抖（那是**服务端票数**的节奏，与拖拽手感无关，
  且「画布上那一枚立刻可见 + 闪描边」已经给了即时反馈）。
- 不动 `StickerCanvas` / 分享图 / 放大弹层 / 排序与冻结机制。
- 不改 `biff.*` 任何存储结构（贴纸数据模型一个字没变）。
- 不做「跨片拖拽 = 把票转给别片」这种新能力。

## 方案取舍

| 备选 | 结论 | 理由 |
|---|---|---|
| 跨片落点 → **不搬迁、弹回原处** | 否决 | 同一张卡内松手才叫「挪位置」，落到别片却原地不动会读成「拖了但没反应」；且与既有出口「拖出画布 = 收回」冲突 |
| 跨片落点 → **收回暂存区**（沿用既有出口） | **采纳** | 不新增规则：画布的边界从「任一画布」收窄为「**这一部自己的**画布」，出界仍是收回；收回可逆（暂存区就在旁边，点一下就贴回来），文案复用「《X》的贴纸收回暂存区了」 |
| 跨片落点 → 弹 toast 讲规则 | 否决 | 收回本身已经是一条 toast，再叠一条会把「发生了什么」讲糊 |
| 暂存区的贴纸也放开落点（保持现状：可拖到别片贴上） | 否决 | 暂存区是「《A》的贴纸暂存区」，同一口径；否则同一个 bug 换个入口立刻复发 |
| 保留 `moveSticker` 的 `toKey`，在视图层拦跨片 | 否决 | 数据层留一个永远不该被调用的路径 = 给下次复发留门；跨片判断只留在视图层（`finishRef`）一处 |
| 用 `useEffect` 继续管监听，只加 rAF | 否决 | 起手的丢帧正是 effect 晚挂造成的，rAF 治不了它 |
| 给拖拽加 `setPointerCapture` | 否决 | pointerdown 的元素是贴纸本身，capture 之后 `elementFromPoint` 仍可取落点，但会改变 click 合成行为（`takeBackByTap` 依赖它），风险大于收益 |

## 验收标准

1. 标记《A》《B》看过 → 给《A》贴一枚 → 把它拖到《B》的画布上松手：
   **《B》的 `.rb-dot` 计数不变（0）、《B》卡片上的红/黑数字不变**；页面上不会再出现第二枚贴纸。
2. 拖拽过程中 `data-rb-hover` 只会出现在**本片**卡片上（别片不亮）。
3. 已有行为不回归：同片内拖动仍是「挪位置」而不是「收回」；拖到页面空白处仍是收回；
   点一下贴纸仍是收回；暂存区点一下仍是随机贴。
4. `npm run verify:ui -- e2e/react/redblack.spec.ts --project=desktop-chromium` 全绿；
   单测 `redblack.test.ts` 全绿。

## 修订 1（2026-09-23，用户追加三问）

用户问：「为什么要顺带那次 setState 就是一次 300 张卡的整页重渲染? 只重新渲染单独那个电影可以吗?
能否实现自己贴的贴纸始终能被自己拖动? 」

1. **原来那句注释是错的**，已订正：`RbCard` 是 `memo` 的，那次 `setState` 只换来「父组件跑一遍 +
   300 次 `memo` 浅比较」，卡片**不会**重渲染 —— 它是白做的一拍，不是延迟主因。
2. **「只重渲染单独那个电影」本来就是现状**，且已**实测**（用户要求给数）：299 张卡挂载下，
   点「标记看过」→ **1 张**、点「贴一枚」→ **1 张**、2.4s 后描边撤掉那一拍 → 也只动同一张。
   数据写进 `RbCard` 的 memo 注释；口径：临时 `data-rb-renders` 计数器 + `dispatchEvent("click")`
   （用 `.click()` 会因自动滚动让预取边界卡触发 `IntersectionObserver`，凭空多出 6 张 —— 踩过）。
3. **「自己的贴纸始终能拖」本来就成立**（真实 DOM / 压在最上层 / 不参与按视口省渲染 /
   `touch-action: none`），新增一条 E2E 把它钉住；顺带补 `.rb-src { touch-action: none }`：
   触屏上「从暂存区拖到画布」原先拖不起来（浏览器把手势判成滚动并补发 `pointercancel`）。
   ⚠ `.rb-canvas` **不**加（它占卡片右半张，加了手机没法滚页面）。

**待定（等用户拍形态）**：「我贴的那一枚」加**常驻**辨识 —— 会放宽 2026-09-22「完全拉平，
只靠能不能拖区分」的口径。候选见对话：A 常驻纸白边（推荐）/ B 小角标 / C 只垫高落影。

## 修订 2（2026-09-23，形态拍板）

用户选 **A：常驻纸白边**。实现：`.rb-dot` 的 `box-shadow` 里插一层 `0 0 0 1.5px rgb(255 255 255 / 88%)`
（在既有内高光之后、外落影之前）—— 纯 CSS，零 JS、零渲染成本，不影响「贴一枚只重渲染 1 张卡」的实测。

- **用白不用 `--brand`**：品牌红 `#ce1e36` 与红贴纸 `--rb-red` `#cf3b52` 几乎同色，红圈在红贴上等于没画。
- `sticker-sprite.ts`（群点）**不跟着加**这一圈 —— 差异只许单向存在；已在 `.rb-ink` 与本节文件头注明。
- 「刚贴」那 2.4s 的 `--brand` 3px 描边**保留**，读起来是「在常驻白边之上又亮一档」，不是两套语言。
- E2E 把口径改名并加断言：`「别人的贴纸」与我贴的那枚同尺寸,只差常驻纸白边与能不能拖`
  （断言只认那一层 `1.5px` 的圈：整个 `box-shadow` 字符串各浏览器序列化不同）。
- 肉眼复核：票数 100 枚的场面下出过一张整画布 + 一张 1:1 特写截图（`.scratch/ring*.png`，未检入），
  那枚在白圈里读得出、与相邻群点区分明显。

## 修订 3（2026-09-23，用户报「点标记看过整页闪一下」）

> 「标记看过 未看过 这个按钮 即使我没有进行贴贴纸动作 好像会触发重新渲染 整个贴纸页面好像闪了一下」

**不是 React 渲染 —— 是布局位移**（探针实测：`.rb-grid` 文档坐标 `434 → 381`，**上移 53px**；
`.rb-hint` 高度 38px，点完之后整条消失）。点「取消标记」再跳回来。

**根因**：空榜引导条的条件混了两个口径 ——

```tsx
{totals.marked === 0 && totals.total === 0 && <p className="rb-hint">…</p>}
```

文案说的是「**榜**还是空的」（= 全站票数 `totals.total`），条件里却塞了 `totals.marked`（本地
「我看过」）。于是每点一次标记，这条挂在**栅格上方**的提示就收放一次，整页跟着挪。

**修法**：条件收敛为 `totals.total === 0` —— 一处口径，改完点标记/取消标记 **0 位移**。
残留：全站第一枚贴纸到达（异步、用户没在操作）时它会收一次；若要连这一处也消除，得让它不占文档流
（改浮层或 toast），但那会改动「怎么开始」的呈现方式，等用户提。

**回归测试**：`点「标记看过」不会把整页顶上去`，判据用**文档坐标**（`rect.top + scrollY`）——
⚠ 不能用视口坐标：Playwright 为点击会自己滚页面，量到的会是滚动不是布局位移（这次差点被骗过去，
`.click()` 把 `scrollY` 弄到 782，害我一度以为滚动才是主因）。
先红后绿：旧条件下断言 `Expected: 434 / Received: 381`。
