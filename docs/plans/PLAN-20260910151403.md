# PLAN-20260910151403 — AI 排片日期 chips 默认全选 → 默认全不选

## 背景 / 用户诉求

> 排哪几天 默认全不选 不要默认全选

(配图:用户仅勾了 9/21(周日)一天,文案还显示「② 排哪几天(默认全选)」,与用户实际行为矛盾。)

**问题**:当前 `selDates` 默认 = `new Set(ctx.cat.dates)`(全 10 天),开弹层瞬间就「全选」——
- 与最近一次改动(默认无片单模式下排得贪心)叠加,易出现「开弹层→直接点开始」= 把 10 天
  700 场全量送给 LLM,白烧 token;
- 用户反馈明确:希望**默认全不选**,让用户主动决定要哪几天,避免误操作把 10 天
  payload 一次性发出。

**功能影响**:
- ① 跑得动:「④ 开始 AI 排片」按钮在 0 天时已禁用(`runBar` 的 `noDate` 分支,见
  `library.ts` 现有 `BTN_DISABLED` + `disabled` 守卫),开弹层后不可点 → 强制用户选日。
- ② 状态提示就位:foot 状态在 0 天时显示红色「至少要选一天才能排片」(已实现),
  runBar 文字显示「请至少选择一天」(已实现),不需要新增 UI。
- ③ 已有「全选/全不选」按钮 + 逐 chip 切换保留,功能不丢。

## 设计决策

1. **`selDates` 默认 = 空 Set**:`new Set<string>()`(原 `new Set(ctx.cat.dates)`)。
2. **标题文案同步**:`② 排哪几天(默认全选)` → `② 排哪几天(默认全不选)`(把意图写在标题里,
   一眼看到「默认啥都没选」;下方红色状态已自带「至少要选一天」提示,不重复)。
3. **代码注释 / 文档同步**:之前「默认全选 = 与旧行为逐字节一致」的措辞是向后兼容说明,
   此次明确改默认 → 同步更新:
   - `src/library.ts` 的 `selDates` 上方块注释(改为「默认全不选 — 防误操作」);
   - `src/ai.ts::buildPayload` 上方块注释「默认全选 = 与旧行为逐字节一致」→ 改为「默认由 UI 决定
     (现为全不选),`buildPayload` 不再预设」;
   - `docs/CONVENTIONS.md` §三 AI 排片条:同步「默认全不选」,并加一句「开弹层后必须先选日期,
     否则按钮禁用」避免后续再退回。
4. **不动**:`buildPayload` 接受 `dates=[]` 时返回空 payload 的逻辑(本就跑不到这一步)、
   runBar 按钮态 / 状态文案、采纳合并(`planMerge`)等。
5. **历史 plan 不改**:`PLAN-20260910143929` 验收标准(日期 chips 默认全选)是当时的设计,
   不追溯修订;只把当前活文档(`src/*.ts` / `CONVENTIONS.md`)改齐。

## 边界与风险

- **离线首屏**:用户开弹层看到 0 选中、按钮灰态、红字「至少要选一天」—— 视觉上不突兀,
  已经过同面板已有「无片单模式 / 至少要选一天」红色提示的设计语言。
- **不破坏 `runBar` 守卫**:`if (running || selDates.size === 0) return;` 与 `BTN_DISABLED` /
  `disabled` 已在位,跑不出空 payload。
- **不动 `addGroupPicks` / `planMerge`**:采纳合并走所选日期的 payload,日期 0 时不会到这一步。
- `src/library.ts` 是并行会话热点文件(`PLAN-20260910151027` 刚改过同一处,行号已变)→
  提交按 SKILL `parallel-agent-safe-commit` 只带自己 hunk。
