### T4 — 控件边框与分隔线共用一个 token，控件边界不可辨

- `var(--line)` 全仓 **81 处**引用；其中 `border…: 1px solid var(--line)` **63 处**。
- 用途混杂：① 分隔线 / 网格线（`border-right` / `border-bottom`、`background: var(--line)`、
  `linear-gradient(… var(--line) …)`、SVG `stroke: var(--line)`）② 容器与控件边界（`border: 1px solid var(--line)`）。
- 实测：`--line` vs `--surface` = **1.37**（浅）/ **1.83**（暗）；vs `--page` = 1.23。
  同时 `--surface` vs `--page` = **1.11**（浅）/ 1.16（暗）→ 卡片与底几乎同色，**边界全靠那 1px 描边**。
- 已确认的**控件边界**样本：`.version-link`（`style.css:1531`，`background: var(--surface)` 压在 `--page` 上）、
  `.preview-full`（`style.css:1652`）。
- 已确认的**不该动**反例：`.screening-info-popover`（`style.css:1645`）与 `.gv-duration-popover`
  （`schedule-parity.css:312`）—— 浮层的可识别性由 `box-shadow: 0 8px 32px #0003` 承担，边框是装饰。
- **为什么当初只有一个 `--line`**：`style.css:20-24` 的注释说明它是「分隔线 / 图例 / 大量非说明文字」共用的颜色档，
  取向是**极简 token 集**。→ 拆分只允许拆出**必要的一档**，不引入完整语义色板（见取舍表）。

## 二、范围

### T1 做 — 路由级 `document.title`

- 在 `App` 壳（`app/App.tsx` 的 `Root`）加**一处** effect：`useLocation()` 变化后读当前页面的 `<h1>` 文本，
  写 `document.title = "<h1 文本> · BIFF Scheduler"`。
  - React 的 effect 顺序保证子组件 effect 先于父组件执行 → 父级读到的 `<h1>` 已是本页渲染结果。
  - 读到空（页面还没渲染出 h1，如 `Loading` / `RouteError`）→ 保留 `index.html:8` 的默认标题，不写空串。
- 影片详情弹层（`films/:filmKey`）单独处理：`FilmDialog` 打开时写影片中文名，关闭时恢复上面的路由标题。
- **不改** `index.html:8`（首帧 / JS 未执行时的兜底要保留）。

### T2 做 — `scroll-padding-top`

1. **窗口级**：`.update-banner` 存在时给它下方的滚动视口留出高度。
   因它**条件渲染**（只在新版本可用时出现），不能用固定常量，方案见取舍表。
2. **容器级**：`.floating-workspace .viewing-panel`（唯一确认成对的组合）加 `scroll-padding-top`。
3. **逐条核对** §一 T2 的"待核对粘性"：**只有内部含可聚焦子元素的才加**，其余在注释里写明「已核对，不加」及理由。
4. 明确**不改** `.update-banner` 的 `sticky`（见 §一 T2 的「为什么当初这么设计」）。

### T3 做 — 触控目标

- 给候选清单补 `pointer: coarse` 兜底，**沿用既有写法：只加 `min-height` / `min-width`，视觉尺寸不变**。
- **分两档做**：
  - **宽松档（可安全撑到 44px）**：`.nav-item`、`.feedback-chip`、`.preview-close`、`.preview-heading button`、
    `.ticket-chip`、`.ticket-transfer`、`.agenda-actions .date-strip.calendar-strip > button`、`.rb-src`。
  - **密集档（`.gantt-info` 26/30px、`.gv-inline-edit > button` 24px 等）**：**先量相邻目标的中心距**；
    中心距 <44px 时不允许靠撑大命中区制造重叠 —— 这种登记为**已知缺口**并在注释里写原因，不硬改。
- 桌面（`pointer: fine`）观感**零变化**。

### T4 做 — 拆出 `--control-line`

- `style.css` token 层新增 `--control-line`（浅 / 暗各一值）。
- 只把**交互控件的可见边界**从 `var(--line)` 换成 `var(--control-line)`；
  判定标准（写进 token 注释，避免下次随意扩散）：
  > 该元素本身可点击 / 可聚焦（`button` / `a` / `[role=button]` / 表单控件），
  > **或**这条边是识别该交互区域边界的**唯一**视觉线索。
  > 容器边框、分隔线、网格线、SVG `stroke`、`background: var(--line)` 一律不算。
- 分隔线继续用 `--line`（**不动**）。

### 不做（四件事共同的边界）

- 不动 `.app-header` / `.app-toolbar`（已核对非 sticky，加 `scroll-padding-top` 是无效改动）。
- 不动 §一 T3 已排除的非指针目标（`.rb-ghost` 等）。
- 不做 2.5.7「拖拽需有按钮替代」的排查（红黑榜贴纸拖拽、行程拖拽排序）—— **另议**，不塞进本轮。
- **不做批一**（徽标 ink 分档，见 `PLAN-20260923122409`）。
- 不碰 `apps/web/legacy/**`（只读回退件）。
- 不引入新依赖、不改 `biff.*` 任何键、不动 `apps/api`。
- 不做与上述四项无关的重构与格式化。

## 三、方案取舍

### T1 标题的形态

| 备选 | 结论 | 理由 |
|---|---|---|
| **读当前页 `<h1>` 文本** | **采纳** | 页面名**已有一处实现**（每页 h1）；新增页面自动生效，零维护；不会出现「h1 改了标题没改」的第二份真相 |
| 路由 `handle: { title }` + `useMatches()` | 备选（若实测时序不稳） | 是 React Router 惯用法，但**把页面名写了第二份**（与 `App.tsx:314-316` 的 h1 文案并存），且 `/schedule` 的 h1 含动态年月，静态 handle 会与可见文案不一致 |
| 每个页面各自 `useEffect` 写标题 | 否决 | 9 处重复实现，直接违反 AGENTS §5「口径单一来源」 |
| 用一张「路由 → 标题」常量表 | 否决 | 同上，且新增路由必须记得改表，漏了不报错（静默失效） |

### T2 条件性 `scroll-padding-top`

| 备选 | 结论 | 理由 |
|---|---|---|
| `html:has(.update-banner) { scroll-padding-top: … }` | **采纳**（首选） | banner 是条件渲染，`:has()` 让它「在则有、无则无」，无需 JS 参与，也不会在 banner 不存在时白留一条空隙 |
| JS 在 banner 挂载时写 `documentElement.style` | 备选（若 `:has()` 实测有兼容问题） | 有效，但要处理卸载时清理，且把布局信息塞进 JS |
| 固定给 `html` 加一个非零 `scroll-padding-top` | 否决 | banner 不在时白留空隙，会让「按 Tab 后滚动位置」显得莫名跳位 |
| 把 `.update-banner` 改回 `fixed` | 否决 | `style.css:194-197` 注释已写明 fixed 会盖住 `.app-header` 品牌位 —— 是当初特意改掉的 |

### T3 触控目标

| 备选 | 结论 | 理由 |
|---|---|---|
| 只加 `pointer: coarse` 兜底（视觉不变） | **采纳** | 与既有两处写法一致；桌面观感零变化；不给密集网格制造重叠 |
| 直接把视觉尺寸改成 44px | 否决 | 会改掉排片表 / 红黑榜的既有视觉密度，且是**全平台**变化（含桌面） |
| 用透明 `::after` 扩大命中区 | 否决 | 密集网格里同样会重叠；且 `::after` 会参与相邻元素判定，比 `min-height` 更难预测 |
| 密集档也一律撑到 44px | 否决 | 会制造互相覆盖的命中区（点 A 触发 B），比"目标偏小"更糟 |

### T4 token 拆分粒度

| 备选 | 结论 | 理由 |
|---|---|---|
| 只拆出 `--control-line` 一档 | **采纳** | 只解决"控件边界"这一处真实缺口；保持 `style.css:20-24` 的极简 token 取向 |
| 拆成套语义色板（border-subtle / border-default / border-strong） | 否决 | 81 处消费方要重新分类，爆炸半径远超收益；且本轮只证实了"控件边界"一处不合格 |
| 保留 `--line`，只把控件边框改成 `color-mix()` 自算 | 否决 | 引入计算值会让对比度不再可静态断言（与 §五 第 4 条的测试冲突），可读性也更差 |
| 顺带把 `--line` 本身整体加深 | 否决 | 分隔线 / 网格线是刻意淡的；加深会改掉整站观感而收益只在控件边界 |

### 候选值（已实测）

| 主题 | 候选 | `--surface` | `--page` | `--raised` |
|---|---|---|---|---|
| 浅 | `#86868e` | 3.61 | 3.26 | 3.37 |

## 五、验收标准

1. **T1**：10 条路径（9 路由 + 404）逐条核对标签页标题非空且与页面主标题一致；
   浏览器前进 / 后退后标题同步；影片弹层打开时标题变影片名、关闭后恢复。
   用 E2E 断言 `page.title()`（比目视可复现），或至少给出逐条核对记录。
2. **T2**：构造 `.update-banner` 出现的场景，把焦点移到 banner 下方的可聚焦元素上，断言
   `focused.getBoundingClientRect().top >= banner.getBoundingClientRect().bottom`（焦点环完整可见）；
   再断言 banner 不出现时 `scroll-padding-top` 为 0（不留空隙）。
   `.viewing-panel` 同理（焦点元素不被 `.viewing-panel-heading` 盖住）。
3. **T3**：以触摸设备描述符（`hasTouch: true`）跑，量候选目标的 `getBoundingClientRect()` ≥44px（宽松档）；
   **同一批目标在 `pointer: fine` 下尺寸与改前逐字节一致**（桌面零回归）；密集档给出「已量中心距 + 决定」的记录。
4. **T4**：新增断言 `--control-line` 对 `--surface` / `--page` / `--raised` ≥3:1（浅 + 暗两主题）。
   测试范式与批一的 `badge-contrast.test.ts` 相同（**读 `style.css` 源码**，不另抄色值表）；
   两个测试文件可以合并为 `contrast-tokens.test.ts`，由实现时定。
5. **通用**：T1–T4 各一个 Conventional Commit（或按 §二 的 1/2/3/4 分四个），
   body 写「为什么 + 验证结果」；无先红用例的（T2 布局、T3 尺寸）须在 body 里写明「无先红用例 + 理由」。
   本地不跑全量门禁，push 后以 Cloudflare 构建与 GitHub CI 为准；push 前 `git fetch origin main` 确认无落后，
   且**经用户确认**（本机约定）。
6. **一次浏览器会话**：T1/T2/T3 的全部浏览器验收**合并为一次**（浅 + 暗、桌面 + 触摸各一轮），
   不许为看效果反复起 dev server。
