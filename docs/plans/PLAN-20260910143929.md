# PLAN-20260910143929 — AI 排片:采纳改「追加合并」+ 日期范围选择

## 1. 用户诉求

> 「AI 排片 而且比如我在设定了一个 9 月 19 号的 我应用为 A 方案 然后我又生成了一个 9 月 20 日的的
> 然后会覆盖我之前生成的 9 月 19 日的」

`AskUserQuestion` 口径确认(用户选定):

| 问题 | 用户选定 |
|---|---|
| 采纳时目标方案已有场次怎么办 | **追加合并** —— 保留已有场次,只把 AI 建议里不冲突、不重复的场次加进来;分天多次排片可累积 |
| AI 排片是否支持只排某几天 | **要** —— 面板加日期范围选择,只把选中日期的场次送给 AI;配合「追加」即可逐天排片 |

## 2. 根因(读代码得出,非凭印象)

采纳出口 = `state.ts::replaceGroup()`,语义是**整组替换**:先清掉目标方案现有全部场次,再落 AI 建议。

```ts
// src/state.ts:395
export function replaceGroup(g: Group, picks: {...}[]): void {
  for (const e of [...store.picks.values()]) {
    const rest = e.picks.filter((p) => p.group !== g);   // ← 目标方案现有场次全被摘掉
    ...
```

故「9/19 采纳进 A」→「9/20 再采纳进 A」时,第二步先清空 A 再落 9/20 —— 9/19 被覆盖。
确认框(`library.ts:795`)虽写了「将覆盖 A 方案现有 N 场」,但语义仍是全量替换。

另:`buildPayload` 把**所有已定档影片的全部日期场次**一次性送给模型(`ai.ts:170`),面板没有任何日期维度,
用户只能靠在偏好文字里写「只排 9/19」间接约束 —— 与「逐天排片」的用法不匹配。

## 3. 设计决策

### 3.1 采纳 = 追加合并(非破坏性)

新增纯逻辑 `ai.ts::planMerge(cat, existingCodes, picks, transitMin)`,逐条判定:

| # | 条件 | 处置 |
|---|---|---|
| ① | 该片在目标方案 g 里**已有场次** | 跳过(每片一场,不重复排) |
| ② | 该 code **已在 g 里** | 跳过(幂等:重复采纳同一份建议不长出重复场次) |
| ③ | 与 g 现有场次**时段冲突** | 跳过 |
| ④ | 其余 | 追加,并把该片档位设为建议档位 |

冲突判定**复用 `conflict.ts::computeConflicts`**(与网格/`parseAiResult` 同一口径:`effEndMin` + 同馆 0 / 跨馆 `transitMin`),
即 `conflictsWith()` —— 保证「并进来之后网格不会红一片」。

写入侧 `state.ts::replaceGroup` → **`addGroupPicks(g, picks)`**:只追加、不清空;另一方案与 g 现有场次都不动。
返回实际加入条数供 UI 回执。

**为什么拆两层**(纯逻辑 vs 写入):`gv.ts` 反向 import `state.ts`(`talkOnOf` 读 `store`),
`state.ts` 再 import `gv.ts` 会成环 → 冲突口径留在 `ai.ts`(它已 import `conflict.ts` + `gv.ts`),
`state.ts` 只做「追加 + 推云」这一件事。

**不做**:保留 `replaceGroup` 作为另一条出口。用户要的是累积,留一条「会清空」的旁路只会再踩一次;
UI 上采纳按钮由「采纳为 A 方案」改文案 **「并入 A 方案」**,与真实语义一致。

### 3.2 采纳不再二次确认

原 `window.confirm` 是为**破坏性覆盖**兜底的;改为追加后无数据丢失 → 去掉确认,
改为**结果回执**:「已加入 N 场 · 跳过 M 场(重复或冲突)」。`add.length === 0` 时明确告知「没有可加入的场次」。

### 3.3 日期范围选择

面板在「② 你的排片偏好」之前插一行**日期 chips**(数据源 `cat.dates`,默认**全选** = 现状不变):

- 点击切换选中态,`paint()` 就地重绘(弹层内改状态必须自己重绘,CONVENTIONS §二);
- 全不选 → 「开始 AI 排片」禁用 + 提示;
- `buildPayload` 的 `dates` 参数语义扩为「**本次考虑并送给模型的日期**」:
  场次按 `date ∈ dates` 过滤,**所选日期内无场次的影片整条不送**(省 token),
  `env.dates` 也改为所选日期(模型据此知道只在这些天排);
- 打包从「面板创建时算一次」改为 `buildNow()`(选中变化后重算);
- runBar 信息补日期口径:「本次送 N 部 / M 场(仅所选 K 天;另有 E 部在所选日期无场次)」,
  其中 `E = wanted.length − payload.films.length − payload.truncated`。

## 5. 边界与风险

- **并行会话热点**:`src/library.ts` / `src/main.ts` / `src/legend.ts` / `src/types.ts` / `public/venues.json`
  / `tools/extract_schedule.py` 有在途改动(影厅 `short` 短名等)。本次只动 `library.ts` 一个热点文件,
  且改动集中在 `aiPanel`(并行会话动的是 `venueShort` 取用点)→ 提交按 SKILL `parallel-agent-safe-commit`
  只带自己 hunk;部署走隔离 worktree。
- **`planMerge` 的冲突口径必须与网格一致** —— 否则「并入成功」但网格立刻红一片(比覆盖更糟)。
  故一律走 `effEndMin` + `talkOnOf` + `computeConflicts`,不自写重叠判断。
- **日期过滤会让「未纳入」列表变短**:所选日期内无场次的影片不再出现在 AI 结果里 —— 这是有意的(不送 = 不排),
  但 runBar 必须把「另有 E 部在所选日期无场次」说清楚,不能静默。
- **默认全选日期** → 不选日期的用户行为与改动前**逐字节一致**(payload 相同、结果相同)。

## 8. 顺带发现(不在本次范围,未改)

`conflict.ts::computeConflicts` 的剪枝 `if (b.start >= a.end) break;` 在**进入转场判定之前**就跳出,
故设置里的「跨场馆转场缓冲」对**不重叠**的两场完全无效 —— 即跨馆相邻 10 分钟、缓冲设 30 分钟时,
网格**不会**标冲突(转场缓冲只在 `markTightPairs` / `gapNote` / `scorePlanRows` 的「紧转场」提示里生效,
与设置项提示语「仅用于判定跨影院场次的冲突」不符)。**既有缺陷,非本次引入**;
`planMerge` 复用同一函数 → 与网格口径**一致**(不会出现「并进来网格就红一片」的反向问题)。

修法(若要修):把 `break` 改成「`b.start >= a.end + maxTransit` 才 break」,或在 `a.end + transit <= b.start`
时 `continue` 而非 `break`。**属独立需求** —— 改完会让一批原先「不冲突」的跨馆相邻场次变红,
需单独确认口径后另开 PLAN。

## 9. 追加需求(同日):不选片也能排 —— 「无片单模式」

> 用户原话:「然后可以在不添加选片的时候也能排片 就排用户在 prompt 提出的偏好 比如我想在下午三点开始看到晚上七点 这样」

### 9.1 现状

`openEngineDialog` 里 `wanted` 只收**已定档**(priority ≠ null)的影片;一部都没打标 → 直接吐一句
「还没有给任何影片打标」并**不打开面板** —— 即「不选片就没法排」。

### 9.2 设计

| 项 | 决策 |
|---|---|
| 触发 | `tagged.length === 0`(= 一部都没打标)→ `noFilmList = true` |
| 候选池 | 「**全部有排期**的影片」(无场次的目录片不送 —— 送过去也排不了),档位统一 `wild` |
| 档位含义 | 该 `wild` 只是「可自由挑选」的**传输标记**,**不代表用户想看它**;Prompt 里显式说明 |
| 怎么排 | **完全由「③ 我的排片偏好」文字决定**(如「下午三点看到晚上七点」「只看 BCC」) |
| Prompt | `callLLM(cfg, payload, signal, { noFilmList: true })` → user 消息追加**【本次模式:无片单】**段:按偏好排、允许空档、**不要因为「没有必看片」而返回空 picks** |
| 空偏好兜底 | 「按评分与 GV 优先,挑一份时间紧凑、转场少的行程」(不是「仅按档位优先级」) |
| 并入档位 | 写 **`null`(未设)** —— 用户没打过标,不替他编「随缘」;`addGroupPicks` 的 `priority` 因此可空,且 `null` **不抹已有档位** |
| UI | 面板顶部加**无片单模式**提示卡:说明候选池多大 / 怎么排看偏好 / 并入后是「未设」/ 建议收窄日期降费用 |
| 边界 | `wanted.length === 0`(连排期都没有)→ 提示「当前没有任何已发布排期,无法排片」 |

### 9.3 payload 体量(实测,关键约束)

| 范围 | 影片 | 场次 | JSON 字符 |
|---|---|---|---|
| 全选 10 天(09-17~09-26) | 277 | 699 | **114,089** |
| 去掉 09-17(9 天) | 277 | 698 | 113,965 |
| 单天(09-19) | 97 | 99 | 20,228 |

全选仍在 `PAYLOAD_LIMIT = 120_000` 内(余量 ≈ 6k),**不触发截断** —— 但余量很薄,故 UI 明确提示
「候选多 → 单次请求又慢又贵,建议先收窄日期」。片单再涨(2026 目录)就必须靠日期收窄。
