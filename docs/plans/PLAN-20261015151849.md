# PLAN-20261015151849 — 补上 Satoko Always（f004）的豆瓣海报

## 目标

用户在影片库 / 详情 / 分享图里一直看不到「Satoko Always · Satoko总是这样」的海报。
用户原话：

> Satoko总是这样为什么一直没有海报?
> 请你去联网搜索 补上这个海报 然后推送下

已核实的事实（读代码 + 实测，非推测）：

- `apps/web/public/films.json` 的 `f004` **整条没有 `poster` 字段**（247 部里 19 部如此）。
- 豆瓣富化 `data/enriched_douban.json` 已把该片挂到条目 `subject 37333129`，且带海报 URL
  `https://img1.doubanio.com/view/photo/l/public/p2933511490.jpg`；
  但 `apps/web/public/posters/` 下**没有** `37333129-{s,m,l}.jpg` ——
  `tools/build_films.py::load_posters` / `tools/build_films_2026.py` 只认**本地已下载**的档位
  （豆瓣图床有 Referer 防盗链，不许外链），故不给 `poster`。
- 实测该 URL 现在带 `Referer` 仍返回 200（m 档 104 KB / l 档 310 KB）→ 是**没下**，不是下不动。
- TMDB 侧 `data/tmdb_map.json` 的 `f004` = `{ "tmdb_id": null }`，2026-09-12 那次检索未命中。

## 范围

**做：**

- 联网下载 `37333129-{s,m,l}.jpg` 到 `apps/web/public/posters/`（带 `Referer: https://movie.douban.com/`）。
- 给 `data/films-catalog-2026.json` 的 `f190` 补 `poster`（源产物对齐，供下次重建）。
- 给 `apps/web/public/films.json` 的 `f004` 补 `poster`（线上立即生效）。

**不做：**

- 不动 TMDB 管线与 `data/tmdb_map.json`（需 `TMDB_KEY` 环境变量，本机没有；豆瓣源已足够）。
- 不重跑 `tools/build_films_2026.py` 重建 `films.json`（需未检入的 `--web films-web.json`，仓库里没有）。
- 不顺手补其余 18 部无海报片（另开需求，避免范围失控）。
- 不改前端代码 / 样式 / 测试。

## 方案取舍

| 备选 | 结论 | 理由 |
|---|---|---|
| 跑 `tools/fetch_tmdb_posters.py` 补 TMDB 海报 | 否决 | 需 `TMDB_KEY`（本机无）；豆瓣源已可直接下载 |
| 重跑 `tools/build_films_2026.py` 重建 `films.json` | 否决 | 需 `--web films-web.json`，抓取产物不在仓库 |
| 重跑 `data/_posters_from_mapping.py` 补富化 | 否决 | 富化表里该片**已有** poster URL，缺的是「下载」这一步，非富化 |
| 下豆瓣海报 + 定点回填两份产物 | **采纳** | 与既有管道口径一致（文件名 `<subject_id>-<档>.jpg`、`poster` 指向 `-m`），零 token |

2. `films.json` 的 `f004.poster == "/posters/37333129-m.jpg"`，且 `git diff` 只新增这一行（无整档重排；
   已实测 `json.dumps(indent=1)` 与原文件逐字节一致）。
3. `node scripts/affected-specs.mjs --files …` 判定走 PR 还是直推；`npm run check:repo` 与相关单测通过。
4. 部署后线上核对：asset hash 相同 + 新增字符串命中 + 阴性对照。
