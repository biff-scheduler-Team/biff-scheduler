# PLAN-20260928003736 — 红黑榜前端性能专项（共享 Observer / 贴纸尺寸 / 叠放顺序 / 规模化渲染）

## 目标

用户 2026-09-28 的三点诉求（原话）：

> 还有什么优化的点吗 对于这个红黑榜现在我看是一次性把 299 个电影都渲染出来了 是吗
> 还有没有更好的办法呢 能不能让这个红黑榜的这个量级做一次特别大的提升
> 然后是不是可以把贴纸也改小一点 这样也能容纳更多一点呢

> 还有一个小 bug 我感觉好像现在黑色的贴纸总是会压住红色的贴纸 是吗
> 能不能按顺序呢 能不能按这被贴的顺序 然后去做一个这样的覆盖在上面的这个这个这个顺序

拆成三件事：

1. **为票数量级增长做架构预备** —— 当前单片最多 160 枚票，未来用户量增长后可能到数百乃至数千枚；
   现有渲染路径（`useLayoutEffect` 同步绘制 + `HTMLCanvasElement` sprite + 每卡一个 Observer）
   在票数激增时会成为瓶颈，需要提前升级而不是届时重写。
2. **贴纸缩小 26px → 20px** —— 同等画布面积容纳更多，视觉更整洁。
3. **修掉「黑贴纸系统性压住红贴纸」的叠放 bug**。

## 范围

**做:**

1. **P1 共享 Observer 单例**：`use-in-view.ts` 改为模块级单例 IntersectionObserver（回调 Map 分发），
   新建 `shared-resize-observer.ts` 供 `StickerCanvas` 使用。Observer 实例 299 → 1（ResizeObserver 同）。
2. **P2 贴纸缩小**：`STICKER_SIZE: 26 → 20`，同步 `redblack-parity.css::.rb-dot` 的
   `width/height: 26px → 20px`，以及拖拽浮标 `.rb-ghost` 28px → 22px（保持「比贴纸大 2px」的相对关系）。
   ⚠ **实现偏离（已核实并保留）**：初版计划写的是 `SPRITE_PAD: 8 → 6`「等比收缩」，实现时**没有改** ——
   落影是 `box-shadow` 的**绝对尺寸**（`0 2px 4px`），不随贴纸变小而变小，跟着等比缩会把最外那层
   阴影裁掉一条边。sprite 总尺寸仍从 `(26+16)×dpr` 降到 `(20+16)×dpr`，内存照样省。
3. **P9 叠放顺序**：`redblack.ts::crowdStickers()` 返回前按落点纵坐标升序排序，
   二级键用 id 哈希打破同 y 并列。红黑不再系统性互相压制，观感像纸片自然堆叠。
4. **P6 外观缓存失效收口**：`sticker-sprite.ts` 的 `colors` / `cache` 为模块级单例且只在首次读取
   （读失败时还会兜底成中性灰 `#8b8b8b`）—— 那次读到的值会**永久生效**。加 `MutationObserver`
   监听 `data-theme`，变化时清缓存并经 `spriteEpoch()` + `onSpriteInvalidate` 让画布重画。
   ⚠ **诚实记录（2026-09-28 review 核实）**：`--rb-red` / `--rb-black` 只在 `:root` 定义一次、
   **没有暗色覆盖**，所以今天切换主题贴纸颜色本就不会变 —— 这一条是**脆弱性收口**，不是
   用户可见 bug 的修复（`style.css` 的 `:root[data-theme="dark"]` 已覆盖几十个 token，
   给贴纸补一档是很自然的下一步）。
5. **P7 弹层懒加载**：`RedBlackShareDialog`（依赖 `redblack-poster.ts`，9KB gz）与 `StickerZoomDialog`
   （2.3KB gz）改 `React.lazy`，主 bundle 减小约 14KB gz。
6. **P8 图片异步解码**：海报 `<img>` 加 `decoding="async"`。
7. **批次 B（规模化预备）**：
   - P3 sprite 缓存升级 `ImageBitmap`（GPU 常驻纹理，跳过 CPU→GPU 上传），保留 canvas 降级路径。
   - P4 绘制从 `useLayoutEffect`（同步阻塞 paint）改为 `useEffect` + `requestIdleCallback`
     （空闲帧绘制，`timeout: 100` 兜底），滚动帧不再被 canvas 绘制拖慢。
   - P5 `StickerZoomDialog` 分帧渲染（先 200 枚，`rAF` 分批追加）。

**不做:**

- ❌ **不引任何新依赖**（`react-window` 等虚拟列表库已明确否决，见方案取舍）。
- ❌ **不做行级虚拟化**（屏外卡换高度占位 div）：299 部时 `content-visibility: auto` 已够用，
  等影片数真实超过 500 再做（见方案取舍里的成本分析）。
- ❌ **不做「真·按贴票时间」叠放**（用户原本的想法，已确认否决，见方案取舍）。
- ❌ **不做密度降级**（热力图 / 聚合视图）—— 用户已拍板「一部片看到每一枚」。
- ❌ **不改 `apps/api`** —— 服务端仍只返回聚合计数。
- ❌ **不改 `biff.*` 数据结构**、不改落点算法（`spotOf` / `tiltOf`）。
- ❌ **不动在途改动**：`AGENTS.md`、`apps/web/vite.config.ts`、`docs/DEVELOPMENT-STANDARDS.md`、
  `apps/web/mock/`、`apps/web/public/mock-redblack.html` 是他人在途改动，只用不改、不提交。

## 方案取舍

| 备选 | 结论 | 理由 |
|---|---|---|
| 引 `react-window` 做虚拟列表 | 否决 | 假设等高行，而卡片高由片名行数决定、两列网格左右各自独立；需配 `auto-sizer` + `VariableSizeGrid`，gzip 约 +12KB。手写 60 行可达同样效果，且规范要求引依赖前先量化 |
| 手写行级虚拟化（屏外换占位 div） | 本次不做 | 当前 299 部下 `content-visibility: auto` 已跳过屏外卡的布局与绘制；Fiber 挂载成本实测可接受。真要做需解决"两列不等高"的高度跟踪，收益要到 500+ 部才显现 |
| 「真·按贴票时间」叠放 | 否决 | 公开接口 `readVoteCounts` 读聚合表 `filmVoteStat`（只有 red/black 计数，无时间）；带 `updated_at` 的明细在 `filmVoteContribution`，规范明文「公开读路径一律走聚合」。且按时间排需回 O(票数) 个时间戳，**与本次量级提升目标直接冲突** |
| 叠放改为「按哈希打散层级」 | 否决 | 红黑虽平等但少了"纸片堆叠"的真实感；按落点 y 排序同时解决观感与压制两个问题 |
| 叠放改为「红黑交替穿插」 | 否决 | 需要按比例取整，会把少数派颜色挤掉（正是 2026-09-22 修掉的那类问题） |
| 贴纸缩到 16px | 否决 | 落影与细条纹在 16px 下基本看不出质感，与 `.rb-dot` 的"纸片"质感目标冲突 |
| 贴纸缩到 20px | **采纳** | 密度 +40%，质感保留；`STICKER_SIZE` 是单一来源，与 CSS `.rb-dot` 两处同步即可 |
| 共享 Observer 单例 | **采纳** | 299 个 IntersectionObserver + 299 个 ResizeObserver → 各 1 个；对外 API 签名不变，业务代码零改动 |
| `ImageBitmap` sprite | **采纳** | GPU 常驻纹理，跳过每次 `drawImage` 的 CPU→GPU 上传；保留 canvas 降级路径 |
| `requestIdleCallback` 调度绘制 | **采纳** | 1200px 预取边距保证画完才进视口，把绘制让给空闲帧，滚动帧彻底解放 |
| 给 299 张卡加 `will-change` | 否决 | 299 个合成层 = 上百 MB 显存（2026-09-22 已否决一次，不再重提） |

## 验收标准

1. 贴纸外观与现状一致（不规则圆片 / ±15° 歪斜 / 质感 / 落影），仅尺寸由 26px 变 20px；
   `.rb-dot` 与 sprite 两处尺寸逐字一致。
2. **叠放**：卡片画布 / 「看全部」弹层 / 分享图三处的贴纸叠放顺序一致，均为「按落点纵坐标」
   —— 不再出现「黑票全部压在红票之上」。
3. **回归测试先红后绿**：`apps/web/tests/redblack.test.ts` 新增断言
   ① 返回数组 `posY` 单调不减；② 红黑交错（存在黑票排在红票之前）。
   先贴出红的那次失败值，再改实现转绿。
4. `data-theme` 变化后画布按新 token 重画（`spriteEpoch()` +1 且订阅者收到通知）。
   ⚠ 当前 token 无暗色覆盖，颜色值本身不变 —— 断言的是**失效链路**，不是某个具体色值。
5. 主 bundle 减小约 14KB gz（`redblack-poster.ts` + 两个弹层不再同步加载）。
6. 批次 B：滚动时绘制不再阻塞主线程；`StickerZoomDialog` 打开单片数千枚不再产生长任务。
7. 收口命令：`npm run verify:quick` 全绿 + `npx playwright test -c playwright.react.config.ts e2e/react/redblack.spec.ts --project=desktop-chromium` 全绿。
