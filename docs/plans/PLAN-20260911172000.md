# PLAN 2026-09-11 17:20:00 — 片名口径统一为「英文名 · 中文名」

> 需求(用户原话):「现在应该优先显示英文名 然后中文名用分隔符来显示 不要只显示中文名」。
> 追问确认:应用范围 = **全部片名显示处**(影片库 / 我的选片 / 我的行程 卡片头 + 甘特图卡片 +
> 资料弹层 + AI 排片面板 + 复制清单 / tooltip);分隔符 = **`·`**(与卡片副标题同款)。
> 前置:`PLAN-20260911165000`(切 2026 数据)、`PLAN-20260911170000`(海报 + 筛选)。
> 本文件 = 本轮唯一规划文档。

## 1. 问题

2026 数据换版后,排期给的是**官网英文名**(`title_en`),目录给的是**中文名 + 原始片名**
(`title_zh` / `title_orig`),桥接率只有 ~55%(`PLAN-20260911165000` §2.4)。于是同一个列表里:

* 对上的片:卡片主标题是中文名,英文名被降级进副标题的一串「原始片名 · 单元 · 国家 …」里;
* 对不上的片:主标题只能印英文名 —— **两种排版并存**,扫读时片名位置不固定;
* AI 排片面板、冲突 / 定位 tooltip、复制清单**只印中文名**(`zh`),对不上的片直接印英文,
  信息层级全凭运气。

## 2. 口径(单一来源)

`util.ts` 新增 **`bilingualTitle(en, zh)`**:

* 英文名在前,中文名以 `·` 跟在后面 → `You, Like a Star · 宛如星辰的你`;
* 任一侧缺失 → 只留存在的一侧;两侧同名(纯排期片的 `zh` 会退化成英文名)→ 只印一次;
* 绝不会产出 `Foo · Foo` 或首尾带分隔符的空串。

取值链:

| 位置 | 来源 |
|---|---|
| 英文名 | 排期官方 `title_en`(`data.ts::loadCatalog` 保证非空:官方只印韩文时用 `title_kr` 兜底);无排期的目录片退回 `title_orig` |
| 中文名 | 排期 `title_zh` → 豆瓣回填 `mapping.title_cn` |

`displayTitle(s, mapTitleCn)` 改为 `bilingualTitle(s.title_en, s.title_zh || mapTitleCn)` ——
**签名不变**,故所有既有调用点(网格卡 / 弹层 / 清单 / ICS / tooltip)自动跟上。

**目录片英文位 `util.ts::filmEnName(f)`**:目录 schema 正在从「`title_zh` + `title_orig`」迁到
「`title_en`(官网英文名)+ `title_kr` + `title_orig`(原始韩/日文名)」。无排期的目录片取不到
排期 `title_en`,故 `filmEnName` 优先读新 schema 的 `title_en`、退回旧 schema 的 `title_orig` ——
否则新数据下「无中文名」的片会印出空标题(实测 91 部)。

**不做的事**:不动 `filmNodeKey` / `filmInfoOf` 的命中规则(否则 key / 片名会漂);
不动 `FilmInfo.zh` 的「无中文退化英文」语义(改了 AI payload 会送出空片名);
不动排序键(`zh`)。

## 3.1 顺带修:豆瓣搜索的「中文搜索」送错词

用户反馈:点「中文搜索」实际搜的是 `Sakoto总是这样 Satoko Always` ——
`modal.ts::buildDoubanBlock` 把 `q` 拼成了 `` `${qZh} ${qEn}` ``(中英混排整串当片名,豆瓣一条都匹配不到)。

改为:**「中文搜索」只送中文名**(`qZh`),无中文名(纯英文片)才退回英文名;
「英文搜索」仍只送英文名。同时目录片弹层 / 影片库的豆瓣外链改用 `filmEnName(film)` ——
新 schema 的 `title_orig` 是原始韩/日文名,拿去搜豆瓣必空。
