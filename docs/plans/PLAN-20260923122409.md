# PLAN-20260923122409 — 徽标 ink 分档：修掉 4 个不达标的徽章对比度（批一）

## 目标

用户 2026-09-23 用 `ui-ux-pro-max` Skill 审核本项目后，要求先落「批一（最小、可量化）」：

> 批一（最小、可量化）：P1-1 徽标 ink 分档 —— 单文件 token + 一处 CSS 分派，配一条锁定 token 值的单测。

即：`.film-badge` 当前用**单一** `--badge-ink: #ffffff` 压在 10 种底色上，其中 4 种（实心 3 种 + 描边 1 种）
的文字对比度低于 WCAG 2.2 AA 的 4.5:1。本 PLAN 把它改成**按底色明度分档的 ink**。

姊妹篇：`docs/plans/PLAN-20260923122500.md`（批二，四项全局口径）。两者无代码交集。

## 一、现状（代码事实）

- `apps/web/src/style.css:43`：`--badge-ink: #ffffff;` —— **只有一档**；`:44-54` 是 10 个底色 token。
- ⚠ `--badge-*` 只在 `:root`（`style.css:6-60`）定义，`:root[data-theme="dark"]`（`:61-79`）**未覆盖**
  → 徽标底色两主题同值。**所以实心徽章的白字对比度在亮/暗主题下是同一个数**，与主题无关。
- `style.css:1624-1632`：`.film-badge` 统一 `background: var(--badge-fallback); color: var(--badge-ink);`
  `font-size: 12px; font-weight: 700;` → 12px 粗体**不属于** WCAG 大字号（需 ≥18.66px 粗体），阈值仍是 **4.5:1**。
- `style.css:1633-1641`：9 条**实心**徽章规则，只改 `background`，`color` 继承 `--badge-ink`。
- `style.css:1642`：`[data-badge="code"]` 是**描边款** —— `background: transparent; border-color: var(--badge-code);`
  `color: var(--badge-code);`。**它的文字落在页面 / 卡片底色上**，与上面 9 条不是同一个失效原因，必须分开处理。
- 消费方只有一个：`components/ScreeningCard.tsx:55` 渲染 `.film-badge` + `data-badge`；
  `legend.ts:2` / `badges.ts:2` 都注明「形状与配色统一由 `.film-badge[data-badge=…]` 承载」。
  → **改 CSS 一处即全站生效**，React 侧零改动。
- 本 token 由 `PLAN-20260923113659` T1（提交 `a2409ac`）刚建立，当时的硬约束是
  「值与原 hex **逐字节相同** → 不预期视觉变化」；**本 PLAN 有意打破该约束**（见取舍表第 1 行）。

描边徽章 `#ff3030` 文字（`background: transparent`）：

| 落在 | 对比度 | 判定 |
|---|---|---|
| `--page` 浅 `#f3f3f5` | **3.31** | ✗ ← 浅主题最坏 |

## 二、范围

**做：**

1. `style.css` token 层：把单档 `--badge-ink` 拆成**按底色明度分档**的 ink（实心款用）。
2. `style.css:1633-1636`：给 3 个亮底实心徽章（`rating-12` / `rating-15` / `rating-ALL`）指定深 ink。
3. `style.css:1642`：给 `data-badge="code"` 的**文字色**单独一档**按主题**的 token（浅色加深、暗色提亮）；
   **边框色保持 `--badge-code` 不变** —— 边框属非文本对比（阈值 3:1），`#ff3030` 对浅底最坏 3.31 / 对暗底 4.16，已达标。
4. 一条锁定 token 值的单测（§四 第 1 条）。

**不做：**

- **不动任何底色 token**（`--badge-rating-*` / `--badge-subs-*` / `--badge-gv` / `--badge-code`）——
  `style.css:39-42` 已声明「官方色卡不随主题变」。
- 不动 `ScreeningCard.tsx` / `legend.ts` / `badges.ts`（React 侧零改动）。
- 不碰已合格的 6 个实心徽章与 `--badge-fallback` 路径。
- **不做批二的那 4 件事**（`PLAN-20260923122500`）。
- 不引入 `prefers-contrast` 分支、不加描边 / 加粗等「补偿手段」（见取舍表）。
- 不碰 `apps/web/legacy/**`。

## 三、方案取舍

| 备选 | 结论 | 理由 |
|---|---|---|
| 按底色明度分**两档 ink**（深字给亮底 / 白字给深底） | **采纳** | 一次关掉 3 个实心失效项；在 token 层解决，`ScreeningCard.tsx:55` 等消费方零改动 |
| 只调最差的 `rating-12`（1.86） | 否决 | `rating-15` 2.84、`rating-ALL` 3.30 同样 <4.5；逐个修会变成 3 次互不相关的改动，且「新增底色再踩同一个坑」的隐患留着 |
| 把官方色卡整体压暗 | 否决 | `style.css:39-42` 已声明色卡不随主题变；且 6 个深底徽章本已合格，压暗破坏既有视觉且零收益 |
| 给亮底徽章加描边 / 加粗字重 | 否决 | 12px 加粗仍不适用大字号豁免；加描边会改掉 3 个徽章形状，与「形状只由 `data-badge` 决定」的口径冲突 |
| 让 CODE 徽章复用实心款的分档 | 否决 | 它 `background: transparent`（继承页面底色），最坏底是浅 `--page` / 暗 `--surface`，与实心款**不是同一个变量**；复用会在某一主题下静默失效 |
| 只加 `@media (prefers-contrast: more)` 修 | 否决 | 默认档就不合格；合规性不能挂在用户手动开关上 |
| 顺手重估 `--badge-fallback: #2b292d` | 否决 | 14.41 已合格，改了只是无理由的视觉变更 |

### 落地形态与 PLAN 的差异

| 项 | PLAN 写的 | 实际落地 | 原因 |
|---|---|---|---|
| 分档命名 | 「`--badge-ink` 拆两档」 | `--badge-ink-on-dark` / `--badge-ink-on-light` | 「dark / light ink」会与暗色主题混淆，改成「压深底 / 压亮底」语义 |

### 实现中的一次自纠

第一版解析器把「`A, B, C { … }` 分组规则」只算到最后一个徽章，还把「只写 `color` 的规则」与基类底色
错配成幽灵组合（`rating-15` 被算成「深字压 `#2b292d`」= 1.18）。已改成**按徽章合并同优先级声明**
（这才是 CSS 对同优先级声明的真实行为），并补了「每个徽章必须自带 `background`」的防空转断言。
