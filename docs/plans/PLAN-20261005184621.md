# PLAN-20261005184621 — 换自己的贴纸皮肤，不该把红黑榜上「别人的贴纸」也换掉

## 目标

用户 2026-10-05 反馈：

> 「为什么我换自己的贴纸皮肤的时候 会出现 把红黑榜别人的皮肤也换了 很奇怪」

即：给**自己**那枚贴纸换一款皮肤，红黑榜卡片上**群点（别人的贴纸）**的外观会跟着变一下，
过一会儿（上报落地 + 重拉）又自己变回去。这是真的 bug，不是错觉。

## 现状还原（读代码得到的机制，不是推测）

皮肤有两个数据源，**两本账**：

1. **服务端按款聚合** `film_vote_skin_stat`（`apps/api/src/db/schema.ts`，主键
   `(edition, film_key, skin, vote)`，**没有 contributor**）→ 客户端 `film-votes.ts::skinCache`
   （`peekFilmSkins`）。它**含我自己那一枚**，服务端不知道谁是「我」。
2. **本地我贴的那几枚** `redblack.ts::StickerBoard`（`biff.redblack.v2`），换款当场就变。

群点画的是「**别人的**贴纸」，所以要从服务端聚合里**扣掉我自己那一枚**：

- **颜色维度**（`redblack.ts::reconcile` / `othersOf`）扣的是**服务端已确认含我**的那份快照
  （`film-votes.ts::synced` / `peekSyncedVotes`）—— 这是 2026-09-23「收回贴纸后仍残留」那次定下的口径，
  所以换色 / 撤票**不会**让群点的数量跳。
- **皮肤维度**（`redblack.ts::othersSkins`）却拿**本地当前款**去扣
  （`RedBlackPage.tsx::RbCard`：`othersSkins(skins, myStickers)`，`myStickers = placed ?? …`）。

**这就是 bug**：换款到上报落地之间（1200ms 防抖 + 一次往返，失败时更久），
本地已经是**新款**、服务端聚合里还是**旧款**，于是——

- 旧款那个桶**没被扣**：群点里凭空多出一枚「我旧款」的贴纸（看起来像别人贴的）；
- 新款那个桶**被白扣一枚**：某个**别人**的新款贴纸从群点里消失了。

两个方向同时发生 = 用户看到的「我把别人的皮肤也换了」。上报成功后自愈，
所以现象是「变一下又变回来」。同一个偏差也存在于分享图（`redblack-poster.ts::toRow` 也调 `othersSkins`）。

## 范围

**做：**

- 给「服务端已确认的我那一枚」补上**款**这一维：`film-votes.ts` 在 `adoptSyncedVotes` 时
  一并记下 `key → { 色, 款 }`（`peekSyncedFaces`）。
- `redblack.ts::othersSkins` 的扣减基准由「本地当前贴纸」改为**服务端已确认的那一面**
  （`{ type, skin }`）—— 与颜色维度 `reconcile`/`synced` 逐字同一套口径。
- 页面（`RedBlackPage.tsx`）与分享图（`RedBlackShareDialog.tsx` → `redblack-poster.ts`）
  共用同一份 synced 快照，两条路径的扣减仍然只有 `othersSkins` 一处实现。
- 回归测试：① `othersSkins` 的「换款当拍、服务端还是旧款」场景；
  ② `film-votes.ts` 记录 / 更新 synced 款（本地换了、上报没成功之前，synced 款必须是旧的）。

**不做：**

- **不改服务端**（`film_vote_skin_stat` 不加 contributor）：公开读接口**刻意不回身份**
  （`film-vote-store.ts` 的硬约束），加身份维度与这条契约直接冲突，代价远大于收益。
- **不动颜色维度的口径**（`reconcile` / `othersOf` 一行不改）—— 它本来就是对的。
- **不动** `crowdStickers` 的铺款算法、群点的落点 / 叠放顺序、`skinsSignature` 的重绘判据。
- **不动** `legacy/`（只读回退件，本 bug 不属于「数据丢失 / 完全打不开」那两类 P0）。
- 不做「换款后先本地乐观扣减」之类的补丁：那是同一口径的第二份实现，正是 AGENTS §5 禁止的。

## 方案取舍

| 备选 | 结论 | 理由 |
|---|---|---|
| 服务端按 `contributor` 聚合，客户端按身份读自己那一桶 | 否决 | 公开读接口刻意不回身份；加了就等于把「谁贴了什么款」暴露出去，且要改表 / 迁移 |
| 换款时先在本地把分布「预扣」成新款，等上报 | 否决 | 同一口径的第二份实现；且上报失败时永远错。与 `reconcile` 用 `synced` 的做法自相矛盾 |
| 干脆不扣自己那一枚（群点里留着我） | 否决 | 会稳定多画一枚我自己的贴纸，这是 2026-09-29 已经修掉的旧 bug |
| **扣减基准换成「服务端已确认的那一面」** | **采纳** | 与颜色维度完全同构；换款 / 换色 / 撤票在**上报落地之前**群点都不动，落地那一拍也无跳变 |

## 验收标准

1. `npm run verify:quick` 全绿（typecheck + lint + 单测 + `check:repo` / `check:test-map`）。
2. 单测：`redblack-skin-crowd.test.ts` 里那条「换款当拍」用例通过 ——
   服务端分布仍是旧款时，扣减结果**只**少我那一枚（旧款桶 −1），别人新款桶**一枚不少**。
3. 单测：`film-votes.test.ts` 里 —— 本地换款后、上报成功之前 `peekSyncedFaces()` 仍是**旧款**；
   上报成功那一拍才切成新款（与 `peekSyncedVotes()` 同拍）。
4. `redblack-poster.test.ts` / `redblack.test.ts` / e2e `redblack.spec.ts` 既有断言不回归。
