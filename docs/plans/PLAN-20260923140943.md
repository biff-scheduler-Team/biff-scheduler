# PLAN-20260923140943 — 红黑榜管理端（subject 白名单 + 读 / 删 / 认领迁移）

## 目标

用户原话：

> 能读取到accountid 吗?我作为管理员user_01M2EVF3GTTJ6JC9NTM8NXYNHY能管理这些贴纸吗?

**已核实的现状（不是推测）**：

- `apps/api/src/**` 搜 `admin` / `角色` / `管理员` / `roles` → **0 命中**；
  `docs/account-integration.md` 同样 0 命中。
- 账号契约 `packages/contracts/src/account.ts:3-11` 的 `accountProfileSchema` 只有
  `userId / displayName / bio / website / avatarUrl / updatedAt / version`，**没有任何角色字段**。
- 结论：biff-scheduler **没有管理员概念**，那个账号在本服务里与任何登录用户权限完全相同；
  它的「管理员」身份是 IFFDAY 账号系统里的，本服务收不到也没消费。

上一轮（`PLAN-20260923124402`）已上线的自查接口刻意**不回** `contributor`，所以管理能力是**新增**的。
用户 2026-09-23 选定：**①门禁 = subject 白名单（写进代码）；②能力 = 读 + 删除 + 认领迁移**。

## 范围

**做：**

- `apps/api/src/admin.ts`：`ADMIN_SUBJECTS` 白名单 + `isAdminSubject()`。
- `/api/admin/*` 两层门禁：先 `requireIdentity`（未登录 401），再校验
  `session.subject ∈ ADMIN_SUBJECTS`（否则 403 `FORBIDDEN`）。
- `GET /api/admin/film-vote-contributions?edition=…`
  → 该 edition 的全部投票行，**含 `contributor` 原文**（subject / `anon:<hash>`），camelCase DTO。
- `DELETE /api/admin/film-vote-contributions?edition=…&contributor=…&filmKey=…`
  → 删掉指定一行；命中 200，未命中 404。
- `POST /api/admin/film-vote-contributions/claim` `{edition?, from, to, dryRun?}`
  → 把某个**匿名身份**的票整份并到指定账号名下：
  - `from` 必须以 `anon:` 开头（本轮只做「匿名 → 账号」）；`to` 走 `accountUserIdSchema` 校验；
  - 冲突（同一部片两票不同色）**保留目标那一票**，并列进 `conflicts`；同色计入 `alreadyHad`；
  - `dryRun: true` 只回会发生什么、不写；
  - 写入顺序：**先并到目标、再清源** —— 中途失败留下的是「两边都在」，重跑一次即收敛（幂等）；
    反序会丢票且不可恢复。
- 复用现成口径：删除与迁移都走 `film-vote-store.ts::replaceContributorVotes`
  （贡献行 + 聚合计数在同一个 batch 里改，带负漂移保护），**不写第二份「减一票」实现**。

**不做：**

- ❌ 账号 ↔ 账号合并（新语义，本轮只做匿名 → 账号）。
- ❌ 引入 `roles` 契约 / 改 IFFDAY 身份链路（上游是否有角色字段本仓库看不到，属跨仓库改动）。
- ❌ 把白名单做成 CF secret —— 使用者没有该 CF 账号的后台 / wrangler 权限，设不了。
- ❌ 匿名行过期回收、自动清理（要定义「多久算废弃」，新语义）。
- ❌ 前端界面：管理端只有 URL 可用（够用，且不动 web 就不会牵动另一个会话）。
- ❌ 不改 schema / 不加迁移（复用 `film_vote_contribution` 与 `film_vote_stat`）。

## 方案取舍

| 备选 | 结论 | 理由 |
|---|---|---|
| 走 IFFDAY 角色（`roles: ["admin"]`） | 否决（本轮） | 上游 profile 契约里没有该字段，本仓库拿不到响应样例；改它要跨仓库 + 契约演进 |
| CF secret / 环境变量门禁 | 否决 | 该 CF 账号不在使用者手里，secret 无从上架 |
| **subject 白名单写进代码** | **采纳** | 校验的是**已登录会话的身份**，不是凭据 —— 别人拿到这个 id 也伪造不出会话，所以它进仓库不构成越权入口。代价：换管理员要改代码重新部署 |
| 管理端单独一套 token | 否决 | 又是一处要保管的凭据，而使用者恰恰没有能安全存放它的位置（后台 / secret 都够不着） |
| 删除/迁移自己写 SQL 减计数 | 否决 | 就是「同一口径第二份实现」（红线 5），且会绕开 `stat-batch.ts` 的负漂移保护 |

## 验收标准

1. 单测（纯函数）：`mergeVoteBoards` —— 并集、冲突保留目标、同色计入 `alreadyHad`。
2. 单测（d1 垫片跑真 SQL）：`readContributorVotes` / `removeContributorVote` /
   `claimContributorVotes` —— 断言**聚合表同步变化**（不是只看贡献表）、claim 后源身份无行、
   `dryRun` 一个字节都不写。
3. HTTP 边界（真 `app.request()`）：未登录 401；登录但不在白名单 403；白名单 200 且**能读到
   `contributor` 原文**；DELETE 命中 200 / 未命中 404；claim 参数非法（`from` 非 `anon:` 前缀、
   `to` 不合账号格式）422。
4. `apps/api` 全量单测 + `eslint apps/api` + `tsc --noEmit` + `wrangler deploy --dry-run` 全绿。
