## 目标

用户原话(2026-10-15):

> biff 官网应该有更新一些信息 比如颁奖了 请你看看有什么还可以 同步到系统的数据

> 重抓 schedule.json(顺带修 510/633/168)
> 再加获奖数据:新增离线产物(如 awards.json)+ 影片/场次级 badge

调研结论(2026-10-15,官网实抓):

1. **官网 10/09 公告**:`Red Thread` 因制片方撤片下架 ——
   普通场次 `510`(10/12 15:30 LOTTE 2)/ `633`(10/13 10:00 KOFIC)取消并全额退款;
   午夜场 `168` 的成员由 `Red Thread` 换成 `Spirit Guardians: The Last Secret Of The First Emperor`。
   官网排期页的做法是 `var removeCodes = ['510', '633'];` + 前端 JS 摘格子 ——
   **本仓 `tools/scrape_biff_web.py` 不解析这行**,所以重抓仍会把已取消场次收进来。
2. **颁奖已公布**(另见 PLAN §B):
   `Busan Vision Awards` 30 项(press release 10/14,`intSeq=103339`)、
   `The Asian Filmmaker of the Year` = Michelle YEOH(官网 Award Winners 页 `page_num=11098`)、
   `Camellia Award` = 许鞍华(10/07 开幕式)。
   主竞赛(`New Currents Award` / `Busan Award for Best Film / Director / Actor /
   Special Jury Prize / Artistic Contribution`,`page_num=11101 / 11345–11349`)**尚未公布**,
   官网页面正文为空 —— 本轮不等待、不做占位。

## 范围

**做:**

A. 排期数据正确性
- `tools/scrape_biff_web.py`:解析每个日期页的 `var removeCodes = [...]`,
  汇总后**从场次里剔除**,并写出 `<out>/cancelled.json`(取消清单,供下游 merge 使用)。
- `tools/merge_schedule.py`:新增 `--cancelled`(默认读 `--web` 同目录的 `cancelled.json`),
  在「册子补官网缺失场次」这一步**跳过已取消的 code** —— 否则册子会把 510/633 补回来
  (`merge_screenings` 的策略是「册子里有、官网没有的一律补进来」)。
- 重抓官网 → 重跑 merge → 刷新 `apps/web/public/schedule.json` / `venues.json`。
  `168` 的 `midnight_members` 由官网自身更新,重抓即自动修正(不写死替换表)。
- 回归测试(先红后绿):510/633 不在公开产物里;168 成员不含 Red Thread。

B. 获奖信息
- 新增离线产物 `apps/web/public/awards.json` + 生成脚本 `tools/build_awards.py`
  (抓官网 press release + Award Winners 页 → 解析 → 与 `films.json` / `schedule.json` 匹配)。
- 新增 `apps/web/src/awards.ts`(照 `extras.ts` 的「可缺省增强数据」先例:fetch + try/catch + 结构守卫)。
- 展示:场次级(场次卡徽章行)+ 影片级(影片库卡片 / 影片资料弹层)。
- 测试:纯函数单测 + 产物哨兵(每条获奖至少匹配到一个 code 或一个 film)。

**不做:**

- **不抓主竞赛大奖**(尚未公布,页面为空)—— 等官方公布后再补一轮,不在本轮留占位数据。
- 不做 `Juries`(评委名单)、`Streaming Schedule`、`Official Daily`、ACFM 市场奖 —— 与「选片 / 抢票」无关。
- 不动 `festival-extras.json` 的过期口径(开票批次 / 倒计时)—— 独立议题,另开 PLAN。
- 不改 `biff.*` localStorage 契约、不动 D1 / API。
- 不改 `apps/web/src` 里与获奖无关的渲染路径;不动在途未提交的「快速投票」改动(他人工作区改动)。

## 方案取舍

| 备选 | 结论 | 理由 |
|---|---|---|
| 取消场次:只从 `schedule.json` 手删 510/633 | 否决 | 下次重抓又回来;根因是抓取脚本不认 `removeCodes`,必须修在源头 |
| 取消场次:抓取脚本删掉 + 不告诉 merge | 否决 | merge 会把册子里的 510/633 当「官网缺失场次」补回来 —— 必须显式传取消清单 |
| 取消场次:把 `removeCodes` 当成前端设置项 | 否决 | 这是**官方下架**语义,不是显示偏好;数据侧就该没有这两场 |
| `168` 成员:写一份「替换映射表」 | 否决 | 官网已自行更新 pack 成员,重抓即对;写死表等于第二份口径,下次换片又得改 |
| 重抓后直接 `cp` 覆盖 `schedule.json` | 否决 | 现有产物是 merge 结果(含册子独有的 MEGABOX 901–942 共 42 场),直接覆盖会丢场次 |
| 获奖数据:手改 `films.json` 加 `award` 字段 | 否决 | `films.json` 是影片目录(单一职责);获奖是另一份口径,且有「同一部片多个奖」的基数问题 |
| 获奖数据:单独产物 `awards.json` + 前端可缺省加载 | 采纳 | 与 `festival-extras.json` / `pni.json` 同款先例:缺文件静默降级,不阻塞主流程 |
| 获奖数据:前端不展示、只存文件 | 否决 | 用户明确要「影片 / 场次级 badge」 |
| 获奖条目与影片的关联:靠片名串匹配 | 否决 | 靠 `films.json` 的 `title_en/title_orig/title_zh` 归一表匹配,产出 `filmIds` + `codes` **双键**并检入产物 —— 前端只查表,不重算 |
| 奖项中文名:机翻 | 否决 | 与 `GUEST_ZH` / `event-titles` 同款先例:人工维护译名表,查不到就只印英文 |
