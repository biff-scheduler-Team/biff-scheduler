# PLAN 2026-09-12 00:25:32 — 移动端极端适配（主视图显性化 + 单日纵向时间线）

> 需求（用户原话）：「极端的适配要怎么做 现在移动端的话 一打开就是一个很大的一个影片库 然后就把那个甘特图挡住了」
> → 范围确认（用户选择）：**A + B** —— ① 主视图显性化（改默认落点 + 明确「时间轴 ⇄ 列表」切换）；
> ② **≤768px 用「单日纵向时间线」替换二维甘特**（先出本 PLAN，再实现）。
> 补充拍板（2026-09-12 第二轮）：
> · 时间线卡片**不带「定位 ▸」**（用户原话「不用了」—— 时间线本身就是时间轴）；
> · **窄屏默认日期 = 今天**（仅当今天落在展期窗口内；用户原话「改成『今天在展期内就用今天』」）。
> 硬约束（用户原话）：「**不能影响现在 PC 端的使用和交互**」—— 见 §6。
> 前置：`PLAN-20260910235000`（窄屏 ≤768px「列表优先」）、`PLAN-20260911140342`（抽屉滑出 / 拖拽调宽）。
> 本文件 = 本需求唯一规划文档。

## 1. 现状（代码事实，均为实读，非推测）

**「一打开就是影片库、甘特图不见了」的三个成因**：

1. `main.ts::boot()` 第 1093 行：`if (isMobileDrawer()) openFilmPicker(libraryCtx(), "lib");`
   —— 窄屏**无条件**打开抽屉，且落点写死 `"lib"`（影片库）。
2. `style.css` 第 518–521 行：`@media (max-width: 1099px) { main.is-picker-open #main-col { display: none } }`
   —— 抽屉一开，主列**整块 `display:none`**。所以甘特图不是「被遮住」，是**根本没有渲染**。
3. `style.css` 第 523–525 行：同断点下 `#picker-drawer { width: 100% }`
   —— 抽屉是全屏，`--picker-w`（520–800）不参与，拖拽手柄也隐藏。

**为什么当初这么设计**（`PLAN-20260910235000` §2.4 有记录）：
甘特图是 **26 厅 × 时间轴**的二维网格（`grid.ts::buildGrid`），缩放下限 `ZOOM_MIN = 0.55`
（行高 `ROW_H 92 × 0.55 ≈ 51px`、字号 55%），横向刻度 `PX_PER_MIN 3.0 × 0.55 ≈ 1.65px/min`；
一天约 14h ≈ 840min ⇒ 轨道 ≈ 1386px + 影厅列。**390px 竖屏要横滚 4 屏以上、同时纵滚 26 行**。
结论：这个形态在手机上本身不可用，所以当年选择「列表优先、甘特降级为次级入口」。

**⚠ 本需求真正的难点不是排版，而是：手机上缺一个可用的时间轴形态。**
只把默认落点从「影片库」改成「行程」，用户点回时间轴看到的仍是那个不可用的二维网格 ——
「被挡住」的抱怨会原样复发。故 B（新形态）是必需项，A（落点）只是顺手把主次讲清楚。

**既有可复用资产**（避免重造）：
- `row.ts::screeningRow()` —— 场次行 / 行程卡的**唯一构造**，已经就是「单行优先 + 内层流式折行」，
  390px 下会自动折成 2–3 行，**不需要为窄屏另写一套行排版**。
- `#grid-wrap` 内的 `#date-chips`（日期条）与 `#grid-filters`（筛选条）—— 时间线可直接复用同一份 DOM 与状态。
- `agenda.ts::gapConnector()` —— 「卡片之间的连接件」这套视觉语言已有先例（赶场间隔三态）。
- `main.ts` 的 `flashScreening()`（按 `[data-code]` 全量闪烁）、`scrollTargetFor()`（容器内居中）、
  `jumpToScreening()` / `jumpToDate()` —— 只依赖 `#grid-scroll` 容器与 `[data-code]` / `[data-card]` 锚点。

## 2. 方案

### 2.1 A：主视图显性化

| 项 | 现状 | 改为 |
|---|---|---|
| 窄屏默认落点 | `openFilmPicker(ctx, "lib")` | **不再自动打开抽屉**（主视图 = 时间线，见 §2.2）；顶栏按钮是「列表 · 行程」入口 |
| 窄屏默认日期 | `cat.dates[0]`（10/6，展期第一天） | **今天**（仅当 `todayIsoLocal()` 落在 `cat.dates` 内，否则回落 `cat.dates[0]`）—— 手机打开就该看到「今天」 |
| 顶栏按钮文案 | 抽屉开 → 「时间轴 ▸」/ 关 → 「列表 · 行程」 | 语义不变，但**主次反转**：默认（关）就是时间线，按钮 = 「去列表」 |
| 抽屉内返回 | 「收起 ✕」 | **只把文案按断点换掉**：窄屏 = 「◀ 时间线」（动作相同 —— 都是 `closePickerDrawer()`；语义不同：不是「收起面板」而是「回到时间轴」）。**不新增按钮**，类名 / 落位 / 宽屏文案逐字不动 |
| 宽屏 | 行程非空自动滑出抽屉（`ensurePickerOpen(ctx,"agenda")`） | **完全不动**（宽屏没有「被挡住」问题） |

> ⚠ 这一步单独落地就能消除「一打开就是影片库」；但**只有 B 落地后才有意义** ——
> 否则「回到时间轴」看到的是不可用的二维网格。故 A 与 B **同轮交付**，A 不单独发版。

### 2.2 B：移动端「单日纵向时间线」（核心）

**形态选择（关键取舍，先论证再动手）**：

| 形态 | 做法 | 结论 |
|---|---|---|
| (a) 真时间轴（绝对定位） | 卡片 `top = (start − axisStart) × pxPerMin`、`height = 时长 × pxPerMin` | ❌ **否**。手机上时间重叠的场次必须并排分列，390px ÷ 2~3 列 ≈ 130px/列，`screeningRow` 的「CODE / 影厅 / 时间 / 时长 / 章组」在 130px 里完全放不下，等于把「不可用」从横向搬到纵向 |
| (b) **流式列表 + 时间轨** | 卡片按开始时间升序依次排列（**不绝对定位**）；左缘一条窄时间轨画竖线与每场的时间点 / `HH:MM`；相邻两场**都已选**且时间重叠 → 卡间红色连接条 + 整卡淡红底 | ✅ **采纳**。牺牲「时长比例」这一条视觉信息，换回可读性与零新排版（直接复用 `screeningRow`） |

**结构**（`src/timeline.ts::buildTimeline()` 产出，**替代 `#grid-scroll` 本身**）：

```
<div id="grid-scroll" data-grid="1" data-timeline="1" class="bg-page rounded-8 p-[10px]">
  <div class="relative grid gap-[6px]">                      ← 轴线的定位上下文
    <span class="absolute top-[14px] bottom-[14px] w-px bg-line-strong">  ← 时间轴竖线（内联 left:45px）
    <div class="grid items-start">                            ← 一行 = 时间轨 + 一张卡
      <div class="relative text-right …">18:00 <i class="dot"></i></div>
      <div data-code="003" data-card="1">…screeningRow…</div>
    </div>
    <div>⚠ 与上一场重叠 18min</div>                           ← 仅**相邻两场都已选**时出现
    <div class="grid items-start"> … </div>
  </div>
</div>
```

- **每张卡 = `screeningRow({ s, cat, rowCls })`**（不带 `headTitle` ⇒ 只返回场次行）。
  这是 `row.ts` 的既有唯一构造，**零新视觉**（CONVENTIONS §二「电影卡片都是同一个设计语言」）。
- **卡片不带任何操作按钮**（2026-09-12 拍板）：不要「定位 ▸」（时间线本身就是时间轴），
  也不要「＋/✓」（整卡点选即加入 / 移出 —— 与二维网格**同一交互**）。
  于是**零新增事件监听**：委托复用 `main.ts` 既有的 `#grid-scroll [data-code]` 分支
  （时间线卡同样挂 `data-code` + `data-card="1"`）。
- 冲突表达复用既有 `@utility in-conf` + `border-2 border-conf`（整卡淡红底红框）；
  「已选」复用 `@utility in-plan`（整卡淡绿底）；未选 = `border border-line`。
  类组合与 `grid.ts::cardStateOf` **逐字同源**。**不引入新色**。
- 时间轨 = 竖线 + **每场一枚时间点 + `HH:MM`**（11px `text-meta`，圆点落在竖线上，已选绿 / 冲突红 / 未选灰）。
  ⚠ 刻意**不画整点刻度**：这是「流式列表 + 时间轨」，不是按分钟定位的真时间轴，
  没有刻度的位置语义；`HH:MM` 已给出每一场的落点。
  跨午夜场按既有 `util.ts::nextDayTag` 加「次日」前缀，**不对小时取模**。

**集成点（`main.ts::renderGrid` 分支，逐一列明，避免踩既有不变量）**：

| 既有机制 | 时间线模式下的处理 |
|---|---|
| `gridKeyNow()` 几何签名 / `patchGridStates()` 就地 patch | **不走**。时间线**始终全量重建**（手机端列表重建成本可接受，且可挂 `content-visibility`）；`renderGrid` 首行按 `isMobileDrawer()` 分支 |
| `drawConflictLinks()` 跨行连线 | **不画**（时间线是单列，冲突由连接条 + 整卡红底表达） |
| `rowAnchor()` / `applyRowAnchor()` 纵向锚点 | **自然失效**（时间线不挂 `data-vrow` ⇒ 函数内 `rows.length < 2` 提前 return），无需改动 |
| `fitGridHeight()` 容器限高 | 时间线模式下**不限高**（`maxHeight` 置空）—— 手机上走页面滚动比「容器内嵌套滚动」自然 |
| `scrollTargetFor()` 纵向居中 | 复用。它读 `[data-grid-ruler]` 算吸顶标尺高度，时间线没有标尺 ⇒ `rulerH = 0`，退化为「按 `clientHeight` 居中」，正确 |
| `flashScreening()` 定位回执 | 复用（时间线卡同样挂 `data-code`，`querySelectorAll` 全量取） |
| `#zoom-ctl` 缩放控件 | 窄屏**隐藏**（`is-hidden`）—— 时间线没有「横向刻度」，缩放无意义 |
| `hourFilter` 小时筛选 | 时间线模式**恒为 `null`**（切到窄屏时清空）；`renderGridMeta()` 不渲染「只看 X 段」pill |
| `filters`（字幕 / 影厅 / GV） | **复用同一份**：时间线里被筛掉的场次**不列**（二维网格里「影厅 = 整行去留」，时间线里自然退化为「该场不列」） |
| `jumpToScreening()` / `jumpToDate()` | 复用。落点由「横向居中卡片」变为「滚到该卡」，`scrollTargetFor` 一次 `scrollTo` 即可。**窄屏先 `closePickerDrawer()`** —— 抽屉是全屏覆盖，「定位」的语义就是「带我去时间轴」，不收起等于没跳 |
| 抽屉开 / 收回调（`setPickerToggleHandler`） | 窄屏**提前 return**（只刷新顶栏文案）：抽屉是全屏覆盖，开 / 收不改变时间线几何，重绘只会白刷列表并把滚动位置 / 闪烁回执清掉 |
| 点卡片后自动弹抽屉 | 窄屏**不弹**（`!isMobileDrawer()` 守卫）：点一张卡就把人从时间线拽走；卡片底色 + 顶栏计数已是即时回执 |
| `resize` 的 `fitGridHeight` 重算 | 窄屏**跳过**（时间线不限高，别给它写 `maxHeight`） |
| 跨断点（宽屏 ↔ 窄屏） | `matchMedia("(max-width: 768px)")` 的 `change` → 清 `hourFilter` + `renderZoomCtl()` + `renderGrid()` + `updatePickerLabel()`；两个形态是**同一块容器**的两种画法，不重画会混着显示 |

### 2.3 纯函数与单测（构建门禁要求）

`timeline.ts` 拆出可 node 单测的纯函数：

```ts
/** 当日时间线条目：过筛选 → 按开始时间升序 → 逐条算「与上一场**已选**」的间隔 / 重叠 */
export function timelineEntries(cat: Catalog, date: string, o: TimelineOpts): TimelineEntry[];

interface TimelineEntry {
  s: Screening;
  picked: boolean;      // 是否已加入行程（底色 / 连接件的判定源）
  overlapMin: number;   // 与上一场已选的重叠分钟（>0 = 画红色「重叠」连接件）
  slack: SlackResult | null; // 与上一场已选的余量判定；null = 本场未选 / 前面没有已选场
  crossVenue: boolean;  // 与上一场已选是否跨馆（连接件文案用）
}
```

⚠ 连接件**只服务已选场次**：时间线列的是当天**全部**场次（≈75 场），给任意相邻两场都算「赶场间隔」
是纯噪声 —— 未排进场次的间隔没有意义。故 `prev` 只在遇到已选场次时推进。

新增 `tests/timeline.test.ts`：排序口径、跨午夜（`end_time ≥ "24:00"`）不取模、重叠判定、筛选剔除。

## 4. 验收口径

**窄屏（390×844，无头 Chromium）**：
1. 打开页面 → **直接看到单日时间线**（不再出现影片库）；场次按开始时间升序；默认日期 = 今天（在展期内时）。
2. 相邻两场**都已选**且时间重叠 → 两卡之间有**红色连接条**且整卡淡红底红框；未选的相邻场次**无连接条**。
3. 点卡片 → 卡片变绿底（`in-plan`）且顶栏计数 +1；**不弹出全屏列表**（留在时间线）。
4. 点顶栏按钮 → 全屏列表（`#main-col` 仍 `display:none`）；面板内「◀ 时间线」→ 回到时间线。
5. 日期条切日期 → 时间线跟随；筛选条（字幕 / 影厅 / GV）→ 被筛场次不列。
6. 时间线模式下**看不到**缩放控件与「只看 X 段」pill。
7. 抽屉里点「定位 ▸」/ 行程日期头 → 抽屉自动让开并落到时间线对应卡片。

**桌面（1440×900）：必须与改动前逐像素一致** —— 见 §6。

**构建门禁**：`npm run build`（= `typecheck && lint && test && vite build`）全绿。

**部署**：按 2026-09-11 口径 —— `git push origin main` → Cloudflare Workers Builds 自动上线 `https://biff.lcandy.co`。

## 5. 风险

| 风险 | 处置 |
|---|---|
| `renderGrid()` 分支后，宽屏的 `pendingAnchor` / `lastGridKey` 等模块级状态被时间线路径污染 | 时间线**不复用**这些变量（走独立函数），分支在最前，宽屏路径逐字不动；`timelineMounted` 在切回宽屏时强制 `force: true` 全量重建 |
| 时间线全量重建 → 每次点选都重建整条列表 | 单日 ≈75 场，重建成本可接受；卡间不保留展开态（时间线卡片无展开语义） |
| 用户从宽屏拖窄到 ≤768px（或反之）时布局突变 | 监听 `matchMedia("(max-width: 768px)")` 的 `change` → 重走 `renderGrid()` + 复位 `hourFilter` + 刷新顶栏文案 |
| `#picker-drawer` 在窄屏 `position: static`，抽屉打开时页面滚动位置影响落点 | 复用既有 `library.ts::scrollRowToTop()` 口径（只滚容器，不滚 `document`） |

## 6. ★ 硬约束：PC 端零影响（用户 2026-09-12 明确要求）

用户原话：「**不能影响现在 PC 端的使用和交互**」。执行手段 = **单一开关 + 逐处守卫**：

1. **所有新逻辑都挂在 `isMobileDrawer()`（= `matchMedia("(max-width: 768px)")`）之后**，
   该函数在 ≥769px 恒为 `false`；桌面走的就是改动前的同一条代码路径。
2. **`grid.ts` 一行不改**（二维网格的构建 / patch / 连线 / 锚点全部原样）。
3. **`style.css` 一行不改**（新增样式为零）。
4. `library.ts` 只改「收起 ✕」的 `textContent` 与 `dataset.tip`，**类名逐字不动** → 桌面按钮像素不变。
5. `boot()` 里桌面的两条行为（默认日期 `cat.dates[0]`、行程非空自动滑出抽屉）**逐字保留**。
6. 新增的 `matchMedia` `change` 监听**只在跨越 768px 时触发**，不参与任何桌面渲染路径。

**验收（提交前必做）**：
- `git diff src/main.ts` 逐 hunk 复核 —— 每一处新增都必须带 `isMobileDrawer()` 守卫（或位于其分支内）；
- 复核桌面独有调用点未被误删（实测曾误删 `setPickerToggleHandler` 里的 `fitGridHeight(grid)`，已恢复）；
- 桌面宽度（≥1100px）无头跑一遍：日期条切日、点卡选中 / 移出、缩放 ±、抽屉开合、定位 ▸ —— 全部与改动前一致。
