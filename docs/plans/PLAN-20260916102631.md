# PLAN-20260916102631 — 讨论区定位态可直接发帖

## 目标

用户原话（逐字保留）：

> 我的行程定位到讨论区的时候 可以直接在讨论区发帖 现在的逻辑是回让你回到行程中 点击讨论按钮
> 但是讨论按钮已经改成定位了

还原成机制：`/discussions?focus=<code>` 的定位条只提供「清除定位」，**没有发帖入口**。
要发帖只能点某个格子的「进入讨论」——而格子是**已存在的帖子**；某场**一条帖子都没有**时，
讨论区里没有任何可点的发帖口。此时页面的空态提示还在说「到『我的行程』里挑一场，点卡片上的
『讨论』写下第一条」，而行程卡上的「讨论」自 `PLAN-20260915233816` 起已改成**跳回讨论区定位**
（不再就地弹层）—— 于是形成闭环：跳回来 → 没帖子 → 被告知回行程点「讨论」→ 又跳回来。

## 范围

**做：**

1. `DiscussionsPage.tsx` 定位条：当 `focus` 对应排期里真实存在的场次时，增加一个 **「发帖」** 入口，
   打开**既有的** `ScreeningDiscussionDialog`（这是发帖 / 反应 / 删除的唯一实现）。
   承接「这场还没有帖子」的场景 —— 定位条本身就把发帖口摆出来了。
2. `ScreeningDiscussionDialog.tsx`：新增可选 `onPosted?(post)` 回调，成功发布后通知调用方。
   讨论区把它接成「把新帖插到方格墙首位」，使**发布后立刻可见**（否则关掉弹层后墙上还是旧内容，
   用户会以为没发出去）。格子上的「进入讨论」同样接上，两个入口行为一致。
3. 空态提示文案订正：原文案指引的路径（回行程点「讨论」写下第一条）已随定位改造失效，
   改为符合现状的说法。
4. e2e `screening-social.spec.ts`：新增一条用例 —— 定位到**零帖子**的场次，定位条上能直接打开发帖弹层。

**不做：**

- **不做独立顶部发帖框**（无场次归属就发不了，接口契约如此）；发帖仍**只**走 `ScreeningDiscussionDialog`。
- **不改接口 / 表结构 / 分页口径** —— 本轮纯前端入口与回调。
- **不改 `biff.*` 键**（`biff.discussionprivacy.v1` 原样）。
- **不做真·瀑布流 / 富文本 / 楼中楼**。
- **不动 `style.css`**（命中 TEST-MAP `allOn` → 三浏览器全量 E2E）；样式仍只落 `screening-social.css`。
- **不动 `legacy/`**（只读回退件，只接 P0）。
- **不动在途改动文件**（`PLAN.md` 文档头、`apps/web/src/poster.ts`、`apps/web/src/share.ts`、
  `apps/web/tests/poster.test.ts`、`apps/web/tests/share.test.ts`、`apps/web/src/redblack.ts`、
  `docs/CONVENTIONS.md` 的**既有段落** —— 只追加本需求段落 / 只改文档头那一行）。
- **本轮不推送** —— 本地跑通 + 起 dev server 交用户验收，用户确认后才推。

## 方案取舍

| 备选 | 结论 | 理由 |
|---|---|---|
| 定位条加「发帖」按钮，打开既有 `ScreeningDiscussionDialog` | **采纳** | 发帖 / 反应 / 删除 / 社区提醒仍是**一份实现**（红线 5）；场次归属由 `focus` 天然给出 |
| 定位条里内嵌一个**行内发帖框**（分类 + 正文 + 发布） | **否决** | 等于把 `ScreeningDiscussionDialog` 的 composer 抄第二份；分类白名单 / 登录门闸 / 提醒口径会漂移 |
| 讨论区顶部加一个全局发帖框 | **否决** | 帖子必须挂场次，无场次的框要么假、要么得改接口与表结构（`PLAN-20260915233816` 已否决） |
| 零帖子时在方格墙里补一个「写第一条」占位格 | **否决** | 占位格不是帖子，会污染 `posts.length` 计数与方格墙语义；入口放定位条语义更直白 |
| 在行程卡上恢复「就地弹层」（同时保留定位） | **否决** | 用户上一轮明确要「直接定位到这个区域」；两套入口 = 讨论有两处家 |
| 关掉弹层后重新拉第一页刷新方格墙 | **否决** | 会丢翻页进度、把用户从当前位置拽回；改用 `onPosted` 只把新帖插到首位 |
| `onPosted` 只接定位条、不接格子「进入讨论」 | **否决** | 同一页面两个入口行为不一致（一个发布后可见、一个不可见），无正当理由 |

## 验收标准

1. `/discussions?focus=<某场>` 打开定位条，「发帖」按钮可见；该场**已不在本次排期**（`cat.byCode` 无此项）时不出现。
2. 点「发帖」→ 打开 `<code> 场次讨论` 弹层（社区提醒 / 分类 / 正文 / 登录门闸**全部与格子上进的一致**）。
3. 零帖子的场次也能走到发帖（定位条文案「这场还没有帖子」+ 发帖口同时在场）。
4. 登录后成功发布 → 关掉弹层，方格墙**首位**立即出现这条新帖，定位条的「共 N 帖」同步 +1。
5. `npm test` 与 `npm run verify:quick` 全绿；`screening-social` spec 通过（贴出计数与断言）。
6. 本地 dev server 可交互，交用户本地验收；**未获用户确认前不推送**。
