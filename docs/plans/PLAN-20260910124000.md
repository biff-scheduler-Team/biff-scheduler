# PLAN-20260910124000 · 2025 影片目录：从册子「影片介绍页」抽出 224 部（含排期关联）

## 1. 现象 / 需求

PLAN-20260910122007 §3.3 要一份与 699 场 2025 排期对得上的影片目录（`public/films.json`）。
2026 目录（250 部，中文名来自用户提供的 xlsx）与 2025 排期**全对不上** —— `filmNodeKey` 100% 落到
`sched:` 分支，影片库「未关联」，点开任何片看不到场次。

## 2. 纠偏：§3.3 原计划不可行

§3.3 写的是「用排期的 `page` 字段定位影片介绍页，按页内坐标就近配对」。实测**不成立**：

- **一个印刷页装 3 部片**，所以 89 个 `page` 值各自对应多部不同影片（如 `page=119` → The Blue Trail + The Chronology of Water），`page` **不是影片唯一键**；
- 另有 10 个 code 的 `page` 为空（`800 / 164 / X1601 / 621–626 / 002`）。

改为**反向关联**：从影片介绍页读出每部片自己的场次 code 清单，用 code 去排期取权威片名。
影片页印的 code 清单是官方数据，权威且唯一。

## 3. 方案：`tools/extract_films_2025.py`（新增，只读 PDF + schedule.json）

- 扫描 **PDF p22–p97**（印刷页 42–194）；每页 **2 栏**（`x0 < 250` 左栏）。
- **归属规则**：一栏内按 `y` 排序，**每个元数据行 `<国别> | <年> | <N>min | <格式> | <color>` 开启一部片**，
  其后直到下一个元数据行之间的所有场次行都归它。**不能用 y 窗口** —— 一页 2–3 部片，窗口切不准。
- 三处版面陷阱：
  1. **国别换行**：国别太长时独占一行，下一行才是 `| 2025 | 89min | …`（实测 p43 右栏 7 国）。
     同一栏里并排着别的 x 子栏（韩文简介 x≈656），**不能只看上一条** → 按 **x 邻近（±20pt）** 回看。
  2. **导演三种情形**：① 有 `Director …` 行（可能排在**场次行之后**，故不能与 code 采集互斥）；
     ② 同一行后面并排着别的职务（`Executive Producer / Co-producers / Script`）→ 遇职务词截断；
     ③ **整页不印 `Director` 前缀**（实测 No Other Choice / Without Permission）→ 用「英文名行 + 纯韩文名行、
     同 x 子栏、行距 ≤14pt」三连判据识别导演信息框。
  3. **联映块名污染**：排期里 code `008/081/164/244` 的 `title` 印的是**块名**（`163, 165 Midnight Passion 1`），
     而这些 code 又会出现在块内各部片的 code 清单里。不排除就会把整块 8 部片**并成一条垃圾目录**。
     → `BLOCK_TITLE` 正则跳过块名再取片名。
- 单元归属：PDF p18「목차」给出各单元起始印刷页，取「最后一个 ≤ 本页印刷页」的单元。
- 输出严格只含 `types.ts::FilmItem` 的 10 个字段（片长 / 韩文名 / code 只用于自检日志，不进 JSON）。

## 4. 验收

1. `npm run typecheck` 通过。
2. `public/films.json` = 224 部；每部都有 `title_orig / country / year / director`（0 缺失）。
3. `filmNodeKey` 关联：**699 场 → 646 场命中 `cat:`**（92.4%）。
4. 剩余 53 场走 `sched:` —— 全部是非影片条目（闭幕式 002 / 颁奖重映 621–626 / 特别对谈 800 /
   Community BIFF 村活动 901–944 / 结业式 X1601），本就没有影片介绍页，属正确行为。
5. 影片库能按单元筛选（16 个单元 chip），点开某片能看到它的场次。
