# PLAN 2026-09-11 21:11:38 — 「我的选片」卡片默认收起

> 需求(用户原话)：「我的选片如果已经添加了选片的 就先收起卡片」。

## 1. 问题:选片一多,「我的选片」tab 一打开就是一条长不见底的场次流

「我的选片」tab 的影片卡片**默认全展开**(`library.ts::openFilmPicker` 里
`const expPick = new Set<string>([...ctx.picks.keys()])` —— 当前每一部选片都进展开集合),
每张展开的卡片都会把**该片全部可选场次**(过排片筛选 + 日期筛选后)逐行铺开。

于是「选片 10 部」时,打开抽屉看到的不是一份**影片清单**,而是十几屏的场次流水 ——
想找某部片只能一路滚(用户口径:「如果已经添加了选片的 就先收起卡片」)。

## 2. 改动

| 文件 | 改动 |
|---|---|
| `src/library.ts` | `expPick` 初值由「当前全部选片 key」改为**空集** —— 打开抽屉时「我的选片」里所有卡片一律**先收起**;注释同步改写(原注释「选片通常 < 30 部,展开才看得到场次列表」的前提已不成立) |
| `docs/CONVENTIONS.md` | §二「抽屉内三个 tab」条目补一句:「我的选片」卡片**默认全收起** |

## 3. 保留什么(刻意不改)

- **「＋ 加入我的选片」(影片库)后仍把该片写进 `expPick`** —— 那是刚动过的那一片,
  且 toast 正引导用户「去那里挑场次」,到「我的选片」直接能挑,不必再点一次;
- **「✓ 已在选片 · 去排场次 ▸」(`goPickShows`)仍展开目标片** + 滚到面板顶 + 闪烁 ——
  这是明确的「带我去挑这部片的场次」动作,与「默认收起」不冲突;
- **「影片库」★ 定档后仍把该片写进 `expPick`**(同第一条:刚打标的那一片);
- `pickerTab`(上次停留的 tab)**跨开合保持**不变 —— 变的是卡片展开态,不是落点。

⚠ `expPick` 是 `openFilmPicker` 的闭包变量,抽屉每次打开都重建内容(见 `pickerRender` 注释),
故本改动等价于「**每次打开抽屉,「我的选片」都是全收起态**」,不记忆上次展开了哪几片 ——
这与「先收起」的字面要求一致(用户要的就是每次先看到清单)。

## 4. 设计取舍

- **不做「按数量阈值决定展开/收起」**(如「选片 ≤ 3 部才展开」):阈值是新的魔数,
  且同一部片在两个用户 / 两次打开时行为不一致,解释成本高于收益;「一律先收起、要看再点」规则单一。
- **不改成「手风琴」(展开一片自动收起别片)**:用户没要求;且选片 tab 的用途是
  「挑场次」,有时确实要对照两部片的场次时间,强制互斥会让这种对照做不了。
- 收起后的卡片头仍带状态章「共 N 场 / 已排 M 场」(或「未排场」),**不展开也知道这部片排了几场** ——
  收起不等于信息丢失。

## 5. 验收

- `npm run build` 全绿(typecheck + eslint + 单测 + vite build;本改动无纯函数可测,DOM 行为走人工核对)。
- 人工路径:打开抽屉 → 「我的选片」→ 所有卡片**收起**,只看到片名 / 副标题 / 「共 N 场 / 已排 M 场」;
  点卡片头展开该片场次;从「影片库」点「✓ 已在选片 · 去排场次 ▸」→ 切过去**仍展开该片**并闪烁。
- `npm run deploy` 上线 Cloudflare Pages production。
