### 正面推翻旧决策（必须写明，不能悄悄加回来）

`apps/web/src/state.ts:107-108` 曾于 2026-09-11 删除「抢票结果」三态，理由是「抢票在票务系统里完成，在排片工具里追踪『已抢到 / 售罄』是多余的中间态」。本次**主动推翻**，理由三条：

1. 它不再是本地孤岛 —— 而是「同场观影人数 + 场次讨论」的共享数据底座（本地状态决定上报哪些 code）；
2. 需求明确要求标记抢票结果并区分「实际行程」；
3. 边界不变：仍是**本地优先、仅登录后随账号同步**，不上传任何未经登录的数据。

同时明确**不复活「售罄」**这类票务系统内部状态 —— 三态全是**用户自述结果**。

### 澄清后的口径

| 议题 | 结论 |
|---|---|
| 举报怎么送到开发者手里 | **后台管理页（只读列表）**，不做 webhook / 邮件推送 —— 用户：「暂时不用太复杂」 |
| 白名单放哪 | **`ADMIN_SUBJECTS` secret**（不进仓库）；本地写 `apps/api/.dev.vars` |
| 后台范围 | **只读举报列表**（不做删帖按钮、不做处理状态） |
| 举报粒度 | 需登录 + 选固定原因 + 可选备注；同一人同一帖只能报一次（唯一索引） |
| 免责 / 范围提醒强度 | 常驻提示 + 首次说明，**不阻断发布**（未选「勾选确认」「独立规则页」） |

### 追加范围

**做：**

1. **社区约定文案**：常驻提示（只聊电影 / 勿发个人信息 / 本站只是信息发布平台、不对纠纷负责）+ 首次说明弹一次。
2. **`screening_report` 表**（D1 迁移 `0006`）+ 唯一索引 `(post_id, reporter)`；**含被举报内容快照**。
3. `POST /api/screenings/:code/discussion/:id/reports`（需登录）+ 举报小窗（原因 + 可选备注）。
4. `GET /api/admin/reports`（`requireIdentity` + `requireAdmin`）+ `/admin` 只读后台页。
5. `ADMIN_SUBJECTS` secret 白名单（`config.ts` 可选字段；**缺省 = 无人可进**）。
6. `/api/account/me` 增 `admin` 字段 → 管理员登录后顶栏出现「举报管理」入口。

**不做：**

- 自动隐藏 / 自动删除被举报内容 —— 会被恶意举报当成武器；
- 举报的「待处理 / 已处理」状态、后台删帖按钮；
- webhook / 邮件推送；
- 建议反馈板（`/feedback`）的举报按钮（举报原因契约按可复用设计，将来直接接）；
- **前端权限判断** —— 白名单只在服务端，前端拿 403 渲染「仅管理员可见」。

### 关键取舍

| 备选 | 结论 | 理由 |
|---|---|---|
| 举报只存 `post_id` | **否决** | 作者可在被举报后删帖 / 改内容 → 证据消失；改存 `post_excerpt` 快照 |
| 复用 `/feedback` 板当举报箱 | **否决** | 那是**公开读**的，举报内容与被举报内容会一起公开 |
| 白名单写进 `wrangler.jsonc` vars | **否决**（用户选） | 用户明确要求不进仓库 |
| 空白名单 = 人人可进 | **否决** | 安全默认必须是「没配 = 谁也进不去」 |
| 前端也判一次管理员 | **否决** | 两份口径，且等于把名单公开 |

### 追加验收

1. 讨论弹层常驻提示含「不对由此产生的任何纠纷负责」；首次说明含四条约定，点「知道了」后不再出现；
2. 帖子卡片对**他人**的帖子显示「举报」；未登录点它弹登录面板；
3. 举报成功 → toast；重复举报 → 「你已经举报过这条内容了。」（服务端 409）；
4. `/admin`：未登录 → 「请先登录」；非管理员 → 「仅管理员可见」且顶栏无入口；管理员 → 列表 + 「同一帖被举报 N 次」；
5. `npm run verify` 全绿；受影响 19 个 spec desktop-chromium **80 passed**。

### 追加后的人工步骤（部署前必做）

`ADMIN_SUBJECTS` 是 **secret**，不进仓库也不会随推送自动创建 —— 推送前需要人工执行一次：

```sh
npx wrangler secret put ADMIN_SUBJECTS -c apps/api/wrangler.jsonc   # 填 user_… （你自己的 subject）
```

subject 取法：登录后看 `GET /api/account/me` 的 `user.id`，或 `SELECT DISTINCT subject FROM app_session;`。
**没配 = 举报后台谁都进不去**（安全默认，不会退化成「谁都能进」）。
