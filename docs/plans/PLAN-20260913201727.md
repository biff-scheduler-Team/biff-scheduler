# PLAN-20260913201727 — 把「靠人记住的规范」改成「机器能挡的闸门」

## 目标

承接「本项目还能引入什么规范」的盘点结论。现状是:**规范写得比执行得好** —— §0–§9 全是要人记住的条款,
真正能挡错误的只有云端那一步 `npm run build`(不含 E2E)。本轮把其中七项落成可执行的东西。

用户原话(2026-09-13):「请你把三个可以先执行的优化点先优化了……可以落到 `docs/TEST-MAP.md`:改动路径 → 必跑 spec,
然后再加上提交门禁的机械与约束,然后还有 Legacy 的退役计划,然后还有依赖更新机制」

**硬约束(用户原话)**:**会话草稿的落点不得绑定某个 IDE** —— 「不要把会话的草稿固定落点在 CodeBuddy 里面,
因为我同事可能用的是 Codex」。故一律走**工具中立**的 `.scratch/`(已 gitignore)。

## 范围

**做:**

- **仓库卫生**
  - 删除根目录 `findings.md` / `progress.md` / `task_plan.md`(历史仍在 git 里,不丢信息)。
  - `.gitignore` 增 `.scratch/`(会话草稿的**工具中立**落点;`.codebuddy/` 与 `.workbuddy/` 已各自忽略,但不得作为规范指定的落点)。
  - 新增 `scripts/check-repo.mjs`:断言根目录条目 ⊆ 白名单、无被跟踪的 `dist/` / `*.log` / `*.tmp.*` / 会话草稿。
    挂进 `verify:quick`,让本地与 CI 都能挡。
  - `eslint.config.js`:删掉已失效的 `functions/**` ignore(该目录不存在)。
- **CI 门禁**:新增 `.github/workflows/ci.yml`。PR 跑 `check:repo` + `verify:quick` + **受影响 spec**(单浏览器);
  `main` push 跑 `verify:full`(三浏览器)。Node 24(与本地 `v24.18.0` 一致 —— `tests/schema.test.ts` 用了 `node:sqlite`)。
- **`apps/api` 单测**:新增 `tests/api-crypto.test.ts` / `tests/api-config.test.ts` / `tests/api-contracts.test.ts`。
  **放在根 `tests/`** 而不是新建 `apps/api/tests/` —— 与既有 `tests/schema.test.ts`(同样从根目录测 `apps/api/src` 内部)同构,
  零配置改动即被 `vitest.config.ts` 与 `tsconfig.tests.json` 覆盖。
- **测试映射表**:`docs/TEST-MAP.md`(改动路径 → 必跑 spec)+ `scripts/affected-specs.mjs`(按 diff 输出 spec,供 CI 挑选)。
- **提交门禁机械化**:`scripts/git-hooks/commit-msg`(校验 `<type>(<scope>): <中文描述>`)、
  `scripts/git-hooks/pre-push`(跑 `verify:quick`,不含 build)、`scripts/install-git-hooks.mjs`(把钩子装进 `.git/hooks/`,幂等、`.git` 不存在时静默跳过)。
  **零新依赖** —— 不引 husky / commitlint(本仓库规则是自定义的,自写脚本更贴合,也符合「未量化不引依赖」)。
- **Legacy 退役计划**:`docs/legacy-retirement.md`(现状 / 冻结条款 / 退役步骤 / 验收)+ 规范里立「legacy 冻结」一条。
- **依赖更新机制**:`.github/dependabot.yml`(npm 按月分组 + GitHub Actions 单独一组)+ 规范里补一条升级窗口。

**不做:**

- **不删 `apps/web/legacy/`**(那是真代码改动 + 回归风险,本轮只出**计划**与**冻结条款**)。
- **不引入 husky / commitlint / lint-staged / prettier**(§三「不推荐引入」的既有结论;prettier 已在 `eslint.config.js` 注明刻意不引)。
- **不测 `apps/api/src/index.ts` 的 revision 状态机** —— 它写在 Hono 路由处理器里,要么重构抽取、要么引
  `@cloudflare/vitest-pool-workers`(新依赖)。两者都超出本轮,列为后续项;本轮**只测可 import 的纯模块**,并在文档里如实标注该缺口。
- 不引入覆盖率百分比门槛(既有结论)。
- 不改任何运行时行为:`apps/web/src/**`、`apps/api/src/**` 一律不碰。
- 不改 `biff.*` 数据契约,无迁移。

## 方案取舍

| 备选 | 结论 | 理由 |
|---|---|---|
| 会话草稿落 `.codebuddy/` | **否决** | 用户明确反对:那是 CodeBuddy 专属目录,同事用 Codex 就失效;落点必须工具中立 |
| 会话草稿落 `.scratch/`(gitignore) | **采纳** | 工具中立、不进版本库、任何 IDE / 编辑器都写得了;同时用 `check-repo.mjs` 兜住「有人又写回根目录」 |
| 会话草稿落 `docs/plans/` | 否决 | 草稿不是 PLAN;混进去会让「只读本需求的 PLAN」这条纪律失效 |
| 把检查写进 CI 而不写成本地脚本 | 否决 | CI 要等 push 才知道;`check-repo.mjs` 挂进 `verify:quick` 本地就能挡,CI 只是复用 |
| 引 husky + commitlint 装钩子 | **否决** | 两个新依赖 + `prepare` 生命周期复杂度,只换来「格式校验」;自写 ~60 行零依赖脚本即可,且能直接编码本仓库的中文描述规则 |
| `pre-push` 跑 `verify:full` | 否决 | 5–9 min 会把「推的时候直接推」彻底毁掉(§2 明确反对在 push 时跑完整门禁) |
| `pre-push` 跑 `verify:quick` | **采纳** | < 1 min、不含 build;它挡的正是红线 1(没跑过测试就 push),不违反 §2(§2 反对的是在 push 时重跑**完整门禁 / build / E2E**) |
| 新建 `apps/api/tests/` + 独立 vitest 配置 | 否决 | 要动 `apps/api/package.json`、`vitest.config.ts`、根 `npm test` 三处;而根 `tests/` 已有测 `apps/api/src` 的先例,零配置 |
| CI 里 PR 跑全量三浏览器 | 否决 | 5–9 min × 每个 PR;规范本来就只要求「受影响 spec + 单浏览器」 |
| 本轮顺手把 legacy 删掉 | 否决 | 一次提交只做一件事;删除需要先有「冻结 → 观察 → 移除」的窗口,否则回归无从定位 |

## 验收标准

1. 根目录不再有 `findings.md` / `progress.md` / `task_plan.md`;`node scripts/check-repo.mjs` 通过。
2. `npm run verify:quick` 全绿,且**已包含** `check:repo`(在脚本里能看到串联)。
3. `.github/workflows/ci.yml` 存在;PR 与 `main` 走不同档位;`docs/TEST-MAP.md` 存在且 `scripts/affected-specs.mjs` 能对给定 diff 输出 spec。
4. `tests/api-*.test.ts` 三条新文件全绿;`npm test` 的计数从 228 上升到新值(必须贴出前后计数)。
5. `scripts/git-hooks/` 三个文件存在;`node scripts/install-git-hooks.mjs` 可重复执行且幂等;
   故意写一条 `bad message` 提交会被 `commit-msg` 拒绝(人工验证一次并记录)。
6. `docs/legacy-retirement.md` 存在,含「冻结条款」与「退役步骤」;规范里能搜到 legacy 冻结。
7. `.github/dependabot.yml` 存在;规范里能搜到升级窗口。
8. `git diff --name-only` 不含 `apps/web/src/**` 与 `apps/api/src/**`(零运行时改动)。
9. `npm run verify`(= typecheck → lint → 单测 → 各 workspace 构建)全绿。

## 备注

- 七个工作流**七个提交**,`type(scope)` 分别为:`chore(repo)` ×2、`ci` ×2、`test(api)`、`docs`、`ci`。
  按 §4「一次提交只做一件事」拆分;最后一次 push 触发一次 Cloudflare 构建。
- 本轮新增的 `check:repo` / `affected-specs` / 钩子脚本都在 `scripts/` 下,而 `eslint` 的 lint 范围是
  `apps packages e2e tests`(**不含 `scripts/`**)—— 与既有 `prepare-cloudflare.mjs` 同等待遇,不额外放宽范围。
- `docs/TEST-MAP.md` 是**人读**的权威表;`scripts/affected-specs.mjs` 里的映射是**机读**副本。
  两者若漂移,以 TEST-MAP 为准并同步脚本(这条写进文档,避免又一处「同一口径两份实现」)。
