# PLAN-20260910110159 · 悬停说明(tooltip)改「窄矩形 + 标题 + 分点」

## 1. 需求

用户指令:

> tootip 不要一整条 需要换行 改成合适大小的矩形吧 然后最好有分点之类的

即:现在 hover 出来的说明是**一条又长又扁的横条**,希望改成:

1. **会换行** —— 收窄宽度,长句折成多行,整体接近矩形而不是长条;
2. **尺寸合适** —— 宽度有上限(既不拉满屏,也不至于太窄导致行数过多);
3. **有分点** —— 多条信息不再挤成一段,逐条列出、便于扫读。

## 2. 现状(根因)

`src/tip.ts` 是全站唯一的悬停说明实现(文档级 `pointerover` 委托,读 `data-tip`),当前:

```ts
const TIP_CLS =
  "fixed z-[300] max-w-[70vw] px-[10px] py-[7px] rounded-[8px] text-[12px] leading-[1.5] " +
  "bg-[var(--toast-bg)] text-on-brand whitespace-pre-line pointer-events-none " + ...
```

根因两条:

- **宽度上限 `max-w-[70vw]` 太大**:1440px 视口下上限 ~1000px。而 `data-tip` 里绝大多数
  是**单行长句**(如 `codeTip()` 约 50 字 ≈ 600px、顶栏图例「我的选片」约 90 字),
  在 1000px 上限内**不触发折行** → 呈现为「一整条」扁横条。
- **`textContent` 单段渲染**:即使有 `\n`(如 `abbrTooltip()` 的 5 行缩写表、
  `grid.ts` 的紧张算式),也只是「多行纯文本」,没有标题层级、没有分点符号,
  扫读性差。

另有两处遗留问题:

- `src/style.css` 里的 `.tip { … }` / `.tip.show { … }` 是**死代码** —— `tip.ts` 早已
  改用全 Tailwind 的 `TIP_CLS` + `is-hidden`,全仓已无任何元素挂 `.tip` 类。
- `index.html:51` 的 `#abbr-help` 同时挂了**原生 `title`** 与 `data-tip`,会先弹一个
  浏览器原生长条 tooltip(样式不可控、正是一整条),再弹自绘的。

## 3. 方案

### 3.1 `src/tip.ts` —— 结构化渲染(核心)

给 `data-tip` 定一个**极简文本约定**(仍是纯文本,不引 HTML/Markdown 渲染):

| 行 | 语义 | 呈现 |
| --- | --- | --- |
| 第 1 行 | 标题 | 加粗 + 底部细分隔线(`border-white/20`) |
| 其余行 | 分点条目 | 自动加 `·` 悬挂缩进;行内首段含 ` — ` 时**加粗前段**(缩写表 `CODE 001 — …` 一眼可扫) |
| 只有 1 行 | 段落 | 直接作正文,靠窄宽自然折行(无标题/无分点) |

- `TIP_CLS` 去掉 `max-w-[70vw]` 与 `whitespace-pre-line`,改挂 `tip-card`(见 3.2)。
- 新增 `paint(node, text)`:分行 → 首行标题 + 其余分点;`replaceChildren()` 复用单例 DOM。
- `place()` 补**垂直翻转**:下方放不下(`y + h > vh - 8`)时翻到光标上方。
  (分点后 tooltip 变高,贴屏底 hover 会被裁掉 —— 这条是变高的必然代价。)

### 3.2 `src/style.css` —— 宽度收敛 + 删死代码

- 删掉死代码 `.tip` / `.tip.show`。
- 新增 `@utility tip-card { max-width: min(320px, calc(100vw - 24px)); }`。
  **用 CSS 写 `min()/calc()`**,而不是 Tailwind 任意值 `max-w-[min(320px,calc(100vw_-_24px))]` ——
  后者要转义空格(`_`),可读性差且易错;本项目已有 `@utility` 先例(`is-hidden`/`hl-card`/`slot-hit`)。

### 3.3 数据侧 —— 把「长单句」改写成「标题 + 分点」

渲染层只认结构,内容得先有结构。逐条改写**长单句**的 `data-tip`:

- `src/badges.ts`:`codeTip()`、GV 徽章 `title`、`abbrTooltip()`(5 条缩写 → 天然分点)。
- `src/legend.ts`:`venueTip()`(全名 + 韩文名 + 分区 + 代码)、`pageChip()`、`durChip()`、
  `timeField()`、`blankChip()`。
- `src/grid.ts`:影院代码 tip(`grid.ts:111`)、`talkTip()`、紧张转场算式 tip。
- `index.html:47~50`:顶栏图例「已选 / 时间紧张 / 完全冲突 / 我的选片」4 条。
- `index.html:51`:删掉 `#abbr-help` 的原生 `title`(只留 `data-tip` 自绘)。

短句(如「影片详情 / 豆瓣」「跳到该影厅时间轴位置」)保持单行 —— 渲染层对单行走段落分支,不受影响。

## 4. 不做

- 不引 Markdown / HTML 渲染器(tooltip 仍是纯文本 → 无 XSS 面,`textContent` 口径不变)。
- 不改 tooltip 的配色 token(`--toast-bg` 深底 + `text-on-brand`,与 toast 同族)。
- 不动并行会话在途的 `tools/extract_schedule.py` / `docs/plans/PLAN-20260910095800.md`。
- 不改短句 tooltip 的文案(只动「长单句」这批)。

## 5. 验收

- `npm run typecheck` ✅ / `npm run build` ✅
- 宽度:1440px 视口下,`codeTip` 这类单句折成 2~3 行(不再是 1 条长横条)。
- 分点:缩写说明(5 条)、紧张转场(标题 + N 条算式)呈标题 + `·` 分点。
- 贴屏底 hover → tooltip 翻到光标上方,不被裁。
- 单句短 tip(「影片详情 / 豆瓣」)仍是一行,不被强行分点。
- 提交 → push GitHub → `npm run deploy` 部署 Cloudflare Pages,线上 `curl` 核对新 JS 产物。
