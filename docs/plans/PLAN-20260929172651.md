# PLAN-20260929172651 — 红黑榜信息层级与操作流重排(§1–§5 样式与文案整批)

## 目标

用户对红黑榜做了一轮设计评审,反馈原话(节选):

> 顶部红底区域……右侧的「全站贴纸 红1·黑1」和「我的:标记看过 1,已贴 1,还剩贴 0」字体较小且排版拥挤,
> 建议通过卡片化或微缩标签(Badge)样式将其整理,区分「全局数据」与「个人数据」。
> 副标题规则「一部电影一枚贴纸:标记「看过」,点红或黑…」稍微有点长……
> 筛选按钮……色彩过于繁杂……建议将主要操作(如「生成分享图」)高亮突出,筛选切换保持统一的 Segmented Control……
> 搜索框内的 Placeholder 占位符可以更简洁,如「搜索影片 / 场次编号」。
> 未标记看过的卡片右侧空白区域重复出现了大量灰色的「标记「看过」后就能贴」字样……
> 「看全部」按钮:建议明确其功能……微调文案以避免歧义。
> 未点击「看过」前应该处于置灰不可用状态(Disabled)……
> 移动端……建议针对小屏设备将展板设计为可折叠/展开的面板,或者上下布局。

问询答复(2026-09-29):
- 范围 = **样式 + 文案整批**(§1–§5 一次交付);
- 红黑按钮 = **改成真正的 `disabled`**(用户给的两个方案里,推荐方案 A:完全禁态 + 视觉降级,
  标记后高亮激活);
- 「悬停红点显示是哪位用户贴的 / 评语」= 用户希望**连同后端一起做**,但见下方「不做什么」。

## 范围

**做:**

1. **§1 顶部 hero** —— 全站数据收进统计卡片、个人数据收成 Badge 行;规则长文案精简,
   完整规则改由尾随的 `?` 图标承载(纯 CSS hover / `:focus-within` 展开,零 JS 状态)。
2. **§2 筛选与操作栏** —— 「总数 / 红榜 / 黑榜」做成真正的分段控件(Segmented Control);
   「只看我贴过」独立成一档筛选 chip;「重新排序」降为弱按钮;说明文字移出排序组、独占一行;
   「生成分享图」改为品牌色主操作;搜索框 placeholder 改文案。
3. **§3 卡片展板** —— 未标记时不再平铺灰色长句:画布换虚线/半透明质感,提示文字默认隐去,

## 方案取舍

| 备选 | 结论 | 理由 |
|---|---|---|
| 规则长文案缩短 + `title` 属性兜底完整规则 | 否决 | 原生 tooltip 样式不可控、触屏不显示、不可聚焦 |
| 规则缩短 + `?` 图标走 **纯 CSS** `:hover` / `:focus-within` 展开 | **采纳** | 零 JS 状态;`:focus-within` 让触屏「点一下 `?`」也能展开,键盘可聚焦;失焦自动收起 |
| 未标记展板:直接不渲染提示文字 | 否决 | E2E 用 `toHaveCount` 断言该节点,改渲染条件会打红 5 条用例 |
| 未标记展板:文字**保留在 DOM**、默认 `opacity: 0`,hover / `:focus-within` 淡入 | **采纳** | 满足 E2E 的 count 契约;桌面端视觉噪音归零;`@media (hover: none)` 下保持常显低对比度,移动端仍有引导 |
| 未标记红/黑按钮:保持 `aria-disabled` 可点 | 否决 | 用户明确要真禁态;且「先标记 → 再表态」的单向流更符合因果(用户原话) |
| 未标记红/黑按钮:真 `disabled`,已贴换色路径保留 | **采纳** | 推翻面最小:19 条 E2E 全部先标记,零回归;`place()` 的未标记分支保留作防御(不再有按钮入口) |
| 已贴时「点另一色换色」也一并 `disabled` | 否决 | 那是 2026-09-28 花了一轮加出来的出口,`disabled` 掉等于让用户只能「先收回、再重贴」,顺带丢掉位置 |
| `≤560px` 展板做成可折叠面板 | 否决 | 折叠要引入 JS 状态(或 `<details>`),而折叠态下画布尺寸为 0 → `StickerCanvas` 的 ResizeObserver 拿到 0×0、backing store 释放,展开瞬间要整块重绘;收益(屏外跳绘)已被 `content-visibility: auto` 覆盖 |
| `≤560px` 改**上下布局**(信息在上、画布在下) | **采纳** | 零 JS;画布拿回整行宽度,贴纸不再挤成一条缝;用户原话里「或者上下布局」即此方案 |
| 「生成分享图」改用品牌红实底 | **采纳** | 用户点名它是「绿色胶囊」的来源(`--selected-line: #388452`);改红既突出主操作,又消掉杂色 |

## 修订 1(2026-09-29,用户第二批反馈:三处「锦上添花」)

用户原话三点:① 展板贴纸「几乎铺满了矩形各个角」,希望「中间密、边缘留白多一点」,并
「确保贴纸不会贴到展板圆角框的边缘线以外(overflow: hidden)」;② 「看全部 239 枚」这类浅灰胶囊
「建议加一个轻微的 Hover 态……而不是一个纯静态 Label」;③ 顶栏「重叠 4」按钮与「回到旧版」
「数据更新」等灰胶囊「混在一起」,建议「放进更隐蔽的下拉菜单」或「换成图标切换」。

**核对后有两处与事实不符,先纠正再动手:**

- **第 ① 点的「溢出」早就处理了**:`redblack.ts:47` 的 `SPOT_MARGIN = 0.08` 把贴纸中心钳在
  `[0.08, 0.92]`,`.rb-canvas` 也**一直有** `overflow: hidden`(`redblack-parity.css`,注释写着
  「超出部分裁掉,免得贴纸漫到隔壁卡」)。真正没做的是**分布**:x / y 各自独立均匀 ⇒ 四角都是点。
  所以本轮只改分布,不加 overflow。
- **第 ② 点其实已有 hover 态**(`border-color` + `color` 变品牌红),只是弱到看不出来 ——
  不是「没有」,是「不够」。所以是**加强**而非新增。
- **第 ③ 点「重叠 N」不是调试按钮,是冲突提示**:`App.tsx` 里它是
  `navigate('/agenda')` 的入口,数字 = 当前行程的时间重叠处数。
  ⇒ **不采纳「放进更隐蔽的下拉菜单」**:它是用户**排片时**要一眼看到的信号,藏起来等于把提醒关掉;
  真正的问题是「它和中性链接长得一样」。改成**视觉分层**(给它本来的语义色 `--conflict`)。
