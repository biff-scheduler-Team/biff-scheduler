# PLAN-20260916004024 — 只有一场的影片，「加入我的选片」直接落进行程

## 目标

> 一些只有一个场次的 比如说《演员之家》和《大师班》 这种的话 你它添加到我的选片里面 你就直接给它添加到行程里面
> 因为只有一场的话就不需要再选了 然后不然会增加用户的使用成本 然后你改完之后直接推送

现状：影片库卡片点「加入我的选片」(`LibraryPage.tsx` → `state.ts::addPickFilm()`)只建一条**空**选片记录，
用户还得再跳去「我的选片」、展开卡片、点一次「加入行程」。只有一场的影片没有第二种选择，这一步纯属白增成本。

## 范围

**做：**

- `state.ts::addPickFilm(key, soleShowCode?)` 增加第二参数：给定唯一场次 → 直接落进行程
  （与 `toggleScreening()` 走同一条 `commit()` 出口），并把「是否自动排了场次」返回给调用方。
- `LibraryPage.tsx::FilmCard`：唯一场次（按**全量** `film.shows`，不受视图筛选影响）时
  按钮改「加入行程」、点击直接落场、toast 说明「只有一场」；
  已在清单且已排该场时按钮改「已在行程，去查看」（不再引导去排场次）。
- 回归测试：单测 `apps/web/tests/state-picks.test.ts` + E2E `e2e/react/workflows.spec.ts`。

**不做：**

- 不改 `legacy/`：旧前端是**只读回退件**，按 §5 只接 P0（数据丢失 / 完全打不开），不接新功能。
- 不动多场片的现有两步流程（「共 N 场」行、`setFilmExpanded("picks", …)` 展开选片卡）。
- 不改「我的选片」里的逐场点选（`ScreeningCard`）—— 单场片在那里本来就只点一下。
- 不改数据、不新增 localStorage 键、不动 `biff.*` 结构。

## 方案取舍

| 备选 | 结论 | 理由 |
|---|---|---|
| 在 `LibraryPage` 调用点自己判单场、直接调 `toggleScreening()` | 否决 | 「单场 → 直接进行程」是**流程口径**，散在视图里，换一个入口就得再写一份 |
| `state.ts::addPickFilm(key, soleShowCode?)` 承载该口径 | **采纳** | 与既有变更入口同一出口（`commit()` → 落盘 / `rebuildIndex()` / 广播）；视图只负责文案 |
| 新开 `addPickFilmOrScreening()` | 否决 | 同一件事两个函数名，调用方还得记住何时用哪个 |
| 用筛选后的 `shows` 判单场 | 否决 | 筛选是视图态；「只有一场」是数据事实，必须用全量 `film.shows` |

## 验收标准

1. 影片库搜「蓦然回首」（唯一场次 `003`）→ 点「加入行程」→ `biff.picks.v2` 立即含
   `{ key: "cat:f002", picks: [{ code: "003" }], note: "" }`，「我的行程」能看到 003。
2. 多场片「彼此的日夜」行为不变：点「加入我的选片」→ `picks: []`，按钮转「已在选片，去排场次」。
3. `npx vitest run apps/web/tests/state-picks.test.ts` 全绿；
   受影响 spec（`workflows` / `review-library` / `parity-library`）全绿。
