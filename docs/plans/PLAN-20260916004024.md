# PLAN-20260916004024 — 只有一场的影片，「加入我的选片」直接落进行程

## 目标

> 一些只有一个场次的 比如说《演员之家》和《大师班》 这种的话 你它添加到我的选片里面 你就直接给它添加到行程里面
> 因为只有一场的话就不需要再选了 然后不然会增加用户的使用成本 然后你改完之后直接推送

现状：影片库卡片点「加入我的选片」(`LibraryPage.tsx` → `state.ts::addPickFilm()`)只建一条**空**选片记录，
用户还得再跳去「我的选片」、展开卡片、点一次「加入行程」。只有一场的影片没有第二种选择，这一步纯属白增成本。

## 范围

**做：**

- `state.ts::addPickFilm(key, soleShowCode?)` 增加第二参数：给定唯一场次 → 直接落进行程
  （与 `toggleScreening()` 走同一条 `commit()` 出口），并把「是否自动排了场次」返回给调用方。
- `LibraryPage.tsx::FilmCard`：唯一场次（按**全量** `film.shows`，不受视图筛选影响）时
  按钮改「加入行程」、点击直接落场、toast 说明「只有一场」；
  已在清单且已排该场时按钮改「已在行程，去查看」（不再引导去排场次）。
- 回归测试：单测 `apps/web/tests/state-picks.test.ts` + E2E `e2e/react/workflows.spec.ts`。

**不做：**

- 不改 `legacy/`：旧前端是**只读回退件**，按 §5 只接 P0（数据丢失 / 完全打不开），不接新功能。
- 不动多场片的现有两步流程（「共 N 场」行、`setFilmExpanded("picks", …)` 展开选片卡）。
- 不改「我的选片」里的逐场点选（`ScreeningCard`）—— 单场片在那里本来就只点一下。
- 不改数据、不新增 localStorage 键、不动 `biff.*` 结构。

## 方案取舍

| 备选 | 结论 | 理由 |
|---|---|---|
| 在 `LibraryPage` 调用点自己判单场、直接调 `toggleScreening()` | 否决 | 「单场 → 直接进行程」是**流程口径**，散在视图里，换一个入口就得再写一份 |
| `state.ts::addPickFilm(key, soleShowCode?)` 承载该口径 | **采纳** | 与既有变更入口同一出口（`commit()` → 落盘 / `rebuildIndex()` / 广播）；视图只负责文案 |
| 新开 `addPickFilmOrScreening()` | 否决 | 同一件事两个函数名，调用方还得记住何时用哪个 |
| 用筛选后的 `shows` 判单场 | 否决 | 筛选是视图态；「只有一场」是数据事实，必须用全量 `film.shows` |

## 验收标准

1. 影片库搜「蓦然回首」（唯一场次 `003`）→ 点「加入行程」→ `biff.picks.v2` 立即含
   `{ key: "cat:f002", picks: [{ code: "003" }], note: "" }`，「我的行程」能看到 003。
2. 多场片「彼此的日夜」行为不变：点「加入我的选片」→ `picks: []`，按钮转「已在选片，去排场次」。
3. `npx vitest run apps/web/tests/state-picks.test.ts` 全绿；
   受影响 spec（`workflows` / `review-library` / `parity-library`）全绿。

## 修订 1（2026-09-16，用户实测：「我加过《Actors' House: RYU Seung-ryong》，行程里没有」）

用户原话：

> 你补数据的时候 避免你出现它这个刷新又回来的问题 你可以去提示用户 比如说你移除行程之后 你就跟他说
> 这个行程只有一场 你在移除它的时候 同时也会把你的选片移除掉 就给他一个提示就好了
> …… 是只对这种只有一个场次的生效 并且要给用户提示 不然还是会出现之前一删掉就把行程也删掉的问题

**问题**：第一版只改了「点按钮那一刻」的行为，**已经存在的空记录不会被补**——
用户旧版加过的单场片（如 `sched:actors’ house: ryu seung-ryong`，唯一场次 `804`）就卡在
「我的选片里有它、我的行程里没有」。

**方案（推翻「一次性迁移标记」的初稿）**：把单场片的口径统一成 **「选定 = 排定」**：

| 环节 | 行为 |
|---|---|
| 载入 | `fillSoleShowPicks()`：单场片若有**空**记录 → 把那一场排进行程（`picks` 非空的一律不动） |
| 影片库入口 | 按钮写「加入行程」，点击直接落场 |
| 取消该场 | **先 `confirm` 说明**「只有这一场，移出行程会同时把它从『我的选片』移除」，确认后**连记录一起删** |
| 清空已排场次 | 单场片整条删（否则会被载入补齐），弹层文案已同步说明 |
| 多场片 | **完全不变**：移出一场仍只动 `picks`、记录与备注保留（2026-09-13 口径） |

**为什么不写「补过」标记**：既然取消时会连记录一起删，就不存在「删掉又回来」的死循环——
标记键反而要在 `biff.*` 里多一个键、并打破 `compatibility.spec.ts` 里三条字节级断言。

**判据单一来源**：`model.ts::soleShowIndex()`（按 `filmNodeKey` 分组，恰好一场才入表）→
`store.tsx::hydrateStorage()` 注入 `state.ts::registerSoleShows()`。未注入 = 旧行为，
所以纯逻辑单测与 `legacy/` 不会被误伤，**也绝不会把多场片当单场片**。

**取消提示的落点**：`components/screening-actions.ts::useScreeningPicker()` ——
网格点选（`SchedulePage`）与场次卡（`ScreeningCard`，选片 / 行程共用）都走它，提示只有一处实现。

**修**：
- `apps/web/src/state.ts`（判据注入 / `fillSoleShowPicks` / `toggleScreening`、`removeScreening`、
  `clearScreeningSlots` 三条口径）
- `apps/web/src/app/model.ts`（`soleShowIndex`）
- `apps/web/src/app/store.tsx`（注入 + 载入补齐）
- `apps/web/src/components/screening-actions.ts`（新：取消前的提示）
- `apps/web/src/components/ScreeningCard.tsx`、`apps/web/src/pages/SchedulePage.tsx`（改用共享出口）
- `apps/web/src/pages/LibraryPage.tsx`（判据改用 `soleShowCode()`）
- `apps/web/src/components/SettingsDialog.tsx`（清空文案）
- `e2e/react/helpers.ts`（`legacyData` 里 f002 的单场空记录改成「已排唯一场次」——
  单场片不可能停在「未排场」，不改的话字节级断言会被补齐打破）
- 测试：`apps/web/tests/state-picks.test.ts` 新增「单场影片：选定 = 排定」5 条；
  `e2e/react/workflows.spec.ts` 新增「载入补齐 + 取消先提示 + 不复活」1 条

**本轮不做（修订 1 范围外）**：
- 登录后从云端**拉回**的记录不在补齐范围内（`fillSoleShowPicks()` 只在载入那一刻跑一次）。
- `legacy/` 不跟进（只读回退件，§5）。
