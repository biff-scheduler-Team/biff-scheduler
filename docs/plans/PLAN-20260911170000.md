## 3. 筛选：抽成 `src/filters.ts`，两个视图共用

### 3.1 为什么要抽模块

网格筛「时间轴上还剩哪些卡」，影片库筛「哪些片还有符合的场」。若各写一份，
「字幕键怎么归一」「未标注算不算命中」「GV 三态怎么互斥」会立刻漂成两套口径 ——
判定（`matchesFilters`）与控件（`renderFilterBar`）双双收口。

### 3.2 形态：圆角矩形，不是胶囊

胶囊（`rounded-full`）是**单值选择**的语言（日期条 / 档位）；筛选是**多选开关组**，
一排圆头挨在一起会糊成一条连续色带，读不出「这是 5 个独立开关」→ 一律 `rounded-6`，轨道 `rounded-8`。
（日期条**保持胶囊** —— 那是官方 Schedule by Date 的形态，用户明确要过。）

### 3.3 两处形态差异

| | 网格 | 影片库 |
|---|---|---|
| 形态 | 三行铺开 | **可折叠**（`▸ 筛选` + 生效摘要 + 清除） |
| 理由 | 宽度够，铺开一眼看全 | 抽屉只有 520px，26 个影厅 chip 铺开会吃掉半屏 |
| 默认 | 展开 | 无筛选时折叠；有筛选 / 勾了任一项时自动展开 |

### 3.4 状态同步

一份 `FilterState` 由 `main.ts` 持有，经 `LibraryCtx.filters` / `GridCtx.filters` 注入两侧。
任一侧改动 → `onFilters` / `onChange` 回给 main，**三处一起重画**：
① 网格侧筛选条 ② 网格淡化 ③ 抽屉列表。
（少了 ③ 会「在库里勾了影厅但列表没动」，少了 ① 会「切回时间轴看到的还是旧的」—— 首版正是漏了 ③，验收时抓到。）

影片库的过滤口径：
* 筛的是「这部片还有没有我要看的场」—— **没有就直接不列**，而不是列出来再全灰；
* 展开后的场次列表同样过筛（否则点开还会列出已被筛掉的场，与列表口径打架）；
* 「我的选片」tab **不受排片筛选影响** —— 那是「我选了什么」的视图，筛掉自己的选片没有意义。
