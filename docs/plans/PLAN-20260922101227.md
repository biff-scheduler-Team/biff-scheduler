## 方案取舍

| 备选 | 结论 | 理由 |
|---|---|---|
| **D1** 弹层 `ScreeningDiscussionDialog` 保留 | **否决** | 页面删掉后它**没有任何调用方**（行程卡入口上一轮已摘），留着就是死代码；用户也说了「相关组件也去掉」 |
| **D2** 后端讨论接口一并删 | **否决**（本轮） | 用户明确「只动前端」。且删后端要连带删契约常量，会打红 `apps/api` 的单测，属于另一层改动 |
| **D3** 保留「讨论数」读数链路 | **否决** | 用户明确「一并去掉，读数链路一起清」。留着会表现为「一个永远不再增长的指标」，比删掉更容易误导 |
| **D4** 保留 `screening-discussion.ts`（只删 `fetchDiscussionBoard`） | **否决** | 其余四个函数只被弹层使用；弹层删了就全成死代码，留一半没有意义 |
| **D5** `screening-counts.ts` 连 `attendance` / ping 一起删 | **否决** | 「同场 N 人」仍在场次卡上使用，与讨论无关 |
| **D6** 删 `screening-social.css` 里夹在讨论样式之间的 `.agenda-actions` | **否决** | 它是 AgendaPage 的顶栏操作行样式，删了行程页按钮排版会塌 |
| **D7** `docs/plans/*` 历史 PLAN 与 `docs/history/` 一并改写 | **否决** | 历史记录不改写；只在本轮 PLAN 与 `CONVENTIONS.md` 记「已下线」 |
