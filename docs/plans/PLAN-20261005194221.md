# PLAN-20261005194221 — 换款轮盘：开环手势收敛成「长按」一条（鼠标与触屏同一套）

> 用户原话：
> 「我希望只保留一个 长按 不管是触屏还是鼠标」

## 目标

把「打开换款轮盘」的手势从**两套**（鼠标悬停 160ms / 触屏长按 500ms）收敛成**一套**：
**按住 500ms** —— 鼠标与触屏走完全相同的代码路径。

现状（代码事实）：

- 开环有三条：鼠标 `pointerenter` + `HOVER_MS=160`、键盘 `focus`（`:focus-visible`）、触屏长按 `PRESS_MS=500`。
- 只有触屏那条**修过**（`PLAN-20261005183113`）：位移阈值、蓄力进度环、触屏专属关环。
  鼠标那条靠 hover，天然不需要阈值。

> ⚠ 本 PLAN 是 `PLAN-20261005183113`（只修触屏）的**替代**，不是它的延续：
> 那一轮把鼠标留在 hover 上，这一轮把鼠标也搬到长按，所以「两套逻辑」这个前提被删掉了。
> ⚠ 开工时那一轮还是**未提交**状态，收尾时已经在 `main` 上了（`2e49271e`）—— 见「修订 2」。

## 范围

**做：**

- **删掉鼠标悬停开环**：`HOVER_MS`、`openTimer` 及其全部 `clearTimeout` 一并删除。
- **长按对所有指针类型生效**：`onPointerDown` 不再对鼠标提前 `return`；
  蓄力进度环（`data-rb-pressing`）鼠标也亮 —— 它是「能长按」唯一看得见的提示。
- **长按的位移阈值与拖拽同一套**（触屏 `DRAG_SLOP_TOUCH=10` / 鼠标 `DRAG_SLOP_MOUSE=8`）：
  越过阈值即作废长按（那一轮是拖拽，由 `beginDrag` 接管）。
- **「拖动优先」沿用既有口径，本轮只是保住它**（用户 2026-10-05 第二次反馈：
  「当时想拖动贴纸 就马上会触发换肤」）：环开着时位移一越过 `slop`，就把环关掉、交给 `beginDrag`。
  ⚠ 本轮第一稿曾**反着做**（加 `data-rb-wheel-open` 守卫，让「按住滑到节点换款」生效）——
    那与用户的第二次反馈直接冲突，**已改回**，见「修订 2」。
- **关环仍是两条**（这条不是「选择」，是正确性）：
  · 鼠标 —— `pointerleave`（贴纸或环）→ 宽限 `WHEEL_GRACE_MS=260` 后关；
  · 触屏 —— `pointerleave` 在触屏上只等于**抬手**，不关；改由「点环外任意处 / 滚动 / 选款 / Esc」关。
  即：`RbCard::onPointerLeave` 里那句 `pointerType !== "mouse"` 的分叉保留。
- **键盘聚焦开环保留**（`focus` + `:focus-visible`）：键盘既不是触屏也不是鼠标，
  去掉它键盘用户就完全没有换款入口，而 E2E「键盘也能走完」那条守着它。
- **删掉开环上的 `fresh`（刚贴下 2.4s 不弹）守卫**：它原来的理由是「悬停时指针正落在这枚上」，
  悬停删掉后这个理由不存在；留着反而制造「刚贴完 Tab 过去不弹、Tab 走开再回来才弹」的不一致。
  `fresh` 本身仍用于闪描边与落地动效，不产生死状态。
- **页面上那行提示改为常显**：`.rb-touch-tip` 改名 `.rb-wheel-tip`（它不再只对触屏说话），
  去掉 `display: none` 与 `@media (hover: none)`。
- **点环外关闭**（`StickerSkinWheel` 里的 `pointerdown` capture）：触屏唯一通用的退路，鼠标也一并受益。
- **节点补 `touch-action: none`**：防止在节点上按下时页面滚动把环带走。
- **测试同步**：4 条 E2E 的「悬停开环」改成「鼠标长按开环」；两条触屏用例沿用 `main` 的原文
  （只往第一条里补了蓄力环的断言），另加一条「环真的画出来了、进度真的在跑」。

**不做：**

- **不动**「单击什么都不做」「双击收回」两条既有契约（2026-09-28 / 09-30 定的，E2E 守着）。
- **不动**环的几何 / 视觉（`WHEEL_RADIUS` / `NODE_SIZE` / 座位 / 视口夹取 / 名称胶囊）。
- **不动**换款的落库与上报口径（`reskin` / `reskinSticker` / 撤销提示）。
- **不动**拖拽本身（阈值、浮标、落点预览、出界提示、跨片判据）。
- 不为此新增 `biff.*` 键、不新增依赖。

## 方案取舍

| 备选 | 结论 | 理由 |
|---|---|---|
| 长按时长改成鼠标短、触屏长（两套参数） | 否决 | 用户要的就是「一条」，两个常数就是两套；500ms 对两者都是系统里「长按」的通用量级 |
| 鼠标长按用右键 / 中键区分 | 否决 | 右键不适合移动端心智，且 `beginDrag` 已把非 0 号键挡掉，改它会牵动拖拽 |
| 连键盘聚焦也删掉，「真的只剩一条」 | 否决（本轮） | 键盘既非触屏也非鼠标；删了键盘用户没有任何换款入口，且与既有 E2E 契约冲突。若用户要，另开一轮 |
| 用 `document.querySelector(".rb-wheel")` 判「轮盘开着」 | 否决 | 每个 `pointermove` 扫一次 DOM；且那是跨模块的隐式耦合 |
| 给 `RbCard` 加一个 ref 属性传给 `beginDrag` | 否决 | 要走 `RbCardProps` + 调用点 + `memo` 三处，而判据其实只有一个布尔 |
| 环开着时**让拖拽让位**（渲染 `data-rb-wheel-open`，`beginDrag` 读到就退出） | 否决 | 与用户第二次反馈冲突 —— 他要的是**拖动优先**。这跟实现难度无关，是**口径**问题 |
| 环开着时位移越过 `slop` → **关环、让 `beginDrag` 接管**（沿用 `main` 的做法） | **采纳** | 用户原话：「当时想拖动贴纸 就马上会触发换肤 这个逻辑感觉有点不对」；判定与长按共用同一个 `slop` |
| 保留 `fresh` 守卫 | 否决 | 其唯一理由（悬停）已被删除，见「范围」 |
| 提示小字只在 `(hover: none)` 显示 | 否决 | 鼠标也没有悬停入口了，桌面端同样需要被发现 |

## 验收标准

1. **鼠标长按 500ms** 弹出轮盘；**鼠标单纯划过**（不按下）一枚贴纸，轮盘**一枚都不弹**
   （改前会弹 —— 这是本轮的回归判据，先红后绿）。
2. 鼠标长按期间位移超过 8px → 轮盘不弹（走拖拽）。
3. 触屏长按 500ms 弹轮盘：期间 5px 抖动不作废、松手不关、点环外才关。
4. 长按开环后**继续移动**（越过 `slop`）：环**当场让位**，且这一拖**真的生效**（贴纸落到松手那一点）。
5. `e2e/react/redblack.spec.ts` 里既有断言（单击不弹、双击收回、方向键微调、跨片拖拽、
   出界收回、键盘换款、滚一下关环、Esc 关环）全部照常通过。
6. `npm run verify:quick` 全绿；本轮改动过的 spec 在 `desktop-chromium` 上全绿。

## 修订 1（2026-10-05，用户追加要求）

> 「长按需要有圆形进度条和动效」

上一轮虽然做了一条「按下就亮、扫满一圈」的环，但**从没看过像素**（只断言了 `data-rb-pressing` 属性），
而且那版有三个真问题，逐条改掉：

| 发现 | 处理 |
|---|---|
| 环只有 **2px** 宽，而且**只有「已走过的弧」、没有底轨** —— 贴纸一放大就基本看不见 | 同一支 `conic-gradient` 里画**底轨**（`--line`）+ **进度弧**（`--brand`），粗细 3.5px、`inset: -5px → -6px`；环落在半径 14.5–18px 这条带上（贴纸半径只有 12px，再往里会被它外扩约 10px 的落影糊住） |
| 没有进场动效，按下去是「啪」一下出现 | 新增 `rb-press-in`：120ms 缩放 0.86 → 1 + 淡入 |
| 只有环在动，贴纸本体一动不动 | 蓄力期间 `.rb-dot__face` 放大到 1.07（160ms 过渡）—— **只动那张「画」**，绝不动外层定位盒子（它是命中区与落库坐标的基准）；松手**即时**复原（`transition` 只写在蓄力那条规则里，属性一去掉过渡也跟着去掉） |
| `prefers-reduced-motion` 会把**功能**也一起关掉 | 该档只保留进度弧（它回答的是「还要按多久」），去掉两处缩放 |

**验证**：无头浏览器**按下途中**截图两张（间隔 220ms）—— 弧真的在扫、贴纸真的在鼓。
E2E 新增断言：直接读 `::after` 的计算样式，`background-image` 含 `conic-gradient`、
`mask-image` 含 `radial-gradient`、`--rb-press-turn` 会从 0 涨起来
（**非零角度同时证明**「角度注册成了可动画属性」与「动画真的在跑」—— 光断言属性存在是证明不了画面的）。

## 修订 3（2026-10-05，用户反馈「一松手圆盘就消失了」）

> 「长按后 一松手圆盘就消失了 应该选了皮肤才消失」

**先复现，再改。** 用 CDP 派发**真实触屏事件**（`Input.dispatchTouchEvent`）——注意它与其他用例那种
`dispatchEvent` 有本质区别：后者不经过浏览器的命中测试、也不带引擎补齐的 `pointerleave` /
兼容鼠标事件，所以它**证明不了真机行为**。在 mobile-chromium（Pixel 7）上量到：

| 操作 | 环还在吗 |
|---|---|
| 按住 800ms | **在**（弹出来了） |
| 干净松手 +500ms | **在**（与报告不符 —— 这条本来就是对的） |
| 松手前带 6px 漂移 | 在 |
| 松手前带 **14px** 漂移 | **不在**（让位给拖拽了） |

结论：会误伤的是**抬手那一下的漂移**。按两条改：

1. **让位阈值与拖拽起点分成两个数**：新增 `WHEEL_YIELD_SLOP_TOUCH = 24` / `_MOUSE = 16`；
   拖拽起点仍是 `DRAG_SLOP_TOUCH = 10` / `_MOUSE = 8`（它另有「跨片拖拽」用例的约束，见那里的注释）。
   真机上按住半秒再抬手，接触点漂移就是 10px 量级（实测 14px）；真想拖的人一动就是几十像素
   （上游那条用例给的是 30px）—— 所以 24/16 两边都不误伤。
2. **「这一轮是不是触屏」取手势类型，不取这一个事件自己的 `pointerType`**：抬手补发的
   `pointerleave` 在有些引擎里会报成 `mouse`，那样触屏会被当成鼠标、环在松手 260ms 后被收掉。
   判据改成 `pointerTouch`（`pointerdown` 时记下手势类型）—— 本来要的答案就是「这一轮手势是不是触屏」，
   直接问手势本身，就不依赖引擎在单个事件上的口径。

**先红后绿**（两条都实跑过、贴过失败值）：① 把让位阈值改回 10px →
`await expect(wheel).toHaveCount(1)` 收到 `0`；② 把 `pointerleave` 的判据改回看事件类型 →
同一条断言收到 `0`。

**顺手修掉一个用例里的落点陷阱**：第 ③ 步那次 `locator(".rb-sort-hint").click()` 会让页面滚动，
缓存的 `origin` 从此过期 —— 拿它当松手点会被判成「出界 → 收回」，把贴纸**真的收走**
（症状是下一条断言报「元素已不在」，而不是报一条关于环的错）。改成用**当下量到的画布中心**当落点。

## 修订 4（2026-10-05，用户第三次反馈：撤销「拖动优先」）

> 「别测了 线上就是有问题 直接改成 不选皮肤就圆环就不会消失就行」

口径最终定成：**环一旦开出来就留着，出口只有「选了皮肤 / 点环外任意处 / 滚动 / Esc」**。
于是撤掉修订 3 那条「让位阈值」（`WHEEL_YIELD_SLOP_*` 一并删除）：位移（含真机抬手那 14px
漂移）不再关环；拖动照常生效（`beginDrag` 的监听挂在 `window` 上，与环无关）。

⚠ **这推翻了 `main` 上那条按用户第二次反馈写的用例**
（`★ 触屏:环弹出后一动就关掉,且这一拖真的生效`）。两种口径互斥，按用户**最后一次**的为准 ——
那条用例已改写为新口径（`★ 触屏:环弹出后照样拖得动贴纸,而环**不会**因此消失`）：
② 位移后环**仍在**；③ 拖照样生效、贴纸落到松手那一点；④ 点环外仍然是有效出口。
