# PLAN 2026-09-10 10:15:00 — 新加入场次不再默认"备选";影片库打标按 wish 继承到行程档位

> 需求(用户原话):「影片库可以加入到我的片单 然后现在在页面"我的行程"选了电影后 下面会显示这个电影是"随缘"但是我并没有标记这部电影为随缘」
> → 澄清确认口径(用户回答):「**首页我的行程 中 即使我没有选为备选 也会默认为备选**」(用户上传的 seg HTML 里 `bg-maybe text-on-brand` 亮在「备选」上,印证了默认档位;原话的"随缘"是同根问题的口语化描述)。
> 本文件 = 本需求唯一规划文档。**与并行 PLAN-20260910100600(hover 联动)、10101115(顶栏右簇)零文件交集**;两者已 commit(8d622ea / 52a24e6),本改动不连带。

## 现状(代码事实,HEAD 52a24e6)

- `src/state.ts:151 toggleCode` 新条目分支:`priority: existing?.priority ?? "maybe"` —— **任何新加入的场次都被默认设成 `maybe`(备选)**,无论用户是否在影片库打标过、也从未询问过用户。`replaceGroup`(智能排片采纳)只写 `must/maybe`(引擎排除 `wild`),故默认问题来自 `toggleCode`。
- `src/agenda.ts:192` 行程行 seg 三段 `[必看][备选][随缘]`:当 `entry.priority === p` 时填实色;`entry.priority === "maybe"` → 「备选」琥珀色高亮 —— 这就是用户在 seg 里看到「亮着备选」的根因。
- 两层档位的设计:`wish`(影片库打标,key=filmNodeKey,影片级)与 `plan.priority`(已排场次级)相互独立 —— PLAN-20260910090312 §F 显式注明「同色系、互不影响」。独立本身没问题,但**新加入场次硬塞一个默认档位**违背了「未标记不应有档位」的直觉。
- D1 契约:`migrations/0001_init.sql` `priority TEXT NOT NULL DEFAULT 'maybe'`;`functions/api/plan/[code].js` `priority = String(body.priority ?? "maybe").toLowerCase()` 强制 maybe。当前架构下「未设优先级」无法穿透云端:即使前端想存 null,API 也会落 maybe,下次 syncFromCloud 拉回 maybe,把前端的 null 覆盖掉。
- `src/engine.ts:87` `scorePlanRows` 把每条 `e.priority` 按 `SCORE_W` 计分;若 `priority` 变 null 而未在引擎里兜底,会出现 `undefined × 数字 = NaN`。
- `src/ics.ts / main.ts copyPicklist` 都假设 `priority ∈ {must/maybe/wild}`;null 走默认 maybe 即可,但要显式兜住。
- 图例(`legend.ts:384`):「两层档位」注释已存在,但未提**新加入按 wish 继承**这条新规则,需补一行。

## 方案

### A. 数据模型:`PlanEntry.priority` 允许 `null`(未设)

- `src/types.ts`:`PlanEntry.priority: Priority | null`(原 `Priority`)。`null` = 用户未给该场设档位(新加入且影片库未打标,或用户主动清空)。
- `src/state.ts`:
  - `toggleCode(code, initialPriority?: Priority | null)` —— 新增第二参(默认 `null`)。新条目分支:`priority: existing?.priority ?? initialPriority ?? null`(`existing.priority` 已存在则沿用,否则取调用方传入的初始值,再否则未设)。
  - `setPriority(code, priority: Priority | null)` —— 允许传 `null` 表示清空。
  - `restoreLocalPlan` —— 解析时:`null/undefined → null`;`must/maybe/wild → 原值`;其它 → `null`(非法值按未设处理)。**不**对历史 `maybe` 数据做回填(分不清「用户设的 maybe」与「默认 maybe」,保守不动)。
- 导出给 ICS / copyPicklist / scoring 的边界统一在调用点兜底:`null → maybe`(导出/排序兜底,scoring 走 0)。

### B. 新加入场次的初始档位 = 影片库打标(若有)

新条目优先级取 `wish.get(filmNodeKey(cat, s)) ?? null`:
- 影片库标了 `必看` → 加入场次即 `必看`(seg 必看亮);
- 标了 `备选` → 加入即 `备选`;
- 标了 `随缘` → 加入即 `随缘`(语义连贯:用户片单说"随缘看看",行程按随缘计;seg 上仍可点 必看/备选 覆盖);
- 未打标 → `null`,seg 三段全 off,`title="未设优先级 · 点选设置"`,不强加备选。
- 已存在的条目不受影响(继续走 `existing.priority`,即用户上次设的值)。

调用点(三处新增场次):
1. `src/main.ts:333` 网格卡片点击:`toggleCode(card.dataset.code!, wish.get(filmNodeKey(cat, s!)) ?? null)` —— 当前拿不到 `s`,改用 `card` 对应的 screening:`const s = cat.byCode.get(card.dataset.code!); if (s) toggleCode(code, wish.get(filmNodeKey(cat, s)) ?? null);`。`(1) `原 `toggleCode(card.dataset.code!)` 调用方 → 改成 `toggleCode(card.dataset.code!, wish.get(filmNodeKey(cat, s)) ?? null)`。`
2. `src/main.ts:326` GV 映后谈点击(未在当前方案 → 加入当前方案):同样按 `filmNodeKey(cat, s)` 取 wish 继承。
3. `src/modal.ts:196` 详情弹层「加入 A 方案」按钮:`FilmModalCtx.toggle` 签名扩为 `(code, initialPriority?)`;点击时 `const s = ctx.cat.byCode.get(code); ctx.toggle(code, s ? wish.get(filmNodeKey(ctx.cat, s)) ?? null : null);`。

### C. 行程行 seg 渲染(`src/agenda.ts`)

- `on = entry.priority === p` —— 当 `priority === null` 时,`null === "must"/"maybe"/"wild"` 全 false,三段全 off,自然呈现「未设」灰底态。无需额外分支。
- `priority == null` 时在 seg 左侧加一枚 `未设` 小字标签(`text-[11px] text-muted`),把「三段全灰」与「默认备选」在视觉上彻底分开 —— 这是用户最初误读的来源。
- seg 容器 `title="未设档位 · 点选设置 · 未设不参与质量分与抢票顺位"`(仅 `priority == null` 时);非空时维持原 `title`。
- **补:再点当前档 = 取消 → 回到「未设」**(`main.ts` 的 `[data-act="pri"]` 分支改成 `cur === p ? null : p`;按钮 `title` 在 on 态改「取消「X」→ 回到未设」)。理由:与「我的选片」打标 seg(`buildWishSeg` 的「再点同档取消」)语义对齐 —— 图例已声明「两层档位视觉口径永远一致」;否则一旦点过任一档就再也回不到未设,是同一处用户预期的另一半。
- 同方案切换、移除、GV 翻转等不动。

### D. 评分与导出兜底

- `src/engine.ts`:
  - `ScoreParts` 加 `unset: { in: number; total: number; pts: number }`;`SCORE_W.unset = 0`。
  - `scorePlanRows`:遍历 `rows` 时按 `e.priority ?? "unset"` 分桶;`pts = count * 0 = 0`,只统计 `in`(用于「已纳入数」显示)。
  - `main.ts:228` 分 pill 标题补 `· 未分级 X ×0`。
- `src/ics.ts pickEntries` 与 `main.ts copyPicklist`:
  - 排序与排版:把 `null` 视作 `maybe`(`PRI_RANK` 兜 1),标签 `未分级/备选`(在抢票清单显示「未分级」,与 备选 同档排)。
  - ICS `PRIORITY_TAG`:null → `'maybe'`(日历优先级 normal)。

### E. D1 / API 支持 null(让"未设"能穿透云端)

- `migrations/0002_priority_nullable.sql`:**SQLite 不支持 `ALTER COLUMN ... DROP NOT NULL`**(只支持 RENAME / ADD COLUMN / DROP COLUMN),故按官方推荐「建新表 → 拷数据 → 换名」重建:
  ```sql
  -- 0002_priority_nullable.sql — 允许 priority 为 NULL(「未设档位」)
  DROP TABLE IF EXISTS user_plan_new;
  CREATE TABLE user_plan_new ( ... priority TEXT, ... );   -- 去掉 NOT NULL 与 DEFAULT
  INSERT INTO user_plan_new (...) SELECT ... FROM user_plan; -- 历史 'maybe' 原样保留
  DROP TABLE user_plan;
  ALTER TABLE user_plan_new RENAME TO user_plan;
  CREATE INDEX IF NOT EXISTS idx_user_plan_group ON user_plan (user_id, group_tag);
  ```
  已在本地 sqlite 3.51 用 0001+0002 全量跑通:旧行(含 `must`)完整保留、NULL 可插入、索引重建、`douban_map` 不受影响。
- `functions/api/plan/[code].js` PUT:
  - `body.priority === null` → SQL NULL 落库;
  - `undefined`/缺失 → `'maybe'`(旧数据兼容);
  - 其它值校验在 `VALID_PRIORITY` 内 → 原值。
  - bind 用 D1 的 JS `null` 直接传(SQLite NULL)。
- GET 不变(`r.priority` 原样返回 null)。
- 部署顺序:`npm run migrate:remote` → `npm run deploy`(前者改库,后者上函数)。`wrangler.toml` 的 `migrations_dir = "migrations"` 已就绪。
