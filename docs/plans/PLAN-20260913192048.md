# PLAN-20260913192048 — 「在 Google 地图打开 ↗」贴住影院地名(去掉行尾靠右)

## 目标

承接 `PLAN-20260913184357`(豆瓣入口落在片名右侧,靠 `gap` 紧贴片名)。

用户 2026-09-13 反馈:「我的行程」场次卡影院块里的 **`在 Google 地图打开 ↗`** 被 `margin-left: auto`
顶到了行右端,与左侧地名(`LOTTE 9` / `LOTTE CINEMA Centum City · 乐天影院 Centum City`)之间隔着
一大片空白;要求它**像 `豆瓣 ↗` 紧靠片名那样**,紧靠着左边的影院地名。

采用口径:**`agenda-parity.css::.venue-map-link` 去掉 `margin-left: auto`**,
让外链作为 flex 行里的普通项,跟在「地名 span」之后,只留 `gap` 的 8px 列间距。

## 范围

**做:**

- `apps/web/src/pages/agenda-parity.css`：`.venue-map-link` 删除 `margin-left: auto`(保留
  `flex-shrink: 0` / 品牌色 / `font-weight: 600` / 无下划线 / `white-space: nowrap`)。
- `e2e/react/parity-agenda.spec.ts`：加一条回归 —— 影院块里地图入口与**前一个兄弟(地名 span)**
  的左/右边缘间距 ≤ 16px(即只剩 flex 列间距),且二者在同一行;靠右贴齐时该间距会被拉大到上百像素。

**不做:**

- 不改 `.douban-jump` / `.title-row`：那两处已是「紧贴」口径,本轮只是把影院块对齐到同一口径。
- 不改影院块的其它视觉(字号 / 颜色 / `↗` 文案 / `title` 提示)。
- 不改 `ScreeningInfoPopover`、`InfoDialogs` 里的「在 Google 地图打开」：它们不在 flex 行里,无此问题。
- 不改 JSX 结构、不动 `biff.*` 数据契约、无迁移、不引依赖。

## 方案取舍

| 备选 | 结论 | 理由 |
|---|---|---|
| 去掉 `margin-left: auto`(外链紧跟地名) | **采纳** | 与「豆瓣紧贴片名」同一口径;行内信息自左向右读完即见入口,空白消失 |
| 保留靠右,改成给地名 `flex: 1` | 否决 | 结果一样靠右,用户要的就是「不靠右」 |
| 外链另起一行左对齐 | 否决 | 多占一行;用户明确说「紧靠着」,是要同一行紧贴 |
| 把 `↗` 与地名合成一个链接 | 否决 | 会污染地名文本语义,且改动面远超需求 |

## 验收标准

1. 「我的行程」场次卡影院块里,`在 Google 地图打开 ↗` 紧贴左侧地名 span,两者在同一行,
   水平间距 ≤ 16px(仅 flex `gap`)。
2. 该行右侧留有明显空白(不再被 `margin-left: auto` 吃满)。
3. 外链视觉不变(品牌色 / `font-weight: 600` / 无下划线 / hover 下划线),`href` 仍为 `mapsUrl(place)`。
4. `npm run verify:quick` 全绿;`parity-agenda`(desktop-chromium)全绿。

## 备注

- `venueInfo` 只有「我的行程」(`AgendaPage` 两处)传,所以只影响该视图。
- 无数据迁移。
