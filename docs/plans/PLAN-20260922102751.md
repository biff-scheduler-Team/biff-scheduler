## 方案取舍

| 备选 | 结论 | 理由 |
|---|---|---|
| **D1** 保留 `batch.ts`（只是没人调） | **否决** | 用户明确要「独占导出与对应单测一并清掉」；且分享去掉批次后它与 `RushPage` 的引用同时归零，留着是一份无人调用的判据实现（红线 5 同向：口径不该有第二份没人用的实现） |
| **D2** 只删 `batch.ts` 的 `BATCH_CATEGORY_EN` / `groupCodesByBatch`，留下 `ticketBatchOf` | **否决** | `ticketBatchOf` 的唯一消费者就是 `ExportDialog`（批次分节），分享去掉批次后它也归零；拆一半留一半没有意义 |
| **D3** `PosterModel` 保留 `sections`（恒单节、`heading` 恒 null） | **否决** | 那是「为批次分节而生」的结构；批次没了它就是一个永远只有一个元素的中间层，`posterHeight` / `drawPoster` 都要为它多绕一圈 |
| **D4** `rush.spec.ts` 只删不迁 | **否决**（用户选了迁移） | 分享文案 / 图片目前只有这一个 spec 覆盖；抢票页下线不该顺手把分享的覆盖也带走。改为在 `/agenda` 上断言「不含顺位 / 批次」 |
| **D5** 保留两个勾选框但让它们恒失效 | **否决** | 用户说的是「去掉」，留着两个点了没反应的开关比删掉更糟 |
| **D6** 导航重排后新增一个独立的 `nav-order.spec.ts` | **否决** | 仓库既有做法是把导航顺序断言放在**最相关页面的 spec 里**（`eats` / `rush-analysis` / 原 `rush`）。避免为一个数组再添一个 spec 文件 |

## 验收标准

1. 主导航顺序恰为：排片表 / 影片库 / 我的选片 / 我的行程 / 红黑榜 / 吃喝 / 数据分析 / 建议（`share-export.spec.ts` 的快照断言）。
2. `/rush` 落到兜底页（「找不到这个页面」）；导航里没有「抢票」。
3. 导出弹层里**没有**「带上顺位」「带上开票批次」两个勾选框；分享文案里不含 `主选` / `备选` / `↳` / `【第 N 批`；
   分享图片的 `__paintedTexts` 里同样不含这些字样，且图高与「只有日期分节」的模型一致。
4. 行程页的票务三态、同场人数、转票补入不受影响（`screening-social.spec.ts` 全绿）。
5. `npm run verify:quick`（check:repo + check:test-map + typecheck + lint + 单测）全绿。
6. `npx playwright test -c playwright.react.config.ts e2e/react/share-export.spec.ts e2e/react/eats.spec.ts e2e/react/rush-analysis.spec.ts e2e/react/parity-dialogs.spec.ts e2e/react/screening-social.spec.ts --project=desktop-chromium` 全绿。
