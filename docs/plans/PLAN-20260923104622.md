# PLAN-20260923104622 — 第二轮 code review 的 4 条收口

## 目标

对工作区**未提交**的红黑榜拖拽改动 + 「更多」菜单折行修复做第二轮 `code-review-skill` 四阶段审查，
得到 2 条 `🟡 important`、4 条 `🟢`（不阻塞）。用户拍板**按 review 里给的收口顺序执行前四条**：

> 开始执行 1-4

即：`🟡-1` `gestureRef` 无失效兜底 → `🟡-2` 放大弹层里认不出自己那枚 → `🟢-3` 双指 E2E 用随机落点当起点
→ `🟢-4` 文档收口（`PLAN.md` 表头 + 本 PLAN 的验证结果）。

`🟢-1`（拖拽浮标没有那圈白边）、`🟢-2`（`pointercancel` 被当成落点结算）本轮**不做**，理由见「不做」。

## 范围

**做：**

1. **`apps/web/src/pages/RedBlackPage.tsx`：`onMove` 加「丢了 `pointerup`」的兜底**
   —— 鼠标在窗口外松手时抬手事件可能根本没送到页面，`end()` 永不执行：`gestureRef` 一直占着，
   之后**每一次** `beginDrag` 都在第一行被挡掉、ghost 还粘在鼠标上（旧实现靠 `useEffect([drag])`
   被下一次 `pointerdown` 顶掉而自愈，现在同步挂监听没有这层）。
   ⚠ **只收尾、不结算**：那个 `buttons === 0` 的 `pointermove` 可能已经是鼠标**重新进入窗口**时的那一帧，
   拿它当「松手点」会把贴纸丢到用户没选过的位置（甚至判成出界而收回）。
2. **放大弹层里也认得出自己那枚**：`StickerZoomDialog` 由「一个 canvas 画 `all` 枚」改成
   **与卡片逐字相同的组成** —— canvas 画 `othersOf(counts, mine)`，我那一枚是压在画布之上的
   `.rb-dot`（带常驻纸白边）。
   - 顺带修掉一个**位置上的谎**：原先弹层把我那一枚画成 `crowdStickers(filmKey, all)` 的**最后一枚**
     （一个由 id 推导的点），与卡片上它的真实坐标不是同一个位置，而 lede 写着「位置与卡片上一致」。
   - 新增 `.rb-dot--still`（`cursor: default; pointer-events: none`）：弹层那枚是**只读**的，
     不能还留着 `grab` 光标——那是在承诺一个不存在的交互。
3. **E2E**：
   - `dispatchPointer` 补 `pointerType` / `buttons` 参数（默认仍是 touch，双指那条不动）；
   - 新增「窗口外松手丢了 `pointerup`：手势不卡死，下一次拖拽照常」（先红后绿，见验收标准 3）；
   - 双指那条的落点从「随机贴纸中心 + 24/18px」改为**由画布矩形推出来的点**（原写法在贴纸随机落到
     画布边缘时会把落点推出画布 → 判成出界 → 断言「确实动了」失败，是偶发**假红**）；
   - 新增「放大弹层里也认得出自己那枚：同位置、同白边」。
4. **文档**：`docs/CONVENTIONS.md` 登记弹层这条口径（以及「我那一枚的辨识边」现在的三处介质实现）；
   `PLAN.md` 表头「最后更新」补 2026-09-23 一行；本 PLAN 补「验证结果」段。

**不做：**

- **不给拖拽浮标 `.rb-ghost` 加那圈白边**（review `🟢-1`）：浮标是 28px 的 `position: fixed` 元素，
  加白边要动它的形状口径，而它只在拖拽过程中存在几百毫秒 —— 收益不抵「三处外观表述」的维护面。
  真要收，应和「浮标要不要复用 `.rb-dot`」一起拍，不塞进本轮。
- **不改 `pointercancel` 的语义**（review `🟢-2`）：旧实现就把它接到 `onUp`，不是本轮引入；
  改它要重新论证「取消 = 不结算」对触屏的影响，另开一轮。
- 不动 `film-votes.ts` 上报防抖、不动分享图 / 排序冻结 / 排序口径、不改 `biff.*` 任何存储结构。
- 不动 `.rb-canvas` 的 `touch-action`（那会让卡片右半张没法滚页）。
- 本轮**不提交、不推送**（§1 第 4 步：本地验收 → 用户确认后才 push）。

## 方案取舍

| 备选 | 结论 | 理由 |
|---|---|---|
| 兜底用 `onMove` 里判 `buttons === 0` | **采纳** | 只补一句、不改语义；鼠标一动就自愈 |
| 兜底用 `window.blur` / `visibilitychange` | 否决 | 覆盖面更广，但要在 `end()` 里配对摘监听、且「失焦」不等于「松手」，语义更绕；本轮选最小改动 |
| 丢了 `pointerup` 时**结算**一次落点 | 否决 | 首个 `buttons === 0` 的 move 往往是鼠标**重新进入窗口**的位置，不是松手点 —— 会把贴纸丢到没选过的地方 |
| `beginDrag` 里「同一根鼠标又按下 → 顶掉旧手势」 | 否决 | 要把 `pointerType` 存进单例才能避免误伤「触屏手指 + 鼠标」同时按的场景（多指守卫会被绕过）；实测价值只是省掉一次「白按」，不值这个复杂度 |
| 弹层高亮：canvas 加 `mine` prop 画白边 | 否决 | 那圈白边就有了**第二处**实现（CSS + canvas），而形状已经有三处表述了；且要改 `DrawKey` 守护键 |
| 弹层高亮：canvas 画 `others` + 我那一枚做成 `.rb-dot` DOM 元素 | **采纳** | 与卡片**逐字相同**的组成（画布只画别人 + 我那枚压在上面），白边自动只有一处实现，顺带修正落点位置 |
| 弹层只在 canvas 里给「最后一枚」描边 | 否决 | 那是**谎**：那个点由 id 推导，不是我这枚的真实坐标 |

## 验收标准

1. **弹层认得出自己那枚**：卡片上标「看过」→ 贴一枚 → 点「看全部」：弹层里 `.rb-zoom-stage` 下有且只有
   一枚 `.rb-dot`，带 `1.5px` 白边，且它的**相对位置**与卡片上那枚一致（容差 2%）；lede 的数字不变（共 N 枚）。
2. **丢了 `pointerup` 不卡死**：派发一次 `pointerType: mouse` 的 `pointerdown` 后紧跟一个
   `buttons: 0` 的 `pointermove`（模拟窗口外松手）→ 贴纸**不被收回、也不被挪走**（只收尾不结算），
   且随后的真实鼠标拖拽**照常生效**（未修前这一步永久失效）。
3. **双指那条不再靠随机落点**：落点由 A 的**画布矩形**推出，断言「发起的那枚被挪到松手那一点」（容差 2px），
   `<B>` 那枚一枚不多、一位不移。
4. 命令：`npm run verify:ui -- e2e/react/redblack.spec.ts --project=desktop-chromium`（含 typecheck / lint /
   `apps/web` 单测 / build web）全绿。
5. `docs/CONVENTIONS.md` 登记弹层这条口径；`PLAN.md` 表头出现 2026-09-23；本 PLAN 有「验证结果」段。
