## 2. 决策

1. **D1 整体退役**：删 `functions/`、`wrangler.toml` 的 D1 绑定、`migrations/`、`migrate:remote` 脚本。
   部署回到「纯静态产物」—— `wrangler pages deploy dist` 不再需要任何后端绑定。
2. **豆瓣映射改由静态 `public/douban.json` 承载**（离线产物、随部署进 dist、**可为空**）。
   `store.mappings` 这个 Map 与 `Mapping` 类型**保留**（8 处消费者一行不改），只把**数据源**
   从 `/api/mapping` 换成 `/douban.json`，并**删掉页面写入口**。
3. **`douban.json` 初始为空 `{"mappings":{}}`**：本轮只做**存储改造**，
   **豆瓣信息拉取不在本轮**（用户明确「不用跑的应该就是豆瓣信息拉取这部分」）。
   将来跑 `tools/enrich_douban.py` 后，把它转换成 `douban.json` 的 `mappings` 即可，**前端零改动**。
4. **兜底 = 中英文豆瓣搜索链接**：弹层「豆瓣」区在**无映射**时保留「中文搜索 / 英文搜索」两个外链；
   影片库「无排期目录片」行内那枚依赖映射的「豆瓣 ↗」直链同样改为**搜索链接**。
5. **不做爬虫 / 代理 / 海报**：豆瓣反爬不在本轮解决范围。

## 3. 数据契约 —— `public/douban.json`

```json
{
  "generated_at": null,
  "source": "tools/enrich_douban.py",
  "mappings": {
    "f012": { "subject_id": 37233337, "title_cn": "疯癫老人日记",
              "douban_url": "https://movie.douban.com/subject/37233337/" },
    "004":  { "subject_id": 37233337, "title_cn": "疯癫老人日记",
              "douban_url": "https://movie.douban.com/subject/37233337/" }
  }
}
```

- **键同时含 `f###` 与 3 位排期 code**：`f###` 供「影片库 / 目录片弹层」取用，3 位 code 供网格 / 行程 / ICS 取用。
- 字段与 `src/types.ts::Mapping` 逐字对齐（`subject_id` / `title_cn` / `douban_url`）。
- 加载容错：文件 404、`mappings` 缺失、空对象 → 一律视为「零映射」，不报错（与 `data.ts::loadJson` 同口径）。
- 进 git（< 100KB 纯文本）；PWA `globPatterns` 含 `json` → 自动进 precache，离线可用。

## 6. 边界与风险

- **旧前端缓存仍会打 `/api/mapping`** → 404 → 旧代码 `req()` 返回 `null` → 灰点降级。无害；
  PWA `autoUpdate` 会在下次访问时接管。
- **映射从「页面可写」变「离线产物只读」**：页面上不能再补 / 改豆瓣链接。这是既定取舍。
- **`douban.json` 为空时行为 = 纯搜索兜底**：所有片都走「中文搜索 / 英文搜索」外链，
  影片库无排期片走「豆瓣搜索 ↗」。这是本轮的预期状态，不是 bug。
- **`doubanChip` 不受影响**：它读 `FilmItem.rating`（`films.json`），与映射无关 —— 别顺手删了。
- **不做海报**：`FilmItem` 不加 `poster` 字段，`public/posters/` 不建。
- 不动 `store.picks`、不动 8 处 `store.mappings` 消费者、不动 `types.ts::Mapping`。
