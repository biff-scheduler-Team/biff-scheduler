# PLAN 2026-09-10 21:16:17 — 我的行程卡片:片名在上 + 影片信息行(对标「我的选片」)

> 需求(用户原话):「我的行程中电影卡片 片名应该要和我的选片中样式一样 片名在上方
> 然后有类似于『cons・France・ 2025・ Olivier ASSAYAS』这种影片信息样式 其实你对标我的选片就行」
> 本文件 = 本需求唯一规划文档。前置:`PLAN-20260910194000`(行程档,已撤销)/`PLAN-20260910195000`(行程行骨架)。
> **本文件已实现**(2026-09-10 21:2x)。

## 1. 现状(代码事实)

| 卡片 | 片名 | 影片信息行 |
|---|---|---|
| 「影片库 / 我的选片」影片卡(`library.ts::filmRow`) | 15px 加粗 | ✅ `原始片名 · 单元 · 国家 · 年份 · 导演`(11.5px `text-meta` 单行截断) |
| 「我的行程」行程卡(`agenda.ts::buildRow`) | 15px 加粗(经 `row.ts::headTitle`) | ❌ 没有 —— 只有片名 + 操作组,下一行直接是 `[CODE][影院][时间][章组]` |

信息行的拼装(`names` + `meta`)只活在 `library.ts::buildFilmList` 的 FilmNode 构造里
(私有的 `catFor` / `catMeta` / `pushName`),行程卡拿不到 → 只能自己拼一份(就是「两个视图不一致」的温床)。

## 2. 决策

1. **把「影片信息」上提为单一来源** `util.ts::filmInfoOf(cat, s, map)` →
   `{ zh, names, meta, cats }`,`filmInfoText(info)` 给一行文案;目录命中规则与 `filmNodeKey` 逐字一致。
   `library.ts::buildFilmList` 改为调用它(顺带删掉 `catFor` / `catMeta` / 局部 byZh·byOrig 索引),
   `agenda.ts::buildRow` 也调用它 —— 两处文案从此**不可能**不一致。
2. **`row.ts::screeningRow` 增加 `headSub`**(片名下方的信息行),与选片卡副标题同款:
   `text-[11.5px] text-meta leading-[1.5] truncate` + `data-tip` 全文(截断时 hover 可读)。
   卡片头由「单行 flex」改为「片名行(flex,操作组贴右)+ 信息行(独占一行)」——
   信息行若与片名同行,长片名会把信息挤没。
3. **行程卡标题取 `info.zh`**(= 目录中文名 → 排期中文名 → 豆瓣回填中文 → 排期英文名):
   与选片卡完全同口径;顺带保证 `names` 里不会出现与标题重复的片名。
4. **不动**:`state.ts` 数据层、网格卡(`grid.ts` 标题仍走 `s.title_zh || map.title_cn || title_en`,
   密集视图保持原口径)、场次行骨架、操作组。

## 4. 边界与风险

- **`buildFilmList` 重构的行为等价性**:原 `catFor` 的索引查找与 `filmInfoOf` 的 filter 命中集合、
  顺序、`zh`/`names`/`meta` 拼装逐条对齐(含「目录条目无原始片名时退回排期英文名」这一分支)。
  `FilmNode` 的字段与下游(`matchNode` / `inUnit` / `filmRow`)完全不变。
- **片名可能变化**:`s.title_zh` 为空、靠 `title_en` 命中目录的场次,行程卡片名从「英文名」变为
  「目录中文名」—— 这正是「对标我的选片」的预期结果(选片卡本来就是中文名)。
- **信息行长度**:单行 `truncate`,520px 抽屉里长片名组合会被截断 → `data-tip` 出全文(与选片卡一致)。
- **Tailwind v4**:新增类均为字面量(`text-[11.5px]` / `text-meta` / `truncate` / `mt-[2px]`),无拼接。
