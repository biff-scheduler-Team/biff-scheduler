# PLAN-20261007231522 — 红黑榜讨论区「全局总览」

## 目标

> 用户原话：**「讨论区需要有一个全局总览的 然后能通过角标或者什么显示是哪个电影的」**

追问确认（2026-10-07，`ask_followup_question`）：

| 岔路 | 用户选择 |
|---|---|
| 形态 | **红黑榜页面里一个专门的总入口**（不是导航里的一级页面、不是新路由） |
| 点条目 | **跳到该片卡片** —— 关掉总览，滚动 / 高亮到红黑榜里对应的那张卡 |
| 范围 | **只有红黑榜讨论区** —— 用户原话「讨论区总览是指的是红黑榜讨论区总览 请你不要混淆了」 |

现状：红黑榜每张卡右上角那枚「讨论区」只回答「**这一部**」，换一张卡就是另一种评语。
**跨片的全局视图不存在** —— 想看别人给别的片写了什么，只能自己一张张卡翻。

## 现状（代码事实，非推测）

- 唯一在线的「讨论区」= 卡片右上角入口 → `FilmCommentsDialog`
  （`apps/web/src/components/FilmCommentsDialog.tsx`），只读**这一部**：
  `loadFilmComments({ filmKey: film.key })`（`:73`）。
- 读端 `filmKey` 是**可选**的：`apps/web/src/film-comments.ts:145`
  （`if (options.filmKey) params.set("filmKey", …)`）；服务端也把它当**可选过滤**
  （`apps/api/src/index.ts:878-882`，非法 / 超长一律当「不过滤」）。
  ⇒ **「跨片全局读」这条读路径已经存在，后端零改动。**
- 每条评语自带 `filmKey`（`film-comments.ts:32-38`；api `CommentItem`
  `film-vote-stats.ts:257-263`）。**没有时间戳** —— `updated_at` 在 `toCommentItems` 里被剥掉
  （它只服务游标），列序由服务端 `updated_at desc` 保证，前端不需要也不该再放一份。
- 卡片根元素**已经有** `data-film-key`（`apps/web/src/pages/RedBlackPage.tsx:1515`）⇒ 滚动定位零改动。
- `useCatalog()` 提供**全量** `filmByKey: Map<string, FilmNode>`
  （`apps/web/src/app/store.tsx:151`），**不受页面搜索 / 筛选影响** ⇒ 片名反查用它。
- 页面工具条 `.rb-controls`（`RedBlackPage.tsx:1085-1149`）已经是本页的动作行。
- 「闪描边定位」的既有手法：`apps/web/src/components/ScheduleGantt.tsx:172-204::flashScreenings`
  —— 加 class → 取 `getComputedStyle().outlineColor` 喂 WAAPI，**只闪描边、绝不动 opacity**。

## 范围

**做：**

1. `.rb-controls` 加一枚常显入口按钮「讨论区总览」（`.rb-board-btn`）→ 打开新弹层。
2. 新组件 `apps/web/src/components/DiscussionBoardDialog.tsx`（**懒加载**，与
   `FilmCommentsDialog` 同一手法）：
   - 复用 `EMPTY_COMMENT_LIST` / `mergeCommentPage` / `loadFilmComments`
     —— **不带 `filmKey`**，即跨片读；
   - 每行：来源角标（红 / 黑）+ **片名角标《片名》** + 正文 + 昵称；
   - 整行可点（`<button>`）→ `onJump(filmKey)`；
   - 游标翻页（「加载更多」，与服务端 `nextCursor` 同口径）；
   - 空态 / 接口挂了都退化成空态（照 `film-comments.ts` 既有降级口径，绝不把整页拖挂）。
3. `RedBlackPage` 的跳转：`onJump(filmKey)` → 关弹层 → 若有 `q` / `only=mine` 先清掉
   → 等重渲染 → `[data-film-key=…]` 滚进视口 + 闪描边（照 `flashScreenings` 手法）。
4. 样式加进 `apps/web/src/pages/redblack-parity.css`（token 是唯一色源）。
5. E2E：`e2e/react/redblack.spec.ts` 新增 2 条（总览列出**跨片**且角标是片名；点条目 →
   弹层关 + 对应卡闪现 / 被过滤时自动清过滤）。

**不做：**

- **不碰后端 / 契约**：`/api/stats/film-comments` 与 `apps/api` 一个字不改（全局读已存在）。
- **不含「场次讨论」** —— 用户 2026-10-07 明确「只有红黑榜的讨论区」；
  已下线的 `/discussions` 页面继续下线。
- 不加导航项 / 不加路由（用户选「红黑榜页面里一个专门总入口」）。
- 不动 `FilmCommentsDialog`（卡片级弹层）的任何行为。
- 不新增 / 不修改任何 `biff.*` 存储结构（总览是**纯读**，不落盘）。
- 不改 `film-comments.ts` 的读路径与白名单。

## 方案取舍

| 备选 | 结论 | 理由 |
|---|---|---|
| 复用现有读路径（不带 `filmKey`） | **采纳** | 后端本就支持跨片读，零后端改动 |
| 新增 `/api/discussions` 汇总（含场次讨论） | 否决 | 用户明确只要红黑榜讨论区 |
| 总览做成导航一级页 / 新路由 | 否决 | 用户选「红黑榜页面里一个专门总入口」 |
| 让卡片级弹层兼职全站 | 否决 | 卡片弹层的语义就是「只问这一部」；混两种语义会让两处口径打架 |
| 给评语接口补时间戳，列表里显示时间 | 否决 | 用户没要时间；列序由服务端保证，前端再放一份时间只多一处会漂移的口径 |
| 服务端加「讨论热榜」按片聚合 | 否决 | 超出需求；总览就是全量按时间倒序一页一页看 |

## 验收标准

1. 红黑榜页工具条有一枚常显「讨论区总览」入口；点击打开弹层。
2. 弹层列出**跨片**评语，每行有红 / 黑角标 + **《片名》角标**（片名取自
   `useCatalog().filmByKey`；反查不到时取中性文案「未知影片」、原始 key 落在 `title` 上，
   且该行**不可跳**）。
   ⚠ 行按钮**刻意不挂 `aria-label` / `title`**：实测（Chromium 无障碍树）两者都会成为
   可访问名、把这行的内容（片名 / 评语 / 昵称）整个替换掉，读屏用户就再也听不到评语 ——
   「点了会跳」由弹层顶部那句 lede 交代；E2E 有一条断言钉着「可访问名 = 行内容」。
3. 点某一行 → 弹层关闭、页面滚到该片卡片并**闪一次描边**
   （`prefers-reduced-motion` 下只留静态描边）。
4. 若该片被 `q` / `only=mine` 挡住，跳转前自动清掉这两个过滤。
5. 接口 404 / 500 / 断网 → 弹层空态，红黑榜页照常可用。
6. `npm run verify:quick` 绿；`e2e/react/redblack.spec.ts` 新增用例绿。
