# PLAN-20261015005652 — 快速投票：候选改「全部有票的」、文案改红/黑、跳过提示移到海报下、划完给「去搜索」出口

## 目标

用户原话（2026-10-15）：

> 不能叫喜欢/不喜欢 应该叫红黑吧 因为是红黑榜的 如果打开之后默认直接所有有过票的都作为滑动的片单吧这样也不会遗漏
> 反正划一下也很快 然后如果用户有片单 你可以提示他 切换成自己的行程片单 然后跳过的那个提示 应该显示在海报下面
> 不然往上滑就看不到跳过那两个字了 然后还有就是 如果用户划完了 他发现没有自己看过的某部冷门电影 你需要提示他
> 类似于没有找到自己看过的电影吗 尝试通过 CODE 搜索

拆成五件事：

1. **文案**：`喜欢 / 不喜欢` → `红榜 / 黑榜`（这一屏是红黑榜的投票入口，`喜欢` 是另一个榜的术语）。
2. **默认候选**：打开卡片默认就是**全站有过票的影片**（服务端聚合里红 + 黑 > 0 的那些），
   不再默认「我的行程」—— 清单全，不会遗漏，划一下很快。
3. **来源提示**：用户自己**有行程**时，给一条「换成我的行程」的提示与入口（可在两个来源间来回切）。
4. **跳过提示**：`跳过` 那两个字**移到海报下面**（常驻图例那一条），往上滑时不再跟着卡片飞出屏幕。
5. **划完的出口**：总结页加一句「没找到你看过的那部？用片名或场次编号（CODE）去搜」，
   并给一枚按钮：关掉卡片 + 把焦点送到页面上的搜索框。

## 方案取舍

| 备选 | 结论 | 理由 |
|---|---|---|
| 候选按**票数降序** | 否决 | 票数一变顺序就变 → `deckSignature` 变了 → `QuickVoteDeck` 重开这一轮、`index` 归零。这正是用户报过的「划了五部又从 5/50 变成 1/50」。改用**最早一场升序**（与 `quickVoteOrder` 逐字同形，复用同一个比较器）。 |
| 候选在**渲染里直接算**（`useMemo([crowd])`） | 否决 | 「我自己那一票上报成功后服务端聚合会多出这个 key」⇒ 队列成员变了 ⇒ 同样触发重开。改成**开卡片那一刻快照一次**（`useState` + 一个 `deckOpen && votesSettled` 的 effect）。 |
| 票数没到就先用「行程」顶上 | 否决 | 队列会**换两次**（行程 → 有票的），刚划掉的那张会被甩回去。票没到就先给空队列 + 「正在取候选…」，与热门榜兜底那条既有做法（「等它到了再给，队列于是只出现一次」）同一口径。 |
| 「跳过」保留在卡片上但挪到底部 | 否决 | 卡片整张会飞出屏幕，卡片上的任何位置都会看不见。放到**常驻图例**那一行（它在海报下方、不跟手飞走），并把「上滑 · 跳过」做成跟手高亮 —— 不新增一行高度（手机矮屏那条不动）。 |
| 总结页给「去搜索」按钮但只关卡片 | 否决 | 卡片是弹层、搜索框在它后面，只关掉的话用户还得自己找输入框。加 `focusToken` 把焦点送过去（实现 6 行，`QuerySearchField` 三个使用点都不受影响）。 |
| 三个来源平铺成一组 tab | 否决 | 用户只要「默认有票的 + 可换自己的行程」。热门榜那一档是兜底（无票无行程时才出现），给它一枚 tab 反而把「兜底」说成了「正常来源」。 |

## 修订 1（2026-10-15 稍晚，用户原话）

> 快速投票还是把影片信息放到海报上吧 中英文名 导演名称 然后 code 就行 然后每次进入红黑榜就是直接默认弹出快速投票

拆成两件事：

1. **海报上叠一层影片信息**：中文名 / 英文名（与中文同名就不重复印） / 导演 / CODE（第一场的场次编号，
   没有排期就不印那一行）。这是对 `73bb53f`（「最好只保留纯海报」）的**部分收回**——
   用户这次明确要「中英文名 导演名称 然后 code」，不是整层文字都不要，是**只要这四样**，
   不恢复之前那一整层（单元 / 国家 / 年份 / 场次时间 / 全站票数 / 简介）。
2. **自动弹出的判据放宽**：原来只在「我的行程里有片」时落地自动弹（`BoardPage` 修订 3）；
   这次要求**每次进入红黑榜**（不论有没有行程）都默认弹出快速投票 —— 判据从「有没有行程」
   换成「有没有从别的 tab / 别的页面进来」。

**做：**

  （叠在海报底部的半透明条），内容 = 中文名 / 英文名(不同名才印) / 导演(有才印) / CODE(有排期才印)。

    （这样「再切回红黑榜」才算得上「又进了一次」，能再弹一次）。
- 测试：`apps/web/tests/quick-vote.test.ts` 不变（`posterOf` 是组件内闭包，不单独导出）；

**不做：**

- 不恢复场次时间 / 全站票数 / 简介 —— 用户只要「中英文名 导演名称 然后 code」，没提这几样。
- 不改「红 ↔ 黑之间来回切」要不要重新弹一次：两者都已经在「红黑榜」里，不算「进入」，
  维持原状（已经开着就不动，已经关着也不强行弹回来，否则会变成关不掉的烦人弹窗）。
- 不改快速投票的候选口径（有票的 / 行程 / 热门榜兜底，修订 0 已定）。
- **不改 `?q=`「去评分」这条路径**：从日程表格子跳过来是奔着**那一张卡**去的，弹模态卡片
  会把它整个盖住，与「进入红黑榜」的泛泛期待矛盾 —— 实现时发现 `e2e/react/redblack.spec.ts`
  那条「讨论区总览：目标被搜索框挡住时,自动清掉过滤再定位」正是走 `/redblack?q=…` 落地，
  被新判据误伤过一次，已经改回**显式排除** `hasQuery` 这个分支（`BoardPage.tsx` 那段 ⚠⚠）。

### 方案取舍（追加）

| 备选 | 结论 | 理由 |
|---|---|---|
| 「每次进入」用 `useEffect` 监听 `tab` 变化，一变成红/黑就强制 `vote=1` | 否决 | 这样用户在红黑榜里主动关掉卡片（`closeDeck`）之后，只要有任何读 `tab` 的重渲染就可能被强行弹回来 —— 关不掉的弹窗。改成**只在「切 tab」或「落地」这两个动作里显式写 `vote=1`**，待在原地不动不会被打扰。 |
| 海报信息用 `ScreeningInfoPopover` / `FilmDialog` 那一套完整渲染 | 否决 | 那两处是「查看详情」的场景，字段多、排版复杂；这里只要四行字叠在海报上，另起一个零依赖的轻量块，不拖一整套对话框逻辑进来。 |
| CODE 取 `card.map?.subject_id` | 否决 | 那是豆瓣 subject id，不是场次编号；用户说的 CODE 是 `Screening.code`（如 "008-1"），取 `card.shows[0]?.code`。 |
