### 根因 1（确定性，用例 1、2）：**默认日期依赖真实「今天」**

- `apps/web/src/pages/AgendaPage.tsx:60-70`：日期条只列「我有行程的日期」，默认落点 =
  「今天有我的场次 → 今天；否则**第一个晚于今天**的；整段都在过去 → **最后一天**」。
- 场次 `001`（彼此的日夜，露天场开幕）在 catalog 里是 **2026-10-06**，且**从未变过**
  （已核对 `1295764` 与 `ee71615` 两版 `schedule.json`，001/003/008/033/037 日期逐字相同）。
- 今天 = 2026-10-16，已晚于全部场次 ⇒ 落点 = 最后一天 **10-07** ⇒ 期望 `001`（10-06）的两条用例必红。

  （全篇只用 `location.search` 喂 `navSearch`），所以 URL 上的日期既没生效、又误导了作者。
- 规模：**20 个 spec / 40+ 处 `ready(page, "/agenda")`** 都踩在同一个坑上；仓库已有正确先例

## 为什么 3–8 必须走 PR 取现场（这条决定了本轮的工作方式）

1. `ci.yml` 在 `main` 上按 `git diff HEAD^ HEAD` 判断：**改动不含 `apps/` 且不含 `packages/` 时整条 e2e job 不启动**。
   本轮（含后续）改的是 `e2e/` ⇒ **推 main 之后 E2E 根本不会跑**，也就看不到红绿。
2. PR 分支会跑「受影响 spec · desktop-chromium」+ 全量三浏览器（`main` 那套），**就是 CI 环境**，
   且能把诊断输出（`console.log`）留在 run log 里 —— 这正是 `3.671875` 这类数字唯一的来源。
3. 因此：**先在 PR 上把现场取回来，再改断言**；改完在同一 PR 上验证到绿，最后 merge 回 main。

## 修订 2（2026-10-16，拿到 CI 现场：3–8 是**一个**根因）

### 怎么拿到现场的

`e2e/` 的改动在 `main` 上会被 `ci.yml` 的 diff 规则**整条跳过 E2E**（`apps/` / `packages/` 都没有），
而 PR 上只跑「受影响 spec」，且 `scripts/affected-specs.mjs` 是**从应用源码推 spec** ——
改 spec 文件**不会把它自己选进来**（实测 PR #37 只选出 `e2e/react/smoke.spec.ts`）。
⇒ 唯一能验证 e2e 改动、并且能拿到 webkit / mobile 现场的路：**分支 + 手动 `workflow_dispatch`**
（`github.event_name != 'pull_request'` 时跑全量三浏览器）。已跑：run `38872322089`（21m13s，红）。

### 统一根因（3–6 是同一件事）

`@react-spectrum/s2` 的样式表带 `@font-face`，字体文件在 **`use.typekit.net`（Adobe Fonts）**；
CJK 那几族由 Adobe 的 **WebFont Loader 异步注入**（`<html>` 上出现 `wf-loading` /
`wf-*-n9-loading`）。所以：

- `document.fonts.ready` **够不着**它们（「未被使用的 face 算 unloaded」）；
- 连 `[...document.fonts]` 里都**没有** han 那几族（本机实测），`load()` 也就无从谈起；
- 换字形的落点因此是随机的：**本机早早换完 ⇒ 全绿；CI 落在两次测量中间 ⇒ 稳定红**。
- 这也解释了为什么 CI 的药丸宽是 `91.796875`(webfont) 而本机是 `81.6875`(回退字形) ——
  `PLAN-20261015172642` 修订 1 把它归因给 `transform: scale(1.04)`，**已被证伪**。

### 决定

1. **E2E 里拦掉 `use.typekit.net`**（`helpers.ts::ready()`，同一 test 只挂一次路由），让本机与 CI
   量**同一份排版**。取舍写明：此后量的是**回退字形**那一版。
2. **不把 3px 溢出当成测试口径问题掩盖**：CI 现场顺手证明「真用 webfont 时 iPhone SE 档弹层要多滚 3px」
   —— 这是**产品侧**的一条（`qv` 内部高度是被内容撑的），**另开一次需求**处理，不在本轮用放宽阈值抹掉。
3. `parity-library` 是**独立**的时序问题（打字前瞻的缓冲），改「打一轮 → 没有就再打一轮」，判据不放松。

### 遗留（明确不做、也不假装做了）

- `redblack:509`（mobile-webkit）与 `redblack:1822` 的 webkit 分支（`bgLive` 仍是透明）**仍是未解**：
  它们的现场与字形无关（是手势/时序），本轮只加了诊断消息，**没有修**。下一轮按 CI 现场单独定位。
