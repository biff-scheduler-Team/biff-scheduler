# PLAN 2026-09-10 19:22:30 — 「我的选片」影片信息里去掉档位控件

> 需求(用户原话):「我的选片中影片信息中不需要改影片的 必看 备选 随缘 因为别的地方有地方改了」
> 本文件 = 本需求唯一规划文档。前置:`PLAN-20260910184745` §8(影片卡片信息层级重构)。
> **本文件只做规划,未实现。**

## 1. 现状(代码事实)

`library.ts::filmRow(n, mode, open)` 是**两个 tab 共用**的影片卡片渲染器:

- `mode === "library"` → 抽屉「影片库」tab(找片 / 打标的主场)
- `mode === "picks"`   → 抽屉「我的选片」tab(已选视图,按档位排序 + 档位 / 日期筛选)

卡片的**上半部(影片信息)**右上角图标组(`library.ts` ≈598–632)当前**两 tab 完全一致**:

| 图标 | 出现条件 | 语义 |
|---|---|---|
| `★` / `☆`(`pick.ts::wishIcon`) | 两 tab 都有 | 弹菜单改档位(必看 / 备选 / 随缘 / 清除) |
| `ⓘ` | `n.shows.length \|\| cat0` | 影片资料弹层 |
| `✕` | 仅 `picks` | 整片移除 |

档位本身还有另外三处入口,**都是同一份 `store.picks`**:

1. 影片资料弹层 `modal.ts::buildWishRow`(三段 seg,两 tab 点 `ⓘ` 都能进);
2. 「我的行程」行程行 `agenda.ts`(★ 星标);
3. 「影片库」tab 的卡片 ★ 星标。

## 2. 决策

**「我的选片」tab 的影片信息里不再渲染档位 ★** —— 该 tab 是「已选视图」,
档位已在列表层表达(默认排序 必看 → 备选 → 随缘 + 档位筛选 chips 带实时计数),
再给每行一枚可改档位的控件是重复入口;改档位去「影片库」tab(或任意 tab 点 `ⓘ` 进资料弹层)即可。

**「影片库」tab 保留 ★**:那是打标的主入口,去掉就没有就地打标的地方了。

**不动**:`pick.ts`(`wishIcon` / `buildWishSeg` 仍被 library(库 tab) / agenda / modal 消费)、
资料弹层的档位 seg、行程行的 ★、`state.ts` 数据层。

## 4. 边界与风险

- **`picks` tab 的图标组不会变空**:`✕` 在该 tab 无条件渲染,`ⓘ` 亦常在 → 右列 `auto` 宽度仍成立,
  `grid-cols-[12px_minmax(0,1fr)_auto]` 无需改。
- **排序即档位**:去掉每行的档位标识后,档位信息由「排序 + 筛选 chips 计数」承载(默认 `全部` 时
  仍按档位从高到低排列),不会出现「看不出这行是什么档」的歧义。
- **`wishIcon` 的 `tipPrefix`**:原本按 `mode` 给「我的选片 · 」前缀,现在只剩库 tab 分支,
  该三元表达式一并删掉,避免留死分支。
- **`setWish` 的默认展开副作用**(`if (p) expPick.add(n.key)`)随 ★ 一起离开 picks tab ——
  无影响:该分支只在「从卡片打标」时触发,库 tab 的 ★ 仍保留此行为。

## 5. 验收标准

1. `npm run typecheck` + `npm run build` 通过。
2. 抽屉「我的选片」tab:卡片右上角只剩 `ⓘ` / `✕`,**没有** `★`/`☆`。
3. 抽屉「影片库」tab:卡片右上角仍有 `★`/`☆`,点击仍弹出「必看 / 备选 / 随缘 / 清除档位」菜单,
   改档后「我的选片」计数与排序同帧更新。
4. 「我的选片」里点 `ⓘ` → 资料弹层的档位 seg 仍可改档(改档位入口未丢)。
5. 「我的行程」行程行的 ★ 不受影响。
6. `npm run deploy` 后线上产物哈希与本地 `dist` 一致。
