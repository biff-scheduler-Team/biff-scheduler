# PLAN-20260920193834 — 明细表加「按场次看」开关：分得清影厅，看得到哪一场人最多

## 目标

用户原话：

> 影片明细 · 想看 TOP 10（按想看人数降序） 需要勾选一个选项 能够区分影厅 知道哪一个场次最多人比较好

现在那张表的「抢票人数」是**按影片汇总**的（该片所有场次的同场人数之和），
所以看不出「是哪一场」「哪个厅」人多 —— 而抢票恰恰是**按场次**发生的。

## 范围

**做：**

- 明细表加一个复选框「**按场次看（区分影厅）**」，默认不勾（保持现状）。
- 勾上后**同一张表**切成场次视角：行 = 当前筛选下各影片的**场次**，
  列 = 影片 / 场次 / 时间 / **影厅** / 抢票人数，按**抢票人数降序**取前 10。
  于是**第一行就是人最多的那一场**，影厅单独成列可区分。caption 随视角改口径。
- 两个搜索框的筛选在两种视角下都照旧生效（场次视角吃的是同一份 `filtered`）。
- E2E 新增一条：勾上后出现「影厅」列、行按人数降序、行数 ≤ 10。

**不做：**

- 不改影片视角的列与排序（用户没提；它回答的是另一个问题「哪部片想看的人多」）。
- **不加**「热门场次」之类的徽章 / 标记：降序排列本身就让第一行是人最多的那场，
  再加个徽章只是多一个要解释的东西（用户这一路的要求都是「少而准」）。
- 不在影片行下做展开（tree）：见方案取舍。
- 不动图表、口径、数据契约。

## 方案取舍

| 备选 | 结论 | 理由 |
|---|---|---|
| 影片行下展开它的场次（树形表格） | 否决 | 要自造展开状态 + 缩进视觉 + 键盘处理；而用户问的是「谁最多」，排序平铺直接回答 |
| 把影厅拼进「抢票人数」那一格 | 否决 | 一部片多场多厅，塞进一格读不出「哪场最多」 |
| 另起一张场次表与影片表并排 | 否决 | 同一份数据摆两张表，版面翻倍；切换比并排省地方 |
| **复选框切换同一张表** | **采纳** | 一个开关、一份数据、两种视角 |

## 验收标准

1. 明细表 caption 上有复选框「按场次看（区分影厅）」，默认不勾时页面与现在完全一致。
2. 勾上后：出现「影厅」列；行按抢票人数**降序**（首行即人最多的场次）；行数 ≤ 10。
3. 场次视角下改搜索词，清单同样收窄。
4. `npm run typecheck` / `lint` / `build -w @biff/web` 通过；`rush-analysis.spec.ts` 全绿。
5. 回写文档：本 PLAN；`PLAN.md` 文档头一行「最后更新」。
