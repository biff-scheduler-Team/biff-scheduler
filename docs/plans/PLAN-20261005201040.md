# PLAN-20261005201040 — 把 Naver 共享收藏夹《부산국제영화제 스태프 추천맛집》的 49 家店并进「吃喝」清单

## 目标

用户原话：

> 请你导入这个 https://map.naver.com/p/favorite/sharedPlace/folder/c90119d8251849efa1b60845364915a0 里面的店铺

用户已裁决（两问两答，不再改）：

1. **导入目标** = 并入现有「吃喝」清单（`apps/web/public/eats.json`），并同步改 `tools/build_eats.py` 的输入 / 合并逻辑 ——
   否则下次重跑管线会被覆盖。
2. **店名** = 只用韩文名 + 英文罗马音，**不翻译**（卡片主名会显示韩文，因为既有口径是「中文优先、其次韩文」）。

## 现状（代码事实，非推测）

- `apps/web/public/eats.json` 现为 **38 家**，单源：腾讯文档《BIFF吃喝》CSV → `tools/build_eats.py` →
  产物检入（`eats.json` 的 `source` 字段只写那一条）。
- 分区判据 `tools/build_eats.py::district_of` 只认 **해운대 / 수영 / 중구 / 동구 / 부산진**，
  推不出来一律 `other`（**不瞎猜**）。中文标签在 `apps/web/src/eats.ts::DISTRICT_LABEL`（口径单一来源）。
- 收藏夹数据不在 HTML 里，也不在 `/p/api/*`（那里只有壳）。真实链路（本次实测还原，非推测）：
  - 页面 `map.naver.com/p/favorite/sharedPlace/folder/<shareId>` 挂一个 **跨域 iframe**
    `https://pages.map.naver.com/save-pages/pc/detail-list/<shareId>`（`map.naver.com` 的 `/p/api/*` 前缀会被网关剥掉，
    所以 `/p/api/bookmark/shares/<id>` 一律 404 —— 实测确认）；
  - iframe 内部调
    `GET https://pages.map.naver.com/save-pages/api/maps-bookmark/v3/shares/<shareId>/bookmarks`
    `?start=0&limit=5000&sort=lastUseTime&createIdNo=false&lang=ko` → `{folder, bookmarkList[], …}`；
  - ⚠ `placeInfo=true` 时 `limit` 上限**只有 20**（实测 `apiErrorCode 1002`），不带它才能一次拿全 49 条；
  - ⚠ **必须带 `lang=ko`**：不加时 `name` 返回罗马音（`Park ki mo jobangnakji`），加了才是韩文原名（`박기모조방낙지`）。
- 收藏夹元信息：`name=부산국제영화제 스태프 추천맛집`、`memo=맛동여지도 X 부산국제영화제`、
  `owner=misi****`、`bookmarkCount=49`、`folderType=SHARED`。
- 49 家的分区分布（用现有 `district_of` 实算）：**수영 26 / 해운대 12 / 중구 2 / 부산진 1 / other 8**。
  → `other` 只占 8 家，**不需要新增分区码**。
- slug（`id`）实测：49 个新 id 与现有 38 个 **零冲突**，49 个之间也零重复。
- 相关回归面：`e2e/react/eats.spec.ts`（E2E）、`apps/web/tests/eats.test.ts`（纯逻辑）、
  `scripts/test-map.json` 的 `eats` 组（命中业务 spec `eats` → 按 §4.5 **走 PR**）。

## 方案取舍

| 备选 | 结论 | 理由 |
|---|---|---|
| 构建时实抓 Naver 接口 | **否决** | 与既有《BIFF吃喝》同一条原则：第三方私有接口不进构建；且该接口有 `lang` / `limit` 两个暗坑 |
| 把 49 家直接手写进 `eats.json` | **否决** | 下次重跑 `build_eats.py` 会被整体覆盖 —— 正是用户点名的风险 |
| 快照检入 + 管线接第二输入 | **采纳** | 产物可 diff、可 review，且重跑幂等；与 `tools/build_eats.py` 既有形态一致 |
| Naver 原始响应原样入库 | **否决** | 带 `thumbnailUrls` / `streetPanorama` 等噪声（单条 ~2KB），仓库里只留管线真正要用的字段 |
| 快照放 `data/_cache/`（跟 CSV 同处） | **否决** | `.gitignore` 的 `data/_*` 会忽略它 → 换个 clone 重跑就丢，等于没解决覆盖问题 |
| `menu` 用 Naver 的**细分**品类（낙지요리 / 베이커리 / 이자카야…） | **否决** | 49 家里 30+ 个互不相同，会让「想吃什么」过滤器退化成噪声；细分只在 `placeInfo=true`（`limit≤20`）里给 |
| `menu` 用 Naver 的**粗分**品类（음식점 / 카페 / BAR） | **采纳** | 这是收藏夹自己的筛选口径，只有 3 个值，稳定且不需额外请求 |
| `link` 放 Naver 精确店铺页（`map.naver.com/p/entry/place/<sid>`） | **采纳** | 源里就给了精确页，零成本；`eats.ts::eatLinkLabel` 已把 naver.com 域映射成「Naver 店铺」，无需新标签逻辑 |
| `link` 留空、精确页只靠 `/api/eats/lookup` 补 | **否决** | 那要配 Naver / Kakao 密钥才点亮；现成数据不该只在有密钥时才可用 |
