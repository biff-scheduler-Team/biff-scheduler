# PLAN-20260910162000 — AI 排片:日期记住上次选择 + 多候选方案让用户自己挑

## 背景 / 用户诉求

> AI 排片 日期默认全不选 请你改下 然后 AI 排片能不能根据当前选的日期 然后这样能减少一些上下文?
> 然后如果有多个方案 优先按照用户的优先级出方案 然后让用户自己挑

三条诉求拆解:

1. **日期默认值要改** —— 上一版(`PLAN-20260910151403`)按用户要求把「② 排哪几天」默认改成**全不选**,
   每次开弹层都要重选一遍,太啰嗦。用户确认改成「**记住上次选择**」(落 localStorage;首次仍全不选)。
2. **只按所选日期排片以省上下文** —— 该能力 `buildPayload(dates)` 已有(场次按日期过滤 + `env.dates`
   同步 + 所选日期内无场次的影片整条不送);本次把它与「记住上次选择」串起来,并在文案里点明
   「收窄日期 = 减少上下文」。
3. **多方案 + 用户自己挑** —— 模型一次给 **1~3 个候选方案**(按用户优先级从高到低排列),
   UI 每个方案一张卡、各自「并入 A/B」,由用户挑一个采用。

## 设计决策

### 一、日期「记住上次选择」

1. 新增 LS 键 **`biff.ai.dates.v1`**(独立于 `biff.ai.v1`),`ai.ts` 提供
   `loadAiDates(): string[]` / `saveAiDates(dates: Iterable<string>)`(纯逻辑 + localStorage,不碰 DOM)。
2. `aiPanel` 初始化:`new Set(loadAiDates().filter((d) => ctx.cat.dates.includes(d)))`
   —— 存档里已不存在的日期(数据换版)自动丢弃;首次无存档 = 空 = **全不选**。
3. 日期变更统一出口 `commitDates()` = `saveAiDates(selDates)` + `paint()`
   —— chip 点击 / 全选 / 全不选三处都走它,避免漏存。
4. 文案:`② 排哪几天(默认全不选)` → `② 排哪几天(记住上次选择)`;块注释同步。

### 二、多候选方案

1. **输出契约**:`SYSTEM_PROMPT` 的【输出】由
   `{"picks":[…],"dropped":[…],"note":"…"}` 改为
   `{"plans":[{"title":"…","picks":[…],"dropped":[…],"note":"…"}],"note":"…"}`,
   并明确「plans = 1~3 个候选方案,按最贴合用户优先级 → 次优取舍从高到低排列;只有一种合理排法时给 1 个,
   不要为凑数硬造雷同方案」。
2. **类型**:新增 `AiPlanOption{title, picks, drops, rejected, note}`;`AiPlan` 由
   `{picks, drops, rejected, note, raw}` 改为 `{options: AiPlanOption[], note, raw}`。
3. **解析**:`parseAiResult` 拆出 `parseOnePlan()`(单个方案的复检:code 白名单 → 同片去重 →
   `conflict.ts` 同口径冲突剔除 → 补齐「未纳入」),顶层:
   - 兼容旧格式(无 `plans` 或为空)→ 退化为单方案;
   - 按「场次 code 排序后拼接」的签名**去重雷同方案**(模型偶尔把同一份排法抄 2~3 遍);
   - **最多保留 3 个**;`plans` 全是空对象时兜底给一个空方案。
4. **UI**:`resultCard` 头改为「AI 给出 N 个候选方案(按你的优先级排序)· 挑一个点『并入 A/B』」;
   新增 `optionCard(opt, idx)` —— 可折叠(默认只展开第 1 个,避免 3 份完整清单一次铺开),
   头部 = 折叠箭头 + 「方案 N」章 + 标题 + 计数 + `并入 A/B`;
   采纳态与回执按**方案下标**各存一份(`adopted: Map<number, Group>` / `adoptNotes: Map<number, string>`),
   各方案互不影响。点「并入」不会顺手折叠(头部 click 里 `closest("[data-ai-adopt]")` 早退)。
5. `run()` / 「强制无片单」开关切换时:清空 `adopted` / `adoptNotes`,并把展开态重置为 `{0}`。

## 边界与风险

- **旧格式兼容**:模型(或旧版 prompt 缓存)返回 `{"picks":…}` 时走 `legacy` 分支,退化为单方案,
  且顶层 `note` 不重复展示(旧格式的 note 已在 `options[0].note` 里)。
- **不改变单方案观感**:只有 1 个方案时卡片头文案为「AI 给出 1 个建议方案」,仍是一张卡 + 并入 A/B。
- **不改变隐私契约**:`biff.ai.dates.v1` 只落本机,不发往本站;`functions/` 不新增任何代理。
- **本地复检口径未放松**:每个方案各自跑同一份 `parseOnePlan`,不存在「多方案就少校验」。
- **上下文控制**:日期选择只影响 `buildPayload` 的过滤;多方案只影响**输出**长度(prompt 里明说最多 3 个)。

## 验收标准

1. `npm run typecheck` 通过。
2. `vite build` 通过。
3. 读代码核对:
   - `ai.ts`:`SYSTEM_PROMPT` 含 `"plans"`;`parseAiResult` 返回 `{ options, note, raw }`;
     `loadAiDates` / `saveAiDates` 使用 `biff.ai.dates.v1`。
   - `library.ts`:`selDates` 初值走 `loadAiDates()` 并过滤 `ctx.cat.dates`;
     chip / 全选 / 全不选三处都调 `commitDates()`;`dateBar` 标题 = `② 排哪几天(记住上次选择)`;
     `resultCard` 遍历 `p.options` 渲染 `optionCard`;`adopted` / `adoptNotes` 以方案下标为键。
4. 手工验收:开弹层 → 选 9/21 → 关闭 → 重开 → 仍是 9/21(记住);
   「全不选」后再重开 → 空(存档为空)。
