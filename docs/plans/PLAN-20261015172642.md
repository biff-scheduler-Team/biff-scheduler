# PLAN-20261015172642 — 稳住两条既有的 flaky E2E 断言（定位闪烁 / 快速投票图例基线）

## 目标

`PLAN-20261015170310`（排行榜弹层加「生成分享图」）合入 main 后，PR #36 的「受影响 spec ·
desktop-chromium」红了 **2 条既有用例**（都不是本需求新增的）：

- `e2e/react/redblack.spec.ts:990` 讨论区总览:目标被搜索框挡住时,自动清掉过滤再定位
  → `expect.poll(...classList.contains("rb-card-located")).toBe(true)` 10s 超时，`Received: false`
- `e2e/react/redblack.spec.ts:1751` 快速投票：左滑 / 右滑的跟手标记是实心底色，跳过药丸高亮不顶动右边「红榜」
  → `Math.abs(rightXLive - rightXIdle) <= 1` 实得 `3.671875`

且 **main 本身就带着这批红**（用户原话：「先推送 推完之后单独修问题」）。

## 范围

**做：**

- 把这两条断言改成**不会因测量方式本身而失败**的写法（断言强度不变，只去掉测量缺陷）：
  - `:990`：那一闪的 `rb-card-located` 是**瞬时**的（`LOCATE_BLINK_MS × LOCATE_BLINKS` = 3s），
    现在是**点完之后**用 `expect.poll` 隔一会儿看一眼 —— 改成**点之前**先挂 `MutationObserver`
    记录「这一闪发生过没有」，再 poll 那个**不会回退**的布尔量。不采样 ⇒ 不会漏。
  - `:1751`：现在是「第 1 次 `ready()`（load A）量的 idle 基线」减「第 2 次 `ready()`（load B）
    拖动中量的 live 值」—— **跨两次页面加载**比一个 1px 的判据。改成在**同一次加载内**
    重取基线再比。
- 回写本 PLAN（本轮只有测试口径变更，无产品代码变更）。

**不做：**

- **不按猜测改产品代码**。`:990` 的 CI 根因**未证实**（见下「已知未证实」）——
  在没拿到现场之前改 `RedBlackPage` 的定位逻辑＝拿猜测当依据。
- 不动 `:933`（同一支 `flashCard` 的另一条断言）：它目前没在 CI 上红过，本轮不扩大范围。
- 不降低任何断言的判据（超时、阈值、断言对象都不动）。

## 现状（代码事实）

- `RedBlackPage.tsx::flashCard`：`node.classList.add("rb-card-located")` →
  `node.animate([...], { duration: 1000, iterations: 3 })` → `animation.finished.then(remove)`。
  即那一闪存在约 3s，之后**没有任何痕迹**。
- `RedBlackPage.tsx` 定位 effect：`useEffect(..., [locateTick, visible, query, onlyMine])`，
  节点找不到时 `if (!query && !onlyMine) jumpTargetRef.current = null`（**放弃**）。
- `:1751` 的两次测量分别在 `ready(page, "/redblack?sort=red&vote=1")` 的前后 —— 那是两次
  `page.goto`（`helpers.ts::ready`），是**两个页面实例**。

## 方案取舍

| 备选 | 结论 | 理由 |
|---|---|---|
| 放宽 `:1751` 的 1px 阈值 / 拉长 `:990` 的 10s 超时 | 否决 | 那是**把判据调松**换绿灯（§8 红线 4 的同类）—— 真实位移与真实丢失都会被掩盖 |
| 删掉 `:990` 里那一闪的断言，只留「卡回来了」 | 否决 | 少一半覆盖：「自动清掉过滤」之后**还要求它被定位到**，这是这条用例的全部价值 |
| `:990` 改成 `MutationObserver` 记账 | **采纳** | 断的是同一件事、同一强度；去掉的只是「采样可能与 3s 窗口错开」这个**测量缺陷** |
| `:1751` 改成同一次加载内取基线 | **采纳** | 判据原话是「高亮**不顶动**右边图例」；跨两次加载比出来的差值里混了「两次加载本来就不同」的成分 |
| 顺手改 `RedBlackPage` 的定位「放弃」分支 | 否决（本轮） | 见下：那条分支在测试路径上**够不到**（总览的行只有在 `boardKeys` 命中时才是按钮），所以它**不是**本次红的原因 |

## 已知未证实（写清，不掩盖）

本地**复现不了**这两条：

- `:990` / `:1751` 单跑 × 3、整支 spec × 1、整支 spec `--workers=8 --repeat-each=2`（114 条）
  —— 全绿；本机 42.3s 跑完整支，CI 要 2.1m（≈3× 慢，2 核）。
- `:990` 的「放弃分支」被排除：总览那一行只有在 `film && boardKeys.has(key)` 时才是
  `<button class="rb-board-row">`，测试点的正是 `.rb-board-row` ⇒ 点击发生时 `boardFilmList`
  **非空**，effect 跑的那一刻 `visible` 也非空 ⇒ 节点本应找得到。
- `:990` 剩下的候选机制（**都需 CI 现场才能区分**）：
  ① 那一闪所在的 `<article>` 被 React 换掉（旧节点上的 class 随节点一起没了，
  而 `animation.finished` 在被换掉的节点上是 **reject**，所以连「摘 class」都不会触发）；
  ② 采样真的错开了窗口。①和②的修法不同：②由本次 `MutationObserver` 解决；
  ①若成立，则本次改动后仍会红 —— 那时它就是**产品 bug**（定位意图被丢弃 / 节点被重挂），
  按 CI 现场单独立项。
- PR #36 那次失败的 `playwright-report` artifact（206MB，含 trace）本轮**未下载**
  （用户跳过该命令），所以上面①/②还分不开。
