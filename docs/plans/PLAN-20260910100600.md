# PLAN 2026-09-10 10:06:00 — 修 hover 联动单向失效(正片卡/行程行自身外晕被自身 hover 阴影吃掉)

> 需求(用户原话):「有映后的场次 我把鼠标放在左侧卡片 只有右侧映后卡片会有高亮 如果放到右侧映后卡片 两张卡片都会有高亮效果」。
> 本文件 = 本需求唯一规划文档。

## 现状(代码事实,HEAD a339ba2)

- 联动实现在 `src/main.ts:601 applyHoverLink(host)`:取 `host.dataset.code` → `want = {code, 同冲突组…}` → 对 `HOVER_SEL = "#grid-scroll [data-code], #agenda [data-code]"` 全量打 `hl-card`(网格内)/ `hl-row`(行程内)。
  - 正片卡 `src/grid.ts:381` `card.dataset.code = s.code`;映后谈块 `src/grid.ts:458` `talkEl.dataset.code = s.code`(同 code)。
  - **结论:联动逻辑本身是对称的 —— 两张都会被打上 `hl-card`。问题纯在样式层。**

### 根因(specificity 冲突)

`src/style.css:182`
```css
@utility hl-card {
  border-color: var(--color-biff) !important;   /* ← 有 !important */
  box-shadow: 0 0 0 3px color-mix(…38%…);      /* ← 没有 !important */
  z-index: 6;                                    /* ← 没有 !important */
}
```

正片卡自带 `src/grid.ts:369`
`… transition-[box-shadow,border-color] … hover:shadow-[var(--shadow-hover)] hover:z-[2]`

Tailwind 生成的选择器与权重:

| 选择器 | 权重 | 属性 |
| --- | --- | --- |
| `.hover\:shadow-\[var\(--shadow-hover\)\]:hover` | (0,2,0) | box-shadow |
| `.hl-card` | (0,1,0) | box-shadow |
| `.hover\:z-\[2\]:hover` | (0,2,0) | z-index |
| `.hl-card` | (0,1,0) | z-index |

→ **hover 正片卡时,卡片自身的 `hover:shadow` 权重更高,把 `hl-card` 的外晕覆盖掉**;`hover:z-[2]` 同理把 `z-index:6` 压回 2。
→ `border-color` 因为有 `!important` 反而生效 —— 所以边框变红、外晕消失,视觉上"这张卡没高亮"。

### 为什么表现为"单向"

| 鼠标位置 | 正片卡状态 | 映后块状态 | 观察结果 |
| --- | --- | --- | --- |
| 正片卡 | **自身 hover → 外晕被 `hover:shadow` 吃掉**(仅剩红框) | 未 hover → `hl-card` 外晕完整生效 | 只有右侧亮 ✅复现 |
| 映后块 | 未 hover → `hl-card` 外晕完整生效 | 自身 hover,但 talkEl **没有** `hover:shadow` 类 → 外晕完整 | 两张都亮 ✅复现 |

映后块 `src/grid.ts:475` 的 className 只有 `border/rounded/flex…`,无 `hover:shadow` —— 这正是它两个方向都正常的原因。

### 同类问题(一并修)

`src/agenda.ts:114/115` 行程行同样带 `hover:shadow-[var(--shadow-hover)]`(无 `hover:z-*`):
→ hover 行程行**自身**时,行自己的 hover 阴影吃掉 `hl-row` 外晕(仅剩红框,`hl-row` 的 `border-color` 有 `!important` 所以边框仍红);
→ 而网格侧那张卡此时未 hover,外晕正常。
即「网格 ↔ 行程」双向联动也是**同一种单向失效**,只是本次用户先撞上 GV 映后这一对。

## 方案

只改 `src/style.css` 两个 `@utility` 的权重,不碰任何 TS/几何/交互逻辑:

1. `hl-card`:
   - `box-shadow: … !important;` ← 修本次 bug 主因
   - `z-index: 6 !important;` ← 修 `hover:z-[2]` 把联动卡压回 2、外晕可能被相邻卡(同层后绘制)遮住
2. `hl-row`:`box-shadow: … !important;` ← 修同类问题(行程行自身 hover 不亮)

**为什么用 `!important` 而不是别的**:同文件 `border-color` 已是该写法(注释 `style.css:194` 亦说明"用 `@utility` + `!important` 压 `bg-card`"是既有约定);`@utility` 生成的是单类选择器,不 `!important` 必输给 Tailwind 的 `hover:` 变体。作用域仅"联动高亮态",卡片**独立** hover 的普通阴影(`hover:shadow-[var(--shadow-hover)]`)保持不动 —— 那是基础反馈语言,不该改。

**不改**:`hover:shadow` / `hover:z-[2]` 本体、`hl-card`/`hl-row` 的 `border-color`(已正确)、`applyHoverLink` 的 JS 逻辑(已对称)、`#grid-scroll [data-talk]:hover { opacity:1 }`(作用在不同属性,无冲突)。

## 改动清单

1. `src/style.css`:`hl-card` 加 `box-shadow` / `z-index` 的 `!important`;`hl-row` 加 `box-shadow` 的 `!important`(1 处,2 个 utility)。
2. `docs/plans/PLAN-20260910100600.md`:本文件。
