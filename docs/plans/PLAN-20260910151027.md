# PLAN-20260910151027 — 全组件对齐审查:统一「信息/状态靠左、操作按钮靠右」,修正按钮落位

## 背景 / 用户诉求

> 请你排查下所有组件 有没有那种全部左对齐右对齐等等不符合设计 按钮位置不合理的 然后改一下

现状(逐文件读代码定位):顶栏 / 面板头 / 弹层头 / 列表行操作 / 设置弹层底部主按钮
**已经**是「左 = 信息与状态,右 = 操作按钮」的语言(见 `PLAN-20260910101115` 顶栏右对齐、
`PLAN-20260910095828` 右组 `ml-auto`、`PLAN-20260910135734` 设置弹层主按钮 `justify-end`)。
但下面几处**没有跟上同一套语言**,读起来「一排全是左对齐」或「主按钮跑到左下角」:

| # | 位置 | 现状 | 问题 |
|---|---|---|---|
| 1 | `main.ts::openTalkMinModal` 底部操作行 | `flex gap-[10px] mt-1`,顺序 `[保存][跟随默认]` | 与设置弹层「主操作独占一行**右对齐**」相反:主按钮在左下角,与全站唯一亮色主按钮的落位语言冲突 |

## 设计决策(本轮定死的对齐语言)

1. **信息 / 状态在左,操作按钮在右** —— 与既有 `readyBar` / `resultCard` / 列表 `ops`
   (`justify-end`)/ 弹层头(`← 返回`+`✕` 靠右)/ 设置弹层底部主按钮一致。
   实现手法:状态元素在前 + 操作组包一层 `ml-auto`(`flex-wrap` 折行后仍靠右,比 `flex-1` 占位符稳)。
2. **弹层底部主操作右对齐,次要操作在其左侧**(`[次要][主]`,主按钮贴右下角)——
   `openTalkMinModal` 对齐 `openSettings`。
3. **唯一例外 = AI 面板的 `runBar`**:主按钮文案自带步骤号「④ 开始 AI 排片」,
   保持左对齐以贴合 ①②③④ 的步骤流(PLAN-20260910135532 §二 态 B 草图即左对齐),本轮不动。
4. 不动任何**业务语义 / 数据契约 / 类名 token**,只改容器 flex 排布与顺序。

## 边界与风险

- `main.ts` / `library.ts` / `modal.ts` 是并行会话热点文件(约定 §一)→ 提交按
  SKILL `parallel-agent-safe-commit` 只带自己 hunk;若有在途改动走隔离 worktree。
- **Tailwind v4 只生成源码里完整出现的字面量类**:本轮新增 `ml-auto` / `flex-1 min-w-0` /
  `justify-end` 均为既有高频类(顶栏、列表 ops、设置弹层已在用),构建后 `grep` 产物 CSS 核对命中。
- 同文件多处改动**串行** Edit(约定 §一),改完 `npm run typecheck`。
