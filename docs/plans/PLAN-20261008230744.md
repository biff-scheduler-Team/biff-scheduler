# PLAN-20261008230744 — 取消「数据更新」提醒模块

## 目标

移除顶栏的「数据更新」入口及其弹层 —— 即 2026-09-14 立的排期更新提示（`PLAN-20260914192552`）整条链路。

用户原话：

> 取消 数据更新 提醒模块

## 范围

**做：**

- 前端：删掉顶栏 `<DataUpdateButton />` 入口（`App.tsx`）、弹层组件（`components/ChangelogDialog.tsx`）、
  加载与纯函数（`src/changelog.ts`）、`store.tsx` 里的 `loadChangelog()` 调用、`types.ts` 里的 `Changelog*` 类型。
- 数据管线：删掉产物 `apps/web/public/changelog.json` 与生成脚本 `tools/build_changelog.py`
  （唯一消费者是上述提醒模块，取消后即为死代码）。
- 测试：删 `apps/web/tests/changelog.test.ts`、`e2e/react/data-update.spec.ts`；
  删 `catalogue-data.test.ts` 里针对 `changelog.json` 产物的 describe。
- 契约表：删 `scripts/test-map.json` 的 `data-update` 规则，以及 `pni` 规则里对 `data-update` spec 的引用。
- 口径文档：删 `docs/CONVENTIONS.md` 里「排期更新日志」条目，并改写 `merge_schedule.py` 幂等说明中对
  `changelog.json` 的引用（幂等沿用 `generated_at` 的理由不依赖该产物）。
- 注释：清掉 `util.ts` / `actions-copy.ts` / `style.css` 里指向已删模块的说明。

**不做：**

- 不删 localStorage 键 `biff.dataver.v1` —— `biff.*` 键**只增不改**（旧部署仍可能写入，删键无收益且有风险）。
- 不改 `tools/merge_schedule.py` 的**行为**（只动注释表述）。
- 不动历史归档：`docs/plans/PLAN-20260914192552.md`、`docs/history/*` 保持原样（历史记录）。
- 不动 `apps/web/src/util.ts::filmNodeKey()` 的实现（它现在没有 changelog 消费者，但仍是全站身份口径）。
- 不动 `legacy/`（只读回退件）。
- 不动工作树里在途的红黑榜海报改动（`PLAN-20261008225335`）；`PLAN.md` 头部「最后更新」待该在途改动落地后再回写。

## 方案取舍

| 备选 | 结论 | 理由 |
|---|---|---|
| 彻底移除（入口 + 逻辑 + 产物 + 脚本 + 测试） | 采纳 | 用户说「取消模块」；保留无消费者的 `changelog.ts` / 产物 / 脚本即死代码，违反「同一口径不留第二份实现」 |
| 只在顶栏隐藏入口、代码全保留 | 否决 | 会留下永不执行的加载、产物、脚本与测试，且 `test-map` 仍要求跑 `data-update` spec |
| 保留 `changelog.json` 产物供将来恢复 | 否决 | 没有消费者的产物会在每次排期更新时继续被构建，且产物校验测试会一直挂着 |
| 删 `biff.dataver.v1` 键 | 否决 | 违反数据契约「`biff.*` 只增不改」 |

## 验收标准

1. 顶栏不再出现「数据更新」按钮；`/schedule` 页面无该元素。
2. `npm run verify:quick` 通过（typecheck / lint / 单测 / `check:repo` / `check:test-map`）。
3. `node scripts/affected-specs.mjs --files <本轮改动路径>` 不再输出 `data-update`。
4. `changelog.json` / `build_changelog.py` 在仓库中不存在，且无任何 import / 引用残留。
