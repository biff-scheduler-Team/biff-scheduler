## 1. 接口取舍(本机实测,2026-09-12)

交接文档(`rev-douban/docs/subject-api-handoff.md` §9.5 / §11.5)里和「相关」沾边的三个口:

| 路径 | 实测 | 对本站的用处 |
|---|---|---|
| `GET /api/v2/movie/{id}/recommendations` | 200,长度为 20 的 **movie 数组**(2026 新片同样有) | **采用**。字段:`id/title/type/card_subtitle/rating/url` |
| `GET /api/v2/movie/{id}/related_subjects` | 200,键 `related_subjects`+`ost`;本届样例经常是空,有内容时是「原著小说」一类跨类型 | **不用**。排片工具要的是电影 |
| `GET /api/v2/movie/{id}/related_items` | 200,是豆列 / 榜单卡,不是影片列表 | **不用** |

抽样 12 部已映射影片,9 部的 20 条推荐里至少有 1 部也在本届片目里
(开幕片《彼此的日夜》4 部,《天使之卵》3 部,《无用之人》8 部)。
这是排片工具该接的数据:不是再跳一次豆瓣搜索,是「豆瓣觉得相关、本届正好也在放」。

仍只走离线管线(浏览器设不了 UA、无 CORS、`app_secret` 不能下发 —— 与 D2/D6 一致)。

## 2. 产物

```
tools/build_douban_related.py     离线:unique subject_id → /recommendations → public/douban-related.json
src/related.ts                    加载 + 按当前 mappings 把推荐拆成「本届 / 站外」
src/modal.ts                      资料弹层豆瓣区下方追加两段列表
```

`public/douban-related.json`:

```json
{
  "generated_at": "…",
  "source": "GET /api/v2/movie/{id}/recommendations",
  "recs": {
    "<subject_id>": [
      { "id": "1477317", "title": "悲伤的贝拉多娜", "year": "1973", "rating": 8.1, "url": "https://movie.douban.com/subject/1477317/" }
    ]
  }
}
```

- 键 = 豆瓣 subject_id(字符串),与 `douban.json` 的 `subject_id` 对齐
- `year` 从 `card_subtitle` 开头四位取出;取不到就省略
- `rating` 仅在 `count > 0` 且 `value > 0` 时写入(避免把「暂无评分」画成 0.0)
- 不存海报 URL(豆瓣图床 Referer 防盗链,外链必 418)
- 「是不是本届」**不写进产物**:前端用当前 `store.mappings` 现查,映射续跑后不用重抓推荐

风控口径与 `douban_match.py` 同源(`{103,1005,1309}` → 停轮保进度)。`--delay` 默认 1.2。

## 3. 前端

资料弹层(排期片 / 目录片同一块):

1. 有映射且该 subject 有推荐 → 在「豆瓣」区下方追加
2. **本届也在放**:推荐 id 命中当前 mappings 的那些;整行可点,压栈打开那部的资料弹层
   (有场次 code → `showFilmModal`,只有 `f###` → `showCatalogFilmModal`;「← 返回」回当前片)
3. **豆瓣也推荐**:其余,最多 6 条,外链到豆瓣条目
4. 两段都空 → 不占位(与 extras 同:增强,不是运行前提)
5. 本届行若目录有海报,用本地 `/posters/…`;没有就不留空列

PWA 已 `globPatterns: **/*.json`,新文件自动进预缓存。

## 4. 不做

- 不把推荐写进 `douban.json`(那份是映射表,prune 靠 `title_en` 防撞号,不该混进列表)
- 不在浏览器打 Frodo
- 不抓 `/related_subjects` 的图书 / OST
- 不下载推荐海报(本届片已有海报管线)
