# PLAN-20261005225416 — 吃喝页「添加心仪的店」支持地图定位(可拖拽 marker)

## 目标

> 用户原话:「现在添加一个我喜欢吃的店 它大概逻辑是怎么样的呢 我希望就是能够有一个
> Google Map 的组件 然后或者说怎么样去定位」→ 经两轮确认后收敛为:
> **在已有「吃喝」模块的「添加心仪的店」弹层里嵌入一张可交互地图,支持拖拽 marker 微调坐标;
> 地图数据源用 Naver/Kakao(不引新 npm 依赖);坐标随店铺一起本地保存 / 账号同步。**

注意:需求的**真实缺口不是「添加店铺」**(那已存在),而是「添加时**没有坐标**、不能在地图上定位」。

## 范围

**做:**

1. 「添加心仪的店」弹层新增**可交互地图**(Naver Maps JS API 优先,Kakao Maps JS 备选),按需动态加载。
2. 三条定位入口:**① 搜店名**(复用已有 `/api/eats/lookup` 拿坐标)、**② 地图点选 / 拖拽 marker**、**③ 当前定位**(`navigator.geolocation`)。
3. `EatSubmission` 增加可选 `lat` / `lng`(可能含 `provider` / `placeUrl`);卡片上有坐标时,地图链接从「搜索」升级为**精确坐标**打点。
4. 前端获取地图 key 的**运行时**通道(见「集成点」),无 key 时**静默降级**:弹层退回现有手填表单,地图区不渲染,不出现任何报错噪声。

**不做:**

- 不做评分 / 评论 / 收藏数(现有上游接口本就不返回评分,`place-lookup.ts:8-10`)。
- 不做「附近 N 公里」「按距离排序」等空间查询(无 PostGIS;本期坐标只用于打点与跳转)。
- 不改 `public/eats.json` 的静态清单结构、不改 `tools/build_eats.py`(静态店仍无坐标,这是**已知且接受**的)。
- 不引入 Google Maps(理由见现状 #6,与既有决策冲突,已否决)。
- 不引任何新 npm 依赖(地图 SDK 走外部 `<script>`,不进 bundle)。
- 不做「登录后才同步」以外的任何新后端存储(复用既有 `biff.*` 同步链路)。

## 关键前置(硬阻塞 —— 只有用户能做,代码绕不过去)

**可交互地图需要一把「地图 SDK 密钥」,它与现有两把搜索密钥不是一回事:**

| 需要注册 | 去哪儿 | 与现有的区别 |
|---|---|---|
| **Naver Maps JS API 的 Client ID(`ncpKeyId`)** | Naver Cloud Platform 控制台 → Maps → Web 服务 URL 登记 | ≠ `NAVER_CLIENT_ID`(那是 Naver Open API 的搜索密钥,两个产品线) |
| 或 **Kakao Maps JS SDK 的 JavaScript key** | Kakao Developers → 플랫폼 > Web > 사이트 도메인 登记 | ≠ `KAKAO_REST_API_KEY`(REST key 不能用于 JS SDK) |

两把都要求**登记域名白名单**,至少要有:

- `http://localhost:31026`(本机 dev,Vite `strictPort` 端口,见 `vite.config.ts:109-112`)
- `https://biff.lcandy.co`(生产)

> ⚠ 这类 key 在脚本 URL 里**天生公开**,安全边界靠**域名白名单**而非保密 —— 与现有两把需要保密的
> REST 密钥是**不同的安全模型**,别混为一谈。
> **在拿到 key 之前,本 PLAN 的「做」第 1 条无法验证**,只能先把第 2/3/4 条的骨架与降级路径做掉。

## 方案取舍

| 备选 | 结论 | 理由 |
|---|---|---|
| Google Maps(用户最初提法) | **否决** | 韩国地图数据受出境限制,覆盖 / 导航远弱于本土;且与 `place-lookup.ts:3-6` 既有决策冲突 |
| Naver Maps JS API | **采纳(首选)** | 韩国店收录最全,与现有 lookup「Naver 优先」口径一致 |
| Kakao Maps JS SDK | 备选 | 亦可用;若 Naver 控制台注册受阻再切 |
| 嵌 Naver 店铺页 iframe | 否决 | **无 key、可白嫖**,但拿不到可拖拽 marker;且上游可能 `X-Frame-Options` 拒绝被嵌 |
| 静态地图图片 | 否决 | 仍需 key,且不可交互,不满足「拖拽微调」 |
| 引 npm 地图库(mapbox/leaflet + 瓦片) | 否决 | 违反 §5 依赖纪律(需量化 gzip 增量),且国内/韩国瓦片来源不如本土 SDK 稳 |
| **运行时端点下发 key** | **采纳** | 前端无 env 注入机制(现状 #8);且 key 本就公开,与现有 `/api/eats/lookup` 的「服务端持有配置、前端探测可用性」模式一致 |
| 构建期 `define` 注入 key | 备选 | 需给 Cloudflare 构建加变量,引入现仓库没有的新机制,成本更高 |
| map key 与 `lat/lng` 同轮交付 | **否决** | 无 key 时地图画不出来;降级路径必须**先于**地图单独可验证 |

## 集成点(既有机制逐条怎么处理)

1. **数据查询**:复用 `eats.ts::lookupPlace()`(`:157`)拿 `PlaceHit.lat/lng`,**不新写**第二个查询口径。
2. **降级**:照抄 `eats.ts:131-132` 的「一次判定、全程静默」手法 —— 新增 `mapDisabled()` 状态,
   端点回 503 即整页不渲染地图,用户看不到任何「定位失败」。
3. **弹层**:继续用 `components/spectrum` 的 `Dialog`(`EatsPage.tsx:21-35` 已在用),不另造骨架。
4. **地图链接口径**:坐标跳转 URL 一律从 `legend.ts` 取(`eats.ts:12` 明确「本模块不自己拼 URL」),
   需要新增「按坐标生成链接」的模板也放 `legend.ts`,禁止在组件里手拼。
5. **迁移**:照 `ticketinfo` 先例(`state.ts:41-43`、`ticket-info.ts:92-97`)——
   读 `biff.eats.v1` → 转 `biff.eats.v2` → **删 v1**;`sync-data.ts` 按前缀自动收纳,**不改同步层**。
6. **key 下发**:新增 `GET /api/eats/map-config`,未配置时回 `503 {error:"MAP_DISABLED"}`,
   **与 `/api/eats/lookup` 同款语义**(`index.ts:1365-1393`);密钥只走 `wrangler secret`,不进 `wrangler.jsonc`。

## 数据契约

- 由 `biff.eats.v1` → **`biff.eats.v2`**(AGENTS §5 / 红线 6:改结构必须「新 key + 一次性迁移 + 删旧 key」)。
- v2 记录在原字段基础上**追加可选** `lat?: number`、`lng?: number`(以及可选的 `provider` / `mapUrl`)。
- 迁移为**纯加法**:旧记录无坐标照常可读;迁移脚本单测必须覆盖「v1 有数据 / v1 为空 / v1 损坏」三态。
- 上限 `MAX_SUBMISSIONS = 200`(`eats.ts:59`)不变;坐标不显著增大单值,但需复核 64KB 服务端单值上限。

## 风险

1. **地图 key 拿不到** → 第 1 条交付物无法验收。**故 PLAN 明确分两批交付**:先「坐标 + 降级」,后「地图 UI」。
2. **外部 SDK 是新的运行时依赖**(vendored via CDN)→ 必须**动态按需加载**(仅在打开添加弹层时注入 `<script>`),
   不得进首屏;加载失败即降级,不得白屏。
3. **PWA / 离线**:电影节现场网络不稳(`vite.config.ts:158-160`),地图 SDK 缓存策略需确认不会拖累 SW 预缓存。
4. **上游配额**:现有 lookup 限流 30/分(`rate-limit.ts:71`);地图 SDK 若走同一 key 需确认配额是否独立。

## 验收标准

1. **迁移**:单测覆盖 `v1 → v2` 三态(有数据 / 空 / 损坏),且断言迁移后 `biff.eats.v1` **已删除**。
2. **降级**:未配 `map-config` 密钥时,打开「添加心仪的店」——表单可用、**无地图区、无任何错误提示**;
   `eats.ts` 的 map 探测**最多打一次**端点。
3. **坐标落盘**:经「搜店名」选中一条 `PlaceHit` 后,保存的 `biff.eats.v2` 记录含正确 `lat/lng`(断言数值)。
4. **地图交互**(拿到 key 后):弹层内地图可拖动 marker,松手后保存的坐标 = 拖拽后位置。
5. **不改静态清单**:`public/eats.json` 与 `tools/build_eats.py` 的 diff 为空。
6. **回归**:`eats` 相关既有单测全绿;`e2e/react/eats.spec.ts` 扩展后通过(新增『无 key 时无地图且表单可用』断言)。
7. 命令:`npm run verify:quick`(typecheck + lint + 单测 + check:repo / check:test-map)。
