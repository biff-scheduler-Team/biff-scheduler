# PLAN-20260922103307 — 「我的行程」页信息架构收拾（工具栏 / 日期条 / 保存入口 / 方案删除）

## 目标

用户对「我的行程」页提了四条界面问题（原话逐字保留）：

> 1. 核心操作按钮悬空（“保存当前方案”）
> 问题：底部的“保存当前方案”按钮目前处于日程表和已保存方案列表之间的空白处，左侧对齐但上下留白较大，视觉上显得比较孤立，且容易随着内容变长而被挤到屏幕下方（甚至溢出屏幕）。
> 建议：
> 方案 A（建议）：将“保存当前方案”提至顶部 Header 或日程表右上角（作为全局/核心操作），比如放在“日程表 / 卡片”视图切换按钮的旁边，提高可见度，避免频繁滚动到底部保存。
> 方案 B：如果属于针对下方列表的生成/保存操作，可以将其收纳进“已保存方案”区块的卡片头部或作为区域 Top Bar，明确其作用域。
>
> 2. 顶部工具栏与状态标签排布重叠/过于分散
> 问题：“添加转票场次”、“仅看实际行程”与右侧的“日程表 / 卡片”同处一行；紧接着下一行又出现了“时间紧张”、“时间重叠”、“韩国时间 KST”等状态/过滤 Tag 以及右侧的“小 / 默认 / 大”缩放按钮。两行控件功能混杂（有切换、有过滤、有视图调节），使得页面视觉焦点分散。
> 建议：
> 将过滤/状态控制（时间紧张、时间重叠、仅看实际行程）统一归类在左侧/同一工具栏。
> 将视图控制（日程表/卡片、缩放“小/默认/大”）统一放置在右侧工具栏，形成标准的 Left: Operations / Right: Views & Actions 布局格局。
>
> 3. 日历/日期选择器位置
> 问题：日期卡片（周二 6、周三 7...）处于工具栏下方，但它本身是一个高频使用的导航/筛选控件。
> 建议：把日期切换栏向上调整，紧贴在顶部统计信息（11部电影 5天...）下方，作为主视图的全局日期 Filter，能让页面层次从“顶部概览” -> “日期导航” -> “具体时刻表”更顺畅。
>
> 4. 底部方案列表的“删除”按钮
> 问题：下方“方案 2”卡片右下角的“删除”按钮过于偏右且字号较小，存在误触风险，且与方案名称“方案 2”距离过远，视觉关联度较弱。
> 建议：将“删除”按钮固定在方案卡片的右上角或右侧垂直居中位置，并采用标准二次确认（Popconfirm）或弱化为图标样式（如垃圾桶 Icon），提升警示度与易用性。

用户对第 1 条已明确选了 **方案 A**（“（建议）”）。

## 范围

**做：**

### A. 「保存当前方案」提到顶部工具栏右侧（第 1 条，方案 A）

- 从 `panels` 里删掉 `.agenda-save` 整块（按钮 + 说明段），按钮改挂顶部工具栏右组、
  紧挨「日程表 / 卡片」之后，成为工具栏最右的主操作（`Button`，仍是主色填充）。
- 保留原语义与禁用条件：`!actualOnly && codes.length > 0` 才渲染；`firstLayerClash` 时 `isDisabled`。
- 撞车时那句解释（“第一顺位有撞车，请先让路再保存。”）**不能丢** —— 改成工具栏里的
  一条 muted 小字，只在被禁用时出现（`title` 在 `disabled` 按钮上弹不出来，故不做成 tooltip）。

### B. 两行控件并成一条工具栏，左操作 / 右视图（第 2 条）

- 把画布图例（时间紧张 / 时间重叠 / 韩国时间 KST）与缩放档位（小 / 默认 / 大）从
  `ScheduleGantt` 的 `.schedule-legend` 行里**提出来复用**，由 `AgendaPage` 摆进同一条工具栏：
  - 左组：图例 + `添加转票场次` + `仅看实际行程（N）`
  - 右组：`日程表 / 卡片` + `小 / 默认 / 大` + `保存当前方案`
- 单一实现，不写第二份：`ScheduleGantt.tsx` 导出 `GanttLegendChips` 与 `GanttZoomControls`
  两个小组件；排片表档仍把二者摆在原来的 `.schedule-legend` 行里（排片表**零变化**）。
- 图例与缩放是**画布**的东西，只在日程表视图且有可排场次时出现（卡片视图 / 空画布不显示）。

### C. 日期条上移到概览条下方（第 3 条）

- 把 `.date-strip.calendar-strip` 从 `.agenda-gantt` 容器里提出来，成为 `.agenda-page`
  的直接子元素，位置在 `.summary-strip` 之后、工具栏之前。
- 条件与原先一致：仅日程表视图、且 `days.length > 0`（镜头一张都没标「已抢到」时整条不出现）。
- 层次变成：页头 → 概览条 → 日期导航 → 工具栏 → 画布 / 卡片。

### D. 已保存方案的「删除」钉到卡片右上角 + 二次确认（第 4 条）

- `.saved-plan` 从「左右两栏（内容 | 删除）」改成「上：方案名 + 删除｜下：摘要 + 查看场次」，
  删除按钮与方案名同行、右端对齐 —— 与它要删的对象贴在一起。
- 保留「删除」文字（不做纯图标：图标更难发现，且用户给的是「二次确认**或**图标」二选一），
  加 `SettingsDialog::ClearDialog` 同款的 `DialogTrigger + Dialog size="S"` 二次确认
  （标题「删除方案 N？」、正文说明不可恢复、`取消` / `确认删除`（negative））。
- `aria-label` 仍是 `删除${plan.name}`（既有 E2E 的关系选择器不动）。

### E. 测试与文档

- `e2e/react/agenda-gantt.spec.ts`：新增一条用例钉住 A–C 的布局（工具栏只此一条、左组含图例 /
  操作、右组含视图 / 缩放 / 保存；日期条在概览条之下、工具栏之上）。
- `e2e/react/parity-agenda.spec.ts`：新增一条用例钉住 D（删除按钮在卡片右上角、与方案名同行；
  点它先出二次确认，确认后才真的删）。
- `e2e/react/review-state-export.spec.ts`：另一标签页删方案的用例补上「确认删除」那一步。
- 本 PLAN 文件；`PLAN.md` 文档头「最后更新」一行。

**不做：**

- **不动排片表（`/schedule`）**：`GanttLegendChips` / `GanttZoomControls` 只是从
  `ScheduleGantt` 里提出来复用，排片表档的 DOM 顺序、类名、样式逐字不变
  （`schedule-toolbar.spec.ts` / `parity-schedule.spec.ts` 是这条的守卫）。
- 不动画布几何 / 缩放口径（`app/vertical-schedule.ts`、`SIZE_OPTIONS`、`setSettings({zoom})` 都原样）。
- 不动顺位 / 冲突组 / 「仅看实际行程」的筛选语义（只是把开关挪了位置）。
- 不动 `biff.*` 任何键，无迁移。
- 不改「已保存方案」的存储 / 导出范围口径（`plans.ts` / `ExportDialog` 不碰）。
- 不引入 Popconfirm 之类的新组件（仓库既有二次确认就是 `DialogTrigger + Dialog size="S"`）。

## 方案取舍

| 备选 | 结论 | 理由 |
|---|---|---|
| **D1** 第 1 条走「方案 B」（收进「已保存方案」区块头） | **否决**（用户已选方案 A） | 「保存当前方案」保存的是**当前行程**（每组第一顺位 + 共同场次），不是下方列表的一部分；放进列表头反而把作用域说错 |
| **D2** 保留 `.agenda-save` 那一块，只在页面上挪位置 | **否决** | 用户要的是「提至顶部 Header / 右上角」；留着它就只能还在两段内容之间，问题原样复发 |
| **D3** 两行控件保留，只调对齐 | **否决** | 用户点名的是「两行控件功能混杂」，只调对齐不解决归类 |
| **D4** 图例 / 缩放留在 `ScheduleGantt` 里，用 CSS 把两条行「拼」成一行 | **否决** | 两行分属不同 DOM 子树（`.agenda-actions` 与 `.vertical-schedule`），CSS 拼不到一起 |
| **D5** 图例 / 缩放各写一份到 `AgendaPage` | **否决** | 违反「同一口径只允许一处实现」：缩放档位表 `SIZE_OPTIONS` 与 `setSettings({zoom})` 会变成第二份 |
| **D6** 图例 / 缩放常驻（卡片视图也显示） | **否决** | 卡片视图没有画布，图例与缩放点了没有任何效果 —— 死控件比不显示更糟 |
| **D7** 日期条放工具栏**下方** | **否决** | 用户明确要求「紧贴在顶部统计信息下方」 |
| **D8** 日期条在两个视图都显示 | **否决** | 卡片视图本身按日整段列出（可折叠），再给一条单选日期条会产生两套「看哪天」的入口 |
| **D9** 删除按钮做成纯垃圾桶图标 | **否决** | 用户给的是「二次确认**或**图标」二选一；纯图标发现性更差，配二次确认已足够防误触 |
| **D10** 删除按钮只挪位置、不加确认 | **否决** | 用户点名「存在误触风险」，删除不可撤销，仓库既有二次确认范式现成 |

## 验收标准

1. 「我的行程」页只有**一条**工具栏（`.agenda-actions`）：图例 + 添加转票场次 + 仅看实际行程 在左，
   日程表/卡片 + 小/默认/大 + 保存当前方案 在右；页面上不再有第二行状态 / 缩放控件。
2. 「保存当前方案」始终在首屏工具栏里（不再出现在日程表与已保存方案之间的空白处）。
3. 日期条（`.date-strip.calendar-strip`）在概览条（`.summary-strip`）**下方**、工具栏**上方**；
   卡片视图 / 「已抢到」为零时不出现。
4. 「已保存方案」每张卡片的「删除」与方案名同行、在**右上角**；点击先出「删除方案 N？」确认，
   确认后才真的删掉。
5. 排片表（`/schedule`）的图例行 / 缩放完全不受影响。
6. `npm run verify:quick`（check:repo + check:test-map + typecheck + lint + 单测）全绿。
7. `npx playwright test -c playwright.react.config.ts e2e/react/agenda-gantt.spec.ts
   e2e/react/parity-agenda.spec.ts e2e/react/schedule-toolbar.spec.ts e2e/react/parity-schedule.spec.ts
   e2e/react/review-state-export.spec.ts e2e/react/screening-social.spec.ts --project=desktop-chromium` 全绿。
